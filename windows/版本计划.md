# Doyah Studio · Windows 版版本计划（功能模块地图 + 子版本进度）

> 本文是 **Windows 侧（温迪小河马）** 自己的版本计划，落点 = 本目录（实现层，直接落笔、不走提案）。
> 跨仓总节奏与三书契约仍以 `Docs/发布计划.md`（macOS 侧定稿）为准；本文只写 Windows 侧那一半，**不代改对侧内容**。
> 对方针（模块大版本）依 2026-10-02 老板口径；模块内容依三书既有条目 + 本侧落点 `Docs/概要设计.md` §8.5（`[独占:windows]`）。

## 0. 版本号怎么读

| 写法 | 含义 |
|---|---|
| **alpha 1.0 / 2.0 / 3.0 / 4.0** | **功能模块大版本** —— 一个大版本只装一个模块：**1 = Database（数据库）· 2 = Workspace（工作区）· 3 = Notes（笔记）· 4 = Retro（复盘）** |
| **1.1 / 1.2 / 3.1 / 3.2 …** | **同一模块内的进度子号** —— 一条主线走一段落，就递一个小号；**大号不变**（模块没换就不换大号） |
| **`alpha<大号>.<子号>`**（如 `alpha1.3`） | **出包标签** —— 包标签 = 里程碑号 + 子号，与移动端（DoyahNotes §5）同一命名法；小改动 +1 |
| **Alpha 1~4 / Beta 1** | **跨仓里程碑** —— 与 macOS 侧同一套地图（`Docs/发布计划.md` §2）；**里程碑号就是模块号** |

两条纪律：

1. **里程碑号不由本侧自己编** —— 按总地图走（1 = Database · 2 = Workspace · 3 = Notes · 4 = Retro；全量那一版 = `beta1.0`）。
2. **Windows 的 `alpha<号>` 与 macOS 的同名里程碑不是同一个包** —— 两端各出各的包，**本侧只借用里程碑号**，不改对侧出包节奏、不主张跨端同包（跨端一致的那部分仍按 §8.5.4「一样」清单判）。

### 0.1 老板已拍板的三条（2026-10-02）

| # | 定案 | 落法 |
|---|---|---|
| 1 | **节奏 = 里程碑编号对表，Windows 按自己的步子递子号** | 大号（1/2/3/4）与 macOS 侧同一套地图、**编号对得上**；Windows **不承诺** macOS 的逐版日期，只在本模块真正可用时递号出包 |
| 2 | **范围 = 每个模块做完整版，但日期不追 macOS** | 本侧**不做「预览版凑数」**；每个大版本按 §2 的出口做成可用功能，出包时机自定 |
| 3 | **子号 = 进度段位（走完一段主线才 +1）** | 子号**不是出包流水**；一个子号 = 一段可验收的场景，验收不过不递号。小修小补不涨号（改版记在包内与人工测试清单里） |
| 4 | **快车道：macOS 侧 Database / Workspace 基本开发完 ⇒ 本侧照着三书实现，不再重新设计**（2026-10-02 老板原话：「Windows 版本可以照着三书完成 win 平台的开发即可，任务进度可以加快」） | ① **规格来源**：三书（需求规范书 / 产品能力规划说明书 / 概要设计）＝唯一事实源，**本侧不重做设计、不发问卷**；② **可照抄的**：对侧已冻结的契约与行为（§8.5.4「一样」清单）；③ **不许照抄的**：对侧的**实现细节**（语言 / 库 / 目录形状）—— 那属 `[独占:macos]`，本侧按自己的栈实现；④ **省掉的那一段**：设计 / 选型 / 需求确认的时间，直接进实现与自测 |

**日历（不承诺日期的落地写法）**：本表**不写交付日**，只写**次序 + 出口**；真到要定日子那天，由本侧按当时实际进度给「最早可出包日」，**不拿日期倒逼虚报进度**。

**与 macOS 侧的关系（一句话）**：**同号不同包** —— 里程碑号相同（都是 Alpha 2 = Workspace），但两端各出各的包、各走各的日期；跨端必须一致的那部分仍按 §8.5.4「一样」清单判。

**一处如实登记（交付判据面）**：按总表 `Docs/发布计划.md` §3「不做」与 §9，Windows 版**不进 macOS 侧的交付判据**（对 macOS 的 alpha / beta 交付不构成阻塞）。本专册管的是**本侧自己的功能地图与出包次序**；要不要让 Windows 进交付判据，是要老板另拍板的一件事（本文不改既有口径）。

### 0.2 数据库测试环境（本机实测，2026-10-02）

**跑 1.x 的「真跑通」这一步，缺一样东西：能连上的 PostgreSQL 口令。** 实测如下：

| 项 | 实测结果 | 对 1.x 的影响 |
|---|---|---|
| **PostgreSQL 18** | 服务在跑（`postgresql-x64-18`）、**端口 5432 通** | **可用** —— 只差口令 |
| 认证方式 | `pg_hba.conf` 本机回环 = **scram-sha-256**（要口令；没有 trust 档） | 无口令就连不上；本机没有 `pgpass` 档 |
| 客户端工具 | `psql` 在 `C:\Program Files\PostgreSQL\18\bin` | 可用（造夹具 / 对照读数） |
| **MySQL** | 有客户端（`D:\Program Files\mysql-8.4.10-winx64`），**服务未起、3306 不通** | 1.8 段的 MySQL 面仍然待老板重新拍板后再排 |
| SQLite | 无 `sqlite3` 命令行；**但 `rusqlite` + `libsqlite3-sys` 已在本机 cargo 缓存里** | 3.x 的笔记本地库**不需要联网取依赖** |
| Docker / Podman | 都没有 | 起不了临时库；只能用本机那台 PG 18 |
| PostgreSQL 驱动 crate | `tokio-postgres` / `sqlx` **不在**本机 cargo 缓存（缓存里只有 `tokio` / `rusqlite`） | 真连库那一片要先联网取 crate |

**因此本侧当前的两条道**：
- **没有口令也能推进的**（现在就能做）：外壳与表示层、连接配置与 URL 解析、对象树 / SQL 编辑面的**行为层**、缩进与自测。
- **必须真库才能算「跑通」的**：真连接、真取数、真对象树、真执行计划 —— 按子号出口判据（§2 第 1 条）**不许拿假数据充「已跑通」**。

**已解（2026-10-02 下午）**：不再需要用户那台 PG 的口令 —— 本侧**自己起了一台专用实验集群**（`initdb -A trust` + 端口 5433 + 数据目录 `_tmp_face2/pglab`），**不动用户现有那台**。夹具 = `app.accounts`（50 行）/ `app.orders`（500 行）。真库端到端判据 = `App/src-tauri/tests/live_lab.rs`（设 `DOYAH_LAB=1` 启用；没设就**跳过并说明为什么**）。**仍缺的一样东西**：那台集群**不会开机自启**（手工 `pg_ctl start` 起），重启机器后要重新起 —— 要不要把它做成服务/脚本，等老板一句话。

**要老板给的一样东西**：本机 PostgreSQL 的连接口令（或一句话授权我在别的端口起一台**专用测试库**，用 trust 认证、不动现有那台）。

## 2. 每个子版本的「出口」（够不够格递号）

一个子号要往上递，三件事缺一不可：

1. **主链能跑通** —— 写进该段的那条场景，在本机（真外壳 + 真 WebView2，或真库）上真的走完一遍；
2. **闸门全绿** —— `windows/Tools/verify-all.ps1` 一条命令（本侧 14 项：构建 / 单测 / 领域层边界 / 文档计数与版本 / 令牌棘轮 / 平台中立性 / 独占节越界 / 等价矩阵 / 平台差异对账 / 压力基准 / 版本号三处一致 / 跑全本身）；
3. **如实报数** —— 没做的、跳过的、读不出来的，逐条列出来（**跳过不是「已通过」**），不拿半成品充数。

## 4. 本侧不做（正式结论，别再来回惦记）

- **自动更新**（与 macOS 侧一致，首版不做）；**签名 / 公证 / 商店分发**（自用口径不需要）。
- **Linux 端实现**（平台设计层各自负责，公司环境自理）。
- **跟着 macOS 逐日追版本号** —— 节奏与范围已定案（§0.1）：编号对表、**日期不追** ⇒ Windows 侧只在模块段真正可用时递号，**不为对齐日期而虚报进度**。
- **跨端同包** —— 两端各出各的包，里程碑号相同不等于包相同。
