## 每轮三段（缺一不算一轮）

0. **环境核查**：`git status --short`。有未提交改动 ⇒ 先判归属（`git diff` + 上一轮日志），属上一轮遗留就先收尾或如实汇报，不叠着改。
1. **取活 + 计划**：按下面队列取 **2~4 项**（优先「可机械验证」的），先写进 `运行日志.md` 新小节再动手。
2. **写代码 + 门禁 + 提交**：每项都要有行为判据（`*.test.ts` / Rust 单测）；本仓门禁 = `./node_modules/.bin/vitest run` + `./node_modules/.bin/tsc --noEmit`（前端）/ `cargo test --workspace`（Rust）。绿了才 `git commit`（`-F <scratch 文件>`，正文不放反引号），再 `git pull --rebase` + `push`（推完用 `git log --oneline origin/master -1` 复核）。

## 停止条件（三类，每轮按编号列）

1. 需人类主人拍板（口径 / 范围 / 取舍）。
2. 需人在界面或真机确认（观感、深色、交互手感）。
3. 缺环境（缺设备 / 账号 / 凭据 / 构建机）。

## 红线

- 门禁不绿不提交、不推送；**不许 `--no-verify`**、不许 force push / rebase 共享历史。
- **不许为了让检查变绿放宽断言**，也不许改已记录的历史数字（新增一条权威说法）。
- 不碰未拍板项；跨侧 / 跨仓冲突上报，不自作主张。
- 未实测的结论不写「已完成」；**用户可见的功能才算完成**，纯逻辑层落地说「逻辑已落地、未接线」。
- 删数据 / force push / 外发消息 / 装全局包 / 改系统配置 ⇒ **先问**。
