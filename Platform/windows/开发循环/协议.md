## 0. 一条铁律（针对上一版循环的病根）

**一轮的产出必须是「用户打开应用能看见 / 能操作」的东西。**

- ❌ 不算完成：只写纯逻辑 + 单测（这正是上一阶段的问题：17 条逻辑落地、界面上一条都看不到）
- ✅ 算完成：一条需求的**端到端**（逻辑 → 接线 → 快捷键/菜单/状态栏可见 → 判据），
  或把若干条已完成的逻辑**一次性接线**成可见功能（例如「⌘/ 能注释、⌥↑↓ 能移行」）
- 判断句：**「主人现在装上这个包，点一下能不能感觉到？」** 答否就不算完成，状态写「逻辑已落地、未接线」

## 2. 每轮四步（缺一不算一轮）

1. **核查**：`git status --short`；有上一轮遗留（未提交改动）⇒ 先收尾或如实汇报，不叠着改。
2. **取活 + 计划**：按 §3 队列取 1~2 条**端到端**需求（宁可少，必须可见），动手前把计划写进 `运行日志.md` 新小节。
3. **做 + 判据 + 门禁**：写代码 + 接线 + 行为判据；门禁 = 前端 `./node_modules/.bin/vitest run` + `./node_modules/.bin/tsc --noEmit`、Rust `cargo test --workspace`。**绿了才提交**（`git commit -F <scratch 文件>`，正文不放反引号）。
4. **推 + 记**：`git pull --rebase` → `push` → `git log --oneline origin/master -1` 复核 → 运行日志写结果（命令 + 数字 + 提交号）。

**单轮 ≤45 分钟**（熔断线，不是坐满）：到点没做完 ⇒ 落断点（做到哪、下一步从哪接）+ 报新 ETA，不硬拼。

## 4. 停止条件（每轮按编号列，主人一眼知道要做什么）

1. **需主人拍板**：口径 / 范围 / 取舍 / 交互设计选择。
2. **需人眼或真机**：观感走查、深色态、手感、装包点验。
3. **缺环境**：缺设备 / 账号 / 凭据 / 构建机。

## 5. 红线

- 门禁不绿**不提交不推送**；禁 `--no-verify`、禁 force push / rebase 共享历史。
- **不许为让检查变绿放宽断言**，也不许改已记录的历史数字（只能新增一条权威说法）。
- 不碰未拍板项；跨侧/跨仓冲突上报，不自行定夺。
- 未实测不写「已完成」；**用户可见才算完成**（§0）。
- 删数据 / force push / 外发消息给第三方 / 装全局包 / 改系统与网关配置 ⇒ **先问**。
- 每轮**一笔提交**（可单笔 revert），提交正文写清「改了什么 + 判据读数」。

## 6. 汇报（三行式 · ≤12 行）

结论（做了哪条需求 + 提交号 + 是否已推）→ 一行证据（命令 + 数字）→ 要主人做的事（没有就写「无」）。
**无事可做 ⇒ 恰好回 `[SILENT]`**。技术细节落 `运行日志.md`，不在聊天里铺命令。

## 7. 节奏与自调速

剩余待办 N：`>8` ⇒ 1 小时 · `6~8` ⇒ 45 分钟 · `3~5` ⇒ 30 分钟 · `≤2` ⇒ 15 分钟。
每轮末尾用 `cronjob_manage action=update` 改自己的间隔；**没有可执行任务 ⇒ `action=pause`** 并写明卡在哪一类。

## 8. 交付批（不是每轮都做）

只有**影响交付的批次**（出安装包 / 给主人验收）才跑全量：18 道闸门 + 截图集 + 说明书/README/台账跟版 + 端上压测。
平时每轮只跑 §2 那条快判据——**不跑文档马拉松**（那是上一阶段的另一个病根）。
