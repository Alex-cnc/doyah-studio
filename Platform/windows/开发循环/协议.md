## 2. 每轮四步（缺一不算一轮）

1. **核查**：`git status --short`。有未提交改动（上一轮被打断 / 遗留）⇒ 先收尾或如实汇报，不叠着改。同时确认**没有上一轮还在跑**（看 `Platform/windows/开发循环/.round.lock`，含 epoch + pid；陈旧锁 >50 分钟判失效）。
2. **取活 + 计划**：按 §3 队列取 1~2 条**端到端**需求（宁可少，必须可见），计划先写进 `运行日志.md` 新小节。
3. **做 + 判据 + 门禁**：写代码 + 接线 + 行为判据；门禁 = 前端 `./node_modules/.bin/vitest run` + `./node_modules/.bin/tsc --noEmit`、Rust `cargo test --workspace`、**插件边界 `node App/tools/check-plugins.mjs`**（后者的由来：它本来只在交付批 18 道里跑，于是第 33~35 轮往插件目录加的两个测试文件静默违规了三轮才被发现 —— 每轮都跑，红当场就看见）。**绿了才提交**（`git commit -F <scratch 文件>`，正文不放反引号）。
4. **推 + 记 + 续跑**：`git pull --rebase` → `push` → `git log --oneline origin/master -1` 复核 → 运行日志写结果（命令 + 数字 + 提交号）→ **立刻把自己排进下一轮**（§6）。

**单轮 ≤45 分钟**（熔断线）：到点没做完 ⇒ 落断点（做到哪 / 下一步从哪接）+ 报新 ETA，不硬拼。

## 6. 驱动：monitor 指纹（没有固定间隔，也没有空转）

用 Hermes cron 的 **monitor（变化检测）** 驱动，而不是定时轮询：

| 项 | 值 |
|---|---|
| `schedule` | `every 1m`（分钟级；**跳的那一跳零 token**，不唤起模型） |
| `monitor` | `Platform/windows/开发循环/fingerprint.py`（纯 stdlib，输出逐字节稳定：`head / remote / dirty / lock / state`） |
| 判据 | 指纹与上一跳**逐字节相同 ⇒ 静默跳过**；不同 ⇒ 唤起一轮，并把 diff 注入提示词 |

**打点即驱动**：每轮末尾写 `Platform/windows/开发循环/state.json`

```json
{ "round": 12, "head": "<本轮提交 sha>", "status": "done|blocked|error|idle", "at": <epoch 秒> }
```

`head` 一变 ⇒ 指纹就变 ⇒ 下一跳（≤1 分钟）自动开下一轮 ⇒ **干完立刻接上，没有等待窗口**。

- **没有可执行任务**：`status=idle` ⇒ 指纹恒定 ⇒ 自然静默，不烧 token（不必 pause）。
- **某一轮挂了**：`status=error` ⇒ 指纹变 ⇒ 立刻被叫起来重试（不会静默躺死）。
- **疑似卡住**：`status=running` 超过 1 小时 ⇒ 指纹里出现 `@stalledN`（每小时最多唤醒一次）⇒ 这是唯一允许随时间变化的成分。
- **主人说停**：直接 `action=pause` 那条 job（在途一轮跑完即止，不 kill 进程）。

**轮次锁**：开工写 `.round.lock`（两行：epoch + pid），收尾删除；超过 50 分钟判陈旧。
指纹里 `lock=held` 时**不开新一轮**（说明上一轮还在跑），跳过并说明。
