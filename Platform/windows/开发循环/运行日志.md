## 第 24 轮（2026-10-18 23:35 起）· 编辑器自己的撤销栈（`FR-EDIT-60` 接线）

### 计划（动手前）

**取活**：`FR-EDIT-60`（撤销语义粒度，SRS §3.2）。三书里这条是 ⬜（macOS 也 ⬜），
而 Windows 侧 `workspace/editing.ts` 里**已经有一个纯函数 `shouldCoalesce`（连续输入合并判断）**，
但全仓**零导入** —— 正是「逻辑已落地、未接线」，也是本循环的铁律 1 要治的那种形状。

**为什么它是真缺口（用户能感觉到的）**：编辑器是 `<textarea>`，原生撤销只认它自己的输入流。
任何**程序化写入** —— 格式化（`applyEdit`）、缩进、注释切换、片段插入、替换 —— 都会把那一条流打断：
之后按 Ctrl+Z，要么**什么都不发生**，要么**把整段 SQL 退回到很早以前**（半路还常把光标甩到末尾）。
现象就是「格式化之后一按撤销，SQL 没了」。要修只能自带一套栈。

**口径（照需求原文）**：① 一段连续输入合并成**一次**撤销；② 行级编辑（移行 / 注释切换 / 补全 / 格式化 /
替换）各算**一步**；③ 合并规则**复用** `shouldCoalesce`（一处判，不另写一份）；
④ 栈里存**全文快照**（字符串在 JS 里共享引用，100 步只是 100 个指针）；
⑤ 别处把文本整篇换掉（切页签 / 回填已保存查询 / 打开文件）时，栈**不许**把 A 页签的文本撤到 B 页签 ——
做法是 undo 前先核「栈顶那份文本 == 屏幕上的文本」，不等就**重建栈并如实说**（不猜、不硬撤）。

**落法**
1. `App/src/workspace/undoStack.ts`（新，纯逻辑）：`newUndoState` / `pushUndo` / `undoOnce` / `redoOnce`，
   返回 `kind: 'applied' | 'exhausted' | 'drifted'` 三档结论（三档各自能说人话，不混成一个 false）。
2. `DatabaseView.vue` 接线：打字（`@input`）与 `applyEdit`（行级编辑）各记一步；`commitFoundText`（替换）也记；
   `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y` 在 `onEditorKeydown` **最前面**接管并 `preventDefault`
   （不让两套栈打架）；「编辑」菜单加**撤销 / 重做**两项，空栈时 `disabled`。
3. 判据：纯逻辑单测（合并 / 分步 / redo 分支被新编辑截断 / 上限 / 三档结论）+ 挂载测
   （格式化后 Ctrl+Z 复原、连打两字符一次撤销回退两字、`Ctrl+/` 注释一步撤销、菜单 disabled 态）。

**边界**：不动 `FR-EDIT-48`（等长替换保光标）那条、不动 macOS 面、不改 `Docs/**`、
不新增能力 / 不改 CSP、不放宽任何既有断言。

**代价**：一轮（≤45 分钟）。
