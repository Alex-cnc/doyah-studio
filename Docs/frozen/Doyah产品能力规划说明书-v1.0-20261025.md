# 第一章 定位

> **能力边界（口径锚点）**：**SQL 编辑器（数据库侧）同样有行号列** —— 行号属于「可编辑多行文本」的基本能力，不是工作区专属；单行输入与富文本编辑面不画行号。


## 1.1 文档分工

> 四件文档的分工 —— 拿到任何一本，第一眼就知道该去哪一本找什么（2026-10-20 起由「三书」扩为「四件」：状态与进展独立成《产品开发计划书》）。[S-01]

## 1.2 定位

**本章讲整族产品的定位，不是某一件的。**

**一句话**：Doyah 是**四个平级产品** —— Agent（通用智能体）、Studio（开发平台）、Notes（笔记）、Retro（资本市场复盘）。**Agent 不是它们的父节点，是它们的赋能者**：Studio 与 Retro 借 Agent 的力量，Notes 独立自足（[S-11]）。

**差异化在哪**：不在模型更强，而在**「敢用」** —— 每一步都能被证明、能追责。

**形态**：Studio 在桌面上是**单窗口**应用 —— 左侧导航（连接列表、元数据对象树、**活动栏** —— 活动栏就是各产品的入口区），右侧工作区（页签式编辑器 + 结果区）；另附**命令行出口**（4.2.35），用于无图形界面时验证与批处理。

### 四个产品

| 产品 | 一句话定位 | 与 Agent 的关系 | 独立性 | 所在章 |
|---|---|---|---|---|
| **Doyah Agent** | **通用智能体** —— 会拆任务、会用工具、会交代结果 | 它自己 | 可独立分发（终端壳即可运行）；装进 Studio 后多一个图形壳 | 第三章 |
| **Doyah Studio** | **开发平台** —— 写代码与连数据库平级并列 | **借 Agent 赋能**（对话、诊断、维护编排） | 不单独分发（形态是**桌面应用 + 随包的命令行出口**，同一份实现；不另出服务端与网页版） | 第四章 |
| **Doyah Notes** | **笔记** —— 随手记、随手找、随手带走 | **不接 Agent**，自己做自己的 | **手机端是独立 App**；**桌面端以插件装进 Studio**，不单独出桌面客户端；数据跨端同步 | 第五章 |
| **Doyah Retro** | **资本市场复盘** —— 把发生过的事摊开看，找出该改的 | **深度借 Agent 赋能**（见下） | 可独立分发；**桌面**，与 Studio 同 | 第六章 |

### 三条约定

1. **赋能不改变身份**：Studio 借了 Agent，仍是开发平台；Retro 借了 Agent，仍是复盘工具。**不是「Agent 的一个界面」**，也不因为用了 Agent 就变成「通用助手」。
2. **领域能力不外包给通用 Agent**：Retro 需要的能力（K 线数据、牛股特征模型、研报、预测）**内置在 Retro 里**，做成 skill 与工作流 —— 不要求用户用自然语言在通用 Agent 里把这件事描述一遍。
3. **引擎只有一份，能力各自长**：同一个 Agent 引擎不为每个产品各养一套；但每个产品**长出自己领域的 skill 与工作流** —— 引擎管「怎么跑」，产品管「跑什么」。

### 边界

- **不是父子，是平级**：Agent 是能力提供方，不是内核根节点；**说「Agent 是所有产品的内核」是错的**。
- **不接不等于弱**：Notes 不接 Agent 是有意的取舍 —— 笔记要**快和静**，不要一个会思考的东西在旁边追问。
- **赋能 ≠ 自然语言入口**：Retro 的用法是**点一下、跑一条工作流**，不是在对话框里描述「帮我找牛股」。自然语言是**兜底**，不是**主路径**。

## 1.3 原则

> 这七条是**不可让渡**的：违反任何一条，功能做得再好也不上线。

| # | 原则 | 含义 |
|---|---|---|
| P1 | **治理优先** | 显式同意、最小外发、权限继承当前连接、写操作逐次审批、审计留痕 —— **缺一条不上线** |
| P2 | **可降级** | 无模型 / 未授权 / 断网时，**既有功能完整可用** |
| P3 | **本地优先** | 支持本地端点且无需密钥；**默认零外发**：出厂即「总开关关闭 + 端点为空」 |
| P4 | **真实数据接地** | 诊断类能力必须站在真实执行计划 / 锁等待 / 统计之上，不做「没有依据的建议」 |
| P5 | **可复核** | 智能体的产出（SQL / 任务定义 / 建议）都以文本可查看、可编辑、可 diff |
| P6 | **原生轻量** | 不打包浏览器内核（系统 WebView 合规）；不引入 Electron / JVM 这类重型运行时 |
| P7 | **跨端等价** | 同一功能在不同桌面平台行为一致；差异只允许出现在适配层以内，并且逐条登记、可查（详见 2.1） |

# 第二章 总纲

> 本章只讲三件**横穿全书**的事：**跨端怎么算等价**、**能力长在哪个面上**、**数据归谁**。产品各自的能力在各章，不在这里。

## 2.1 跨端等价

> **这一节规定的是一件能力要求**：同一功能在多个桌面端之间**必须等价** —— 一旦纳入范围，就要按下面四条对齐。
>
> **不在这里规定「哪些平台在范围内」** —— 平台范围不在本书规定。本书只负责：**纳进来的，就必须等价；没纳进来的，不算能力缺失。**[S-13]

> **本节不是能力点**：下面三段讲「同一能力在不同端怎么算等价」，是这一节正文的组成部分，供评审逐条对照；不按「是什么 / 不是什么 / 边界」展开，也不在《需求规格说明书》里逐条立需求。

**什么算一样**

| 维度 | 要求 | 怎么判 |
|---|---|---|
| **能力清单** | 同一个功能两端都有入口，条目**一一对应**，不是「差不多」 | 逐个功能点对照，缺一即不算等价 |
| **行为语义** | 取消要真的传到执行端；影响行数只报一次；结果被截断必须看得见；写操作逐次审批；密钥不入配置与日志 | 两端各跑同一组行为用例 |
| **判定口径** | 同一条能力在两端用**同一套判据**，不各写一套 | 判据只有一份 |
| **交互与观感** | 间距、字号、状态色出自**同一份视觉规范** | 取值一致，对比度达标 |

**可以不同**

菜单与快捷键的**平台约定** · 窗口与停靠行为 · 字体回退 · 原生控件外观 · 安装与签名 · 终端行为 · 文件访问授权 · 系统集成（通知、深色模式跟随）。

**要求**：每一处差异都要说得清两件事 —— **为什么必须不同**、**用户能感觉到什么**。说不清的就是漏做，不是差异。

**禁止**

- **禁止**把某一侧的库名、类型名、机制名写进能力描述 —— 能力描述必须在两端都成立。
- **禁止**同一件事有两个真相：一个能力只有一种描述、一套判据。
- **禁止**一侧加了能力而另一侧不知情：加能力时两端一起改，不许先加一边「以后再说」。

## 2.3 数据归属

> 只说归属与形态，不说选型 —— **用什么引擎、怎么封装，是概要设计的事**。

- **工作区与复盘数据在本地**：不依赖云端，断网照用（P2 可降级）。
- **笔记与待办主存在本地**：数据归用户所有，**联网时才同步到云端**（云端作多端交换与备份，5.1.8）—— 断网照读照记，云端不可用只影响跨端可见性，不影响本机使用。
- **一种组织方式，各自持有契约**：跨端与跨产品用**同一套数据组织方式**（同一套字段语义与引用规则），但**每件产品持有自己那份契约** —— 笔记的跨端格式归笔记产品（5.1.8），不复用别人的实现细节；数据可以**互相引用**（回边 3.7.2 的前提）。
- **原始数据留在文件系统**：可读、可 diff、可喂给 Agent —— 二进制与运行状态才进库，**结论与原文不做二次加工**。
- **导出的产物照旧落盘**：导出不是「另一份真相」，是从库里取出的一份副本。

**边界**：不把二进制大块塞进库（备份与迁移会失控）；不因为「方便查」就把原文改写成结构化再存（原文永远保留原样）。**两侧的真相各归各**：工作区与复盘以本地文件为准，笔记与待办也**以本地为准**、云端只是同步副本 —— 云端是通道与备份，不是第二个真相。

# 第三章 Doyah Agent

> **一个服务，两个壳。** 内核与能力只有一份，跑成一个**服务**；**终端壳**（CLI / REPL / TUI 三种呈现）与**图形壳**（Studio 界面）都只是它的壳 —— **换壳不换脑**。
>
> **形态边界**：没有 Studio 时，Agent 是可独立运行的 CLI 工具；装了 Studio，界面是同一个服务的另一个壳 —— **不存在「Studio 版 Agent」和「CLI 版 Agent」**（[S-08]）。

> **本章场景**（承诺 → 能力 → 判据，与第四/五/六章同一读法）。六个场景已全部拍板，取舍原话见 [S-02]；**优先级顺序 4 → 5 → 2 → 1 → 3 → 6**（同一条原话里的排序），本表按序号排列、不另设优先级列。**[S-03]**

| 序 | 场景 | 用到的能力 | 做到什么算成 |
|---|---|---|---|
| **1** | **它记得我的偏好，不用重复交代** | 记忆 3.4.1 · 灵魂 3.3.2 · 先验 3.1.3 | 说过一次的偏好，下次不说也对；改了主意它能记住新值、不再沿用旧的 |
| **2** | **它越用越顺手** | 技能 3.4.2 · 记忆 3.4.1 | 同一个坑不踩第二次；这次的教训能写进技能库、下次被检索到 |
| **3** | **手机上丢一句话，它做完给结果** | IM 通道 3.6.2 · 队列 3.1.5 · 循环 3.1.1 · 回边 3.7.2 | 手机发一句，电脑上跑完，结果回到手机；断线不丢消息、不重复执行 |
| **4** | **早上主动给出今天该干什么** | 定时 3.5.10 · 记忆 3.4.1 · 先验 3.1.3 | 到点自己开工；**开跑前知道工作区实况**（未提交改动、昨天没做完的），不靠猜 |
| **5** | **它自己发现工作区的问题并提出来** | 后台 3.5.10 · 技能 3.4.2 · 刹停 3.1.2 | 主动报出「哪有问题 + 证据」，**不擅自改**；改了要能撤回 |
| **6** | **出事时能查清它做了什么** | 留痕 3.3.3 · 会话持久化 3.1.4 | 能回答「谁改的、什么时候、依据什么」；记录断档能被发现 |

**读法**：左列是**承诺**（产品对人的承诺），中列是**能力**（本书要写清的东西），右列是**判据**（需求书要验收的东西）。三列缺一，这个场景就是空话。

## 3.1 执行内核

> 这一组是其余所有能力不成立的那一层：拆掉它，Agent 就不是 Agent 了。

### 3.1.1 循环与工具

**是什么**：把目标一步步跑出来 —— 每步调一个动作，看结果再决定下一步，直到能给出结论。内核提供的是**「怎么跑」的机制**，不是「能做什么」的清单。**拆解本身归 3.2.1，这里只管跑。**

**不是什么**：**内核不是一组工具**，也不自带工具集 —— 工具是可增删的对象，**内核不随工具变**（换一组工具，循环照旧）。模型选哪一档见 3.5.9；结果怎么呈现见 3.5。

**边界**：动作**落在当前工作区**（读文件 / 列目录 / 搜索 / 写文件 / 跑命令）；需要外部信息时取网页，按 3.5.2 与 3.3.5 的口径走；越出工作区去碰别的目录直接拒绝并说明原因，不许绕路；**只读是默认**，写入与执行按 3.3.1 的授权口径。**工具缺失或返回空时不许空转** —— 要换路子或如实说「我做不到」，不许把同一个动作重试上百次当努力。**预算按单次任务计**：一次任务最多 **150 步**、**256K token**（[S-15]）；新任务重新计数、不结转；逼近与触顶都要当场说清「停在哪、做完哪些」，不许静默截断，也不许把「预算用完」说成「任务完成」。

### 3.1.2 及时刹停

**是什么**：识别到**伤害性动作**（删别人的东西、花钱、对外发布、改口径）时，在**动手之前**停下。

**不是什么**：刹车管「该不该继续」；审批管「能不能做」（3.3.1）。

**边界**：停下**不建审批单、不执行、只留痕**；宁可误停，不可不可逆地做错。同一工具同参数反复、且没有新证据，也算一种「该停」——停下时**必须把已有文本当答复交出来**，不许只交一句「我停了」。

### 3.1.3 上下文先验

**是什么**：开跑之前就把已知事实摆到面前 —— 工作区顶层结构、git 分支与脏文件、当前打开的文件。

**不是什么**：先验是「开局就知道」，记忆（3.4.1）是「跨会话还记得」。

**边界**：先验只给**结构**，不给内容（内容靠读）；先验过期会让模型基于旧事实行动，因此每次开跑重取，不做缓存。

### 3.1.4 会话持久化

**是什么**：一次任务的执行现场（走到第几步、每步工具回了什么、哪些还在等确认）落盘；进程重启、换壳、机器重启后能接着跑。

**不是什么**：**不是记忆**（记忆是「跨会话知道什么」，会话是「这一次在干什么」）；也不把「没批准的写入」当成已完成。

**边界**：崩溃后恢复到**最后一个已完成步骤**，已生效的写操作不许重跑；恢复时要说清「从哪一步接上」，不许悄悄从头来。

### 3.1.5 队列

**是什么**：进来的任务先入队，按序或按优先级执行；长任务不阻塞新任务。

**不是什么**：**不是「多开几个线程」就叫队列**；也不做无上限并发（会把工具、连接、模型额度一起打爆）。

**边界**：**按会话隔离** —— 每个会话一条队列、一份上下文，会话之间**不共享可变状态、不互相阻塞**；同一会话内严格串行。多壳（桌面壳 / 移动侧 / 服务端）同时开工时，各自写各自会话的作用域，不靠跨会话协商；会话结束后其队列即作废，不许把上一个会话的排队状态带到下一个（[S-16]）。

## 3.2 规划

> 从「听懂」到「收工」是一条独立的链：拆解 → 澄清 → 边走边修 → 判断做没做完 → 半路失败怎么恢复。

### 3.2.1 任务分解

**是什么**：把一句话的目标拆成有顺序、有依赖、可验证的步骤 —— 不是「我会先……再……」的泛泛承诺。

**不是什么**：**不是把目标复述一遍**；也不是每一步都写死（要留出根据结果调整的空间）。

**边界**：每步要说清「做完的标志」；步骤之间有依赖的要标出来（B 得等 A）；拆不出可执行步骤时，说明缺什么（信息 / 权限 / 工具），而不是硬拆。

### 3.2.2 主动澄清

**是什么**：目标有歧义、或缺少关键约束时**先问一句**，而不是猜一个版本埋头做完。

**不是什么**：**不是「什么都问」** —— 能从上下文、记忆、既有约定推断的就不问；问也要一次问完，不来回挤牙膏。

**边界**：问的时候要给出**我的理解和备选**（「我理解是 A，也可以是 B，按 A 做？」），而不是空问「你要什么」。**该在开工前问清的问完再动手** —— 跑到一半才发现的缺口、风险、权限不足，走 3.7.6 求助通道，不在这里补问。

### 3.2.3 计划修订

**是什么**：跑到一半发现假设被推翻，就改**路径**并把为什么改说清楚。

**不是什么**：不是「边跑边改目标」 —— 目标不动，改的是到目标的走法。

**边界**：改计划要保留已完成的成果；改到第三次要停下来跟人确认方向。

### 3.2.4 完成判据

**是什么**：开工前就知道「什么算做完」，收工时按这个判据自查；判据不成立就继续做或如实说没做到。

**不是什么**：**不是「跑完最后一步就算完成」** —— 步骤跑完但目标没达到，不算完成。

**边界**：判据要能被外部复核（测试通过 / 文件存在 / 输出对得上），不许自定一个「看起来成了」的标准。

### 3.2.5 失败自恢复

**是什么**：工具失败先自己救 —— 重试（仅瞬时错误）、换路径（换工具或参数）、降级（少做一点但给可用结果）。

**不是什么**：**不是「失败就重试到成功」**（无脑重试＝空转）；权限、逻辑这类不可恢复的错要立刻停。

**边界**：每次换路径要说清换了什么；三次不成如实上报，不许把失败包装成部分成功。

## 3.3 约束

> 内核决定「能做什么」，这一层决定「允不允许做」。

### 3.3.1 权限与审批

**是什么**：开跑前定一次范围（这次能碰哪里），动作超出范围或不可逆时回来问。

**不是什么**：审批管「能不能做」，刹车（3.1.2）管「该不该继续」。

**边界**：便宜可撤的事（口味、排版、命名、实现方式）**直接按已知偏好做**；贵或不可逆的事（删东西、花钱、对外发布、改口径）**必须问**。审批是**前置**，不是执行后的提醒。

### 3.3.2 灵魂

**是什么**：三级口径 —— **L0 角色**（我是谁：说真话、办对事、越用越准）、**L1 领域角色**（在这个领域我是谁）、**L2 项目做法**（这个项目怎么做）。

**不是什么**：灵魂是「以什么身份做事」，记忆是「记得什么」。

**边界**：**优先级 L0 > L1 > L2** —— 任何工作区规则不得覆盖 L0，领域角色不得被项目做法顶掉；注入顺序 L0 → L1 → L2（3.4.3）→ 记忆 → 会话；灵魂文件里出现密钥形态即拒绝载入。

### 3.3.3 留痕

**是什么**：每次动作（工具调用、文件写入、审批、外发）留一条可回查的记录：**谁让做的、做了什么、依据什么、结果如何**。

**不是什么**：**不是调试日志**（不写代码内部细节）；**不记密钥与正文**（只记路径、摘要、指纹）。

**边界**：必须能回答「那三个文件是谁改的、什么时候、凭什么」；记录**断档要能被发现**（连续性检查），不许悄悄缺一段还看不出来。

### 3.3.4 隔离执行

**是什么**：危险或不可信的动作在隔离环境里跑（沙箱 / 容器 / 受限目录），炸了只炸那一块。

**不是什么**：不是所有动作都进沙箱（会慢且难用）；也不是「进了沙箱就可以随便来」。

**边界**：进不了沙箱要明说，并降级为只读或需人工 —— **不许偷偷在真实环境跑**。

### 3.3.5 数据边界

**是什么**：明确哪些数据不许外发（源码、口令、客户信息），外发前脱敏或拦下。

**不是什么**：不是「用户点了同意就都发」；也不是靠模型自觉。

**边界**：外发要能查到（谁发的、发了什么摘要）；**拿不准按不外发处理**；**截图 / 整屏录屏类外发默认要人工确认** —— 一屏里可能同时有代码、聊天、密钥、客户数据，脱敏做不干净。

### 3.3.6 成本配额

**是什么**：token / 费用 / 调用次数有上限，接近先提示，超了就停。

**不是什么**：不是「月底看账单」；也不是只统计不拦。

**边界**：上限可按任务设；被上限停掉要如实说「预算用尽」，**不许说成任务完成**。

## 3.4 知识

> 长期性的东西：记得什么、会怎么做、这个项目怎么做事、装不下时怎么压缩。

### 3.4.1 记忆

**是什么**：把用户说过的偏好、项目里定过的规矩、做过的事记住，下次不用再说一遍。

**不是什么**：记忆是「跨会话」，先验是「本次开局」，技能（3.4.2）是「会怎么做」。

**边界**：记**结论与偏好**，不记原文流水；**可读、可删、可解释来源**；删除必须真的不再复述。记忆不替用户做决定，只减少重复提问。

### 3.4.2 技能

**是什么**：一类活干成功之后，把做法沉淀成下次可直接复用的步骤，下次遇到同类活**先查有没有**。

**不是什么**：技能是「怎么做」，记忆是「知道什么」。

**边界**：只从**成功且被确认**的任务里抽；技能必须**可检视、可作废**；不许把一次偶然的做法当成通用规则。

### 3.4.3 项目上下文

**是什么**：开工先读「这个项目怎么做事」 —— 规则文件、目录约定、既有风格、构建方式，并遵守。

**不是什么**：不是把项目文档全读一遍；也不把自己的偏好强加给项目。

**边界**：项目规则与公共灵魂冲突时按 3.3.2 的分层处理并说明；找不到约定要明说「没找到」，不许假装有。

### 3.4.4 上下文压缩

**是什么**：会话太长时压缩历史，**关键约束不能丢**（目标、禁忌、已确认的决定、还没做完的事）。

**不是什么**：**不是简单截断**（把前面的对话砍掉），也不是摘要成一段「大概聊了什么」。

**边界**：压缩后要能回答「我原本要干什么、哪些不能碰」；压缩本身是**必然发生的事件**，不是边缘情况。

## 3.5 手段

> 它能动用的资源：工具、模型、时间。这一层最可装卸，换掉一样，Agent 还是 Agent。
>
> **其中三项不是「自己做」，是「接进来」**：文档解析（3.5.3）· 图像理解（3.5.4）· 语音输入与输出（3.5.5 / 3.5.6）—— 能力来自外部库或外部模型，产品负责的是**送得进去、带得回来、送不进去时说清楚**，以及外发边界（3.3.5）。

### 3.5.1 局部精确编辑

**是什么**：改文件只动该动的那几行，其余原样保留（按匹配片段替换，不整文件重写）。

**不是什么**：**不是「读全文 → 改 → 整篇写回」** —— 那会毁掉无关改动、冲掉别人刚改的地方。

**边界**：匹配不唯一时要先确认改哪一处；匹配不到就报错，**不许猜位置硬改**。

### 3.5.2 网络检索

**是什么**：需要外部信息时能**搜索**（找有哪些来源）与**抓取**（取某个 URL 的正文 / 接口返回），并把来源带回。搜索与抓取是**两个动作**：能搜不能取，等于看见标题读不到内容。

**不是什么**：不是「搜到就用」（要判断来源可信度）；抓不到时**不许编**。

**边界**：被墙 / 限流 / 付费墙要说清并给替代路径；引用要能追到 URL。

### 3.5.3 文档解析

**是什么**：读 PDF / Office / 扫描件，抽出文字与结构（标题、表格）。

**不是什么**：**不是自研解析器**（PDF / Office / OCR 都来自外部库或服务）；不是「看文件名猜内容」；OCR 不确定的地方要标出来。

**边界**：解析不出来要明说（画质差 / 加密 / 无文字层），**不许静默返回空**。

### 3.5.4 图像理解

**是什么**：把截图、设计稿、报错图**交给支持视觉的模型**，取回「里面有什么、问题在哪」—— 产品管的是**送之前怎么处理、送不进去怎么说**。

**不是什么**：**不是自研识图**（视觉来自模型，不是自己长出来的本事）；**不是所有模型都能看图** —— 当前档位不支持视觉时，**必须说不支持**，不许拿文本模型的猜测当结论；也不做医学、法律这类专业判读。

**边界**：图片的体积、格式、缩放上限要说清（超限先压再送，压到看不清就说看不清）；**截图可能含密钥与客户信息，外发前按 3.3.5 处理**；哪一档模型能看图，由 3.5.9 的档位能力决定，切档失败要说出来。

### 3.5.5 语音输入

**是什么**：把说的话转成文字（**识别来自外部服务**，不是自己长出来的本事），再当普通输入用。

**不是什么**：**不自研识别模型**；不承诺方言与嘈杂环境的效果；**档位没有识别能力时要说没有**，不许把猜的词当原话。

**边界**：转写置信度低要标注（哪几个字不确定）；**录音可能含他人的话与背景信息，外发按 3.3.5 处理**；原始音频留不留、留多久要说清。

### 3.5.6 语音输出

**是什么**：把结论读出来（**合成来自外部服务**），用于「不看屏幕」的场景（开车、手在忙）。

**不是什么**：**不是把整段回答念一遍** —— 只读结论与要害，细节留文字；**档位没有合成能力时要说没有**，不许静默变成没声音。

**边界**：长文本要先摘要再读（照念没人听得完）；**播报内容里不许带密钥、口令、客户姓名**（3.3.5）；可被打断，打断即停。

### 3.5.7 界面操作

**是什么**：像人一样操作图形界面（点击、输入、截图观察）—— 给没有 API 的软件用。

**不是什么**：**不是替代 API**（有接口就用接口）；不做无人监督的长时操作。

**边界**：每一步可回看（截图留痕）；不可逆操作要人工确认。

### 3.5.8 子任务委派

**是什么**：把可并行的子任务分出去（多个子代理或多次调用），结果由主线归并。

**不是什么**：不是「越多越快」 —— 并行度受控；也不让子任务改主线状态。

**边界**：每个子任务要有明确输入与输出；子任务失败不许静默丢弃，归并时要说清。

### 3.5.9 模型多档

**是什么**：可以配多档模型（不同端点、不同价位），**按任务需要的能力选档**，不是一律用最贵的。

**不是什么**：多档管「用哪个模型」，循环管「怎么用它」。

**边界**：**每档要标清「能干什么」** —— 能不能看图、能不能调工具、上下文多长、语种支持、价格档位；**档位表是选档的唯一依据**，没标的当作没有；每档的端点、模型名、密钥由用户自己填；密钥只进钥匙串，助手**不碰、不显示**；切档失败要退回上一档并说明，不许静默降级继续；**降档后能力缩水要明说**（例如「这一档不能看图」），不许假装还在。**档位的端点与模型名可以预填**（主流提供商的起点值），预填值当场可改、改完照常工作 —— 预设是起点不是白名单。

### 3.5.10 定时与后台

**是什么**：到点自动起一次会话（例如每早拉一次数据、每晚生成日报）。

**不是什么**：定时管「什么时候跑」，循环（3.1.1）管「跑的时候怎么走」。

**边界**：**定时不构成授权** —— 到点只代表「可以开始」，具体动作仍受 3.3.1 约束；跑了什么、成功失败，必须能回看。

## 3.6 接入

> 与外界的接口：外面怎么连进来（网关、IM），它怎么连出去（MCP），能力怎么装卸（插件）。

### 3.6.1 网关

**是什么**：Agent 以**常驻服务**形态跑着，任何壳随时连上来；支持开机自启、健康检查、断线重连。

**不是什么**：**不做「每个壳起一个服务」** —— 那正是把壳变成身份的老路。也不强制常驻：没有常驻服务时按需拉起，跑的是同一个服务。

**边界**：服务挂了必须能被发现（健康检查 / 日志），不许静默变成「连不上但没人知道」；重启后会话可恢复。

### 3.6.2 IM 通道

**是什么**：把 Agent 接到即时通讯（QQ / Telegram 等），手机上就能派活、收结果。

**不是什么**：**不自己实现协议栈**（用平台 API / 现成网关）；也**不做「IM 里功能更少」** —— IM 连的是同一个 Agent、同一份记忆。

**边界**：每条消息要能追溯回会话；密钥只进钥匙串，不进配置、不进日志；断线要重连并补齐未读，不许丢消息还装作送达。

### 3.6.3 MCP

**是什么**：Agent 通过 MCP 协议调用外部工具（也能被外部调用），工具由用户自己配置。

**不是什么**：**不自带工具市场**，也不替用户挑工具；**不做「一次批准永久有效」** —— 批准只对这一次、这一组参数有效。

**边界**：没人确认时默认不放行（超时即拒绝）；每个请求只回一个响应；界面审批通道借不来弹窗时，走两侧共用的文件队列，且待审批项要摆出将执行的语句。

### 3.6.4 插件

**是什么**：**能力层可装卸** —— 记忆后端、模型来源、工具库、定时任务源、通道、存储，都按**明确的扩展点**接入；装一个能力不动内核。

**不是什么**：**不是「到处都能挂钩子」** —— 扩展点是**封闭清单**，不是任意拦截点：只有那六类能扩展（记忆后端 / 模型来源 / 工具库 / 定时任务源 / 通道 / 存储），想加第七类得改内核，那不算装插件。内核五项（循环 / 刹停 / 先验 / 会话持久化 / 队列）**不可插件化**；**壳不是扩展点**（换壳不叫装插件）；**审批的执行点**也不是（可以加检查，不能替人放行）。**子产品装配不算这一层的插件** —— 把笔记装进 Studio 是宿主侧的事（4.1.39），不占六类里的任何一类；接口怎么定属概要设计。

**边界**（三条，都是硬的）：

1. **插件只能扩展「能做什么」，不能改变「怎么决定、何时停」。**
2. **策略钩子只能收紧，不能放宽** —— 插件可以说「不许」，**不能说「不必审批」**（fail-closed，单向）。
3. 插件不得绕过审批与审计；装卸插件不改变已装能力的授权范围。

## 3.7 交互

> 人怎么用上它、怎么在过程中插手。终端壳与图形壳是同一份实现的两个壳。

### 3.7.1 对话

**是什么**：在工作区里直接对话 —— 带着当前文件、选中文本、终端输出作为上下文；回答能落成动作（改文件、跑命令）。

**不是什么**：对话管「说清楚要什么」，3.2 管「怎么做到」。

**边界**：**上下文是「带过去」的，不是「猜出来」的** —— 用到了哪个文件、哪段选中，回答里要说清；对话不替代编辑器，改完仍需人看差异。

### 3.7.2 回边

**是什么**：把执行结果退回对话里 —— 跑完的命令、改完的文件、失败的原因，都能在对话中看到并继续追问。

**不是什么**：回边管「结果回来」，规划（3.2）管「下一步做什么」。

**边界**：**回边必须带原始输出**（不许只回一句「完成了」）；失败要把错误原文带回，不许改写成人话后丢掉细节。

### 3.7.3 过程可见

**是什么**：跑的时候人能看到它在干什么（当前步骤、调了哪个工具、拿到什么），不是等一个终局。

**不是什么**：**不是把每一步都刷屏**（那是噪音）；也不是跑完才给一份事后报告。

**边界**：默认收起细节、只留当前一步与进度；出问题时要能展开看到完整轨迹。

### 3.7.4 中途干预

**是什么**：跑的过程中人可以**打断**、**追加要求**、**纠偏** —— 三种语义要分开，不能混成「发消息就完事」。

**不是什么**：**不是「再发一句它就懂」** —— 打断是停、追加是排队在下轮生效、纠偏是改当前目标，各有各的结果。

**边界**：打断要真停下（不是等这一步跑完）；追加要说清是「这次生效」还是「下次生效」；纠偏要保留已做的工作，不从头来。

### 3.7.5 主动通知

**是什么**：任务跑完、卡住、或到了该提醒的时候，**主动把人叫住**（IM / 通知 / 界面提示），而不是等人来问。

**不是什么**：**不是把每一步都推给人**（那是骚扰）；也不是只写日志等人自己翻。

**边界**：通知要说清三件事 —— 做完了什么、卡在哪、要不要人做决定；同一条结果只通知一次，不重复轰炸。

### 3.7.6 求助通道

**是什么**：需要人做决定时（风险、预算不足、缺权限），有一个**明确的找人路径**，并且能等。

**不是什么**：**不是失败了就结束** —— 失败也要说清在等谁、等什么；也不是什么都推给人（能自己决定的自己决定）。

**边界**：**与 3.2.2 主动澄清的分界** —— 开工前目标本身不清楚、要先问明白的，归 3.2.2；这里只管**跑到一半**才冒出来的求助（风险、预算、缺权限、要人拍板），不把「一开始就该问清的事」拖到中途。求助要带上下文（做到哪、卡在哪、建议怎么办）；等人期间不空转；超时要说明「未获答复，停在这里」，而不是继续硬做。

### 3.7.7 会话生命周期

**是什么**：会话能恢复、分支（从某步另开一条）、回滚（退回某步）、导出。

**不是什么**：不是「坏了只能从头再来」；导出不得含密钥与敏感正文（3.3.5）。

**边界**：分支与回滚不影响原会话；回滚后**已发生的外部副作用要说清**（文件已改，不能假装没改）。

### 3.7.8 多端一致性

**是什么**：同一个任务换设备能接着看、接着做。

**不是什么**：不是「同步聊天记录」就完事 —— 要同步**进行中的状态**。

**边界**：两端同时操作要能发现冲突并说明，不许静默覆盖。

## 3.8 质量

> **横切属性在层上的投影**（不是并列的层）：它说做完了，是真做完了吗。

### 3.8.1 结果自验

**是什么**：交付前自己验一遍 —— 跑测试、跑构建、核对输出，用**真实执行结果**支撑「做完了」。

**不是什么**：**不许只声称完成**（「已修改」不等于「已生效」）；也不许把「命令没报错」当成「功能对」。

**边界**：验不了要明说验不了（没有测试、环境缺失），不许跳过还说通过。

### 3.8.2 长任务一致性

**是什么**：几十步之后仍对得上最初的目标，不偏题、不跑成别的任务。

**不是什么**：不是每一步都复述目标（噪音）；也不是最后才检查一次。

**边界**：阶段性地回到目标核对；发现偏离先纠回，不许把跑偏的结果当好结果交上去。

### 3.8.3 不确定性表达

**是什么**：不知道就说不知道；把握不足时给区间与理由，而不是给一个确定答案。

**不是什么**：不是「什么都说可能」（那是废话）；也不是把不确定藏在措辞里。

**边界**：区分**事实 / 推断 / 猜测**三档并标清。

### 3.8.4 断言可溯源

**是什么**：关键结论能落到可查证据 —— 文件行号、URL、查询结果、日志时间。

**不是什么**：不是每条都加引用（噪音）；**也不许引用一个不存在的文件或行**。

**边界**：溯源信息要能被机器核对（路径存在、行号对得上、结果可复跑）。

## 3.9 可运营

> **横切属性在层上的投影**：看不见就修不了，改一次坏一次就没人敢改。[S-05]

### 3.9.1 可观测

**是什么**：能看到每次运行的轨迹、用了多少 token、花了多少、为什么失败。

**不是什么**：不是只记「成功 / 失败」；也不是把内部细节全倒给用户。

**边界**：数据可导出；失败原因要能分类（模型 / 工具 / 权限 / 环境）。

### 3.9.2 可配置

**是什么**：模型、工具、策略、限额可按环境切换（本机 / 公司 / 客户）。

**不是什么**：不是「改配置文件重启」才算；**也不许配置能绕过策略**（3.3）。

**边界**：配置变更留痕；切换后能力清单要能自检（哪些能力因此不可用）。

### 3.9.3 可评测

**是什么**：一批回归用例（真实任务）能稳定跑过 —— 改一次能知道有没有坏。

**不是什么**：**不是单元测试**（单测证明函数对，不证明任务能完成）。

**边界**：每条用例要有判据（什么算做对）；结果可重复（同环境同结论）。

### 3.5.11 命令执行

**是什么**：在本机起一条命令（构建、测试、只读查询），把**标准输出 / 标准错误 / 退出码**带回来；跑在后台、可中断，不占界面。

**不是什么**：不是给模型一个万能后门 —— 每条命令走审批并记审计，且只允许在用户授权过的目录里跑；不是「跑完就算过」—— 退出码非零要如实回传，不许把失败说成成功；不接管交互式程序，需要 TTY 的一律拒绝。

**边界**：单条命令超时默认 60 秒、可配；输出超过 2000 行或 1 MB 即截断并明说「已截断」；非零退出码原样上浮；危险形态（删库、递归删除、改系统路径、管道里带下载执行）进审批，不做静默白名单。

## 4.1 Workspace

> 一个打开着的目录，加上一套把代码看明白、改对、跑起来的手段。

### 4.1.1 Home 页

**是什么**：打开工作区先看到的一页：最近文件、常用动作、当前目录概况。

**不是什么**：**不把设置堆在首页**（Home 是入口，不是控制台）；不做成数据看板。

**边界**：空工作区要给出「下一步做什么」，不许一片空白。

### 4.1.2 文件树

**是什么**：左侧常驻的工作区目录树，所有文件操作的入口。

**不是什么**：**不显示版本库内部**（`.git` 等隐藏目录默认不展示）；不做编辑器的事情。

**边界**：只认工作区内路径；大量文件要懒加载，不许打开就卡。

### 4.1.3 新建文件

**是什么**：在工作区任意目录新建文本文件，建完立刻进编辑器并出现在文件树里。

**不是什么**：不做「从模板生成项目」，也不猜你要建什么类型 —— 名字与后缀由你定。

**边界**：重名必须拦下并提示；写入失败要如实报错，不许留一个空文件假装成功。

### 4.1.4 重命名

**是什么**：就地改文件名或目录名，内容与位置随之而来。

**不是什么**：**不替你改代码里的引用** —— 改名就是改名，重构是另一件事（不在本能力内）。

**边界**：目标名已存在时拦下；失败要把名字回滚到原名，不留半改状态。

### 4.1.5 删除

**是什么**：删文件或目录，进系统废纸篓（可恢复）。

**不是什么**：**不提供「永久删除」按钮** —— 不可逆的动作不该出现在日常路径上。

**边界**：删除前确认；删完树里立即消失；被占用/无权限时如实说明原因。

### 4.1.6 打开与识别

**是什么**：双击按类型打开 —— 代码进编辑器、图片进预览、二进制提示不可编辑。

**不是什么**：**不认识就别装认识** —— 不做半渲染，不把二进制当文本打开。

**边界**：同一文件重复打开复用已有页签；外部「用本应用打开」要在树里定位到它；**不做万能预览** —— 不可预览的类型就是不可预览，不猜。

### 4.1.7 编辑与保存

**是什么**：改内容、标记未保存、保存到磁盘；有未保存改动时关闭要拦一次。

**不是什么**：**不自动保存**（不替你决定什么时候落盘），也不静默格式化。

**边界**：磁盘上的文件被外部改动时要提示冲突，不许直接覆盖别人的修改。

### 4.1.8 编辑动作

**是什么**：**在光标处一步做完的动作** —— 列表里回车接着写、任务框一键翻转、行注释开合、整行上下移与复制；都不打断正在写的那句话。

**不是什么**：**不是代码重构**（不改语义、不重命名符号）；**不是格式美化**（那是 `4.1.21 格式化`）；也不改你的缩进风格。

**边界**：与 `4.1.7 编辑与保存` 的分界 —— 7 管「存到哪、从哪读回」，这里管「改的时候手顺不顺」；与 `4.1.21 格式化` 的分界 —— 一个改行结构，一个整篇排版。**一步只改一处**（不顺手重排、不动别的行）；每个动作**都能一步撤销**；不认识的结构**原样放行**，不猜意图。

### 4.1.9 查找替换

**是什么**：在当前文件内查找、逐个替换或全部替换。

**不是什么**：**不做跨文件替换** —— 那是工作区搜索（4.1.10）的范围。

**边界**：全部替换要给出替换条数；正则写错要报错，不许「零命中」糊过去。

### 4.1.10 搜索与定位

**是什么**：工作区标头一处搜索，按文件名与内容查找，回车打开并跳到命中行。

**不是什么**：**不做替换**（替换在 4.1.9 的当前文件内）；不搜二进制与忽略目录。

**边界**：大仓库搜索要给进度，不许假死；命中要能直达那一行。

### 4.1.11 终端

**是什么**：工作区内的终端面板，跑构建、测试、脚本。

**不是什么**：**不自建 shell** —— 用系统 shell，不替他改写命令。

**边界**：命令在工作区根执行；面板高度可拖拽 —— 拉不高，长输出就没法看；输出可回溯不截断。

### 4.1.12 页签

**是什么**：多文件并存，可切换、可关闭、可重排。

**不是什么**：**不强制单页签**（不爱多开是个人偏好，不是产品约束）。

**边界**：关闭未保存的页签要给三个选择（保存 / 不保存 / 取消），不许只给「确定」。**页签条的高度只由内边距与字高决定** —— 空白页签与有地址有标题的页签同高，页签多了横向滚动，不换行、不靠内容撑高。

### 4.1.13 会话恢复

**是什么**：重启后回到上次的工作区、页签与光标位置。

**不是什么**：**不恢复未保存的改动** —— 恢复的是「看什么」，不是「改了什么」。

**边界**：文件已被外部删除时，恢复要提示而不是静默丢弃。

### 4.1.14 撤回

**是什么**：把**一次任务里做过的多处修改**（可能跨好几个文件）当成**一个批次**撤回，回到那次任务开始前的样子。

**不是什么**：**不是编辑器撤销**（`⌘Z` 只管当前文件、只管人敲的字）；也**不是版本库回滚**（不需要先提交、不依赖 Git）。

**边界**：撤回前要摆出「将撤回哪些文件、各改了几处」；**只撤 Agent 做的改动，人手改过的部分不动** —— 同一个文件里两边都改过时，要说清冲突在哪并让人决定；**撤回本身也留痕**（3.3.3），且撤错了能再撤回来。

### 4.1.15 Git 状态

**是什么**：显示当前分支、未提交 / 未跟踪 / 有冲突的文件 —— 这是 Agent 开跑前**先验**的来源之一（3.1.3）。

**不是什么**：**不是 Git 客户端** —— 不提供提交、推送、合并、切分支（那些在终端里做，4.1.11）。

**边界**：**只读**（读状态不改工作区、不锁仓库）；无仓库 / 游离头（detached HEAD）/ 仓库损坏都要如实说明，不许显示成「干净」。

### 4.1.16 看差异

**是什么**：按文件看行级差异（工作区对基线），也能只看某次任务改了什么。

**不是什么**：**不替代撤回**（4.1.14）；也不做三方合并界面（真冲突时交给终端里的 Git 处理，4.1.11）。

**边界**：二进制或超大文件要**明说无法展示**，不许留一片空白；**换行符差异不得伪装成内容改动**；只读，不改动工作区。

### 4.1.17 语法高亮

**是什么**：按语言把关键字、字符串、注释、类型、数字分开上色，让结构一眼看得出来；语言由文件类型与内容判定。

**不是什么**：不是「按后缀涂色」——后缀不改、内容不对就认不出；也不是装饰，**颜色错会让人误读代码**（把字符串当注释，把注释当代码）。

**边界**：着色规则可配、跟随主题；深色与浅色两套都要满足对比度（不许「深色下注释看不见」）；**认不出语言就不上色，不猜**。

### 4.1.18 自动补全

**是什么**：在光标处按上下文给候选（变量、函数、字段、关键字），键盘上下选、回车插入；候选按相关度排，不是按字母排。

**不是什么**：不是「把词表倒出来」；**不打断正在输入的词**（补全时还能继续打字）；也不只是补名字 —— 要能给出签名与类型，否则等于让人猜参数。

**边界**：候选来自语言服务，不是硬编码表；**服务不可用要明说「补全不可用」**，不许静默退化成空白；插入后光标位置要可预测（能接着打字）。

### 4.1.19 跳转与大纲

**是什么**：跳到定义、找引用、看文件符号大纲；跳走之后能一键**回到原处**（跳转历史）。

**不是什么**：不是「全文搜一遍同名」——同名不同作用域要分得清；也不只是文件内，跨文件同样要能跳。

**边界**：项目未建索引时如实提示「尚未索引」，**不许给出错误位置**；符号重名时列出候选让人选，不默认跳第一个。

### 4.1.20 诊断

**是什么**：语法 / 类型 / 未使用变量这类问题在行内标出，另有问题列表可逐条跳转；**输入时就有反馈**，不必先跑一遍构建。

**不是什么**：不是把构建的错误搬进来；也不是把警告都当错误 —— **分三级**（错误 / 警告 / 提示），否则满屏红线等于没有线。

**边界**：诊断来源要说清（哪个工具、哪一版规则）；误报可关，且关掉要记得；**不许一直挂着修不掉的假错** —— 修不好就说明为什么留着。

### 4.1.21 格式化

**是什么**：按语言规范一键重排（缩进、换行、引号、对齐），可只格式化选中范围。

**不是什么**：**不是「保存时自动改」** —— 什么时候格式化由人定；**不动语义**（格式化不许顺手改逻辑或重命名）。

**边界**：格式化失败要说清原因（语法不完整 / 没有格式化器 / 版本不匹配）；**不许悄悄只改一半**；格式化算一次可撤销的操作。

### 4.1.22 多光标

**是什么**：在多处同时编辑（选中相同词批量改、按行尾批量加字），或按列块选中改写。

**不是什么**：**不是「循环替换」** —— 光标是真同时在；也不只是批量改名，插入、删除、整块缩进都要支持。

**边界**：一次多光标操作算**一步撤销**；光标数过多要提示（几百个光标改起来人会失控）；列编辑遇到不等长行要说清怎么处理（补空格 / 跳过 / 停在第几行）。

### 4.1.23 代码折叠

**是什么**：按块（函数 / 类 / 导入 / 自定义区域）折叠，只留骨架，用来看结构。

**不是什么**：**不是「删掉不看」** —— 折叠不改变文件内容，**搜索仍能搜到里面的字**；也不只有自动折叠，要能手折。

**边界**：折叠状态随会话恢复；折叠区内的命中要能**展开显示**（不许「搜到了但看不见」）。

### 4.1.24 命令面板

**是什么**：一个入口搜所有动作（命令、文件、符号），边打边筛，带快捷键提示。

**不是什么**：不是「菜单的另一种排法」—— 要能用**模糊词**命中（`renfile` 能找到「重命名文件」）；也不只列能用的，要**把不能用的也列出来**。

**边界**：不可用的动作显示为**禁用并说明原因**，不许点了没反应；面板里每个动作都要能查到它的快捷键；**面板里有的动作，菜单里也必须有**（不许藏成私有入口）。

### 4.1.25 分屏

**是什么**：同一窗口左右 / 上下分屏，看两个文件，或同一文件的两处；每侧独立滚动与光标。

**不是什么**：不是「多开窗口」—— 分屏共享一个工作区状态；也不是「复制一份编辑器」（**同一文件两处编辑要实时同步**）。

**边界**：分屏布局随会话恢复；关一侧不关整个工作区；同一文件两侧同时改同一行时**由编辑器自己合并**，不许把冲突丢给人。

### 4.1.26 缩进与括号

**是什么**：自动缩进、回车继承缩进、括号与引号配对高亮与自动闭合、整块缩进 / 反缩进。

**不是什么**：不是「全自动排版」—— 只做**局部、可预测**的辅助；也**不自动重排已有代码**（那是格式化的事）。

**边界**：缩进宽度、空格还是 Tab **跟随项目约定**（3.4.3）；自动闭合后继续打字要能「穿过」右括号，而不是再插一个；**粘贴进来的代码不许被强制改缩进**。

### 4.1.27 编码与换行

**是什么**：识别并显示文件编码（UTF-8 / GBK 等）与换行符（LF / CRLF），需要时可转换。

**不是什么**：**不是「悄悄统一成一种」** —— 编码与换行符的变更必须显式；也不是按扩展名猜编码。

**边界**：转换前提示影响行数；**非 UTF-8 的中文要能正确读出**（读成乱码不许保存回去）；有没有 BOM 要看得出来；混用换行的文件要能标出是哪几行。

### 4.1.28 大文件承载

**是什么**：几十 MB 的日志或数据文件能打开、能滚、能搜，界面不卡。

**不是什么**：不是「打开就假死」；**也不是「截断一半假装全文」** —— 少了多少要说出来。

**边界**：超限时降为只读并说明原因；搜索要能**流式进行**（边搜边出、可中断）；超长行要横向滚动而不是折成一团。

### 4.1.29 调试器

**是什么**：设断点、单步（步入 / 步过 / 步出）、看变量与调用栈、在断点处求值；与编辑器共用同一份文件状态。

**不是什么**：**不自研调试协议**（用各语言既有的调试器，经 DAP 接入）；**不替代日志**（有些问题该看日志而不是断点）；不做多机远程编排。

**边界**：断点要落在**真实可执行行** —— 若被移到别处必须说出来，不许静默挪；启动失败要给原因（缺调试器 / 端口占用 / 构建失败）；**调试期间改了文件要提示「当前代码与运行中的不一致」**。

### 4.1.30 编码辅助

**是什么**：在编辑器里按当前位置的上下文给补全或改写建议（补一行、补一段、改错、解释这段在干什么），**接受前能看到差异**，逐块接受或整段拒绝。

**不是什么**：**不是自动改**（不点不接受就一个字不动）；**不是整文件重写**（只给与光标相关的片段）；也不是「问一句答一段」的聊天窗口 —— 它贴在代码上。

**边界**：建议要能说清**依据**（读了哪些文件、依据哪个符号）；**未保存内容不外发**（遵守 3.3.5 数据边界）；拒绝即结束，不追问、不改口；跨多行的建议要能**逐块接受**，不许「要么全要要么全不要」。

### 4.1.31 许愿式编程

**是什么**：**不进编辑器**，用一句话说想要什么（「给这堆接口加上重试」「把这份 CSV 变成导入脚本」），Agent 在工作区里读代码、改文件、跑构建与测试，产出**待验收的改动**。

**不是什么**：**不是「改完就生效」** —— 一律先出改动、等人验收；**不是只生成新文件**（改现有文件才是主场景）；**不是绕过工程规矩**（项目规则、构建脚本、代码风格照旧遵守）。

**边界**：**改动范围先划** —— 哪些目录可动、哪些只读，越界即停并说清；**构建/测试不过要如实报**，不许说「应该没问题」；产出以 **diff + 一句话说明「改了什么、为什么」** 呈现；验收后才落地；**整批可撤回**（4.1.14），且撤回不留半截状态。

### 4.1.32 外部改动监听

**是什么**：工作区在**本编辑器之外**被改动时（切分支、别的工具改文件、脚本生成文件），文件树与已打开的页签**跟着变**，并说清变了什么。

**不是什么**：**不是「悄悄重载」** —— 正在编辑的文件被外部改动，必须让人选（重新加载 / 保留我的 / 看差异），不许直接覆盖；也不是全盘扫描硬盘。

**边界**：监听范围限当前工作区（不跟随符号链接跑到别处）；**改动来源不明时只提示不自动处理**；一次切分支动了几百个文件，要合并成一条「工作区已被外部改动 N 个文件」而不是刷几百条通知。

### 4.1.33 工作区切换

**是什么**：在多个根目录之间切换（前端一个仓库、后端一个仓库），**各自保留自己的页签、展开状态与会话**。

**不是什么**：**不是一个窗口同时管多个仓库** —— 同一时刻只有一个活动工作区，`3.1.3 先验`、`4.1.15 Git 状态`、改动范围都按它算；也不是「关掉再打开」。

**边界**：切换保留各工作区的历史与页签，切回来接着干；关闭工作区前提醒未保存的改动；**越界访问另一工作区的文件默认拒绝**（要显式打开）。

### 4.1.34 内嵌浏览器

**是什么**：工作区里能开一个**浏览器页签** —— 输入地址、前进后退、刷新、停止、下载；**本机的网页文件不是只能看源码** —— 打开 `.html` 一类文件可在编辑器内切「预览」看渲染后的页面（与 Markdown 预览同一套交互），也可以放到浏览器页签里带地址栏打开。对它打开的站点来说，这就是一个**常规浏览器**在访问，而不是「某个应用里嵌的一块面板」。

**不是什么**：**不是「网页预览」** —— 只给截图、把页面剥成纯文本、砍掉脚本与跳转的「简易视图」，都不算这条能力；**不是**把外部浏览器窗口拉进来当一块面板；**也不是**数据库工作台的一部分 —— 浏览器属于工作区，不属于某个数据库连接；**不承诺**绕开站点的安全策略（伪装成别的东西骗过风控不算能力）。

**边界**：与 `4.1.6 打开与识别` 的分界 —— 普通文件进编辑器或预览，**网页进浏览器页签**（同一个 `.html` 文件可以两种方式打开，互不覆盖）；与 `4.1.11 终端` 的分界 —— 终端跑命令、浏览器看网页，各自独立，谁也不嵌在谁里面。 绝大多数站点应当正常打开，包括需要登录、需要跳转、需要第三方凭据的站点。少数场景下无论谁来做都过不去 —— 要求硬件密钥、要求播放受版权保护的内容、站点政策明文禁止嵌入式环境。这类不硬绕：**说清原因，并给出「用常规浏览器打开同一地址」的出路**，不让用户在壳里反复试、猜不清是自己错还是站点不让。

**本机网页文件的边界**：只放行**工作区内 / 用户已授权目录内**的网页文件及其同目录资源；越出授权范围的路径一律拒绝并说明。理由：否则一个下载来的页面就能读遍本机文件。

### 4.1.35 授权与版本

**是什么**：应用能说清「我是什么版、能用哪几块、什么时候到期、绑了几台设备」，并按授权决定**哪些入口出现** —— 三块能力（开发工作区 / 数据库 / 笔记）由**同一份**授权决定，不是三套开关。

**不是什么**：**不是收费系统，也不是加密锁** —— 不联网激活、不做反调试、不靠混淆；**到期不锁数据**：能看、能导出，只是新入口不给；**不是「灰掉诱导」** —— 没授权的入口**不出现**，而不是摆在那里点了才发现不能点。

**边界**：与 `4.1.1 Home 页` 的分界 —— Home 说「这是哪个版本、版权归谁」，授权页说「能用哪几块、还剩多久、几台设备」；与各能力点的分界 —— **能力点不各自判断授权**，只看一个判定结果（入口出现 / 不出现），否则同一件事会在十几个地方各判一遍，迟早判得不一样。 设备配额是**备用能力**（默认上限 5 台），只用随机标识、不采硬件指纹；换机靠「释放设备」解决，不靠后台封禁。

### 4.1.36 帮助与关于

**是什么**：一条**能查、能问、能查版本**的通道 —— 帮助入口给出快捷键表、常见操作说明与当前版本 / 构建号；用户遇到问题时知道该去哪求助，而不是靠猜。

**不是什么**：**不是在线文档系统**（不内嵌网页手册、不连云文档）；**不是客服工单**（不在应用里发工单）；**不是把菜单塞满** —— 帮助只占一个入口，不散在各处。

**边界**：与 `4.1.35 授权与版本` 的分界 —— 授权页说「能用哪几块、到期没到期」，帮助页说「怎么用、这是什么版」；**版本含义与升级路径只在帮助页解释**（别处只显示版本号，不各解释一遍）。 帮助内容**随包发、离线可看**（不依赖网络）；版本号与构建号**只有一个出处**（不许两处手写）；帮助里**不承诺没做的入口** —— 列出来的必须点在手上真能用。

### 4.1.37 外观与主题

**是什么**：**看得清、调得动** —— 跟随系统的深浅色、字号与缩放；可按环境切换主题（例如生产用冷色、测试用暖色），让「我现在连的是哪」在视觉上先说话。

**不是什么**：**不是皮肤商店**（不做主题市场、不装第三方美化包）；**不是编辑器配色全家桶**（只调界面与语法着色两套基调）；**不改信息架构** —— 换主题不换布局与位置。

**边界**：与 `4.1.17 语法高亮` 的分界 —— 语法高亮管「代码里的词怎么着色」，主题管「窗口、面板、状态的底色与强调色」；与 `4.2.7 连接失败` 的分界 —— 错误仍用同一套语义色，不因主题而歧义。**对比度有门槛**（正文与底色、强调色与表面，深浅两档都要过）；换外观**不动数据、不改布局**；用户选择与系统设置冲突时以用户为准，并说清生效范围。

### 4.1.38 工程与工具链

**是什么**：把「工程该由什么构成」写成可重复执行的描述 —— 由描述生成工程文件、用一条命令构建与跑测试、产出可直接运行的应用包，全程不依赖图形 IDE。

**不是什么**：**不是包管理器的替代**（依赖仍交给包管理器）；**不是 CI 服务**（不做流水线托管与排队）；**不手改生成物** —— 工程文件是产物，不是手写源。

**边界**：与 4.1.11 终端的分界 —— 终端是「人敲命令的地方」，工程与构建是「不敲也能一条命令跑完的链路」（构建、跑测试、出包各一条入口）；同一份描述两次生成结果必须一致；生成物被手改要能**发现并说明**，不许当没看见；构建与测试要给**真实结果**（失败不许报成通过，命令没报错也不等于功能对，见 3.8.1）；依赖来源可切换（镜像 / 私有源），但切换改了哪一层要说清；构建失败给原因，不许只丢一句「失败」。

### 4.1.39 插件装配

**是什么**：把**另一个产品**（笔记）以**同进程模块**装进宿主 —— 出现在宿主的**活动栏与菜单**里、跟随宿主的主题与授权、与宿主共用同一份运行时。

**不是什么**：**不是 Agent 的插件体系**（那条管的是 Agent 能力层可装卸，见 3.6.4）；**不是独立进程 + 进程间通信**；**不是可卸载的第三方包**（那要跨进程边界与公开 ABI）；插件**不各自授权**。

**边界**：与 4.1.35 授权与版本的分界 —— 授权只回答「这块能不能出现」，装配回答「它怎么住进来、数据放哪、边界在哪」；两者不互相判断（可见性只由授权那一个判定处给结论）。宿主向插件**单向**给上下文，**只给文本与标识、不给结果行数据** —— 要给必须显式确认并永久留痕；插件的数据落在**它自己的数据家**里，不写进宿主的数据；插件不得依赖宿主的数据库 / 工作区类型，只可用**代码解析这类公共件**（不碰数据、不碰状态）；**装配本身不引入网络出口** —— 要不要联网同步，由插件自己的产品能力决定（5.1.8），不由宿主装配顺手打开；未授权时入口**不出现**（不是灰掉），且「出不出现在入口里」只有**一处判据**，不在各视图各判一遍。

## 4.2 Database Client

> 连上一个库之后能做的事：看清结构、跑语句、改数据、诊断、维护。

### 4.2.1 新建连接

**是什么**：填主机 / 端口 / 库 / 账号，保存后出现在连接列表里，点开即连。

**不是什么**：**不自动探测你没有的库**，也不替你猜端口之外的东西。

**边界**：必填项缺一不给保存；连通性失败要说清失败在哪一层（网络 / 认证 / 库不存在）。

### 4.2.2 连接管理

**是什么**：**已有连接的那一堆怎么管** —— 列表可见可选、编辑不出来错、删除二次确认并连带清凭据、记住上次选中、显示名带上登录账号。

**不是什么**：**不是连接池管理**（不改服务器端配置）；**不替你猜哪个是生产** —— 颜色与标签要你自己打（`4.2.3 连接组织`）。

**边界**：与 `4.2.1 新建连接` 的分界 —— 一个管「怎么填对一个新连接」，一个管「已有的一堆怎么管」；与 `4.2.4 上下文栏` 的分界 —— 列表是全集，上下文栏是当前选中的那一个。**删除连带清凭据**（不许留孤儿口令）；重命名不改底层标识（历史记录仍对得上）；口令**不显示**、也不许用掩码长度泄露位数；批量删除先给逐条清单。

### 4.2.3 连接组织

**是什么**：**按项目 / 环境把连接收拢** —— 分组折叠、颜色与「生产 / 预发 / 测试」标签、只读连接与连接后自动执行的 SQL。

**不是什么**：**不是权限系统**（不改服务器角色与授权，那是 `4.2.33 会话与权限` 的只读视图）；**不是环境编排**（不替你切流量、不建跳板）。

**边界**：与 `4.2.2 连接管理` 的分界 —— 2 管「有哪些」，这里管「怎么摆、怎么一眼认出」；与 `4.2.14 高危确认` 的分界 —— 颜色是提示，真正的拦截在 4.2.14。**只读连接要真拦住写操作**（不是只换个颜色）；分组与标签只改展示，不改连接参数；连接后自动执行的 SQL 失败**不阻断连接**，但必须报出来。

### 4.2.4 上下文栏

**是什么**：**当前在哪个服务器、哪个库** —— 两个下拉显式说出执行上下文，切换即改后续语句的落点，不必回连接列表里找。

**不是什么**：**不是默认库设置**（不写回连接配置）；**不是权限配置器** —— 只列出当前账号可见的库，看不到的就是没有。

**边界**：与 `4.2.2 连接管理` 的分界 —— 列表管全集，这里管当前；与 `4.2.8 树形浏览` 的分界 —— 上下文栏说「在哪」，对象树说「里面有什么」。**只列当前账号可见的库**（看不到就是没有，不摆灰色假项）；切换上下文要**清掉上一库结果的归属**（不许把 A 库的结果挂在 B 库名下）；上下文**不写回连接配置**。

### 4.2.5 凭据

**是什么**：口令进系统钥匙串，连接时按需取用。

**不是什么**：**不在界面、日志、导出物里显示明文**；不把口令写进连接配置文件。

**边界**：钥匙串不可用时要明确报错，不许静默降级成「每次都问密码」。

### 4.2.6 SSH 隧道

**是什么**：经跳板机连数据库：本地端口转发到远端。

**不是什么**：**不代管你的 SSH 私钥**（用系统已有的）；不做密钥分发。

**边界**：隧道断了要断开连接并提示，不许让界面停在「看起来还连着」。

### 4.2.7 连接失败

**是什么**：连接失败时给出可执行的下一步（检查端口 / 检查账号 / 检查库名）。

**不是什么**：**不编造原因** —— 拿不到底层错误就照原样给出。

**边界**：错误原文必须可复制。

### 4.2.8 树形浏览

**是什么**：库 → 模式 → 表 / 视图 / 函数 / 存储过程逐层展开；**表 / 视图 / 函数 / 存储过程这几层可以右键加过滤器** —— 过滤器生效时，只看名字满足表达式的对象。

**不是什么**：**不一次性把整库拉下来**（大库会卡死）；不做「猜测式」补全；过滤器**只筛节点显示**，不放宽任何权限，也不改查询结果。

**边界**：按需展开、可刷新；展开失败的节点要标出来而不是留空；**过滤器按节点记住**（同一节点再展开仍生效，可一键清除）；表达式写错**当场说**，不许静默变成「什么都没匹配到」。

### 4.2.9 表结构

**是什么**：看列、类型、默认值、索引、外键。

**不是什么**：**不在浏览时改结构**（改结构是 4.2.20 表设计）。

**边界**：结构信息要能复制成 DDL 片段。

### 4.2.10 刷新

**是什么**：结构变了（别人加的列、新建的表）能**手动**刷到最新；刷的是**元数据**，不是重连。

**不是什么**：**不做后台轮询** —— 不给自己造「看起来实时」的假象；也不是「刷新=断开重连」（正在跑的事务会被连累）。

**边界**：刷新保留展开状态与当前选中；**刷新失败要保留旧视图并说明原因**，不许把树清空成空白；有查询正在跑时刷新要提示「会打断还是等它跑完」。

### 4.2.11 单次执行

**是什么**：写 SQL、执行、看耗时与影响行数；支持只跑选中部分。

**不是什么**：**不自动加 `LIMIT`**（不替你的语句做决定）。

**边界**：语句错误要把数据库返回的原文贴出来（含位置）。

### 4.2.12 结果与错误

**是什么**：**跑完之后看到什么** —— 多结果集可切换、行列数与耗时、影响行数、错误原文含位置、执行中的页签关不掉。

**不是什么**：**不是报表**（不聚合、不出图表，导出在 `4.2.21 导出`）；**不是日志**（错误只属于这一次执行）。

**边界**：与 `4.2.11 单次执行` 的分界 —— 11 管「发出去、跑完」，这里管「跑完怎么呈现」；与 `4.2.16 展示` 的分界 —— 展示管表格本身（列宽、复制、NULL），这里管这次的结果集与状态。**服务端错误原文不改写**（可以加解释，不许替换原话）；影响行数未知就写「未知」，不拿客户端计数冒充；执行中的页签**关不掉**（等它跑完或先取消）。

### 4.2.13 工具栏与事务

**是什么**：**把常用动作摆出来的一条工具条** —— 执行 / 停止 / 检查的图标按钮与快捷键，以及事务的开始 / 提交 / 回滚。

**不是什么**：**不是菜单的重复** —— 每个按钮都要有对应命令（`4.1.24 命令面板`），只有图标没有命令的动作不许存在；**不隐藏能力**。

**边界**：与 `4.2.11 单次执行` 的分界 —— 这里只管入口形态与可达性，执行语义仍归 11；与 `4.2.15 中断` 的分界 —— 停止按钮是入口，能不能真停下来归 15。 事务状态**必须看得见**（有未提交改动要有标记，切连接 / 退出前要提醒）；**未提交就断开要说清会回滚**；工具栏不许有「仅在界面可达」的动作 —— 每个按钮都要有对应命令。

### 4.2.14 高危确认

**是什么**：无 `WHERE` 的 `UPDATE` / `DELETE`、`DROP`、`TRUNCATE` 执行前弹确认。

**不是什么**：**不是「提醒一下就算了」** —— 确认前不发送语句。

**边界**：确认框要显示将要执行的完整语句与目标库。

### 4.2.15 中断

**是什么**：长查询、长事务可以中断，**中断的是这条语句，不是这条连接** —— 中断后连接仍可用。

**不是什么**：**不假装「已中断」** —— 数据库不认账时要如实说还在跑；也不是「杀掉连接」当万能手段（会连累同一连接上的其它事）。

**边界**：中断结果三态（成功 / 失败 / 未知）都要显示，并说清**数据库此刻是否还在跑**；中断后要说清**已产生的副作用**（部分写入是否已提交）；连续中断要提示可能是锁等待而不是慢查询。

### 4.2.16 展示

**是什么**：表格展示，NULL 与空串可区分，列宽可调。

**不是什么**：**不把 NULL 显示成空**；不做隐式类型转换。

**边界**：超宽表要能横向滚动而不是截断列。

### 4.2.17 排序筛选

**是什么**：按列排序、按值筛选，不改动原语句的结果语义。

**不是什么**：**排序与筛选只改「看的顺序」，不改语句、不重新执行查询** —— 改了就不是同一个结果集了。

**边界**：筛选后要显示「已筛掉多少行」。

### 4.2.18 大结果承载

**是什么**：大结果分页或虚拟滚动，明确告知还有多少没显示。

**不是什么**：**不一次渲染十万行**把界面卡死。

**边界**：显示「共 N 行，已显示前 M 行」。

### 4.2.19 行编辑

**是什么**：直接在结果里改单元格、增行、删行，生成对应 DML 执行。

**不是什么**：**不做无主键表的隐式匹配**（没有唯一键就明确拒绝编辑）。

**边界**：改动前给出将执行的语句；执行失败整批回滚。

### 4.2.20 表设计

**是什么**：建表、加列、改类型、加索引，生成 DDL 并执行。

**不是什么**：**不「点一下就 alter」** —— 必须先预览 SQL。

**边界**：破坏性变更（删列 / 改类型）要单独确认。

### 4.2.21 导出

**是什么**：结果或整表导出 CSV / JSON —— 可导当前一页，也可导全部；列由你勾选，顺序按你的勾选走。

**不是什么**：**不含敏感列除非你显式勾选**；不做「猜测你要脱敏」的自动替换，导出的内容与屏幕上看到的一致。

**边界**：导出完成要报数（多少行、多大、落在哪）；中途取消不留半截文件，失败要说清卡在哪一步。

### 4.2.22 导入

**是什么**：从 CSV / SQL 文件导入数据。

**不是什么**：**不做「尽力而为」的静默跳过** —— 失败行必须报出来。

**边界**：导入前给字段映射预览；结束报成功 / 失败行数与失败原因。

### 4.2.23 执行计划

**是什么**：把语句的执行计划按节点展开，标出代价与扫描行数。

**不是什么**：**不给「应该加索引」的结论** —— 只给读数，结论由人来下。

**边界**：不同库的计划格式差异要显式说明。

### 4.2.24 统计读数

**是什么**：缓存命中率、活动语句、连接数等运行时读数。

**不是什么**：**扩展没装就说没装**（例如语句统计类扩展），不拿别的数凑。

**边界**：每条读数标注来源视图与采样时刻。

### 4.2.25 锁与等待

**是什么**：谁在等谁、等了多久，按阻塞链一层层展开（谁握着锁、谁在排队、各自等了多久）。

**不是什么**：**不自动杀会话** —— 只显示，处置由人决定；也不给「谁对谁错」的裁决。

**边界**：识别不到等待链时明说「看不到」，不拿相邻读数凑；查看本身必须是只读且带超时，不能把库再拖住一层。

### 4.2.26 对话式诊断

**是什么**：把执行计划、统计读数、锁等待**交给 Agent 读**，让它用人话说清「这次慢在哪、可能是什么原因、下一步该看什么」—— 回答要挂着具体读数，不是泛泛而谈。

**不是什么**：**不是「一键优化」** —— 不替你改索引、不执行任何 DDL/DML；也**不是拍脑袋**（4.2.24 统计读数的判据同样适用：结论必须站在真实读数上）；更不是「问一句就给你一条 SQL」。

**边界**：**每条判断要标出是「读数」还是「推断」**（推断要说明依据哪个数、什么假设）；**拿不到读数时不许猜**（例如扩展没装，就说看不到，而不是编一个原因）；**建议改结构时必须说清风险**（锁表、磁盘、回滚方案），执行与否由人在 4.2.20 表设计里决定。

### 4.2.27 任务定义

**是什么**：把 VACUUM / 重建索引 / 备份编成任务，可定时。

**不是什么**：**不内置「最佳实践模板」** 替你决定跑什么。

**边界**：任务要写明目标库与影响对象；**失败怎么处置要提前定** —— 重试几次、隔多久、连续失败是否暂停、告警给谁；同一对象的任务**串行执行**（两个 VACUUM 撞上只会互相拖死），不许排队排到自己等自己。

### 4.2.28 审批

**是什么**：动作执行前经审批，**批准才跑**；审批要看得到上下文（哪条语句、哪个库、预计影响多少行）。

**不是什么**：**不是执行后的提醒**（前置才叫审批）；也不是「一次批准永久有效」—— 批准只对**这一次、这一组参数**。

**边界**：审批记录可查（谁批的、哪条语句、何时、结果）；**无人应答要超时拒绝并说明**，不许一直挂着等；审批人与发起人是同一个人时，要提示「这不是双人复核」。

### 4.2.29 执行回执

**是什么**：跑完给出改了什么、影响多少行、耗时。

**不是什么**：**不把「完成」当回执**。

**边界**：失败要停，不许继续下一个任务；**回执要留存可回查**（谁发起、何时、哪条语句、影响行数、耗时、结果），失败也要留 —— 只留成功的回执等于没有账。

### 4.2.30 方言差异

**是什么**：同一功能在**不同方言**上的语法与行为差异显式标注（支持哪些库不在本书规定）。

**不是什么**：**不假装一致** —— 不支持的写法直接说，不「看起来能用、跑起来报错」。

**边界**：差异清单要能被界面读取（不支持时禁用而不是报错）。

### 4.2.31 驱动接入

**是什么**：新增一种库 = 实现一套驱动接口，不改界面。

**不是什么**：**不为某个库改通用层**（改了就是把差异漏进内核）。

**边界**：驱动要自报能力位（支持哪些功能）。

### 4.2.32 查询历史

**是什么**：记下在这条连接上跑过的语句与关键读数（耗时、影响行数、执行时刻），能翻回去、能重跑、能对比两次的差异。

**不是什么**：**不是「自动收藏所有成功的 SQL」**（那是噪音）；也**不是审计日志**（3.3.3 管谁让做的，这里只管「我查过什么」）。

**边界**：**按连接分开记**（生产与测试的语句不许混在一列）；**敏感值不入历史**（语句里的字面量若要脱敏，说清脱敏规则）；历史可清、可导出；**重跑前要提醒**「这条当时改了 N 行」—— 改过的语句重跑是最常见的事故。

### 4.2.33 会话与权限

**是什么**：把**服务器上正在发生的事**摆出来并可管 —— 当前有哪些会话、各自在跑什么、占了多久；能终止自己发起的会话；能查看库 / 对象属主与授权关系，把权限问题定位到「谁、对什么、能做什么」。

**不是什么**：**不是监控平台**（不采指标、不做告警、不存时序）；**不是权限管理员** —— 不替他人在服务器上建号、授权、改 `pg_hba`；看不到的会话就**如实说看不到**（普通用户只能看到自己的）。

**边界**：与 `4.2.25 锁与等待` 的分界 —— 锁说「谁在等谁」，会话说「谁在跑、跑多久」；与 `4.2.24 统计读数` 的分界 —— 统计给累计与排行，会话给**此刻**；与 `3.3.3 留痕` 的分界 —— 留痕记我们做过什么，会话看服务器上正在发生什么。**看不到就如实说看不到**（不拿空表冒充「没有会话」）；终止他人会话要先有权限，被拒就显示服务端原话；权限面**只读展示**，不代改。

### 4.2.34 自动归档

**是什么**：**执行过的 SQL 自动按天落成文件** —— 回头看得到「某天我跑了什么、在哪条连接上」，文件可被 grep、可带走。

**不是什么**：**不是版本控制**（不存多份、不做 diff）；**不是查询历史**（`4.2.32 查询历史` 是连接侧记录，两者不互相代替）。

**边界**：与 `4.2.32 查询历史` 的分界 —— 归档是磁盘文件（离线可查、可提交进仓库），历史是库内记录（可重跑、可比两次差异）。**只追加不覆盖**（同一天跑多次，旧记录不许被顶掉）；语句里的敏感字面量按 4.2.32 查询历史**同口径脱敏**后才落盘（口令、连接串、证件号一类一律不写）；文件名与内容可预测（时间 + 连接名）；写不进去**当场说**，不许静默丢；关掉归档后不产文件，也不假装有历史。


### 4.2.35 命令行出口

**是什么**：不打开界面也能连库、执行语句、看库里有哪些对象 —— 给脚本与无图形环境用，和界面**同一份实现**。

**不是什么**：**不是 Agent 的终端壳**（那是跑对话与任务的壳，见第三章）；不是第二套客户端；不做交互式界面。

**边界**：与 4.2.11 单次执行的分界 —— 执行语义、结果格式、危险语句拦截**完全同一条路径**，命令行只是它的无界面出口，不另立一套判断；连接参数从环境变量读，**密钥不进命令历史与日志**；结果要能被脚本消费（列名与类型）；失败给**非零退出码**并区分「连不上 / 语句错 / 读不到对象」三档；输出默认不截断，被截断要说清少了多少。

## 5.1 Notes 能力

> **形态**：笔记是**独立产品** —— 手机端是独立 App，**桌面端以插件形态装进 Doyah Studio**（不单独出桌面客户端）；平台范围不在本书规定。
>
> **它不接 Agent**（1.2 · [S-12]）：笔记要**快和静** —— 没有对话、没有自动改写、没有自主执行。凡出现「帮你润色」的念头，都先问是不是该放到别的产品里。
>
> **但「不接 Agent」不等于「不用模型」**：语义检索、相似推荐这类**理解与排序**可以调用模型；模型只做「帮你找到、按相关排」，**不替用户改内容、不替用户做决定**。两者的分界是：**模型理解，Agent 行动**。

### 5.1.1 快速捕获

**是什么**：从任何位置**一个动作**就能记下 —— 全局快捷键、分享菜单、桌面小组件都是入口，按下去直接进输入框；**不需要先选笔记本、选模板、填标题**。

**不是什么**：**不是「打开 App → 新建 → 选笔记本 → 选模板」** —— 那是整理，不是捕获；也不要求捕获时就想好放哪。

**边界**：**先落盘再排版** —— 不许因为格式没想好就丢内容；**离线、断网也要能记**，恢复网络后自行补同步；捕获失败必须明确报错（磁盘满 / 无权限），不许「看起来记上了其实没有」。

### 5.1.2 编辑与格式

**是什么**：富文本编辑：标题、列表、引用、代码块、表格、任务框、分割线；输入即时渲染。

**不是什么**：**不是「所见即所得就得随心所欲」** —— 格式要收敛在有限几种，允许的样式越多，导出的语义越难保；也不做排版设计（字号字体是主题的事）。

**边界**：**格式可长期演进** —— 旧笔记在新版本里必须能打开，不许「升级后老笔记变乱码」；撤销栈要够深（至少几十步）；**粘贴进来的内容不许悄悄改结构**（表格与代码块尤其）。

### 5.1.3 附件与图片

**是什么**：截图直接粘、文件拖进来，附件跟着笔记走；图片在正文里就地显示。

**不是什么**：**不是「压缩到看不清也算存了」** —— 附件原样保存；也不是无限大（要说明单文件与总容量的上限）。

**边界**：附件**按原文保存**，不二次编码；附件缺失时要**在正文里标出「这里原来有个附件」**，不许静默留白；同步时附件是「随笔记一起传」还是「按需下载」要说清（决定离线能看到什么）。

### 5.1.4 列表与检索

**是什么**：首页列表 + 全文检索（标题与正文），支持筛选、置顶、多选；检索结果高亮并直达命中处。

**不是什么**：**不是「按时间倒序翻到底」** —— 几千条之后必须靠搜；也不是「搜到就跳首条」（多条命中要给列表）。

**边界**：大仓库**不许一次全渲染**（懒加载或分页）；搜索要有防抖，输入中不卡；**搜不到要说「没有匹配」**，不许假装在搜。

**两种检索，说清用哪种**：**关键词**（精确匹配，离线可用）与**语义**（按意思找，需要模型）。**语义不可用时要退回关键词，并且说出来** —— 不许让用户以为「搜遍了全文」，其实只搜了字面。

### 5.1.5 整理

**是什么**：标签、笔记本、置顶、收藏 —— 让仓库从几十条长到几千条还能用。

**不是什么**：**整理动作不改变内容**（打标签不许顺手改正文）；也不是「只能有一种归类法」—— 标签与笔记本并存，同一个笔记可以在多处出现。

**边界**：排序语义统一（置顶优先于时间，且全局一致）；**删标签不许删笔记**；重命名笔记本要连带更新归属，不许留下孤儿。

### 5.1.6 历史版本

**是什么**：每次保存留一个版本，能看「改前 / 改后」，能只回退这一条。

**不是什么**：**不是 Git** —— 不做分支、不做提交信息、不需要用户懂版本库；也不是「只留最后一次」（那等于没有）。

**边界**：版本要有**保留期**并说清楚（多久、多少条之后开始丢）；回退是**新增一个版本**而不是抹掉历史；**回退只影响这一条笔记**，不连带别的。

### 5.1.7 删除与恢复

**是什么**：删除先进「待删」，给一个可撤销的窗口，再真正落库。

**不是什么**：**不是「删了就没了」** —— 必须有后悔的机会；也不是「彻底删除藏起来」—— 要显式二次确认，且说清后果。

**边界**：撤销窗口内**一定能恢复**；彻底删除要二次确认；**多端同步时删除的影响要说清**（别处会不会一起消失、离线设备上会不会复活）。

### 5.1.8 同步与账号

**是什么**：多端之间同步正文、标签、附件（附件本身与索引怎么传，见 5.1.3）；状态可见（同步中 / 已同步 / 失败原因）。每条记录带**严格递增的 `rev` 与更新时间**，删除留**墓碑**（不是「凭空消失」）。

**不是什么**：**冲突不许静默丢数据** —— 留下两份并说明来源与时间，让人自己合；也**不做「静默覆盖旧版」**（那是最容易丢东西的路径）。

**边界**：数据**归用户所有** —— 任何时刻都能完整导出带走；**主存储在本地**，**联网时才同步到云端**（云端承担多端交换与备份，[S-18]）；**断网照常读写**，联网后补同步；**不许拿云端覆盖本地未同步的改动**，也不许把「还没同步上去」说成「已备份」。跨端格式是**同一份契约**，由笔记产品持有，不归桌面端或移动端任何一侧。**云端可以关掉**：关掉之后就是**不联网的离线笔记**，本机功能一个不少，只是跨端看不到 —— 拿不到网络的部署按这条走，不许因此变成「功能残缺版」。 <!-- contract-change：5.1.8 存储口径由人类主人 2026-10-20 当面更正（S-18），能力书与 notes 镜像同批改 -->账号只用于**同步与识别设备**，口令与令牌进钥匙串、不进配置与日志；**退出登录要说清本地数据怎么办**（保留 / 清空 / 导出）；同步失败要能重试，且不许把失败说成已同步。

### 5.1.9 冲突合并

**是什么**：同一篇笔记在两台设备上都被改过时，以**记录级 LWW（`rev` + `updatedAt`）定一版为准**，**被覆盖的那一版原样留底** —— 两版都能打开、都标出处与时间，谁也不丢。

**不是什么**：**不是「静默覆盖」**（覆盖了却看不到被覆盖的那版，就等于丢）；也**不是「按段落自动拼成一篇」** —— 把两份混成一份，谁改的、哪一版算数都说不清；冲突一律整份留两版，由人定；更**不是「留两份文件让你自己粘」**（那是把活推给人）。

**边界**：
- **不丢**：合并在**整条笔记**这个粒度上发生（记录级），落败的那一版必须能打开、能另存，并标出处设备与时间。
- **删除与改写同时发生**：删除是墓碑（`rev` 严格递增，见 5.1.8 的同步边界） <!-- contract-change：5.1.9 原引用下游「核心契约」，按 1.1 单向依赖改指本书 5.1.8（人类主人 2026-10-20 定稿前通读） -->，墓碑与改写**都留**，不许悄悄让删除生效、也不许被高 `rev` 副本按 LWW 覆盖回来。
- **粒度**：不做段落级拼接 —— 两边各自新增的段落不会自动合成同一份；落败的那版整份留底，能整份打开。
- **合并结果是一个新版本**（5.1.6），原始两版都还在，可回退。
- **合完要能一键改成「以我这版为准」或「以那版为准」** —— 一键是**人按的**，不是默认。

### 5.1.10 导出与迁移

**是什么**：单条或整库导出（Markdown / PDF / HTML），也支持**连附件、标签一起打包带走**。

**不是什么**：**导出不是迁走** —— 导出是一份副本，库里还在；**迁移**是换工具时把全部带走（含附件与标签结构）。

**边界**：导出**不许丢附件、不许改正文**；PDF 只作交付用（不可再编辑，要说清）；**导出前告诉我会得到什么、少什么**（哪些格式在目标格式里表达不了）。

### 5.1.11 私密保护

**是什么**：给单条笔记加一道锁（本机生物识别 / 系统口令），锁住的内容不对旁人可见。

**不是什么**：**不是「整机加密」** —— 它防的是「别人拿到你解锁着的设备随手翻」，不防拿到磁盘的人；也不是「锁了就搜不到」（锁住的内容**默认不进检索结果**，要能解释为什么搜不到）。

**边界**：锁的**强度与范围要说清**（仅界面遮挡 / 正文也加密落盘）；**忘记口令的后果要说清**（能不能恢复）；加锁与解锁都要留痕（谁、何时），且**不影响同步**（锁是本地访问控制，不是把内容藏起来不同步）。

### 5.2.1 清单

**是什么**：待办事项的列表 —— 每条有标题、状态、时间、优先级与标签，可选提醒时间与**重复规则** <!-- contract-change：5.2.1 字段与需求条目对齐（标题/状态/时间/优先级/标签 + 提醒/重复规则），人类主人 2026-10-20 定稿前通读 -->；按时间与状态分组，能新建、完成、改期、删除。

**不是什么**：**不是笔记的另一种视图**（独立对象、独立列表）；不是提醒引擎的全部（只定「有提醒时间这个字段」，到点怎么提醒见平台实现）。

**边界**：**清单是唯一事实源** —— 任务数据只有一份；删除要能撤销；完成不等于删除（完成后仍可回看、可复原）。

### 5.2.2 日历

**是什么**：月 / 周视图，把待办铺在日期上，拖着改期。

**不是什么**：**不是第二套任务数据** —— 日历只是清单的另一种渲染，不另存一份、不产生第二套状态。

**边界**：在日历上完成 / 改期，与在清单上操作是**同一次写入、同一事务**；日历里看不到的（无日期的）待办不许因此丢失；**带重复规则的待办按发生日铺开**，但库里**只有一条记录** —— 不许预先展开成一堆副本，也不许「改一次只改了其中一天」却不说清。

### 5.2.3 完成与改期

**是什么**：改状态、改时间；两处入口（清单 / 日历）改的是同一条记录。

**不是什么**：不是「各端各存一份进度」；不是把完成当成归档。

**边界**：同一事务内落定；写完立刻在另一处可见；冲突时以最后写入为准并留痕，不静默丢一次操作。

### 5.2.4 与笔记互转

**是什么**：笔记详情里「生成待办」—— 标题或选中正文行变成待办标题，正文进备注，**回指原笔记**；待办也能「记成笔记」。

**不是什么**：**不是改类型**（原笔记不变）；不是复制粘贴文本（带的是快照 + 引用）。

**边界**：回指双向可见（双方详情页都显示「来自 / 已生成」并可跳转）；生成后可撤销；来源被删时保留快照文本并标注「来源已删除」，不静默丢内容。

## 6.1 数据

> 一切研究站在数据上。这一层的红线只有一条：**数据从哪来、什么时候取的、口径是什么，必须查得到**。

### 6.1.1 行情接入

**是什么**：接入日 / 周 / 月 K 线与成交量、成交额，支持前复权 / 后复权 / 不复权三种口径；多来源可交叉校验。

**不是什么**：**不是「能拉到数就行」** —— 来源、抓取时刻、复权方式必须一起记下来；**不做实时行情推送**（那是交易软件的事，这里是复盘）。

**边界**：**复权口径必须显式标注**（同一只票不同口径画出来的图不一样，不标就会得出相反结论）；**多来源数据不一致要说出来**，不许静默取一个；停牌、退市、代码变更要有映射表，不许留成断点。

### 6.1.2 数据落库

**是什么**：把拉到的数据**存在本地**，增量更新，只补缺口 —— 不每次全量重拉。

**不是什么**：**不是「每次现拉现算」**（慢且不可复现）；也**不是「只留最新一版」**（历史被覆盖，回测就没法复现）。

**边界**：增量更新要能**识别缺口并补齐**；同一根 K 线被来源修订时要保留修订记录（谁改的、原值多少）；**数据版本要能固定**（同一个回测跑两次结果必须一样）。

### 6.1.3 数据健康

**是什么**：能查出数据自身的问题 —— 缺口、跳空异常、成交量为零、复权前后对不上、日期不连续。

**不是什么**：**不是「跑完没报错就算健康」**；也不是把异常自动「修好」（改了就不是原始数据了）。

**边界**：异常要**标出来并保留原值**，由人决定怎么处理；健康报告要能按标的、按时间段查；**缺数据的地方不许画成连续曲线** —— 那是最容易骗人的一张图；**口径不一致（前复权混不复权、财报用报告期不当披露日）必须拦住计算并说明**，不许算出一个漂亮的数字；数据缺失要影响结论强度（说「样本不足」，不是给一个漂亮的百分比）。

### 6.1.4 财报与事件

**是什么**：接入财报关键项（营收、利润、现金流、负债）、公告与行业分类，按报告期对齐到日线时间轴。

**不是什么**：**不自己推算财务指标**（除非口径写清并标注为「推算」）；也不把「公告标题」当「事件结论」。

**边界**：财报要标**报告期与实际披露日**（回测必须用披露日，不能用报告期，否则就是未来函数）；行业分类变更要留历史；**同一指标不同来源不一致要并列显示**。

## 6.2 研究

> 这一层是产品的价值所在：把「我觉得它像牛股」变成「按这套口径算，它在过去 N 年成立过多少次」。

### 6.2.1 个股档案

**是什么**：一只票的一页全景 —— 走势、关键区间、历史事件、财报节奏、历史复盘记录。

**不是什么**：**不是行情软件的复刻**（不堆几百个指标）；也不给评级、不给目标价。

**边界**：所有图与数都要标口径与时间范围；**同名不同代码要说清**（改名、重组、借壳）。

### 6.2.2 特征模型

**是什么**：把「牛股特征」写成**可计算的定义** —— 一组指标 + 阈值 + 时间窗（例如「连续 N 日缩量后放量突破 M 日均线」），保存为可复用的模型。

**不是什么**：**不是「描述一段感觉」** —— 特征必须是算式，能对任意标的、任意时间段求值；也不是让模型现编一个特征（含糊的规则无法回测）。

**边界**：每个特征要写清**参数、时间窗、用到的数据字段**；**参数是事后挑的要标注出来**（挑出来的参数在样本外往往失效）；特征之间可以组合，但组合后的自由度要算得出来（组合越多越容易过拟合）。

### 6.2.3 选股与筛选

**是什么**：按一个或多个特征模型，在指定股票池与时间段里跑出候选清单，带命中原因。

**不是什么**：**不是「推荐买入」** —— 输出是「符合这套口径的标的」，不是「该买的标的」；也不隐藏筛选条件（结果必须能复现）。

**边界**：股票池范围与剔除规则（ST、停牌、上市不足 N 日）要显式；**命中原因要能追溯到特征与数据**；同一套条件重跑结果必须一致。

### 6.2.4 回测引擎

**是什么**：一条**时间游标**往前推，把历史按「当时能看到的样貌」一天一天放出来 —— 读到哪一天，就只用那一天之前的数据；规则与信号在这条游标上逐日判定买卖点，多只标的可以共用一条游标同步推进。

**不是什么**：**不是「用今天的数据回看昨天」**（未来函数）；**不是「拉一条曲线看涨跌」**（那是行情工具）；**不是模拟盘的实时撮合** —— 回测只回答「当时会不会触发」，不承诺成交。

**边界**：与 `6.2.7 历史情形` 的分界 —— 历史情形是**检索相似段落**（找到像今天的过去），回测是**按规则走一遍**；与 `6.2.5 验证与样本` 的分界 —— 引擎只管「放得出来、放得对」，算出来的数算不算数由 6.2.5 判，**引擎不出结论**。**交易成本、滑点、涨跌停不可成交要显式计入并在结果里标注**。**未来函数零容忍** —— 任一信号用到游标之后的字段，该次回测即判无效；换手 / 停牌 / 涨跌停不可成交必须显式标注；同一份数据两次回测的推进序列一致（可复算）。

### 6.2.5 验证与样本

**是什么**：把模型放到历史区间跑出**命中率、超额收益、最大回撤、样本数**，并做样本外验证 —— 回答「这个模型到底有没有用」，以及「样本够不够支撑这句话」。

**不是什么**：**不是「跑出漂亮曲线就算成功」** —— 必须看样本内外差异；**不是「一次跑赢就推广」** —— 样本太少要明说结论不可靠；**不是替你决定买什么** —— 验证给概率与分布，不给建议。

**边界**：与 `6.2.4 回测引擎` 的分界 —— 引擎保证**过程正确**，验证负责**结论成立**；与 `6.2.2 特征模型` 的分界 —— 模型定义「什么算牛股」，验证回答「这个定义在历史上站不站得住」；与 `6.4.3 归因分析` 的分界 —— 验证看**模型**，归因看**我自己的交易**。验证结果要能导出并被第三方复算。**样本量低于阈值一律标「不足以参考」**；样本内与样本外**分开报**，不合并成一个漂亮数字；产出**不含目标价与买卖建议**；结论可导出、可被他方复算。

### 6.2.6 研报生成

**是什么**：把一只票（或一个组合）的研究结论组织成**结构化文本**：结论 → 依据 → 反方观点 → 风险 → 数据附录。

**不是什么**：**不是「让模型写一篇像研报的东西」** —— 每个结论都要挂到可查的数据与特征上；**不写买卖建议**。

**边界**：**每条结论可溯源**（点开能到具体数据与计算）；**不确定的地方要写明不确定**；生成的文本要能改（是草稿，不是终稿）；**同一份数据换一次生成，结论不许自相矛盾**。

### 6.2.7 历史情形

**是什么**：给定当前的形态，把**历史上相似的情形**找出来，给出**样本量、后续 N 日的涨跌分布**（中位数与分位、最大回撤）—— 只描述**过去发生过什么**。

**不是什么**：**不做面向未来的陈述** —— 不说「接下来会涨」、不说「这里要突破」，也不给目标价；**不把历史频率说成概率**（「过去 62% 上涨」不等于「现在有 62% 的机会涨」）。

**边界**：相似度怎么算（哪些字段、什么阈值、时间窗）要写明；**样本量低于阈值要标「不足以参考」**，不许拿 8 个样本讲规律；分布要给**中位数与分位**，不能只给均值（均值会被极端值带走）；同一输入两次查询结果必须一致；结论要能被第三方复算。

**为什么只到这儿**：越过「描述过去」这条线，就变成投顾了（[S-14]）。

## 6.3 工作流

> 把「取数 → 计算 → 出文本 → 推送」串成一条可复用的流水线 —— 这是「AI 赋能行业」与「聊天机器人」的分界：**口径固定、可重复、可对比**。

### 6.3.1 工作流编排

**是什么**：把若干步骤（取数、算特征、跑回测、生成文本、推送到 IM）编成一条**可命名、可复用、可定时**的流水线；参数可改，步骤可拆开单独跑。

**不是什么**：**不是「写一段提示词让它自己发挥」** —— 步骤与口径是固定的；也不是通用编排引擎（只服务本产品的研究流程）。

**边界**：每步的**输入输出要能检查**；失败要停在失败那步并保留中间产物；**同一条工作流两次运行的结果差异要能对比**（哪一步变了）。

### 6.3.2 市场口径

**是什么**：把行业口径固化成**名词与算法**：放量、缩量、突破、回踩、背离、量价配合、板块轮动……每个 skill 有明确的定义与参数。

**不是什么**：**不是「让模型解释这些词」** —— 定义必须落到算式；也不是封闭黑箱（用户能看到定义、能改参数、能加自己的）。

**边界**：内置 skill 的口径要**写明出处与适用范围**；**同一名词在不同流派定义不同时要并列**（不许偷偷选一个）；用户自定义 skill 与内置的**冲突要显式**。

### 6.3.3 定时与提醒

**是什么**：**收盘后**自动跑数据更新与工作流；周报、特征命中、异常形态都基于**当日收盘数据**推送（IM / 通知）。

**不是什么**：**不做盘中盯盘** —— 不追逐笔、不做分钟级异动提醒（那是交易软件的事）；也不是「到点就一定能跑成」，数据源没更新、网络断了要明确报失败；也不是把所有变化都推给人（会变成骚扰）。

**边界**：**定时不构成授权**（3.5.10 同样适用）：到点只代表可以开始；推送要写明**基于哪一天的收盘数据、哪个口径**；**当日数据没就绪不许拿昨天的当今天**；失败要重试并最终如实报「今天没跑成」。

## 6.4 复盘

> 复盘不是写感想：把**做过的动作**与**市场结果**对齐，找出可改的那一条。

### 6.4.1 交易记录

**是什么**：手工记或从券商导出成交明细导入，形成带时间、标的、方向、价格、数量的流水。

**不是什么**：**不替你连券商下单**（不做交易通道）；也不猜你没记的那笔交易。

**边界**：导入要能**去重**（同一笔导两次不许变两笔）；字段缺失要标出来，不许默认填 0；**记录一旦用于复盘就不许悄悄改**（改要留痕）；**支持哪些来源与导出格式不在本书规定** —— 本书只承诺「能导入并映射到统一字段」，不承诺覆盖所有券商。

### 6.4.2 复盘查询

**是什么**：按时间、标的、策略、标签回看一段时间的操作与结果，能把「当时的判断」与「后来的走势」摆在一起。

**不是什么**：**不是「只看得失金额」** —— 要看决策过程；也不是只显示赚钱的单子（亏损的才是最该看的）。

**边界**：查询范围与口径要显式；**同期对比基准要说明**（大盘、行业、自己的另一策略）；结果可导出。

### 6.4.3 归因分析

**是什么**：把盈亏拆开 —— 选股、择时、仓位、交易成本各贡献多少，哪类操作反复出错。

**不是什么**：**不是「算个总收益率」** 就叫归因；也不把运气说成能力（样本少时要说明）。

**边界**：归因方法要写明（拆解口径与假设）；**样本不足要标「不足以归因」**；结论要能回到具体交易。

### 6.4.4 AI 复盘

**是什么**：检出异常操作（追高、频繁交易、不止损、逆势加仓），提炼可复用的做法，写成可读的复盘稿。

**不是什么**：**不是「让模型点评我」** —— 结论必须挂在原始记录上；也**不许生成不存在的成交**。

**边界**：**结论必须可溯源到原始记录**；模型只**组织与解释**，不判断对错之外的行情走向；**同样的记录两次复盘不许给出相反结论**。

# 第七章 非目标

> 这一章是**反向的**：不写要做什么，写**明确不做什么**。
> 价值在于挡住「顺手加一个」 —— 每次有人提需求，先来这里看一眼。

## 7.1 明确不做

| 不做 | 为什么 | 替代路径 |
|---|---|---|
| **Git 写操作**（提交 / 推送 / 合并 / 切分支） | 一旦做写入，凭据、冲突、rebase、签名全都要接，是另一个产品量级，还会跟终端抢活 | 终端里用 Git（4.1.11）；本书只做**只读**状态与差异（4.1.15 / 4.1.16） |
| **交易通道**（连券商下单） | 这是持牌业务，不是工具能力 | 只做复盘与记录（6.4.1） |
| **投资建议 / 荐股 / 目标价** | 越过「描述过去」就变成投顾 | 只给数据、统计、历史情形（6.2.7） |
| **自研调试协议** | 各语言已有成熟调试器 | 经 DAP 接入既有调试器（4.1.29） |
| **自研语音识别 / 合成 / OCR** | 这些是专门的模型与服务 | 接外部服务，产品只管送进去、带回来（3.5.3 / 3.5.5 / 3.5.6） |
| **自研 IM 协议栈** | 平台协议变动频繁，自研等于永远在追 | 用平台 API / 现成网关（3.6.2） |
| **自研浏览器内核 / 把浏览器做成独立产品** | 内核是「十年、十几人、持续安全响应」的量级，如今在用的内核只有三个；自己造出来也不会成为本产品的优势，书签 / 扩展 / 账号体系更是另一个产品 | 用**系统提供的网页渲染能力**（4.1.34）：网页能在编辑器里预览、能在工作区里浏览；系统能力之外的东西（受版权保护的内容、浏览器扩展、站点政策明文禁止嵌入式环境）**如实说明并交出去**，不硬绕 |
| **多根并发工作区** | 一旦并发，先验、Git 状态、改动范围全要改成复数，代价远大于收益 | 多工作区**切换**（4.1.33），同一时刻只有一个活动工作区 |
| **只在界面里能点、命令里没有的动作** | 那是「界面私有能力」—— 进不了脚本、别的 Agent 调不到、没法复现 | 每个界面动作都要有一条对应命令：Agent 侧走终端壳（第三章），Studio 数据库侧走命令行出口（4.2.35） |
| **自动替人做决定**（自动保存、自动格式化、自动合并、自动删改） | 决定的成本要由人承担，工具不能替人承担 | 一律**先出结果、等人确认**（4.1.31 / 5.1.9） |

**读法**：这张表里的每一条，都在正文某处有一个**对应的能力** —— 不是「没做」，是「**故意只做到这条线为止**」。
