# 界面设计节 · 写作规范

> 适用：`Docs/Doyah产品概要设计说明书.md` 第九章各端实现节里的「界面设计」部分。
> 这份规范放在**仓库里**，因为对侧没有本侧的技能包；规则必须跟着代码走，不能跟着某个人的机器走。

## 0. 分工（人类主人 2026-10-22 令）

- **《Doyah产品概要设计说明书》全部由大河马（`hugehippo`）负责**：所有端（macOS / Windows / Linux / iOS）的设计节都由本侧落笔。
- 小河马（`babyhippo`）**只负责自己一侧的《开发计划书》进度更新**（§3 台账 / §5 矩阵），不写设计节。
- 因此 `[独占:windows]` 这类标记约束的是**改动的审阅范围**，不是「只有该端能写」。本侧代笔 Windows 节时，提交信息带 `exclusive-allow` 与理由。

## 1. 为什么要有这份规范

第九章程的每一节都是「契约 → 某端实现」。契约层（第三章）与界面契约（第七章）已经写好，各端要做的是**把契约落到自己那套界面技术上**，并写清「这套界面长什么样、点下去发生什么、坏的时候什么表现」。

写作对象是**接手的一方**：他拿到这一节，应该能照着搭界面，不靠问人。

## 2. 必需的小节（按端分三档）

| 档 | 适用 | 必需主题 |
|---|---|---|
| `full` | 有独立界面的端（macOS、Windows） | 八项全要 |
| `reuse` | 复用他端前端的端（Linux 复用 Windows 前端） | 窗口模型、命令与键位、六态、与第七章对应、已知缺口 |
| `target` | 尚无代码的目标形态（iOS） | 窗口模型、六态、与第七章对应、已知缺口 |

`full` 的八项如下：

在 `## 9.x` 节内新增 `### 9.x.N` 小节，编号从该节现有最大号续排，**不重排既有编号**。

| # | 小节 | 必须回答的问题 |
|---|---|---|
| 1 | 窗口模型 | 几个窗口？标题怎么来？关闭窗口与会话是什么关系？ |
| 2 | 区域骨架与伸缩次序 | 从外到内有哪几块？哪块固定、哪块可调、哪块折叠？为什么这样排（一句理由，不是审美） |
| 3 | 构件与尺寸 | 每个构件的尺寸从哪个令牌来？**零引用的令牌要写明「令牌存在但视图未读」** |
| 4 | 命令与键位 | 键位清单从哪来？本端如何映射（如 `Ctrl` 代 `⌘`）？有冲突要列出 |
| 5 | 各区域六态 | 空 / 载入 / 进行中 / 失败 / 禁用 / 已截断，逐区给落法（不许一句「统一处理」） |
| 6 | 主题与外观 | 深浅色、密度、缩放、字体怎么落 |
| 7 | 与第七章对应表 | 7.1~7.9 每一条落在本节的哪一小节 |
| 8 | 已知缺口 | 写清「不做」与「没做」；不许留空 |

## 3. 每条都要能指到代码

- **陈述事实的表格**末列固定为「依据」，写 `文件路径` 或 `文件路径:行号`；纯规格表（尺寸档位、六态矩阵、键位映射）可不带，因为它们的依据是契约章与令牌表本身。
- 查不到的写「待定」，并在节末列「需要补的事实」清单。**禁止编造视图名、令牌名、键位、需求编号。**
- 需求编号必须是需求规格书里真实存在的（`FR-<产品线>-<域>-<子域>-<序号>` 形态）。

## 4. 禁止项（脚本会拦）

1. 进度符号：`⬜` `🟡` `✅`（状态唯一来源是《开发计划书》§3 台账）。
2. 旧版引用：`旧本` `原 §x`（全新项目开局，历史只在 git 里）。
3. 编造的标识符：文中出现的 `Metrics.*` / `Spacing.*` / `Radius.*` / `AppShortcut.*` 必须在代码里存在。
4. 表格缺「依据」列。
5. 在 Windows 节里写 Linux/macOS 的界面做法（除文件路径形式）；Linux 节同理。跨端共用的部分指向第七章。

## 5. 样板

`Docs/Doyah产品概要设计说明书.md` §9.1（macOS）是**唯一认可的样板**：23 小节、每表带依据、缺口单列。写之前先读 §9.1.1~§9.1.8（骨架、令牌、键位、六态、主题、对应表、缺口），照着这八节的形写自己那端。

## 6. 自检（提交前必须跑）

```bash
python3 Scripts/check-ui-design-section.py --platform windows   # 或 linux / ios / macos
```

脚本检查：主题小节齐不齐（按档）、事实表有没有「依据」列、有没有进度符号与旧本字样、`Metrics/AppShortcut/需求编号` 是否真实存在。**退出码非 0 不许提交。** 该脚本已挂进 `Scripts/verify-all.sh` 第 4 项，与文档类判据同批跑。
