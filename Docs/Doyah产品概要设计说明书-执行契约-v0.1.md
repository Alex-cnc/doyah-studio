## 1. 设计范围与边界

### 1.1 本设计是什么

覆盖四条产品线的跨端契约与 macOS 实现口径；代码面 `Core/`（平台中立）、`App/`（macOS 装配层）、`Plugins/Notes/`、`Platform/macOS/`。

必须实现的能力（按域）：

1. **智能体**：回合循环、上下文组装、工具调用、审批与审计、会话持久化、记忆与技能。
2. **数据库工作台**：连接与凭据、驱动与方言、执行与取消、结果集、对象树、结构变更、导入导出。
3. **工作台界面**：编辑器、文件树、页签、命令面板、内嵌浏览器、主题令牌。
4. **笔记与待办**：本地库、正文投影、云同步与冲突合并、待办与日历。
5. **交易复盘**：行情接入、特征、回测、复盘稿、周报（契约形态为 ⬜，见 §14）。

### 1.2 本设计不是什么

- 不是详细设计：窗口模型、构件尺寸、具体文件落点 → `Docs/实现要点-<端>.md`。
- 不含测试读数、门禁结果、真库读数 → 验收台账（机器生成）；本文件只写判据 ID 与命令。
- 不含进度与状态 → 开发计划书。
- 不引入：消息队列、独立后端服务、多租户、云数据库代理。跨端一律本机优先，离线可用是硬约束。
- 不包含：管理后台页面、移动端布局适配、未登记的新入口。

### 1.3 边界与判据

| 边界项 | 允许 | 禁止 | 判定依据 |
|---|---|---|---|
| 功能边界 | 需求书 `FR-*` 已列的能力 | 新增未登记能力（含"顺手"优化） | `Scripts/check-req-ids.py`；新能力必须先有 FR |
| 技术边界 | `Core` 只用平台中立 API；界面只能经 `Core` 的类型拿数据 | `Core` 里 `import AppKit/SwiftUI`；界面层持有连接/事务/文件句柄 | `check-core-portability.py`、`check-platform-neutrality.py` |

## 2. Agent 执行总则

1. 只实现本文件与需求规格书明确要求的内容；不做任何"顺手优化"。
2. 新增依赖必须先出现在 §11 允许清单；未列出即不得引入（含 Swift Package、npm 包、系统命令）。
3. 每个接口必须实现四类行为：成功、失败、非法输入、**禁止兜底**（§4）。
4. 状态变化必须符合 §6；不得新增状态或流转。
5. 错误必须按 §9 返回；禁止用空对象、默认值、静默成功掩盖失败。
6. 每个页面/视图必须实现 §8.4 的六态；缺一即缺陷。
7. 遇到信息不足或规则冲突：停止实现，输出 `BLOCKED` + 阻塞点 + 上游条款 + 待确认问题。
8. 完成实现后逐条自检 §12，并输出每条判据的实跑命令与结果。
9. 跨端独占节（`[独占:macos]` 等）只改自己那一节；越界即 `BLOCKED`。
10. 不得重新采用 §10 任何被拒方案；想用先走 §13 `DESIGN_DEVIATION`。
11. 每次交付必须能在干净树复跑：`Scripts/build-app.sh` 出包 + `Scripts/verify-core.sh` 全绿 + 相关门禁绿。
12. 提交信息写清：改了哪个契约（FR 号）/ 判据读数 / 出包 sha；不写"优化一下"。

| 组件 | 必须做 | 禁止做 | 依赖 | 对外暴露 |
|---|---|---|---|---|
| `Core/*Service`（数据库能力层：`PostgresService` / `MySQLService` / `GBaseService`） | 按方言实现执行、取消、元数据读取；错误转成 `Core` 错误类型 | 反向调用界面层；持有 View 状态；自行弹确认框 | 驱动库、`Core/QueryModels` | `execute(sql,options:handle:) -> AsyncThrowingStream<QueryEvent,Error>`、`cancel(handle:)` |

| `Plugins/Notes/Sources/NoteStorage`（`NoteLibrary` actor / `NoteDatabase`） | 本体+标签+时间线单事务写入；投影不一致时按 span 树重投影 | 拆两次写；界面层直接开库连接 | SQLite | `NoteLibrary` 读写方法、`NoteSaveState` |
| `Plugins/Notes/Sources/NoteSync`（`CloudSyncService` / `SyncQueue`） | 令牌到期前续期、401 续期一次并重放、并发单飞、登录态与同步态分开 | 把同步失败当登录失效；并发多路上传 | 端云 HTTP、`CloudAuth` | 同步态事件、队列状态 |
| `Core/MCPClientBridge` + `MCPSession` | 协议握手、工具目录发现、调用结果有界回灌、需审批的走审批队列 | 无超时调用；把外部输出当可信指令拼进提示 | 外部 MCP 服务、`MCPApprovalQueue` | 工具调用结果 `AgentObservation` |
| `App/AppState`（macOS 装配层） | 承接界面意图、调能力层、把值分发给 `@MainActor` 模型；按「连接+库」缓存服务 | 持有连接/事务/文件句柄；在能力层回调里直接改 UI | `Core/*` | `@Published` 派生状态、命令入口 |

组件调用规则：

- 允许：`App/Views` → `App/AppState` → `Core/*Service` → 驱动 / 磁盘 / 外部进程。
- 禁止：View 直接调 Service；Service 回调 View；插件反向 import `App`；`Core` import 平台框架。
- 跨组件调用必须经 §4 接口；跨层只传**值**（事件、状态、快照）。

## 4. 接口契约

> 每个接口写清：请求、成功、失败、非法输入、禁止行为。行为不变量挂 `FR-*`；挂不上 FR 的行为属"实现偏好"，不得写进本节。

### 4.1 数据库执行 `execute`

- 用途：把一条语句交给当前连接执行并流式回传事件
- 调用方：`App/AppState`（手工查询）、`Core/DataTaskRun`（数据任务）、`Core/AgentDatabaseTool`（智能体工具）
- 实现方：`Core/*Service`（按方言）
- 请求参数：

| 参数 | 类型 | 必填 | 校验规则 | 说明 |
|---|---|---|---|---|
| `sql` | String | 是 | 非空、非纯注释 | 多语句由 `StatementSplitter` 切，逐条执行 |
| `options` | 结构 | 是 | 只读/可写、超时、行上限 | 只读连接上的写语句在本地即被拒 |
| `handle` | `ExecutionHandle` | 是 | 属于本连接 | 取消与归属 |

- 成功：`resultSet`（列定义 + 行批）+ `finished`；空结果 = `resultSet` 零行 + `finished`
- 失败：

| 场景 | 返回 | 禁止行为 |
|---|---|---|
| 语句错误 | 抛 `Core` 错误（含可读原因） | 静默降级为「0 行」 |
| 空语句 / 纯注释 | 立即抛错，不连库 | 发到服务器再报错 |
| 只读连接写语句 | `ExecutionSafety.refused` | 提供「仍然执行」 |
| 连接失效 | 抛错并标记连接态 | 自动重连并重放（等于多执行一次） |

- 幂等性：不保证；重复执行由调用方负责（页签不自动重试）
- 超时/重试：超时由 `options` 给；**不自动重试**

### 4.2 查询取消 `cancel`

- 调用方：`App/AppState`（取消按钮 / 关闭页签）；实现方：`Core/*Service`
- 成功：后端确认取消 ⇒ `CancelOutcome.cancelled`
- 失败：拿不到后端 PID / 连接已断 ⇒ `CancelOutcome.failed(reason:)`，**原因必须说出来**
- 非法输入：句柄不属于本连接 ⇒ 抛错，禁止"尽力取消"
- 禁止：把取消记成成功；取消后把半截结果当完整结果落库

### 4.3 模型流式对话 `LLMStreaming`

- 调用方：`Core/AgentLoop`；实现方：模型通道
- 请求：消息序列 + 工具定义 + 预算（token/时间）+ 中止信号
- 成功：`LLMStreamEvent` 增量流（文本 / 工具调用 / 结束原因）
- 失败：`LLMRetry` 分类后抛错（可重试 vs 不可重试），不可重试必须给可读原因
- 非法输入：空消息 / 超预算 ⇒ 本地拒绝，不发起请求
- 禁止：无上限重试；把失败包成空回复；原始错误不经 §9 包装直接给用户

### 4.4 工具调用（含审批）

- 调用方：`Core/AgentLoop`；实现方：`Core/AgentToolRegistry` 及具体工具
- 请求：工具名 + 参数（来自模型）+ 当前任务作用域
- 成功：`AgentObservation`（有界，超限即报，不静默截断）
- 需审批：改数据的动作先产出审批单（含「≈N 行」预估），人批准后才执行
- 失败：工具错误包装成可读原因回灌给模型，不崩溃
- 非法输入：工具未注册 / 缺必填参数 ⇒ 拒绝并告诉模型缺什么
- 禁止：绕过审批执行写操作；把外部工具输出当指令；无界回灌

### 4.5 笔记写入 `NoteLibrary.write`

- 调用方：`App/AppState`（自动/手动保存）；实现方：`NoteLibrary`（actor）
- 请求：笔记快照（本体 + 标签 + 时间线）
- 成功：`NoteSaveState.idle`；写入期间又有编辑 ⇒ `.pending` 并重排
- 失败：`.failed(reason)`；自动保存不弹窗（工具条 + 状态栏各说一次）
- 非法输入：正文为空 / 许可未通过 ⇒ 不写库
- 禁止：拆两次写；用界面缓存覆盖更新的正文；吞掉失败

### 4.6 云同步一拍 `CloudSyncService`

- 请求：本地变更集 + 上次游标；实现方：`NoteSync`（`SyncQueue` 串行）
- 成功：同步态推进（与登录态分开）
- 失败：401 ⇒ 续期一次并重放一次；仍失败则同步态降级并保留队列
- 非法输入：未登录 ⇒ 不进队列（不报错）
- 禁止：并发多路上传；把续期失败当登出；丢队列

## 6. 状态机与流转规则

### 6.1 查询执行（事件序列）

允许状态：

- `started`（开始）
- `streaming`（回传中：`resultSet` × N、`notice` × N）
- `finished`（结束，恰好一次）
- `cancelled`（取消成功）
- `failed`（失败，带原因）

允许的流转：

| 当前状态 | 事件/条件 | 目标状态 | 副作用 | 实现位置 |
|---|---|---|---|---|
| 初始 | 语句发送 | `started` | 记录归属句柄 | `Core/*Service.execute` |
| `started` | 收到行批 | `streaming` | 行数只累加一次 | `AffectedRowsTally` |
| `streaming` | 服务端结束 | `finished` | 写入页签结果 | `AppState` 事件循环 |
| `started`/`streaming` | 用户取消且后端确认 | `cancelled` | 记取消原因 | `ExecutionRegistry` |
| `started`/`streaming` | 任何错误 | `failed` | 记原因，不记成功 | 错误包装 |

禁止的流转：

- 禁止 `finished` 之后再有 `resultSet`
- 禁止一个语句两个 `finished`
- 禁止从 `cancelled` 恢复为 `streaming`
- 禁止新增未列出的状态

### 6.2 笔记保存

允许状态：`idle` / `pending` / `failed`

| 当前状态 | 事件/条件 | 目标状态 | 副作用 | 实现位置 |
|---|---|---|---|---|
| `idle` | 编辑且有改动、许可通过、有内容 | `pending` | 取消上一发，重开 1.5 s 窗口 | `NoteAutosave` |
| `pending` | 写库成功 | `idle` | 状态栏清掉保存中 | `AppState` |
| `pending` | 写库失败 | `failed(reason)` | 工具条 + 状态栏各说一次 | 同左 |
| `pending` | 期间再编辑 | `pending` | 保持并重排，不抹掉新按键 | `NoteAutosave` |

禁止：无改动也写库；许可未过仍写库；自动保存弹窗；切走时等写盘完成。

### 6.3 审批单

允许终局只有三种：**执行成功** / **执行失败（带原因）** / **被拒绝**。⬜ 过期与撤回的终局口径待定（§14）。

禁止：新增第四种终局；把未裁决显示成"已通过"；批准后执行另一条 SQL。

### 6.4 智能体回合

允许：一轮到底（思考 → 工具 → 回答）；期间新提问只入队，不打断当前轮；队列 FIFO，空白提问不入队。

禁止：并行跑两轮；轮内并发执行多个改数据工具；静默丢弃排队项。

## 7. 关键流程与调用顺序

### 7.1 执行一条 SQL

允许的调用顺序：

1. `AppState` 提交编辑器缓冲 → `ExecutionScope.resolve`（有选区跑选区，无选区跑整篇，取**显示中**的编辑器）
2. `SQLParameters.hasParameters` → 先取参数（未取值不得执行）
3. `ExecutionSafety.check` → `needsConfirmation` 进确认；`refused`（只读连接）直接拒
4. `TransactionSession.prepareStatement()`（手工模式首条语句前懒发 BEGIN）
5. 按「连接 + 库」取服务 → `execute`
6. 消费事件流（§6.1）→ 结果进页签，行数只累加一次
7. 写历史与 SQL 归档（取消记失败并带原因）

禁止的调用顺序：

- 禁止跳过第 3 步直接执行
- 禁止第 4 步失败后继续发语句
- 禁止绕过 `ExecutionScope` 用缓存里的编辑器内容
- 禁止把同一份结果同时写进表格与日志（两页签重复）

失败处理：

| 失败点 | 必须行为 | 禁止行为 |
|---|---|---|
| 第 2 步（缺参数） | 停在参数面板，保留输入 | 空参执行 |
| 第 3 步 `refused` | 明说不允许并解释只读连接 | 提供「仍然执行」 |
| 第 4 步（事务） | 报错误状态，只接受回滚 | 继续发后续语句 |
| 第 5 步起 | 按 §9 包装，结果区留空态 | 保留上次结果冒充本次 |

### 7.2 智能体一轮

允许顺序：输入 → 上下文组装（预算内）→ 模型流 → 工具调用（改数据先审批）→ 审计 → 回答 → 会话落盘。

禁止：未审批执行写操作；无界回灌工具结果；轮内并行两个改数据工具；把失败包成空回答。

失败处理：

| 失败点 | 必须行为 | 禁止行为 |
|---|---|---|
| 模型不可用 | 明说原因并保留输入 | 清空输入 / 静默丢弃 |
| 工具失败 | 包装后回灌给模型继续 | 崩溃 / 隐藏错误 |
| 审批被拒 | 如实写"被拒绝"并结束该动作 | 换个写法偷偷执行 |
| 会话落盘失败 | 明说"这次会话没存住" | 假装已保存 |

### 7.3 一条笔记从编辑到落盘

允许顺序：编辑 didSet → `pending` + 重排自动保存（1.5 s 窗口）→ 三条守卫（许可 / 有内容 / 有改动）→ span 树快照 → 单事务写库 → `idle`。

禁止：拆两次写；切走时等写盘；失败静默。

失败处理：

| 失败点 | 必须行为 | 禁止行为 |
|---|---|---|
| 许可未通过 | 不写库，状态栏说原因 | 静默跳过 |
| 写库失败 | `failed(reason)`，工具条 + 状态栏 | 丢掉待写快照 |
| 切走 | 先快照再排队（不等写完） | 阻塞手势回调 |

## 8. 界面契约

> 本节只定义"界面必须怎么行为、禁止怎么行为"。视觉参数（颜色/尺寸/字体/间距）见 §0 视觉设计规范；冲突时行为以本节为准，视觉参数以规范为准。

### 8.1 界面范围与边界

覆盖的视图：

- 查询页签（`db`）：SQL 编辑、结果集、消息面 —— 普通查询与数据浏览
- 对话页签（`agent`）：智能体转写、审批卡、输入区 —— 智能体交互

- 复盘屏（`retro`）：曲线、归因、复盘稿（⬜ 契约待补，§14）
- 工作区页签、浏览器页签、底部面板、状态栏

不覆盖：管理后台页面、移动端适配、系统级菜单之外的集成。

| 边界项 | 允许 | 禁止 | 判定依据 |

### 8.2 页面/视图清单与职责

### 8.3 导航与流转契约

允许的流转：

| 起点 | 触发 | 终点 | 前置条件 | 禁止行为 |
|---|---|---|---|---|
| 任意页签 | 活动栏点击 | 对应产品线屏 | 无 | 禁止在活动栏外新增同级入口 |

禁止的流转：

- 禁止在未保存/未确认状态下离开当前页导致数据丢失
- 禁止跨产品线直接跳进别人的审批（审批只在对话内）
- 禁止新增未登记快捷键

### 8.4 界面状态契约

| 状态 | 必须呈现 | 禁止行为 |
|---|---|---|
| 加载中 | 进度或等待字形（盲文十帧循环 90 ms/帧）；关键按钮禁用 | 空白无反馈；允许重复提交 |
| 空数据 | 空态文案 + 引导动作 | 显示错误；空白页无说明 |
| 错误 | 位置 + 原因 + 重试入口（§9 包装后） | 静默失败；用空数据冒充成功 |
| 权限不足 | 明说缺什么权限、怎么给 | 先展示操作再报错 |
| 提交中 | 进行态 + 可取消（能取消的动作） | 允许二次提交 |
| 部分失败 | 明确列出失败项与成功项 | 整体回滚却不告知 |

### 8.5 交互规则

必须做：

- 表单校验通过前，提交类按钮保持禁用（连接表单、参数面板）
- 请求进行中按钮置进行态且不可重复点击（执行、同步、保存）
- 不可逆操作先二次确认：删除连接、覆盖保存、删笔记/待办、结构变更落库
- 所有异步操作都有进行中与结果两段反馈
- 跑着时回车 = 排队（不打断当前轮），队列项显示 `⇥ n. 预览` + `✕` 撤销

禁止做：

- 禁止把关键操作藏在二级菜单
- 禁止用 toast 承载需要用户决策的错误（如审批、覆盖确认）
- 禁止在界面层做只有能力层能信任的权限判断（只读连接、许可状态由 `Core` 判）
- 禁止静默吞掉接口错误

### 8.6 表单与校验契约

| 表单/字段 | 前端校验规则 | 后端（能力层）校验规则 | 错误呈现位置 | 禁止行为 |
|---|---|---|---|---|
| 连接四元组 | host/port 非空、port 1–65535 | 实际连通性与版本探测 | 表单字段下方 | 仅前端校验；错误不定位字段 |
| SQL 参数占位符 | 必填项未填则禁用执行 | 类型/长度按列定义 | 参数面板逐项 | 空参执行 |
| 笔记标题 | 允许空串，不接受纯空白 | 归档/同步规则 | 标题行下方 | 静默改写用户输入 |
| 结构变更 DDL | 预览差异后才可执行 | 事务与权限 | 差异面板 | 直接执行不预览 |

前端校验与能力层校验必须一致；能力层为最终依据；禁止"前端过了就等于能成"。

### 8.7 界面动作与接口映射

| 界面动作 | 调用接口 | 成功行为 | 失败行为 | 禁止行为 |
|---|---|---|---|---|
| 执行查询 | §4.1 | 结果进表格 + 状态行 | 错误态 + 保留 SQL | 失败后清空用户 SQL |
| 取消查询 | §4.2 | 状态行写取消结局 | 说明拿不到后端 PID | 把取消显示成"已完成" |
| 发送提问 | §4.3 | 转写追加、开始新回合 | 保留输入 + 说明原因 | 清空输入 |
| 批准执行 | §4.4 | 审计追加一条、显示结果 | 写失败原因 | 批准后执行另一条 SQL |
| 编辑笔记 | §4.5 | 保存态 `idle` | `failed` 提示 | 失败后假装已保存 |
| 同步 | §4.6 | 同步态推进 | 降级但保留队列 | 把续期失败当登出 |

### 8.8 错误呈现规则

- 字段级错误：呈现在字段附近（表单下方），禁止只弹全局提示
- 页面级错误：呈现在页内错误区，含原因 + 重试入口
- 不可恢复错误：阻断当前动作并说明下一步，禁止让用户停在不一致状态
- 文案：必须来自语言表 `Core/Localization.swift`，禁止 Agent 自创模糊文案；中文缺键即失败（`check-core-localization.py`）

### 8.9 可访问性与一致性约束

- 必须：键盘可操作、焦点可见、语义化标签、对比度达标（主题令牌已含对比度校验）
- 必须：字形（`❯/┊/⚡/◈`）对辅助技术隐藏，朗读顺序「角色 → 正文」
- 禁止：仅靠颜色传达状态；禁用默认焦点样式却不提供替代
- 禁止：用底纹区分角色（行首栏一旦有底纹就失效）

## 9. 错误处理与兜底规则

错误分级三级，判据是"界面还能不能继续走"：

| 级别 | 判定 | 界面表现 | 禁止 |
|---|---|---|---|
| 可恢复 | 换输入/换连接/重试即好 | 就地提示 + 重试入口 | 弹模态框打断；丢已输入 |
| 阻断 | 当前动作做不下去，应用还能用 | 明说原因与下一步 | 静默降级；假装成功 |
| 静默 | 只进日志（如缓存清理失败） | 无提示 | 用它掩盖会影响结果的问题 |

包装：跨层错误必须转成 `Core` 错误类型再上浮；每层只加信息不改语义；用户可见文案走语言表。

禁止的兜底方式：

- 返回空对象冒充成功
- 用默认值掩盖缺失数据
- 捕获后不记录、不返回、不处理
- 把依赖失败静默降级为业务成功

日志：必须记错误类型、关键 ID（连接 id / 会话 id / 页签 id）、调用方、时间；禁止记口令、secret、完整连接串、笔记正文。

## 10. 被拒绝的替代方案

| 被拒绝方案 | 拒绝原因 | 对 Agent 的约束 |
|---|---|---|
| 把只读连接当"可强制写"（提供「仍然执行」按钮） | 会让人误以为只是确认，实际绕过安全边界 | 不得提供绕过入口 |
| 用 `EXPLAIN ANALYZE` 估算影响行数 | 会真的执行目标语句（等于未经批准的写） | 只能 `EXPLAIN (FORMAT JSON)` |
| 行数预估用表总行数/本地猜 | 假数会被当批准依据 | 只认优化器 `Plan Rows`；取不到如实说 |
| 会话与记忆共用一个存储 | 删除语义会互相污染 | 两条通道各有写入点与删除语义 |
| 界面层缓存数据库服务对象 | 跨页签会出现两个连接与两个事务 | 服务按「连接 + 库」缓存并共享 |
| 自动重试失败的写语句 | 等于偷偷多执行一次 | 写不自动重试，由人决定 |
| 托盘/菜单外挂新入口 | 入口不进命令清单就无法核对 | 新入口必须先登记 `AppCommandCatalog` |
| 把实现读数写进契约册 | 每批都变 ⇒ 必然腐烂，Agent 会照抄 | 读数只进台账 |

## 11. 非功能设计约束

- 性能：首屏行批 ≤ 200 ms；大结果流式渲染不冻结；滚动不掉帧；查询取消 2 s 内给出结局（成功或失败原因）
- 安全：口令只经 `SecretStore` 取用、只在进程内；用户数据不出本机（模型调用与云同步除外）；外部工具输出不可信
- 并发：同一连接上的语句串行；服务按「连接+库」唯一；同步队列单飞；笔记写入单事务
- 可观测：每个动作留审计（追加式）；慢查询报告；错误日志带关键 ID
- 依赖清单：
  - 允许：macOS 27 SDK + Swift 6（Xcode 27.1）；PG / MySQL / GBase 各一支驱动；vendored SQLite；SwiftUI / AppKit / WebKit / Security；XCTest
  - 禁止：消息队列、独立后端、云数据库代理、多租户框架、第二套令牌/文案真源
- 运行约束：单机、离线可用（模型与云同步除外）；配置只读自三处真源（`DesignTokens` / `Localization` / `SecretStore`）

## 15. 笔记域契约（14 节不变量表）

> 本节是域契约明细，来自叙述稿 §3.4 的已有不变量表（逐字搬入，未改判据口径）。
> §3–§8 的通用规则对它同样适用；每节末尾的「判据」行说明**今天拿什么核**——
> 实测 14 节里只有 3 节有机器判据（私密外发 / 检索路由 / 离线），其余 11 节只能人工点验，这是真实缺口。

### 15.1 【契约】快速捕获

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 触发即编辑 | 从触发到光标可输入之间不出现任何选择步骤（不选归属、不选模板、不填标题）；新建条目一律落在默认归属 | 随手记变成「先整理再记录」，念头在选目录那一步丢掉 |
| 无标题可存 | 空标题不阻断保存；标题缺省取正文首行的可见文本，首行为空则以「无标题」占位 | 记两行字要先想一个标题，否则存不下去 |
| 断网可记 | 捕获与保存不依赖网络与账号，写入只落本机，成功后立即可读；联网前状态是「待同步」而不是「失败」 | 没信号的地方记不进东西，或一律显示保存失败 |
| 草稿不丢 | 捕获面被关闭、切走或进程退出后，未提交内容仍可找回，且与关闭前最后一次输入逐字相同 | 「刚才写的那句哪去了」，且说不清丢在哪一步 |
| 捕获不承担整理 | 捕获路径上不出现标签、归属、模板的必填项；整理只发生在捕获完成之后，不阻塞捕获 | 每记一条都要做一次归类决策，记的频率自然下降 |

对应需求：`FR-NTS-NOTE-CAPTURE-001`

**判据**：无机器判据（需人判）：触发即编辑 / 断网可记 / 草稿找回三面只靠人工点验

### 15.2 【契约】附件与图片

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 字节在盘、引用在库 | 库内只有引用（标识、原文件名、字节数、内容摘要）；库体积不随附件字节线性增长 | 备份与同步被图片拖到几百兆，删条目还连带丢附件 |
| 原件不改写 | 缩放、旋转、裁切只作用于显示；原始字节与像素在任何操作后摘要不变 | 插进去的图越存越糊，原图取不回来 |
| 同内容一份 | 内容摘要相同的附件只存一份，多条笔记共享同一份；引用归零才允许回收 | 同一张图在十条笔记里各存一份，占用与笔记数同速增长 |
| 缺失必须说出来 | 引用解析不到字节时显示「文件不在了」并给出原文件名与原位置，不画空白框、不静默删掉引用行 | 正文里剩一个空框，没人知道原来是什么 |
| 删除分级 | 删笔记只让引用失效（条目进回收站），不回收字节；彻底清除时才判断是否仍被其它未删条目引用，并要一次确认 | 删一条笔记，把另一个归属里还在用的图一起带走 |

对应需求：`FR-NTS-NOTE-ATTACH-001`

**判据**：无机器判据（需人判）：字节在盘·同内容一份·删除分级无自动用例

### 15.3 【契约】导出与迁移

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 导出是副本 | 导出前后逐条比对正文摘要、更新时间与归属，全部不变 | 导出一份 Markdown，库里时间全被刷新 |
| 三形态同源 | Markdown、纯文本、备份包由同一份正文权威源派生；同一批条目在三种产物里的条数一致 | 同一批笔记导三次得到三个不同的集合 |
| 备份包可完整还原 | 导入自己导出的备份包后，条数、标题、正文、标签集合、创建与更新时间、附件引用逐条相等 | 导进去少一半，或标签全平掉 |
| 有损要声明 | 目标格式表达不了的成分（附件、合并单元格、格式清单外的语法）在产物内逐条标注，不静默丢弃 | 导出「成功」，打开后少了几段而无人在场知晓 |
| 版本位在前 | 备份包带格式版本位与条目清单；包里版本高于本端支持范围时拒绝导入并说明，不做半懂不懂的读取 | 新端导出的包被旧端读成残缺数据，且没有任何报错 |

对应需求：`FR-NTS-NOTE-EXPORT-001`

**判据**：无机器判据（需人判）：三形态同源与备份包还原无自动用例

### 15.4 【契约】正文格式与编辑

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 一份权威源 | 正文以带版本位的结构化形态为权威；Markdown、纯文本、导出产物、检索索引都是派生物，可由权威源重新算出 | 界面、导出、检索各显示一个样子，且分不清哪个是真的 |
| 格式清单封闭 | 允许的块级与行内格式是有限、可枚举的一份清单；清单外的语法按字面文本保存，不做猜测性解释 | 粘贴一段外部内容后，样式随来源漂移，收不回来 |
| 双模式往返无损 | 所见即所得与源码互相切换，每种格式进出后语义不变；同一篇文档连续往返多次，序列化结果逐字节相同 | 切一次源码，加粗变星号、缩进塌一层 |
| 撤销以段落为粒度 | 一次撤销回退一个编辑事务（一段输入或一次格式操作），不逐字符、也不整篇回退 | 敲错一个字要按十几下撤销，或一按就退回上一版 |
| 大文档可用 | 万行级正文可打开、可编辑、可检索，滚动与输入不触发整篇重排；超过单篇上限时提示并保持可读可编辑 | 长文一打开就卡，或直接被拒绝打开 |

**跨端判法**：同一条笔记在两个端打开，正文文本、块级结构、行内样式、段落顺序完全一致。允许不同的是光标位置、折叠状态、输入法临时标记这类不落库的视图状态。

对应需求：`FR-NTS-NOTE-FORMAT-001`

**判据**：无机器判据（需人判）：双模式往返无损与撤销粒度靠人工

### 15.5 【契约】整理：标签 / 收藏 / 置顶 / 归档

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 整理不动内容 | 打标签、收藏、置顶、归档、改归属都不改标题与正文，也不刷新内容更新时间（整理另记时间） | 加个标签，笔记就蹿到「最近更新」最上面 |
| 批量先给影响面 | 任何批量操作执行前显示「将影响 N 条」；N 与实际执行由同一份判定算出，预览与执行不各算一次 | 显示影响 12 条，实际改了 40 条 |
| 一步可撤销 | 整理类操作（含批量、含跨归属移动）可整体撤销到操作前；撤销后正文、标签、归属、排序位逐条复原 | 「撤销」只退了一半，或退完顺序变了 |
| 归档不等于删除 | 归档只移出默认视图，条目仍可被检索到（受搜索范围约束）并可原样取回；归档不占回收站，不受回收站到期清除影响 | 归档几天后东西凭空消失 |
| 标签是集合 | 同一条目同一标签只有一份；删标签只解除关联，不删条目、不改正文；重名标签不擅自改写大小写与空白 | 同一个标签出现两次，或在正文里被顺手替换掉 |

对应需求：`FR-NTS-NOTE-ORG-001`

**判据**：无机器判据（需人判）：批量影响面与一步撤销无自动用例

### 15.6 【契约】私密保护与加密边界

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 私密不进检索 | 标为私密的条目不出现在任何检索路径（关键词、语义、标签、全局搜索）的结果里，也不计入可见计数与摘要卡片 | 搜到了自己藏起来的那条，标题还在结果行上照旧显示 |
| 私密不外发 | 私密条目不进入助手上下文、不进入消息与外发通道、不进导出（含备份包）、不上传；被引用时以「一条私密条目」占位并明说不可读 | 私密笔记被助手复述到对话里，或被同步上云 |
| 二次验证才可读 | 打开、预览、尝试导出都要过一次验证；验证未过时不泄露标题、首行与字符数 | 锁定只画了个锁形，内容在预览缩略里露出来 |
| 存储格式不分叉 | 私密标记不改变存储形状与加密方式；存储层加密若开启属整库层的事，与单条私密标记正交 | 出现两套存储形态，换端读不了同一份数据 |
| 边界与退出要说清 | 它挡的是「本机已解锁时被人随手翻」，不挡拿到磁盘的人；取消私密要二次确认，并说明此后该条会被检索、同步与导出覆盖 | 用户以为标了私密就等于加密，真遇到拿到磁盘的人时毫无防线 |

对应需求：`FR-NTS-NOTE-PRIVACY-001`

**判据**：`check-network-egress.py`（外发面）+ 需人判（不进检索、二次验证、退出说明）

### 15.7 【契约】列表与检索

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 两条检索都在 | 关键词检索与语义检索各自可用，结果可分栏并列对照；任何一条不能用时如实标出，不用另一条顶替 | 语义检索坏了，界面只给关键词结果，看上去像「语义从来没命中过」 |
| 降级要说话 | 语义检索不可用时明写「当前只有关键词结果」，并按可读类别给出原因（索引未建 / 能力不可用 / 离线受限） | 结果少了，界面一个字都不解释 |
| 覆盖字段一致 | 检索至少覆盖标题、正文、标签；同一查询在两个端命中的字段集合相同 | 同一条笔记一端搜标签能中，另一端搜不到 |
| 次序是总序 | 同一查询结果次序确定：先命中强度、再更新时间、再标题；刷新与重查不改变次序 | 同样的搜索连按两次，列表顺序变了 |
| 超时与无命中分开说 | 万条量级下检索在可接受响应内返回；超时报「还在查」，不把超时当成「没有匹配」 | 大库搜不到东西，用户以为笔记丢了 |

对应需求：`FR-NTS-NOTE-SEARCH-001`

**判据**：`check-note-search-route.py`（检索路由单一）+ 需人判（私密排除、搜索范围）

### 15.8 【契约】同步与冲突合并

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 本地为主，可带走、可恢复 | 云端关闭、不达或账号失效时，新建、编辑、检索、导出、待办全部照常，唯一差异是跨端看不到，重新登录后按同一套规则接上；任何时刻可完整导出；本地数据丢失后从云端副本恢复到新位置并校验通过才切换，不就地覆盖现有库 | 断网或关掉云之后写不了也搜不了；或恢复动作把还在的本地数据覆盖掉 |
| 离线可写、联网可合、状态可见 | 离线写入在本地排队，联网后按序合并；同一批重放两次结果相同；每条或每批的同步状态至少能区分已同步 / 待同步 / 冲突，并能说出这一档的原因 | 联一次网同一条变成两条，或内容被吞掉；「刚才那段到底同步了没有」无法回答 |
| 判定键唯一、由人定 | 记录级判胜：先比严格递增的记录版本号，版本号相同再比更新时间，仍相同按固定次序（设备标识）兜底，三个端同一套比较规则；无人工选择时不做静默覆盖，默认保留两版并标冲突 | 同一场冲突两端判出不同胜者，来回同步成乒乓；或界面自动挑了一版，用户永远不知道另一版存在 |
| 落败版留底、合并可回退 | 被覆盖的那一版原样保留（不进回收站、不被裁剪），可打开、可另存为新条目，两版都标来源设备与时间；合并产出一个新版本，参与合并的两版仍可取回 | 冲突后只剩一份，另一份修改无人知道曾存在；合错了回不到合并之前 |
| 删除不被复活 | 删除以墓碑传播，墓碑的版本号严格递增，且不被更高版本号的副本按同一套判定覆盖回来 | 删除在同步里被当成一次普通修改，被另一端的历史版本顶回来 |
| 令牌自动续期，同步不因过期而中断 | 访问令牌快到期（余量 60 秒内）时**先续期再发请求**；服务端回 401 时**续期一次并重试同一请求一次**；续期用的是刷新令牌，不是让用户重新登录；连续自动同步跨过任意次令牌到期都不出现「令牌过期」这类错误 | 每次自动同步都报「token 过期」；用户被迫反复登录；或把令牌有效期调长当作修法（只是把报错推后，到期照样断） |
| 登录态与同步态分开表述 | 令牌过期 ≠ 账号失效：本地读写检索导出照常，同步暂挂并显示「登录待续期」；只有刷新令牌本身失效才显示「需要重新登录」，且给出登录入口 | 令牌一过期就提示「账号失效」并锁住本地功能；或什么都不说，只是同步静默失败 |

对应需求：`FR-NTS-NOTE-SYNC-001` `FR-NTS-NOTE-SYNC-002`（令牌续期与登录态/同步态分开，属 `FR-NTS-NOTE-SYNC-001` ③「账号失效时本地仍可读」的前置条件）

**判据**：`check-notes-offline.py`（离线不报失败）+ 需人判（冲突合并结果）

### 15.9 【契约】删除与回收站

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 删除只进回收站 | 删除把条目移入回收站，正文与附件引用保留；回收站内可看、可预览、可恢复 | 删错了没有回头路 |
| 清除只有两种触发 | 彻底清除只在两种情况发生：用户显式确认，或超过保留期 / 容量上限；两种都事前提示后果，含不可恢复与附件一并处理 | 东西某天忽然没了，全程没有提示 |
| 上限可见 | 保留期与容量上限可查；接近上限时提示，自动清除前一次提醒，清除后能说出清了哪些 | 上限只写在文档里，清理是不可预期的 |
| 墓碑跨端传播 | 删除以墓碑同步且版本号严格递增；离线端上线后不复活已删条目，也不出现「一端已删、另一端仍能编辑」 | 删掉的条目在另一端还在，还能改出新版本同步回来 |
| 恢复回原位 | 恢复放回原归属与原排序位；原归属已不存在时落默认归属并说明，不留无归属条目 | 恢复之后散在「全部」里，找不到原来的位置 |

对应需求：`FR-NTS-NOTE-TRASH-001`

**判据**：无机器判据（需人判）

### 15.10 【契约】历史版本

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 内容保存才留版 | 每次内容类保存产生一个版本；整理类动作（标签、收藏、置顶、归档、改归属）不产生内容版本 | 打一个标签就多一个版本，历史被噪声淹没 |
| 回滚生成新版本 | 回滚不删任何既有版本，回滚本身产出一个新版本（内容等于被回滚到的版本），因此回滚可再回滚 | 回滚之后「回滚前那一版」消失，等于换一种方式删除 |
| 版本可辨认 | 版本列表带时间与摘要（变更字数或首若干字的可见文本），不带附件字节；任意两版可对照看出增删的块 | 版本列表只有时间，分不清哪个是改对的那一版 |
| 保留策略写明上限 | 保留条数或天数可配，上限写在设置项当场；被策略淘汰的版本以「已清理」明示，不静默消失 | 想找上周那版，才发现早被清掉了 |
| 版本与同步同源 | 版本序列按内容版本号单调递增；冲突合并产生的两版都进同一版本序列，不另立一套历史 | 冲突留下那版只能从冲突入口看到，历史里查不到 |

对应需求：`FR-NTS-NOTE-VERSION-001`

### 15.11 【契约】待办清单与组织

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 本体四字段齐备 | 标题、截止时间、重复规则、完成态都可编辑，空值语义明确：无截止即空（不是今天）、从未完成即完成时刻为空 | 「没设截止」被存成「今天到期」，清单里冒出一堆假逾期 |
| 独立对象、同一链路 | 待办有独立入口与独立列表，不塞进笔记列表；存储、同步、加密与笔记走同一条链路，不另开第二套 | 待办在自己的通道上，笔记好了它没好 |
| 五列可见可改 | 清单行显示标题、截止时间、完成态、优先级、标签，五列都能就地改；从新建到可见不超过一个动作 | 改个优先级要先进详情，改完刷新才看见 |
| 分组筛选可组合 | 分组（按时间 / 按状态 / 按标签）、筛选（今天 / 本周 / 已过期 / 无截止）、排序可叠加，结果由同一份数据算出 | 筛「今天」再按标签分组，条数对不上 |
| 标签只有一维 | 标签与清单归类是同一维，不设第二套分类字段；未知的优先级取值按「未设置」处理，不因一个不认识的取值拒收整条 | 另一端多了一档优先级，这边整条任务读不进来 |

### 15.12 【契约】完成与改期

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 清单是唯一事实源 | 任务数据只有一份；清单与日历都是它的渲染，日历侧不存任务、不产生第二套状态 | 日历里完成一条，清单里还挂着，两边各自「看起来都对」 |
| 一次写入、两处立即可见 | 完成与改期在清单与日历上是同一条记录的同一次写入（同一事务）；写完另一处不经刷新即可见 | 在日历上划掉的任务，切回清单还在 |
| 完成态只有一条写路 | 改标题、改标签、改期、改归属都不改写完成态与完成时刻；完成与重开是独立动作 | 打开一条已完成的任务改个错字，保存后它变回未完成 |
| 改期只动截止 | 改期写新的截止时间并刷新内容更新时间；完成态、重复规则的归属（这一条还是这一串）不被顺手改写 | 改一个日期，整串重复任务的规则跟着变了 |
| 冲突不丢操作 | 两个端同时改同一条时，按同一套记录级判定出胜者，落败的那次操作留底可查 | 一边标完成、一边改期，最后两个动作都没了 |

### 15.13 【契约】日历

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 视图不改数据 | 月 / 周切换、翻页、选中某日都是视图状态，不落库、不复制任务；来回切换后清单条数一份不差 | 翻两个月再切回清单，任务多了几份 |
| 铺在截止那天、点了有事 | 任务出现在其截止时刻所在的那一天；点某天列出当天任务、点任务进详情；没有任务的一天明写「这天没有任务」，不留点了没反应的格子 | 无截止的任务被塞进「今天」，或点开一格什么都没有 |
| 重复按发生日铺开 | 带重复规则的任务按发生日在日历上展开，存储里仍只有一条记录，不预生成副本；改一次要显式回答改的是这一条还是这一串 | 一次重复任务生成几十条记录，删一条删不干净 |
| 日界与周界写死 | 一周从周一开始；月视图按整周补齐（前后补相邻月的日子并标为非本月），格数是七的整数倍；「今天」由调用方显式传入，不各自读系统时钟 | 两端的月视图错开一列，或月初落在错误的格子里 |
| 逾期判定唯一 | 逾期 = 未完成且截止时刻早于今天起点（正好等于今天起点算今天，不算逾期）；日历与清单给出同一结论 | 同一条任务在日历上标红、在清单上写「今天」 |

### 15.14 【契约】待办与笔记的双向转化

| 不变量 | 判定条件 | 越界后的可见症状 |
|---|---|---|
| 转化是新建，不是改类型 | 笔记生成任务、任务记成笔记都产出新对象，原对象的类型、正文与时间均不变 | 转成任务之后，原笔记从笔记列表里消失 |
| 双向可见可跳转 | 两端详情都能看到「来自 / 已生成」并可直接跳到对方 | 生成完就断了线，只能靠标题回忆是从哪来的 |
| 链接带快照 | 关联由目标标识与生成时刻的快照（标题与摘要）组成；目标后续被改时不自动改写对方内容 | 改一处另一处跟着变，追不出改的是谁 |
| 可撤销 | 生成动作可整体撤销：删掉新对象并解除回指，撤销后两端都不留悬挂引用 | 撤销只删了一头，另一头指着不存在的东西 |
| 来源被删要标注 | 来源进回收站或被清除时，另一端保留快照并标「来源已删除」；不显示断链、也不跟着删 | 一处删了，另一处静默消失或点开报错 |

对应需求：`FR-NTS-TODO-LINK-001`
