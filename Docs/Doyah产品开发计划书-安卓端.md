| # | 项 | 缺口（真话） | 收口动作 | 估时 |
|---|---|---|---|---|

| 🟡-3 | **导出与分享 4 条** | 入口与实现都在，缺「点一次」的人工确认（真机/模拟器逐项） | 端上逐条点验 + 记读数 | 0.5 天 |

## 4. 待开发批次（⬜）

### 批次 B · 笔记本 / 书架两层结构（NOTE-29~35，7 条，3~4 天）

现状：**安卓端完全没有**（49 个 `.kt` 里零命中「笔记本/书架」）。这是笔记域最大的功能缺口。

| # | FR | 内容 |
|---|---|---|
| B-1 | NOTE-33/34 | 两层结构：笔记本架 → 笔记本 → 笔记；默认架不可删 |
| B-2 | NOTE-29 | 笔记必须且只能归属一个笔记本；笔记本 = `uid` 稳定身份 |
| B-3 | NOTE-30/35 | 删笔记本/删架：默认不可删；其它显式二选一（一并删 / 移到默认） |
| B-4 | NOTE-31/32 | 跨笔记本移动（单篇+批量，不刷新 `updatedAt`）；列表/搜索范围切换 + 结果标所属笔记本 |

判据：迁移老笔记全落默认笔记本；移动后 `updatedAt` 不变；范围切换后计数与全表对账一致。

### 批次 C · 账号全流程（AUTH-03~07，5 条，3 天）

找回/重置口令（一次性令牌 + 作废旧会话）· 改绑邮箱/改口令/解绑（剩一条禁止解绑）· 多端会话（可单端/全端登出）· 注销（冷却期 + 删云端数据）· 多凭据模型预留。
判据：每条都要能在 CloudBase 测试环境跑通；注销后 `uid` 数据确删（不是软删）。

### 批次 D · 笔记 UI 逐条收口（NOTEUI 未落 6 条，1~2 天）

按安卓现状逐条核：浮动书架（NOTEUI-02）随批次 B 一起做；左栏间距（21）· 默认紧凑（19）· 统一图标母版（20）按现状核；保存键纯图标（15）等图标化项核对读屏名。
