# 第一章 产品定位

## 1.1 三书分工

> 口径（人类主人 2026-10-18 原话）：「产品能力说明书是方向性的，说清楚产品是什么，每个能力点都要说清楚能力边界不能有歧义更不能说引用其他文档；需求说明书说清楚要什么，来自于产品能力说明书；区别就是产品能力说明书是什么但不一定是我们都要的，需求说明书基于产品能力说明书提出要什么且进一步细化明确这个功能是什么；概要设计说明书就是基于需求说明书讲清楚如何实现我们要的功能，又分两部分：契约部分描述平台无关的实现方式，平台实现层就是具体平台相关的描述。」

| 书 | 回答的问题 | 写什么 | 不写什么 |
|---|---|---|---|
| **本文件**（**Doyah 产品能力说明书**，PC-CAP-001） | **是什么** | 产品定位、能力清单与**每个能力点的边界**（做到哪、不做哪、和别的能力怎么分）；方向与先后 | 不写验收判据、不写实现方式、**不引用下游文档**（引用即意味着本文件有疏漏，要在这里补全） |
| **Doyah 产品需求说明书**（PC-SRS-001） | **要什么** | 从本文件的能力点派生出可验收的条目（做成什么样、怎么判过） | 不新增本文件没有的能力 |
| **Doyah 产品概要设计说明书**（PC-HLD-001） | **怎么做** | ① **契约层**：平台无关的结构与接口；② **平台实现层**：各平台的具体做法 | 不改变"要什么" |

**依赖是单向的**：`Doyah 产品能力说明书 → Doyah 产品需求说明书 → Doyah 产品概要设计说明书`。下游可以引用上游；上游不引用下游。
**"是什么"≠"都要做"**：本文件列出的是产品可能是什么；需求规范书从中**挑选**要什么，未挑选的留在本文件里不消失。

## 1.2 原则

**定位**：**具备 AI 功能的开发平台（代码 + 数据整合）** —— 原生、轻量的**开发工作台**：**写代码**（编辑器/终端/工作区）与**连数据库**（连接/查询/对象树/DDL）**平级并列**；把**智能体**作为一等能力内置（默认关闭、每一步看得见、可审批、可审计、绝不自动执行）。**数据库面能力不减、叙事降权**：它是平台的一个能力面，不是产品身份。

**定位调整（2026-10-11 人类主人令）**

- **Studio 的定位 = 具备 AI 功能的开发平台**：**写代码与连数据库 = 代码与数据的整合**，二者**平级并列**；**不单独突出其数据库客户端的功能** —— **能力不减、叙事降权、入口并级**（数据库面从"产品身份"降为"平台的一个能力面"）。
- **基础核心功能之外的「笔记」与「回放」功能，通过插件架构引入**；**在其他平台（如移动端），笔记是独立产品**（Studio 只通过插件引用，笔记能力的定义只在 Doyah Notes 的书里）。
- **逐字原话**：「整体架构我想做个调整，Studio的定位是一个具备AI功能的开发平台，写代码和连数据库是代码和数据的整合，不单独突出其数据库客户端的功能。基础核心功能之外的笔记和回放功能通过插件架构来引入，在其他平台比如移动端，笔记是独立产品，这个调整你评估分析一下，对已有版本重构的代价有多大？」
- **本次只落口径**：能力实现、需求条目与验收标准**未改**；**插件装配机制**与 **`FR-AI-16~21`** 待评估拍板后另办（评估报告见派单仓 `doyah-dispatch/docs/Studio定位与架构调整-评估-Hermes体系调研-20261011.md`）。


同一个产品做**两个平台实现**：macOS 版与 Linux 版（**2026-10-14 令：Linux 版 = 本仓实现**；~~公司电脑~~ 作废），功能一致，只有平台与编程语言不同 —— 口径见 2.1（P7）。

若与竞品（如 DataGrip 的 AI 能力、各类 MCP 数据库网关）比较，本产品的差异化**不在模型更强，而在「敢用」**：每一步都能被证明与追责。

| # | 原则 | 含义 | 依据 |
|---|---|---|---|
| P1 | **治理优先** | 显式同意、最小外发、权限继承当前连接、写操作逐次审批、审计留痕 —— **缺一条不上线** | NFR-AI-01 / 03 / 05、FR-AI-09、FR-AI-12；调研书结论「安全边界是协议层与产品层的硬约束」 |
| P2 | **可降级** | 无模型 / 未授权 / 断网时，**全部既有功能完整可用** | NFR-AI-02 |
| P3 | **本地模型优先 / 默认零外发** | 支持 OpenAI 兼容本地端点且免 Key；默认配置即「总开关关闭 + 端点为空」 | NFR-AI-06、NFR-AI-02 |
| P4 | **真实数据接地** | 诊断类能力必须站在真实执行计划 / 锁等待 / 统计之上，不做"没有依据的建议" | FR-DIAG-01、FR-DIAG-05、FR-SESS-01 |
| P5 | **可复核** | 智能体产出（SQL / 任务定义 / 建议）都以文本可查看、可编辑、可 diff | NFR-AI-05 |
| P6 | **原生轻量** | 无 JVM / 无 Electron；不为功能引入重量级运行时（**判据 = 不打包浏览器内核 / 不用 Electron · JVM** ⇒ **系统自带 WebView 合规**；「必须系统控件」的严格读法不使用） | 1.2 产品目标 |
| P7 | **双平台等价** | macOS 与 Linux 是**同一个产品的两个实现**：能力清单、行为语义、验收标准一致；差异只允许出现在「平台适配层」以内，并且**逐条登记、可查、不可悄悄有** | SRS 1.1.8、§10.9、§10.10；概要设计 §3 平台适配层契约 |

# 第二章 能力总纲

## 2.1 三端等价

### 2.1.1 什么算一样

| 维度 | 要求 | 判定方式 |
|---|---|---|
| **能力清单** | 两侧需求条目集合一致（数量与编号对应） | SRS §10.10 等价矩阵，由 `Scripts/gen-platform-parity.py --check` 强制 |
| **行为语义** | 契约级不变量一致：取消必须传到执行端且双向生效、受影响行数只报一次、结果截断必须可见、写操作逐次审批、密钥不入配置 / 审计 / 日志 | 概要设计 §3.2 / §3.10 的不变量清单；两侧各写等价契约测试 |
| **验收标准** | 同一条需求的判定标准两侧共用，不各写一套 | SRS 验收标准列（平台专属判定须在 §10.9 登记） |
| **交互与观感** | 设计令牌（间距 / 圆角 / 字号 / 表面与文本色 / 状态色 / 分类色）取值一致 | 概要设计 §3.9；两侧各有一份令牌表与对比度单测 |
| **文档** | 三书是**唯一共享事实源**，随代码一起进 Git，靠 GitHub 同步 | 本文 + SRS + 概要设计入库；`Scripts/verify-all.sh` 校验 |

**不算「一样」的部分**（允许不同，但必须登记）：菜单 / 快捷键的宿主约定、窗口与停靠行为、字体回退、
原生控件外观、安装与签名方式、终端仿真与 PTY、沙箱与文件授权机制、系统集成（通知 / 深色模式跟随）等。
每一处都进 SRS §10.9 平台差异登记表（**编号范围以该表为准，不在这里写死区间** —— 同一个数字不在两处各写一遍），写清「为什么必须不同」与「用户可感知的差异」。

### 2.1.2 分工与禁止

- **契约向下、实现向上**：概要设计 §3 是两侧都必须满足的接口契约（`【契约】`）；平台实现细节标注 `【macOS】` / `【Linux】`，可自由替换。
- **禁止**：把一侧的库名、类型名、机制名写进需求条目 —— 需求描述必须在两侧都成立。工具会拦（`Scripts/check-platform-neutrality.py`，棘轮只降不升）。
- **禁止**：同一件事有两个真相。需求书 §3/§4 的「状态」列是 **macOS 基线**；Linux 状态只在 `Docs/平台实现状态.json` 登记。
- **禁止**：一侧加能力而另一侧不知情。新增 / 修改 `【契约】` 条目时，等价矩阵与差异登记表必须在同一次提交内更新。

### 2.1.3 收敛

- **等价矩阵**：216 条需求全部登记在册（`Scripts/gen-platform-parity.py` 生成，改文档后自动核对）。
- **中立性**：**严格档已清零** —— 需求条目的「需求」列与需求说明书 / 5.1 正文里没有任何平台专属词（配额 0，`Scripts/check-platform-neutrality.py` 逐行守，负例已验证会拒绝）。**报告档 165 处**在「状态 / 证据 / 验收要点」列、附录 D 风险记录与 §10 附录里 —— 那些地方本来就在记 macOS 基线做了什么，**只统计不拦截**。两档口径写在 SRS 1.1.8：既不让实现细节当需求被照抄，也不逼人删实现记录。
  - 纠正一处我自己的口径错误：第一版脚本按"行"一刀切，把 190 处变更记录与 43 处证据列也算成负债（246 处），既收敛不到 0，也会逼人删掉有价值的实现记录。**是尺子不对，不是文档不对** —— 改按列归因后，真正混进需求正文的只有 25 处，现已全部改写为行为描述。
- **分工（2026-09-26 结构重排后）**：两台电脑**各做一个产品** —— 本机（macOS）做 **Doyah Studio**（目标三端 **macOS / Windows / Linux**），另一台做 **Doyah Notes**（鸿蒙 / 安卓 / iOS 的生活助手，作为插件进入 Studio 的 macOS / Windows）。因此 **Studio 的 Windows 与 Linux 端目前没有进行中的实现**；下面的契约（1.1.8 / §10.9 / §10.10 与概要设计 §3）**保留待用**，但不要把它读成「正在排期」。真要开第二、第三个桌面端时，按这三份契约起手。

## 2.3 四个产品面

> 后面每章讲一个产品面。本节先把边界一句话说清，避免「某个功能到底算谁的」反复扯。

| 产品面 | 一句话 | 形态 | 对应章 |
|---|---|---|---|
| **Doyah Agent** | 智能体本体：循环、工具、记忆、技能、定时、插件 | **可独立运行的 CLI**；装进 Studio 则是 profile | 第三章 |
| **Doyah Studio** | 工作台：Workspace（IDE）+ Database Client | 桌面应用（macOS / Windows / Linux） | 第四章 |
| **Doyah Notes** | 笔记：跨端同步、编辑器、检索 | 插件形态装进 Studio（macOS / Windows）；移动三端自有形态 | 第五章 |
| **Doyah Retro** | 交易复盘：记录、归因、统计 | 装进 Studio 的能力 | 第六章 |

**边界口径**（人类主人 2026-10-18 令）：

- **Doyah Agent 是独立产品，不是 Studio 的子模块** —— 它是「可独立运行的 CLI 工具，等同于 Hermes 与 DSH 的集合体」；装进 Studio 下运行时，是「类似 DSH desktop 的 profile 工具」。
- **Studio 是 Agent 的宿主，不是上级** —— 有 Studio 就用上界面，没有 Studio 也能在任意 terminal 里用 CLI 跑。**界面与 CLI 是同一份实现**，不存在两套。
- **Notes / Retro 是 Agent 的作用面**，不各建一套 Agent（见 2.4）。
- **能力条目现登记在需求书的 Studio 域（`FR-AI`）**；Agent 独立成产品后这套条目怎么拆，见附录 C。

## 2.4 能力与作用面

## 2.5 存储分层

> **需求提出者原话**：「统一到SQLite，主存进库、原始数据与附件留在文件系统确认」

| 项 | 决定 |
|---|---|
| 引擎 | **桌面各端统一本地 SQLite**（`FR-PLUG-08`），WAL + 事务 |
| **进库** | 笔记元数据 / 正文 / 标签 / 时间线 / **附件索引（只存路径）**；将来复盘侧的成交明细、周报索引同引擎 |
| **不进库** | **原始行情快照仍 CSV/JSON**（可读、可 diff、喂脚本与 AI 零摩擦）；**附件二进制**留文件系统；导出产物照旧落盘 |
| 接入方式 | **vendored `sqlite3.c`（公有领域）+ 本工程薄封装**，沿用 `Vendor/` 纪律；**不引第三方 Swift 封装** |
| 判据 | 四条 4/4 命中：数据持续增长 / 有并发写与多进程读 / 要按条件查与全文检索（FTS5）/ 要崩溃不坏数据的硬保证 |
| 为什么是现在 | **换引擎成本最低点**：实测 `notes.json` 仅 395 字节；L-03 已演练一次性迁移 + 原子写 + 坏文件回退 |
| 排除 | GRDB（官方仅 Apple+Linux，Windows 社区探索中）、SwiftData / Core Data（Apple 独占）、JSONL（查询要自建索引）、DuckDB（分析型，不适合作事务主存，可作日后分析层） |

**与移动侧的关系**：移动端的 `relationalStore` 底层同为 SQLite ⇒ 三端将来可共用一种数据契约（`Q22` 随之更好答）。

# 第三章 Doyah Agent

> **形态**：Doyah Agent 是一个**可独立运行的 CLI 工具** —— 等同于 Hermes 与 DSH 的合集：常驻服务、长期记忆、技能自进化、内置 cron、工具循环、插件扩展。
> **装配**：装进 Doyah Studio 就是一个 profile（类似 DSH desktop 的 profile 工具），此时多出界面；不装 Studio 也能在任意 terminal 里用 CLI 跑。
> **同一套**：界面与 CLI 是**同一份实现**，不是两套 —— 能力只在本书写一遍，宿主只决定"有没有界面"。

## 3.1 执行内核

> 这一组是其余所有能力不成立的那一层：拆掉它，Agent 就不是 Agent 了。

### 3.1.1 循环与工具

**是什么**：把一句话的目标拆成若干步，每步调一个工具，看结果再决定下一步，直到能给出结论。

**边界**：工具**只在当前工作区内**生效（`read_file` / `list_dir` / `search` / `write_file` / `run_command`）；越界请求直接拒绝并说明原因，不许绕路；**只读是默认**，写入与执行按 3.2.9 的授权口径。循环**没有"步数少"这种保护** —— 长任务是正常的，防跑飞靠 3.2.2。

**不是什么**：循环只管"下一步做什么"；模型选哪一档见 3.2.7；工具结果怎么呈现给用户见 3.3。

### 3.1.2 及时刹停

**是什么**：识别到**伤害性动作**（删别人的东西、花钱、对外发布、改口径）时，在**动手之前**停下。

**边界**：停下**不建审批单、不执行、只留痕**；宁可误停，不可不可逆地做错。同一工具同参数反复、且没有新证据，也算一种"该停"——停下时**必须把已有文本当答复交出来**，不许只交一句"我停了"。

**不是什么**：刹车管"该不该继续"；审批管"能不能做"（3.2.9）。

### 3.1.3 上下文先验

**是什么**：开跑之前就把已知事实摆到面前 —— 工作区顶层结构、git 分支与脏文件、当前打开的文件。

**边界**：先验只给**结构**，不给内容（内容靠读）；先验过期会让模型基于旧事实行动，因此每次开跑重取，不做缓存。

**不是什么**：先验是"开局就知道"，记忆（3.2.4）是"跨会话还记得"。

## 3.2 约束

> 内核决定"能做什么"，这一层决定"允不允许做"。

### 3.2.1 权限与审批

**是什么**：开跑前定一次范围（这次能碰哪里），动作超出范围或不可逆时回来问。

**边界**：便宜可撤的事（口味、排版、命名、实现方式）**直接按已知偏好做**；贵或不可逆的事（删东西、花钱、对外发布、改口径）**必须问**。审批是**前置**，不是执行后的提醒。

**不是什么**：审批管"能不能做"，刹车（3.2.2）管"该不该继续"。

### 3.2.2 灵魂

**是什么**：三级口径 —— **L0 角色**（我是谁：说真话、办对事、越用越准）、**L1 领域角色**（在这个领域我是谁）、**L2 项目做法**（这个项目怎么做）。

**边界**：**L0 优先于 L1**，任何工作区规则不得覆盖 L0；注入顺序 L0 → L1 → 记忆 → 会话；灵魂文件里出现密钥形态即拒绝载入。

**不是什么**：灵魂是"以什么身份做事"，记忆是"记得什么"。

## 3.3 能力

> 可替换、可关闭、可多档的能力层；拆掉某一项仍然能用，只是少一种本事。

### 3.3.1 记忆

**是什么**：把用户说过的偏好、项目里定过的规矩、做过的事记住，下次不用再说一遍。

**边界**：记**结论与偏好**，不记原文流水；**可读、可删、可解释来源**；删除必须真的不再复述。记忆不替用户做决定，只减少重复提问。

**不是什么**：记忆是"跨会话"，先验是"本次开局"，技能（3.3.2）是"会怎么做"。

### 3.3.2 技能

**是什么**：一类活干成功之后，把做法沉淀成下次可直接复用的步骤，下次遇到同类活**先查有没有**。

**边界**：只从**成功且被确认**的任务里抽；技能必须**可检视、可作废**；不许把一次偶然的做法当成通用规则。

**不是什么**：技能是"怎么做"，记忆是"知道什么"。

### 3.3.3 定时与后台

**是什么**：到点自动起一次会话（例如每早拉一次数据、每晚生成日报）。

**边界**：**定时不构成授权** —— 到点只代表"可以开始"，具体动作仍受 3.2.9 约束；跑了什么、成功失败，必须能回看。

**不是什么**：定时管"什么时候跑"，循环（3.2.1）管"跑的时候怎么走"。

### 3.3.4 模型多档

**是什么**：可以配多档模型（不同端点、不同价位），按任务切换。

**边界**：每档的端点、模型名、密钥由用户自己填；密钥只进钥匙串，助手**不碰、不显示**；切档失败要退回上一档并说明，不许静默降级继续。

**不是什么**：多档管"用哪个模型"，循环管"怎么用它"。

## 3.4 接入

> 与外界的接口。MCP 连别人，插件被连。

### 3.4.1 MCP

**是什么**：双向 —— 作为**宿主**接入外部 MCP 服务器；作为**服务**把本产品能力暴露给外部。

**边界**：接进来和暴露出去都受同一套权限与审计约束；外部服务器的工具**不得绕过**审批与外发日志。

**不是什么**：MCP 是"接谁"的通道，插件（3.2.11）是"装什么"的载体。

**接入形态（原 3.4 并入）**
**为什么先做协议层与权限判据**：MCP 的互操作价值取决于两件事 —— 报文对不对、**权限有没有真的继承当前会话**。
这两件事都不需要真实 MCP 客户端 / 服务器在场就能验（假对端足够），而"接上某某客户端"恰恰是最后一步。

**已经交付什么**
  · 两个方向**共用一套 JSON-RPC 报文**（同一份解析与生成，因此不可能两个方向不一致）；未知字段保留、坏报文 `-32700`、
    未实现方法 `-32601`、协议版本不一致时如实回报我们支持的版本。
  · 暴露四个工具（查询 / 对象列表 / 表结构 / 导出），**刻意不暴露**连接管理与口令、备份恢复与维护任务、工作区文件读写。
  · **不另开特权**：能力从当前连接推导、外部请求改不了；没会话就一律拒；只读连接上的写语句被拒且批准也不能绕过。
  · **按次审批**：写语句即使在只读工具里也要审批；批准单位是"这一次调用"。
  · 每次调用进审计（可落盘 JSONL）。

**一个被脚本抓出来的漏洞（值得记下来）**：最初审批按**工具名**算，于是"允许 `query_sql`"等于允许通过它下发**任何**语句 ——
实测真的把 `DELETE FROM customers` 下发了，只是被外键挡下。改成**按次**（工具名 + 参数指纹）之后，
"逐次审批"才是逐次审批。**没有假对端脚本，这个漏洞会一直躺在代码里直到某天真删了数据。**

**证据**：20 项单测 + `Scripts/test-mcp.sh` 13 项断言（假 host 驱动我们的 server：真连 PG 跑查询、真下发一条被批准的写语句、审计 11 条；假 server 驱动我们的 host）。

**界面审批通道（同日补齐）**：MCP server 跑在 CLI 的 stdin/stdout 上（协议通道，借不来弹窗），
所以两侧共用一个**文件队列**：server 入队并等，面板显示待审批项（**要执行的 SQL 摆最显眼处**），
人点允许 / 拒绝写决定，server 读决定再执行。三条口径：**批准只对这一次有效**（指纹级）、
**没人确认时默认不放行**（超时 = 拒绝）、队列位置可见。

**又一次被脚本抓到的缺陷**：配了队列时会话先回"需要审批"、批准后再回结果 —— **一个请求两个响应**，
违反 JSON-RPC，客户端会把真结果当成多余报文丢掉。改成"配了队列就先不回，点完只回一个"。

**什么还没做（如实登记）**：host 方向是批处理式最小闭环（不做长连、不处理服务器反向请求）；
未接真实 MCP 客户端 / 服务器；资源只做了 `resources/list` 的最小实现；面板观感需人工看一眼。

### 3.4.2 插件

**是什么**：能力可以按插件装卸（记忆、复盘、压缩、派单……），装一个能力不动内核。

**边界**：插件**不得绕过**审批与审计；装卸插件不影响已装能力的授权范围。

**不是什么**：插件管"扩展什么"，MCP 管"连谁"，内核三件（3.2.1 ~ 3.2.3）不可插件化。

## 3.5 交互

> 人怎么用上它；CLI 与界面是同一份实现的两个壳。

### 3.5.1 对话

**是什么**：在工作区里直接对话 —— 带着当前文件、选中文本、终端输出作为上下文；回答能落成动作（改文件、跑命令）。

**边界**：**上下文是"带过去"的，不是"猜出来"的** —— 用到了哪个文件、哪段选中，回答里要说清；对话不替代编辑器，改完仍需人看差异。

**不是什么**：对话管"说清楚要什么"，3.2 管"怎么做到"。

### 3.5.2 回边

**是什么**：把执行结果退回对话里 —— 跑完的命令、改完的文件、失败的原因，都能在对话中看到并继续追问。

**边界**：**回边必须带原始输出**（不许只回一句"完成了"）；失败要把错误原文带回，不许改写成人话后丢掉细节。

**不是什么**：回边管"结果回来"，3.2.1 管"下一步做什么"。

# 第四章 Doyah Studio：Workspace 与 Database Client

> Doyah Studio 是 Doyah Agent 的**宿主**（之一），而不是 Agent 的上级。它做两件事：给 Agent 一个能看能改的工作区，给 Agent 一个能查能改的数据库。

## 4.1 Workspace

> 一个模块（工作区），下面是它的功能点。每个功能点三段：**是什么 / 不是什么 / 边界**。

### 4.1.1 Home 页

**是什么**：打开工作区先看到的一页：最近文件、常用动作、当前目录概况。

**不是什么**：**不把设置堆在首页**（Home 是入口，不是控制台）；不做成数据看板。

**边界**：空工作区要给出"下一步做什么"，不许一片空白。

### 4.1.2 文件树

**是什么**：左侧常驻的工作区目录树，所有文件操作的入口。

**不是什么**：**不显示版本库内部**（`.git` 等隐藏目录默认不展示）；不做编辑器的事情。

**边界**：只认工作区内路径；大量文件要懒加载，不许打开就卡。

### 4.1.3 新建文件

**是什么**：在工作区任意目录新建文本文件，建完立刻进编辑器并出现在文件树里。

**不是什么**：不做"从模板生成项目"，也不猜你要建什么类型 —— 名字与后缀由你定。

**边界**：重名必须拦下并提示；写入失败要如实报错，不许留一个空文件假装成功。

### 4.1.4 重命名

**是什么**：就地改文件名或目录名，内容与位置随之而来。

**不是什么**：**不替你改代码里的引用** —— 改名就是改名，重构是另一件事（不在本能力内）。

**边界**：目标名已存在时拦下；失败要把名字回滚到原名，不留半改状态。

### 4.1.5 删除

**是什么**：删文件或目录，进系统废纸篓（可恢复）。

**不是什么**：**不提供"永久删除"按钮** —— 不可逆的动作不该出现在日常路径上。

**边界**：删除前确认；删完树里立即消失；被占用/无权限时如实说明原因。

### 4.1.6 打开与识别

**是什么**：双击按类型打开 —— 代码进编辑器、图片进预览、二进制提示不可编辑。

**不是什么**：**不认识就别装认识** —— 不做半渲染，不把二进制当文本打开。

**边界**：同一文件重复打开复用已有页签；外部"用本应用打开"要在树里定位到它；**不做万能预览** —— 不可预览的类型就是不可预览，不猜。

### 4.1.7 编辑与保存

**是什么**：改内容、标记未保存、保存到磁盘；有未保存改动时关闭要拦一次。

**不是什么**：**不自动保存**（不替你决定什么时候落盘），也不静默格式化。

**边界**：磁盘上的文件被外部改动时要提示冲突，不许直接覆盖别人的修改。

### 4.1.8 查找替换

**是什么**：在当前文件内查找、逐个替换或全部替换。

**不是什么**：**不做跨文件替换** —— 那是工作区搜索（3.3.4）的范围。

**边界**：全部替换要给出替换条数；正则写错要报错，不许"零命中"糊过去。

### 4.1.9 搜索与定位

**是什么**：工作区标头一处搜索，按文件名与内容查找，回车打开并跳到命中行。

**不是什么**：**不做替换**（替换在 3.1.8 的当前文件内）；不搜二进制与忽略目录。

**边界**：大仓库搜索要给进度，不许假死；命中要能直达那一行。

### 4.1.10 终端

**是什么**：工作区内的终端面板，跑构建、测试、脚本。

**不是什么**：**不自建 shell** —— 用系统 shell，不替他改写命令。

**边界**：命令在工作区根执行；面板高度可拖拽（不可拖拽等于不可用）；输出可回溯不截断。

### 4.1.11 页签

**是什么**：多文件并存，可切换、可关闭、可重排。

**不是什么**：**不强制单页签**（不爱多开是个人偏好，不是产品约束）。

**边界**：关闭未保存的页签要给三个选择（保存 / 不保存 / 取消），不许只给"确定"。

### 4.1.12 会话恢复

**是什么**：重启后回到上次的工作区、页签与光标位置。

**不是什么**：**不恢复未保存的改动** —— 恢复的是"看什么"，不是"改了什么"。

**边界**：文件已被外部删除时，恢复要提示而不是静默丢弃。

## 4.2 Database Client

> 一个模块（数据库客户端），功能点按**连接 → 看 → 跑 → 改 → 诊断 → 维护**的顺序排。

### 4.2.1 新建连接

**是什么**：填主机 / 端口 / 库 / 账号，保存后出现在连接列表里，点开即连。

**不是什么**：**不自动探测你没有的库**，也不替你猜端口之外的东西。

**边界**：必填项缺一不给保存；连通性失败要说清失败在哪一层（网络 / 认证 / 库不存在）。

### 4.2.2 凭据

**是什么**：口令进系统钥匙串，连接时按需取用。

**不是什么**：**不在界面、日志、导出物里显示明文**；不把口令写进连接配置文件。

**边界**：钥匙串不可用时要明确报错，不许静默降级成"每次都问密码"。

### 4.2.3 SSH 隧道

**是什么**：经跳板机连数据库：本地端口转发到远端。

**不是什么**：**不代管你的 SSH 私钥**（用系统已有的）；不做密钥分发。

**边界**：隧道断了要断开连接并提示，不许让界面停在"看起来还连着"。

### 4.2.4 连接失败

**是什么**：连接失败时给出可执行的下一步（检查端口 / 检查账号 / 检查库名）。

**不是什么**：**不编造原因** —— 拿不到底层错误就照原样给出。

**边界**：错误原文必须可复制。

## 4.2 元数据浏览

### 4.2.5 树形浏览

**是什么**：库 → 模式 → 表 / 视图 / 函数逐层展开。

**不是什么**：**不一次性把整库拉下来**（大库会卡死）；不做"猜测式"补全。

**边界**：按需展开、可刷新；展开失败的节点要标出来而不是留空。

### 4.2.6 表结构

**是什么**：看列、类型、默认值、索引、外键。

**不是什么**：**不在浏览时改结构**（改结构是 4.5.2）。

**边界**：结构信息要能复制成 DDL 片段。

### 4.2.7 刷新

**是什么**：结构变了（别人加的列）能手动刷新到最新。

**不是什么**：**不做后台轮询** —— 不给自己造"看起来实时"的假象。

**边界**：刷新要保留展开状态与当前选中。

## 4.3 SQL 执行

### 4.2.8 单次执行

**是什么**：写 SQL、执行、看耗时与影响行数；支持只跑选中部分。

**不是什么**：**不自动加 `LIMIT`**（不替你的语句做决定）。

**边界**：语句错误要把数据库返回的原文贴出来（含位置）。

### 4.2.9 高危确认

**是什么**：无 `WHERE` 的 `UPDATE` / `DELETE`、`DROP`、`TRUNCATE` 执行前弹确认。

**不是什么**：**不是"提醒一下就算了"** —— 确认前不发送语句。

**边界**：确认框要显示将要执行的完整语句与目标库。

### 4.2.10 中断

**是什么**：长查询可中断，中断后连接仍可用。

**不是什么**：**不假装"已中断"** —— 数据库不认账时要如实说还在跑。

**边界**：中断结果（成功 / 失败 / 未知）都要显示。

## 4.4 结果集

### 4.2.11 展示

**是什么**：表格展示，NULL 与空串可区分，列宽可调。

**不是什么**：**不把 NULL 显示成空**；不做隐式类型转换。

**边界**：超宽表要能横向滚动而不是截断列。

### 4.2.12 排序筛选

**是什么**：按列排序、按值筛选，不改动原语句的结果语义。

**不是什么**：**不做服务端重查**（本地排序，避免把大查询再跑一遍）。

**边界**：筛选后要显示"已筛掉多少行"。

### 4.2.13 大结果承载

**是什么**：大结果分页或虚拟滚动，明确告知还有多少没显示。

**不是什么**：**不一次渲染十万行**把界面卡死。

**边界**：显示"共 N 行，已显示前 M 行"。

## 4.5 数据与结构

### 4.2.14 行编辑

**是什么**：直接在结果里改单元格、增行、删行，生成对应 DML 执行。

**不是什么**：**不做无主键表的隐式匹配**（没有唯一键就明确拒绝编辑）。

**边界**：改动前给出将执行的语句；执行失败整批回滚。

### 4.2.15 表设计

**是什么**：建表、加列、改类型、加索引，生成 DDL 并执行。

**不是什么**：**不"点一下就 alter"** —— 必须先预览 SQL。

**边界**：破坏性变更（删列 / 改类型）要单独确认。

## 4.6 导入导出

### 4.2.16 导出

**是什么**：结果或整表导出 CSV / JSON。

**不是什么**：**不含敏感列除非你显式勾选**。

**边界**：导出完成要报数（多少行、多大、落在哪）。

### 4.2.17 导入

**是什么**：从 CSV / SQL 文件导入数据。

**不是什么**：**不做"尽力而为"的静默跳过** —— 失败行必须报出来。

**边界**：导入前给字段映射预览；结束报成功 / 失败行数与失败原因。

## 4.7 诊断

### 4.2.18 执行计划

**是什么**：把语句的执行计划按节点展开，标出代价与扫描行数。

**不是什么**：**不给"应该加索引"的结论** —— 只给读数，结论由 4.7.3 或人来下。

**边界**：不同库的计划格式差异要显式说明。

### 4.2.19 统计读数

**是什么**：缓存命中率、活动语句、连接数等运行时读数。

**不是什么**：**扩展没装就说没装**（例如 `pg_stat_statements`），不拿别的数凑。

**边界**：每条读数标注来源视图与采样时刻。

### 4.2.20 锁与等待

**是什么**：谁在等谁、等了多久。

**不是什么**：**不自动杀会话** —— 只显示，处置由人决定。

**边界**：识别不到等待链时明说"看不到"。

## 4.8 维护编排

### 4.2.21 任务定义

**是什么**：把 VACUUM / 重建索引 / 备份编成任务，可定时。

**不是什么**：**不内置"最佳实践模板"** 替你决定跑什么。

**边界**：任务要写明目标库与影响对象。

### 4.2.22 审批

**是什么**：动作执行前经审批，批准才跑。

**不是什么**：**不是执行后的提醒**（前置才叫审批）。

**边界**：审批记录要能查到谁批的、批的哪条语句。

### 4.2.23 执行回执

**是什么**：跑完给出改了什么、影响多少行、耗时。

**不是什么**：**不把"完成"当回执**。

**边界**：失败要停，不许继续下一个任务。

## 4.9 多库驱动

### 4.2.24 方言差异

**是什么**：同一功能在 PostgreSQL / MySQL / GBase 8a 上的语法与行为差异显式标注。

**不是什么**：**不假装一致** —— 不支持的写法直接说，不"看起来能用、跑起来报错"。

**边界**：差异清单要能被界面读取（不支持时禁用而不是报错）。

### 4.2.25 驱动接入

**是什么**：新增一种库 = 实现一套驱动接口，不改界面。

**不是什么**：**不为某个库改通用层**（改了就是把差异漏进内核）。

**边界**：驱动要自报能力位（支持哪些功能）。

# 第五章 Doyah Notes

## 5.1 Notes 能力

> 形态：笔记能力以**插件**形态装进 Doyah Studio，可用平台为 **macOS / Windows**（Linux 不带）；移动三端（iOS / 安卓 / 鸿蒙）是该产品自己的形态。

### 5.1.1 捕获与新建

**是什么**：从任意位置最快地记下一句话（灵感、待办、摘录），先存下来再整理。

**边界**：**先落盘再排版** —— 不许因为格式没想好就丢内容；离线和断网时也要能记。

**不是什么**：捕获管"先记下"，编辑（5.1.2）管"写成什么样"。

### 5.1.2 编辑与格式

**是什么**：富文本编辑：标题、列表、引用、代码、表格、任务框。

**边界**：格式**可长期演进**（旧笔记在新版本里必须能打开）；撤销栈要够深，误删能回来。

**不是什么**：编辑管内容形态，列表（5.1.3）管怎么找到它。

### 5.1.3 列表与检索

**是什么**：首页列表 + 全文检索（标题与正文），支持筛选、置顶、多选。

**边界**：大仓库**不许一次全渲染**（懒加载）；搜索要有防抖与高亮，命中处可直达。

**不是什么**：列表管"翻"，检索管"找"。

### 5.1.4 整理

**是什么**：标签、笔记本、置顶与收藏 —— 让仓库从几十条长到几千条还能用。

**边界**：整理动作**不改变内容**；排序语义统一（置顶优先于时间）。

**不是什么**：整理管"归类"，检索管"命中"。

### 5.1.5 删除与恢复

**是什么**：删除先进"待删"再落库，给一个可撤销的窗口。

**边界**：**可后悔** —— 撤销窗口内一定能回来；彻底删除必须显式二次确认。

**不是什么**：删除管"去掉"，同步（5.1.6）管"别处还有没有"。

### 5.1.6 同步与账号

**是什么**：多端之间同步，账号与凭据的云端契约。

**边界**：**冲突不许静默丢数据** —— 冲突要留下两份并说明来源；同步状态要可见（同步中 / 已同步 / 失败原因）。

**不是什么**：同步管"多端一致"，存储层（5.1.5 的数据层抽象）管"存在哪"。

# 第六章 Doyah Retro

## 6.1 Retro 能力

### 6.1.1 数据获取

**是什么**：盘后按自选池抓行情 / 资金流 / 财务 / 板块；支持导入券商对账单与交割单。

**边界**：**抓不到就说抓不到**（不许用旧数据顶替）；数据要带来源与复权口径，跨源可对齐。

**不是什么**：获取管"把原始数据拿进来"，档案（6.1.2）管"整理成人能看的"。

### 6.1.2 个股档案

**是什么**：一键生成个股跟踪档案（基本面 + 走势 + 我的操作记录）。

**边界**：档案**可追溯到原始记录**，不许只给结论。

**不是什么**：档案管"单只股票"，周报（6.1.3）管"一片"。

### 6.1.3 周报

**是什么**：整合行业板块与国际趋势，产出周报，并可转成笔记。

**边界**：周报**复用笔记的存储形态**（不另造一套格式）；结论要能溯源。

**不是什么**：周报管"定期汇总"，复盘查询（6.1.4）管"随时回溯"。

### 6.1.4 复盘查询

**是什么**：按标的 / 时间段回溯：当时我看到了什么、做了什么、结果如何。

**边界**：查询结果**按时间对齐**（行情与我的操作在同一时间轴上）。

**不是什么**：查询管"看历史"，分析（6.1.6）管"从历史里得出规律"。

### 6.1.5 提醒

**是什么**：触发线到点提醒。

**边界**：**复用宿主（系统）的提醒能力**，不自建推送通道。

**不是什么**：提醒管"到点叫我"，分析管"该不该叫"。

### 6.1.6 分析

**是什么**：异常操作检出、策略/模型提炼。

**边界**：结论必须**指向具体交易记录**；样本不足时明说"样本不足"，不下结论。

**不是什么**：分析管"规律"，AI 复盘（6.1.7）管"对话式地问"。

### 6.1.7 AI 复盘

**是什么**：把行情、成交、周报作为数据源，做对话式复盘。

**边界**：**结论必须可溯源到原始记录**；模型只组织与解释，不生成不存在的成交。

**不是什么**：AI 复盘是"用 3.2 的能力做复盘"，能力本体在 3.2，不在此重复。

### 6.1.8 数据健康

**是什么**：抓取失败、字段漂移、数据断档的监控与告警。

**边界**：首版只做**导入侧如实报数**，不做预测性判断。

**不是什么**：健康管"数据可不可信"，其余各点都依赖它。
