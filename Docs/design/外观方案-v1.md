## 1. 为什么当前界面"简陋"（量出来的，不是感觉）

| 项 | 现状 | 后果 |
|---|---|---|
| 主题 / 令牌层 | **不存在** | 每个视图各自为政，同一语义在不同面板里不是同一个值 |
| 显式字号 | 全 App 只有 **3 个**（14 / 15 / 9），其余靠默认 `.body` | 没有排版级差：标题、正文、表头、辅助信息长得一样 |
| 材质 / 毛玻璃 | **0 处** | 工具栏与侧栏是纯色平铺，没有"浮在窗口上"的层次 |
| `Divider()` | **46 处** | 分隔靠系统实线，又多又重；精致感来自**更少、更淡的发丝线** |
| padding | `2` 出现 **139 次**，另混着 1 / 3 / 6 / 10 / 12 / 20 / 150 | 没有刻度 → 对齐"差一点点"，这是"看着不精致"的第一来源 |
| 颜色 | 语义色 + 零散 `Color.orange/.red/.blue`、`NSColor.system*`，**无调色板** | 同一种"警告橙"在不同面板里不是同一个橙 |
| 主窗口 | 就是一个 `NavigationSplitView`，无自定义 toolbar / 背景 | 层次全靠系统默认 |
| 结果网格 / 终端 | 自绘 AppKit | 完全可控，也完全没有系统加成 |

**结论：不是"macOS 风格不对"，是"没有设计层"。** 精致感的真正来源是一致性、层次、克制的细节。

## 4. 样张自检（41 项全过）

渲染脚本不只看图，还会**取样核对**（空白图也是合法 PNG）：

1. 不变式「内容区是明度最高的表面」（深浅两套都成立）；
2. 表头 / 侧栏必须与内容可区分；
3. 强调色**分类**：按钮处取样必须最接近本次使用的候选；
4. 三个候选彼此必须可区分（距离 > 0.15）；
5. 文本与图标真的画上去了（编辑区 / 网格 / 侧栏 / 终端四块的非背景像素占比）。

**自检当场抓出并修掉了两处我自己设计里的缺陷**（深色层次只有 3/255、浅色侧栏与内容明度只差 0.009），
另外还发现「逐字节比对」这个判据本身是错的：位图是 deviceRGB，写进去的 sRGB 会被显示器 profile 转换一次
（`#16181D` 读回 `#21242C`），因此判据改为**结构关系 + 分类**。

### 8.6 两端怎么用（跨平台）

- **令牌层跨平台**：本方案落在 `Core/DesignTokens.swift` 的**同一套令牌名**（`window` `sidebar` `content` `panel` `raised` `hairline` `textPrimary` `textSecondary` `textTertiary` `textBright` `accent` `accentGlow` `accentSoft` `teal` `warm` + 语法着色），**macOS 与 Windows 共用一份值**，差异只在材质与控件形态：
  - **macOS**：NSColor / SwiftUI 绑定；毛玻璃 `.ultraThinMaterial` 作为**叠加层**，不改令牌值
  - **Windows**：Tauri 2 + Vue 3 侧导出同名 CSS 变量（`--doyah-window` …）；Mica / 亚克力是**窗口背板**，对比度必须按**不透明兜底色**算（系统关闭透明效果时回落）
- 门槛两端共用一套单测：正文 ≥4.5 / 强对比 ≥7 / 图标线 ≥3，**深浅两态都要过**
- Linux（公司环境，手工搬运三书）：同一张表，自行映射，不承诺视觉一致

### 9.6 两轴正交（深浅 × 配色）—— 2026-09-29 第 83 轮 · 队列 L-85

**外观是两条独立的轴**，口径一句话：**深浅轴**（`AppearancePreference`：跟随系统 / 总是深色 / 总是浅色）
× **配色轴**（`DesignTheme`：科技蓝 / 星空紫 / 豆芽绿 / 玫瑰金）。两轴**互不读取**，组合起来 3 × 2 × 4 = **24 组**。

| 项 | 口径 | 落点 |
|---|---|---|
| **深浅轴（三态）** | 三态齐全；**未知值回落「跟随系统」**（偏好文件被手改 / 版本降级都不该让界面起不来）；两处出口同答案（`resolvesToDark` 纯函数与 `forcedDark` 给 SwiftUI） | `Core/AppearancePreference.swift`；落盘键 **`appearance.mode`**（终端另有一个键 `terminal.appearance`，允许单独覆盖） |
| **配色轴（四选一）** | 一个主题 = 一组令牌值（底色基调 + 强调色家族 + 语法着色）；选主题**同时套用该主题的配套强调色** | `Core/DesignTheme.swift`；落盘键 **`ui.designTheme`** |
| **两轴互不重置** | 切主题只写 `ui.designTheme`、切深浅只写 `appearance.mode` —— **谁都不许写对方的键**（串轴的表现是「切了主题，深浅档被顺手重置」，用户看不出原因） | `App/AppState.swift`（深浅档的写盘点）+ `App/DesignThemeManager.swift`（配色轴的写盘点）；探针 `TestsUISnapshot/AppearanceAxesProbeTests.swift` 在**真管理器 + 真 `UserDefaults`** 上验 |
| **组合可达** | 18 组逐组可达、不重不漏；**「跟随系统」这一档在系统深浅两态下都取得到值、都过同一套门槛**（正文 ≥4.5 / 强对比 ≥7 / 图标线 ≥3）—— 只测一态时，另一态可能落在看不清的颜色上，这正是「随系统主题」的全部风险 | `Tests/AppearanceAxesTests.swift`（真值表 / 正交 / 矩阵 / 门槛四类） |
| **组合到像素** | 快照画布角上铺的是该档的 `window` ⇒ 角像素必须等于**这一主题这一档**的 `window` 值（拿错主题或拿错档当场红）；同一主题浅 / 深两图的角像素必须差得远 | `TestsUISnapshot/UISnapshotKit.swift` 的取色口子 `sampledRGB(ofPNGAt:at:)` + `TestsUISnapshot/UISnapshotPanelsTests.swift` 的角像素断言 |
| **判据** | `Scripts/check-design-themes.py` **判据 H**（闭环第 6 项，项数仍十八）：三态与真值表逐格 / 两轴互不读取（键分开 + 各自写盘点里不许出现对方的键）/ 24 组组合可达 / 取色口子 + 角像素断言 + **实测容差**（PNG 往返偏移 ≤4 ⇒ 8）/ 本文档这一节的登记 | `--self-test` **25 例**（含 3 例负例：深浅轴少一态 / 两轴串键 / 组合没到像素） |

**边界如实写**：像素断言看的是**角像素**（唯一确定、不依赖面板内部排版）；快照 PNG 往返会把通道值偏移最多 4，
所以容差取 8 —— 而四个主题在**深色** `window` 上的实测值至少有一个通道差 **14** 以上（星空紫与其余三套的最小通道差，2026-10-01 实测），**拿错主题照样红**。
浅色档三个原点主题刻意都接近白（通道差 ≤ 10），单靠浅色图判不出「换没换主题」—— 靠深色图那一半兜；**星空紫**的浅色 `window`（`#E4E7ED`）比它们深一档（通道差 ≥ 15），浅色图上也能判出。
**不属于本节的**：改**系统**外观后界面与终端是否同时跟着重画 —— 那一条要真人点验（待人工验收清单 §1）。

### 9.7 星空紫「星云皮肤」（2026-10-01 · 需求提出者要的「皮肤」质感 · 队列 `L-153`）

**由头**：需求提出者 2026-10-01 对第 4 个主题（星空紫）补了一句 —— 「**我说的可能是皮肤更准确**」：
要的不是「更亮的蓝」，而是表面带**星云云气 + 星点**的质感（参照 NASA 韦伯「宇宙悬崖」）；随后实测又给了一条
（派单 `T-20261001-031` / `T-20261001-037`）：「我要的皮肤效果是**整个界面**，不是只有导航栏、工作编辑区，**底部区域也要有**」。

| 项 | 口径 | 落点 |
|---|---|---|
| **只对星空紫生效** | 别的主题没有「星云」语义，偷偷加星星是走样：主题不是 `.stardust` 时**逐像素回到纯色表面** | `App/Views/NebulaBackground.swift` |
| **覆盖三层表面** | 侧栏（`NebulaSurface(.sidebar)`，先铺表面令牌再叠星云）/ 内容区（`ZStack`：内容令牌 + 星云 + 内容）/ **下方面板**（`LowerPaneView` 根底）—— 强度各自不同（`content` 最克制：它是长时间注视的阅读区） | `App/Views/MainWindow.swift` / `App/Views/LowerPaneView.swift` |
| **底色只有一个出处** | 三处视图撤回各自的 `.background(Theme.surface(…))`（改 `Color.clear`）—— 子视图再铺一层不透明色会把星云**整片盖住**（实测症状：侧栏看得到、内容区看不到） | 同上 + `App/Views/ConnectionListView.swift` 等 |
