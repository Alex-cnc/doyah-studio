## 0.4 关于「授权」的实话（2026-09-29 查实）：**不需要你授权**

需求提出者问：「我电脑上跑的 Hermes 没有界面、是随系统启动的后台网关进程，怎么授权？」—— 查实本机形态后的结论是：**这条路既难走也不必要**。

**为什么不好走**（三条叠起来，TCC 归因无从落地）：

| 事实 | 证据 |
|---|---|
| 入口 `hermes` 是 **shell 脚本**、**未签名** | `file` = POSIX shell script text executable；`codesign -dv` = `code object is not signed at all` |
| 真正执行者是**自装、未签名的 python** | `~/.hermes/tools/python-3.14.7+…/bin/python3` |
| launchd 还夹了一层 `osascript` | plist 的 `ProgramArguments` = `/usr/bin/osascript -e do shell script "exec … hermes gateway run …"` |

⇒ 在「隐私与安全性」里点 `+` 加上 Hermes **大概率不生效**（TCC 认的是真正干活的二进制），而且工具链一升级（路径含构建号）授权立刻失效 —— 与 DoyahStudio 的 ad-hoc 签名同一个坑。

**为什么不必要**：那 5 条（鼠标上报 / 方向键 / 右键菜单 / 多光标 / 逐行右键）可以用**应用内探针**收掉 —— 在 App 进程内部**自己触发界面动作**（`NSApp.sendAction` / `performClick` / 视图层直接调用），判读用**已有的自渲染快照**（`TestsUISnapshot/`）。
**合成事件只有「跨进程」才需要辅助功能授权；自己点自己不需要。**

### 所以你现在什么都不用做

- **B 类 13 条** → ✅ **已全部机器化**（队列 **L-89** ㈠㈡㈢ 收口，2026-09-30 第 114 轮），不需要你做任何事
- **D 类 5 条** → 改走 App 内探针（队列 **L-90**），**零权限**、本侧自主可做
- 只剩 **§0.3 的 5 条**要你（⌃C 那条已机器化），其中 4 条是"眼睛 / 手 / 真文件"，1 条是"有台能 SSH 的机器"

> 真到了非跨进程模拟不可的那天（例如要验系统级弹窗、或要操作别的 App），再回头研究授权；届时对象应当是**真正干活的二进制**（自装 python 或某个固定签名的壳），而不是那个 shell 脚本入口，也**不要**给 ad-hoc 签名的 DoyahStudio.app（重打包即失效）。
