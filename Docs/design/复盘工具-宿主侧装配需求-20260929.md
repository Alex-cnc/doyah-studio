## 1. 结论先给（三条）

1. **「宿主侧」= 装配，不是再实现一遍。** 桌面宿主的活儿只有三样：把笔记存储、提醒、AI 助理**接进来**，把复盘视图**装进去**。契约口径与移动端同源（`DoyahNotes/Docs/核心契约.md` §9.1「装配，不是重复实现」）。
2. **已有形态的两条链不是「从零」**：笔记存储的宿主侧实现**已经在盘上**（`Core/NoteStorage/NoteDatabase.swift`，schema v1：`note` / `note_tag` / `note_timeline` / `note_attachment` + FTS5 `trigram`），AI 数据源的「可溯源」机制**也已经是一等公民**（`Core/DiagnosisContext.swift` 的证据编号 + `Core/DiagnosisAdvice.swift` 的引用校验）。**缺的是「复盘产物」这一形态的落点与「按记录取证」的接入位**，不是底层能力。
3. **本文只出分析与清单，不落契约条文。** 跨仓条目（`HC-*`）的语义要先定：其中「提醒能力的跨仓契约」已由 spec §6 记为 **Q25 随分工转移 → 对侧**；宿主装配边界还受 **Q28（能力仓 vs 独立产品）/ Q31（数据契约归属）** 两个未决项约束 ⇒ **本侧不代决**。

## 2. 三条复用链的宿主侧要求

### 2.1 链 ①「周报 / 复盘产物 = 带 schema 的笔记」（复用笔记存储）

| 要求 | 宿主侧现状（取证） | 判定 |
|---|---|---|
| 不新建存储：产物落在既有笔记库里 | `Core/NoteStorage/NoteDatabase.swift:34` 表集合 = `note` / `note_tag` / `note_timeline` / `note_attachment` / `note_fts`；库为本机单文件 SQLite | ✅ 落点存在 |
| 标签 | `note_tag`（`:73`） | ✅ 已有 |
| 时间线 | `note_timeline`（`:81`） | ✅ 已有 |
| 附件**只存路径**（二进制留文件系统） | `note_attachment`（`:91`）+ `NoteAttachment`（`:133`）+ `addAttachment`（`:366`）+ `attachments(of:)`（`:433`）；口径 = `FR-PLUG-08` | ✅ 已有 |
| 长文可被检索 | `note_fts`（`:104`，FTS5，`tokenize='trigram'`）；判据 = 查询串 ≥3 字（L-25 第 1 批实测） | ✅ 已有，且**有边界**（1~2 字中文走子串兜底） |
| **产物类型**（周报 / 复盘）在来源枚举里有位置 | `Core/Note.swift:12` 的 `NoteSource.Kind` = `manual` / `diagnosis` / `maintenance` / `sql` / `skill` —— **没有「周报」「复盘」「结构化长文」** | ⬜ **缺口**，落点见 `HC-02` |
| **带 schema 的结构化头** | `note` 表列 = `title` / `body` / 来源四元（`source_kind` / `source_connection_name` / `source_fingerprint` / `source_captured_at`，`:60`~`:63`）+ `contains_row_data`（`:66`）+ `storage_version` —— **没有承载「结构化头 / schema」的列或旁挂表** | ⬜ **缺口**，落点见 `HC-02` |
| 数据边界（哪一类内容可入笔记库） | `contains_row_data` 位 + 来源只记**连接名**（`Core/Note.swift:5`~`:9` 三条口径：默认不存结果集行数据 / 口令与连接串永不入库 / 来源可追溯） | ✅ 已有，复盘侧照抄同口径 |

**小结**：链 ① 的宿主侧是**一条已铺好的路**，缺的只有「产物形态」两处（类型枚举、结构化头）—— 而这两处属**数据契约**，不能由宿主单方面加列（见 §3 `HC-02`）。

### 2.2 链 ② 提醒（复用 Notes 的调度能力）

| 要求 | 宿主侧现状（取证） | 判定 |
|---|---|---|
| 调度语义**不重写**，复用 Notes 的提醒定义 | `DoyahNotes/Docs/核心契约.md` §3.12（`ReminderRule` / `ReminderUnit` / `ReminderState` / `ReminderSchedule`，`FR-NOTE-02`），不变量 **I9**（下一次到点 == 逐日扫描结果，严格晚于参照时刻），用例【18】**109 项**对拍矩阵（独立暴力实现） | ✅ 定义侧已有 |
| 宿主侧有**装配位**（能算到点、能投递系统通知、能取消） | `grep -rn "UNUserNotificationCenter\|UNNotification\|NSUserNotification\|UserNotifications\|Reminder" --include=*.swift Core App CLI Tests` ⇒ **命中 0** | ⬜ **宿主侧零代码** |
| 「到点由谁负责」的桌面端口径 | 契约 §9.2 只写「搜索 / 提醒走 §3.10 / §3.12 的语义，口径不因端而异」；Notes 侧 Q7 定的是**移动端本地通知 / 服务端推送**，**桌面端未写** | ⬜ **跨仓待答复**，见 `HC-01` |

**小结**：链 ② 是三条链里**唯一宿主侧一行代码都没有**的一条；它也是**唯一必须先跨仓对齐**的一条（本侧只能定「装配位」的形状，定不了「到点由谁负责」的语义）。

### 2.3 链 ③ AI 助理数据源（「不许无依据断言」+ 可溯源）

| 要求 | 宿主侧现状（取证） | 判定 |
|---|---|---|
| 结论必须**可指回原始记录** | `Core/DiagnosisContext.swift:26` `DiagnosisEvidence`（每份证据带编号 `e1`…、取证用的 SQL、行数据，`:51`）+ 三种**必须分得开**的状态（取到有行 / 取到零行 / **根本没取到**）；`:109`~`:115` 「能作为依据」的集合只含 `isAvailable` —— **没取到的证据不允许被引用** | ✅ 机制已有，**但取证对象是「SQL 语句」** |
| 无依据的结论**整条拒绝** | `Core/DiagnosisAdvice.swift:43`~`:46` 两类拒绝理由（没引用任何证据 / 引用了不存在的编号） | ✅ 已有 |
| 取数规划是纯函数（可离线测） | `Core/DiagnosisContext.swift:174` `DiagnosisEvidenceQueries` / `:212` `DiagnosisContextBuilder` / `:269` `evidencePlan`（按方言给清单；**执行计划不用 `EXPLAIN ANALYZE`**） | ✅ 已有 |
| 产物入笔记时**同一套元信息** | `Core/AICapture.swift:13`（标题 / 正文 / 来源同源） | ✅ 已有 |
| 动作留痕与导出 | `FR-AI-09`：`Core/AgentAudit.swift`（审批状态机 + 追加式 JSONL + 导出脱敏） | ✅ 已有，但**覆盖的是「智能体动作」**，不是「复盘结论」 |
| 对外暴露为数据源 | `FR-AI-10`：`Core/MCPToolCatalog.swift` 四工具（`query_sql` / `list_objects` / `describe_table` / `export_result`） | ✅ 形态可参照 |
| **复盘记录**（成交 / 行情）能当证据 | —— | ⬜ **接入位要新建**，见 `HB-01` |

**小结**：链 ③ 的机制**已经在盘上**（证据编号 + 引用校验 + 三态），要新建的不是机制而是**取证对象**：把「一条成交 / 一条行情记录」变成可编号的证据。

## 6. 验收条件（换台机器照着验收）

1. **装配而非内嵌**：复盘视图卸掉后宿主仍能正常启动（宿主不因缺复盘数据而报错）。
2. **产物即笔记**：复盘 / 周报产物在笔记列表里**能被搜到**（FTS5 `trigram`，≥3 字）、带标签与时间线、附件**只存路径**。
3. **可溯源**：每一条 AI 结论都能指回一条真实记录（引用编号存在；「没取到」的证据被引用 ⇒ 必须被拒）。
4. **提醒不重复**：到点时刻与三端**逐条相同**（I9 口径），且宿主不产生第二条同刻提醒。
5. **不新建存储**：撤销复盘功能后，笔记库**一个字节不被改动**（无迁移、无新库文件、无新 `.json`）。
