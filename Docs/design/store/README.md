# 展示图（封面）—— App Store 式

| 文件 | 内容 |
|---|---|
| `doyah-studio-stardust-dark.png` | 星空紫主题 · **深色** |
| `doyah-studio-stardust-light.png` | 星空紫主题 · **浅色**（与深色**同构**：同版式、同文案，只换深浅两态） |

来源：需求提出者 2026-10-01 的任务 **T-20261001-031** ——
「封面的意思就是类似 App Store 打开软件详细给出的 Demo 图一样」+
「让大河马实际做一版，深色和浅色各来一张即可」。落点与文件名由本侧定（ASCII 文件名，README 引用稳）。

## 怎么出的

```bash
./Scripts/render-store-shot.sh              # 默认就写进本目录
./Scripts/render-store-shot.sh /tmp/out     # 也可以写到别处（试版式时用）
```

`Scripts/render-store-shot.sh` 做三件事：① 用 `Scripts/render-design-mock.sh` 把**真样张**渲染到临时目录；
② 把 `Scripts/render-store-shot.swift` 与 `Core/DesignTokens.swift` / `Core/DesignTheme.swift`（+ 强调色 /
对比度 / 语言表）一起 `swiftc` 编译；③ 产出上面两张图。

## 与「样张」的分工（别混）

- **样张**（`Docs/design/样张-*.png`）= **工程证据**：必须与产品**逐像素同源**，由
  `Scripts/check-design-mock-tokens.py` 钉住（脚本里不许有色值字面量、入口必须编译真令牌、深色底带蓝调）。
- **展示图**（本目录）= **营销物料**：图上有产品里没有的像素（渐变 / 大标题 / 卖点标注 / 圆角容器 / 阴影）
  ⇒ **不并进那条链路**（并进去会破坏「同源」判据）。
- 但「分开」只分**像素**，不分**色源**：展示图的底 / 字 / 强调色全部取
  `ThemePalette.of(.stardust)`，产品窗口那一块**贴的就是真样张**（先在样张自己的色彩空间里重采样再 1:1 贴，
  直接缩进画布空间会整片偏紫）。⇒ 展示图里不可能出现产品没有的颜色。

## 它自己的自检（13 项，渲染时打印）

尺寸 2048×1280 · 角像素 = 星空紫该态的 `window` 值（容差 = 实测 PNG 往返 8）· 贴图区与样张的局部均值
最大差 ≤ 12（实测 ≤ 8）· 左栏每行文字的实际宽度都在 860 以内（**版式不压到窗口上**）· 强调色真的画在图上
（实测命中 179 / 286 处，下限 150，网格采样）· 深浅两态角像素差 ≥ 40（实测 647）。

门槛都是**实测定的**（`Scripts/render-store-shot.swift` 的 `StoreMinimums`）。

## 边界（如实写）

- **观感（构图 / 配文 / 视觉层次）必须人工点验** —— 机械判据只能证明「色与图源同源」「贴的是真样张」
  「版式不重叠」「深浅两态确实不同」。这一条每次渲染都会打印出来。
- **只入库封面图**：`Docs/design/` 下 17 张历史样张**不入库**（单张 ~550 KB、二进制没法增量存储，
  全入库会让仓持续膨胀）。样张要可复现 —— 跑一次渲染入口就有。
- 改值表（`Core/DesignTheme.swift` 的 `stardust`）之后**要重跑本入口**，否则封面图会停在旧配色。
