## 1. 设计目标与约束

| 目标 / 约束 | 说明 | 跨平台要求 |
|---|---|---|
| 协议层与方言层严格分离 | 驱动只做协议传输；所有 SQL 文本由方言层生成 | **契约**，各端同构（NFR-MAINT-02） |
| 领域逻辑可单测 | 领域层不得依赖 GUI 框架；一条命令跑完全部单测 | **契约**（NFR-MAINT-01）；其它端（Windows / Linux）同样要求"GUI 框架不得进入领域层" |
| 事件流驱动界面 | 执行过程以**事件流**暴露，界面按事件更新，不阻塞 UI 线程 | **契约**：事件种类、顺序与不变量见 §3.3 |
| 安全与隐私 | 凭据只进系统凭据库；查询历史不落盘；目录访问走用户授权 | **行为契约**；具体机制按平台替换（§4 P-02 / P-03） |
| 跨平台行为等价 | 同一需求在各端上**行为一致**（含错误分类、空态、确认弹窗、快捷键语义） | **契约**：凡"允许不同"的必须在 §4 登记，否则视为必须一致 |
| 可验证 | 每个关键行为都有单测 / 链路脚本 / 手工验收之一 | **契约**：各端都要有等价的闸门（见 §8.3） |

## 2. 分层架构（语言无关）

```
┌──────────────────────────────────────────────────────────────────┐
│ 表示层（平台 GUI：窗口 / 菜单 / 列表 / 编辑器 / 结果表 / 终端视图）  │
│  只读应用状态、只发用户意图；不含业务规则                          │
└───────────────▲───────────────────────────┬──────────────────────┘
                │ 状态通知                   │ 用户命令
┌───────────────┴───────────────────────────▼──────────────────────┐
│ 应用状态层（连接 / 页签 / 结果 / 上下文 / 历史 / 服务缓存 / 任务）  │
│  唯一状态源；UI 线程亲和；一个页签一个执行任务                      │
└───────────────▲───────────────────────────┬──────────────────────┘
                │ 事件流 / 元数据             │ SQL 文本
┌───────────────┴───────────┐  ┌────────────▼──────────────────────┐
│ 协议层（驱动契约）          │  │ 方言层（SQLDialect 契约）          │
│  connect/execute/cancel/事务│  │  库列表 / 引用 / 分页 / 事务 / 类型名│
└───────────────▲───────────┘  └────────────┬──────────────────────┘
                │                            │
┌───────────────┴────────────────────────────▼──────────────────────┐
│ 服务层：元数据枚举（对象树）、结果格式化、导出、语句拆分              │
└───────────────▲───────────────────────────────────────────────────┘
                │
┌───────────────┴───────────────────────────────────────────────────┐
│ 领域工具层：词法分析 / 静态检查 / 格式化 / 补全 / 设计令牌 /         │
│ 本地化 / 智能体治理（闸门 / 护栏 / 审批 / 审计 / 配额）/ 归档 / 记忆  │
│  —— **纯逻辑，无 GUI、无网络副作用、可单测**                        │
└───────────────────────────────────────────────────────────────────┘
```

**平台适配点只有三处**（其余全部应当是共享契约或纯逻辑）：
1. **GUI 框架**：macOS = SwiftUI + AppKit 桥接（§8.1）；**另一平台（Windows）= WPF**（§8.5.1，由该侧自定）；**Linux 自用第三端 = 由公司环境选定**（GTK / Qt / 其它）。
2. **系统能力**：凭据库、目录授权、剪贴板、字体与输入法、进程与 PTY、外部程序调用。
3. **打包与分发**：macOS = `.app` + 签名 / 公证；**Windows = MSIX（签名）+ 便携 zip**（§8.5.1）；**Linux 自用第三端 = 发行包**（deb / rpm / AppImage…）。

> **纪律**：任何"新功能"若必须落在适配层，说明它要么是系统能力（登记到 §4），
> 要么是设计漏了（应当回到领域层实现）。

## 3. 【契约】平台适配层契约（跨平台不变量）

本节是**各端必须一致**的部分。另一平台（Windows，§8.5）与 Linux 自用第三端（§8.6）照此实现即可，不必读 Swift 代码；
macOS 侧现有的 Swift 类型是它的一个实现（对应关系见 §8.1）。

### 3.1 连接配置（ConnectionConfig）

**凭据存储的两种形态（NFR-SEC-01 / R-38）**：Core 只声明 `SecretStore` 协议，实现可换 ——
| 形态 | 实现 | 何时用 | 安全边界 |
|---|---|---|---|
| 系统凭据存储 | `Platform/macOS/KeychainSecretStore.swift` | **发布形态**（默认目标） | 由操作系统保护；代价是每次访问要人工授权 |
| 项目内文件 | `Core/LocalSecretStore.swift`（`FileSecretStore` / `FileAgentKeyStore`） | **开发 / 验收形态** | MD5 派生密钥做 XOR 流 —— **是混淆不是加密**：防「翻开文件看到明文」与误提交，不防拿到代码的人；文件 0600 且不入库 |

切换只改 `AppState` 里的一行注入。**契约不变**：密码不落配置文件、重启后可恢复、可被明确清除、不进错误日志。

**位置（实测踩过后写死）**：文件形态**按候选列表解析**（`DOYAH_SECRETS_DIR` → 工程根 `.secrets/` → 应用数据目录 `.secrets/`），**读时按序回退、写时镜像到所有可写候选**。原因是两种构建能读的位置不同 —— 非沙箱（开发 / CLI）读项目内那份，**沙箱构建只能读容器内那份**；只认一个位置时，沙箱版就会报「读取密码失败」（2026-09-23 实测）。`DoyahCLI secret --file <path>` 用于**逐文件**验证与排障（多候选下，回退会让「读到了」变成假证据）。


| 字段 | 语义 | 要求 |
|---|---|---|
| `id` | 稳定标识（UUID） | 配置文件里的主键；改名不改 id |
| `name` | 展示名 | 允许重名；UI 需消歧 |
| `dbType` | 数据库类型枚举 | 至少 `postgresql` / `gbase8a`（`mysql` 见 FR-DRV-09） |
| `host` / `port` / `username` / `database` | 连接参数 | 端口按类型给默认值（PG 5432 / GBase 5258 / MySQL 3306） |
| `sslMode` | SSL 模式枚举 | PG 六档（disable / allow / prefer / require / verify-ca / verify-full）；GBase 默认 disable |
| `timeout` | 连接超时（秒） | 默认 5，可配置 1–60 |
| `schemaVersion` | 配置格式版本 | 为将来迁移预留（FR-CONN-10） |

**不变量**：
- **配置文件绝不包含密码**（NFR-SEC-02）；凭据按平台存系统凭据库（§4 P-02）。
- 配置写入必须**原子**（不产生半截文件），损坏时给可读错误、不静默清空（NFR-REL-03/04）。

### 3.2 驱动契约（DatabaseService）

| 方法 | 语义 |
|---|---|
| `connect() → ServerInfo` | 建立连接；`ServerInfo` 含版本、当前库、当前用户 |
| `disconnect()` | 关闭连接；**必须可重入** |
| `execute(sql, options) → 事件流` | 流式暴露执行过程（§3.3） |
| `cancel()` | 请求**服务端**中断当前语句（不是只停本地消费） |
| `beginTransaction()` / `commit()` / `rollback()` | 事务控制 |

**不变量（每条都可作为跨平台验收点）**：
1. **取消必须同时作用于两处**：① 中断本地消费；② 请求服务端中断。
   只做①是**缺陷**（评审 R-29：剩余语句会照旧执行）。
2. **取消必须可达**：拿不到服务端会话标识时要给出可读状态或退化为"断开连接"，
   **不得静默无操作**（评审 R-30）。
3. **一条语句的影响行数只报告一次**（评审 R-32：不得既随结果集又单独报告）。
4. **截断必须可见**：命中行数上限时结果需带 `isTruncated` 标记（评审 R-31）。
5. 每条语句的执行**恰好**产生一组事件，顺序见 §3.3；异常路径也必须收尾。
6. 驱动不得吞错：错误要带可读原因与错误码（§6）。

### 3.3 执行事件模型（QueryEvent）

```
.started(index)                  每条语句开始（index 从 0 递增）
.resultSet(QueryResult)          有结果集时（列元数据 + 行 + 可选影响行数）
.affectedRows(count)             DML 影响行数（与 .resultSet 二选一，见 §3.2 不变量 3）
.notice(message)                 服务端通知 / 警告（可 0..n 次）
.finished(QuerySummary)          全部结束（语句数 + 总耗时），恰好一次
```

**不变量**：`.started(i)` 之后才会出现该语句的事件；`.finished` 恰好一次且最后；
消费方被取消时，生产方**也必须停止**（§3.2 不变量 1）。

**结局必须可区分**（跨平台统一）：成功 / 失败（带可读原因）/ **被取消** / **被截断**。
"被取消"不得记成"成功"（评审 R-29）。

### 3.4 结果模型（QueryResult / ColumnMeta）

| 形状 | 字段 | 要求 |
|---|---|---|
| `ColumnMeta` | `name` / `typeName` / 可空标记 | `typeName` 用**数据库方言的原名**（不翻译） |
| `QueryResult` | `columns` / `rows: [[String?]]` / `affectedRows?` / `executionTime` / `isTruncated` | `rows` 是**已格式化的展示字符串**，`null` 表示 SQL NULL |
| `QueryOptions` | `maxRows?` / `statementTimeout?` / `fetchSize` | **默认值必须给上限**（评审 R-31）；超时未实现视为缺陷 |

**不变量**：
- **单元格格式化在领域层完成**（不是 UI 层）：NULL → `null`；二进制 → 可读占位
  （如 `<binary N bytes>`）；日期 / 时间 / 数值的一致表示。
  这条保证**两个平台看到的同一份数据长得一样**。
- 数值列的可排序性：能解析为数字的列按数值排序（FR-RES-08）。

### 3.5 方言契约（SQLDialect）

必须覆盖：库列表、标识符引用、分页语法、事务语句、类型名映射、表结构查询、
执行计划、会话列表 / 取消 / 终止、权限探测（三态：可 / 不可 / 未知）。

**不变量**：**任何 SQL 文本都不得出现在驱动层或界面层**；
新增数据库类型只加一份方言实现（NFR-MAINT-02）。

### 3.6 元数据与对象树

| 形状 | 字段 | 要求 |
|---|---|---|
| `DatabaseObject` | `id` / `kind` / `name` / `schema?` / `detail?` / `isExpandable` | `kind` 至少含 server / database / schema / table / view / column |
| 层级 | PG：服务器 → 库 → schema → 表 / 视图 → 列；GBase 8a：服务器 → 库 → 表 / 视图 → 列（**无 schema 层**） | 层级差异由方言声明，两平台一致 |

**不变量**：**单层懒加载**（展开才读下一层）；展开状态由界面自维护；
刷新由"元数据版本号"驱动（避免全树重建导致闪烁）。

### 3.7 终端屏幕模型（内嵌终端）

**这份契约是"终端看起来一样"的关键**，与 GUI 框架无关：

| 能力 | 要求 |
|---|---|
| VT 子集 | 光标移动 / 擦除 / 插入删除行与字符 / 滚动区域 / SGR（16 色 + 256 色 + 真彩）/ DECSC·DECRC / 延迟换行 |
| 宽字符 | 中日韩占 2 格，右半格标记为"续格"；**绘制必须按格定位**（不得靠字体前进宽度累加） |
| 回滚缓冲 | 上限与行为固定（当前 2000 行）；提供"视口偏移"读取 |
| 备用屏 | `?1049` / `?47`：保存并恢复主屏与光标；**备用屏上滚屏不得灌入回滚区** |
| 输入 | 控制键 / 方向键 / 功能键 → 固定字节序列；**可打印输入必须走输入法通道**（IME 组字） |
| 选择与复制 | 选区按格吸附（宽字符整字选中）、行尾裁剪、反向拖动一致 |
| 窗口尺寸 | 尺寸变化 → 通知子进程（POSIX: `TIOCSWINSZ` → SIGWINCH） |

### 3.8 工作区（用户自选目录）

**不变量**：
1. 目录必须**由用户选择**产生（不得硬编码路径）；授权凭据可持久化（机制按平台，§4 P-03）。
2. 文件树**单层懒加载**；忽略名单（构建产物 / 依赖 / 版本库元数据）；
   **符号链接只显示不跟随**。
3. **路径包含判定按路径分量比较**，不得用字符串前缀（`/ws-evil` 不是 `/ws` 的子路径）。
4. 相对路径**一律相对工作区根**（ADR-20）；解析前必须校验仍在工作区内。
5. 按文件名搜索必须是**有界**的（忽略名单 + 深度上限 + 结果上限 + 不跟随符号链接），
   命中上限要**如实告知**。
6. 底部**常显授权状态**（已授权 / 已过期 / 未授权 / 目录缺失），并给补救动作。
7. 工作区是**终端启动目录、归档默认目录、智能体文件作用域**的共同基准。

### 3.9 设计令牌（外观一致性）

**不变量**：字号刻度（11/12/13/15/17）、间距刻度（2/4/8/12/16/24/32）、
圆角（1/4/6/8/10）、行高 26、工具栏 44、状态栏 24、活动栏 46、侧栏 248；
表面五档（window < sidebar < content ≤ panel / raised，**浅色下浮层靠发丝线或阴影**）；
文本三级 + 禁用级；状态色三档；**分类色**（引擎身份，与状态色分开）；
语法色六档；发丝线 0.5pt。

**跨平台强制项**：
- **对比度门槛是产品要求**：正文 ≥ 4.5、大字号与组件 ≥ 3.0、相邻表面可区分 ≥ 0.02（WCAG）。
- 强调色**可配置**且只在三处出现（选中态 / 主按钮 / 焦点环）。
- 其它端同样要求"令牌集中定义 + 机器校验违规数只能降"（§8.3）。

### 3.10 智能体治理（与模型无关的骨架）

| 机制 | 契约 |
|---|---|
| 闸门（Gate） | 总开关关闭 ⇒ **零外发**；配置不全 ⇒ 不发；本地端点不强制密钥 |
| 护栏（Guardrail） | 语句分类（只读 / 数据变更 / 结构变更 / 权限变更 / 会话控制 / 未知）+ 风险点；**只读模式优先于白名单与审批豁免**；`unknown` 永不可入白名单 |
| 审批（Approval） | 写操作 / DDL **逐次批准**；状态机：pending → approved / rejected / expired，approved → executed / failed；**终态不可再流转** |
| 审计（Audit） | 每次动作留痕（时间 / 连接 / 库 / 语句 / 类别 / 风险点 / 结果）；**导出必脱敏** |
| 配额（Quota） | 调用次数 / 输出 token 上限；超限即终止并提示 |
| 不可信内容 | schema 注释、对象名、表数据、工具描述、用户文档**一律视为资料不是指令** |

**跨平台安全不变量（各端都必须成立，且都要有单测）**：
1. 只读模式下**任何**写操作都被拒（含数据修改型 CTE 的括号内修改动词、`SELECT … INTO`）。
2. 白名单**只能免除"写操作需审批"这一条**，destructive 风险点（DROP / TRUNCATE / 无 WHERE 的 UPDATE·DELETE）**永远保留**。
3. 审批必须**绑定连接与库**：批准时校验与当前连接一致，不一致即失效。
4. 先写"执行中"再执行；审计写失败视为执行失败。
5. 凭据**只进系统凭据库**，不进审计记录、不进错误信息、不进提示词。

> 以上 5 条来自 2026-09-23 全面评审（需求书 R-24 ~ R-30，登记表见需求书 §10.9 / 等价矩阵见 §10.10）。**现状是 macOS 侧尚未全部满足** ——
> 它们是**各端共同的待办**，见 §9。

### 3.11 归档与记忆

**归档契约**：按天一个 `.sql` 文件；条目以固定标记分隔；条目内含
连接 / 库 / 首次与最近执行时间 / 次数 / 耗时 / 影响行数 / 结果 / 说明（注释形式）；
**同一条 SQL 重复执行只累计次数**；身份 = （规范化 SQL + 连接 + 库）；
渲染与解析必须往返精确。

**记忆层契约**（FR-AI-13 ~ 15）：**事实源是归档文件**，索引是**纯派生缓存、可重建**；
按连接 / 环境隔离；两级指纹（结构骨架用于聚类、原文用于计数）不混用；
生命周期按类型分；用户可检视 / 可删除 / 可解释。

### 3.12 内嵌浏览器（FR-EDIT-34）

**视图契约**：浏览器是**编辑器区**里的一类页签（与 SQL 页签同级），不是下方面板的一个页签。
因此它必须能与 SQL 页签并排、切换、关闭，并随会话恢复（URL / 标题 / 前进后退历史）。

**行为契约（与实现引擎无关，P-14）**：

| 约束 | 内容 | 为什么 |
|---|---|---|
| 默认不外发 | 新建页签为空白页 + 地址栏，**不加载任何远程内容**；一切导航由用户显式发起 | 与「默认零外发」的既有纪律一致；页签恢复时也不自动重放导航 |
| 出网必留痕 | 每条出网请求（文档 / 子资源 / 下载）写进**统一外发日志**（§3.13） | 浏览器是第一个通用出网入口，不可观测就等于放弃这条承诺 |
| 存储隔离 | **独立** Cookie / 缓存 / 存储目录，不与连接凭据或客户端数据混放 | 网页内容不可信，不能让它碰到数据库凭据 |
| 文件访问 | 下载与本地文件访问沿用**授权目录**模型（§3.8），不静默写盘 | 与 FR-AI-08 同一套授权语义 |
| 不注入能力 | **不向页面注入客户端脚本桥**，网页无法调用数据库能力 | 防"网页 → 本地能力"的越权通道 |
| 引擎可换 | 渲染引擎、Cookie 存储位置、权限提示方式按平台实现 | 见 §4 P-14 |

**实现状态（2026-09-23）**：**契约层已完成** —— `Core/BrowserPage.swift`（`BrowserPage` / `BrowserNavigationPolicy` / `BrowserSession`）+ `Tests/BrowserContractTests.swift`（13 项）；平台引擎适配（`WKWebView`）与页签集成**均已完成**（细节与手工回归清单见 `Docs/design/浏览器页签-设计说明.md`）；**仍待做**：页签会话持久化。**边界**：`WKWebView` 不暴露单个子资源请求，日志按导航级记录。

**平台验收点（两侧都要有）**：默认页签不出网；显式导航产生日志条目且条数与请求类别对应；
关闭浏览器后日志不再增长；删除浏览器数据存储不影响连接与凭据。

### 3.13 统一外发日志（NFR-SEC-08）

**契约**：**所有**离开本机的网络请求写进同一份日志。范围包括：智能体模型调用、内嵌浏览器
导航与子资源、外部程序调用（`pg_dump` / `ssh` 等）、更新检查。

**记录字段（两侧一致）**：时间、目标（主机 / URL 或程序名）、**触发来源**（哪个功能、哪个页签或会话）、
结果（成功 / 失败 / 被闸门拒绝）。可查看、可导出（JSON / CSV，与既有智能体审计日志同格式）、可清空。

**不变量**：

1. **零外发可验证**：关闭智能体、未打开浏览器、未调用外部程序时，日志为空。
2. **不记敏感内容**：不含密钥、不含结果集行数据（与 NFR-SEC-05 同纪律）。
3. **一个写入点**：脱敏与字段形状只在一处实现；各功能不得自行写日志或另建日志文件。
4. **拒绝也留痕**：被闸门拦下的请求同样记一条（"想发但没发出去"和"没想发"是两件事）。

**实现（macOS 侧，2026-09-23）**：`Core/EgressLog.swift`（模型 + actor 存储 + 净化 + 导出）、`EgressRecordingTransport`（装饰 `HTTPTransport`，所有 HTTP 出网自动留痕）、`App/Views/EgressLogSheet.swift`（⇧⌘E 面板）；拒绝路径在 `AgentSQLGenerator` / `DataTaskSpecGenerator` 的 `AgentGate.decide` 判定处记 `denied`。**其余平台按同一契约实现**：记录字段与四条不变量是契约，存储位置与查看入口属实现。

**与既有实现的衔接**：智能体审计日志（`AgentAuditLog`）聚合的是**动作与审批**，
外发日志聚合的是**出网请求**；两者字段有重叠但不合并 —— 一次动作可能产生零次或多次出网请求。

### 3.14 结果区客户端视图（FR-RES-08 / 09 / 10，R-21）

**契约**：结果区提供**客户端**排序、筛选、分页，三者的共同前提必须对用户可见 ——
**它们只作用于已取回的行，不改变服务端返回的数据**。

**状态与行为（两侧一致）**：

| 行为 | 契约 |
|---|---|
| 表头点击 | 升序 → 降序 → **取消**（第三下回到服务端顺序，不是停在降序） |
| 多列排序 | 追加次序键；界面必须能看出**谁是次要键**（表头指示器只表达第一键，不足以表达） |
| 排序语义 | 数字感知（`2 < 10`）、文本自然序（`item2 < item10`）、**稳定**、NULL 位置固定 |
| 加 / 改 / 删筛选条件 | 一律回到第 1 页 |
| 换每页行数 | 回到第 1 页 |
| 页码越界 | **夹取**到有效页（筛掉一半行后不能停在空白页） |
| 换结果集 | 客户端视图状态**归零**（旧条件套到新数据上会被误读成"查询结果不对"） |
| 复制 | 复制的是**当前显示的行**（显示与复制必须同一份，否则分页后会复制到看不见的行） |

**不变量**：

1. **视图层不改数据**：客户端排序 / 筛选 / 分页只决定"显示哪些行"，`QueryResult` 不被改写。
2. **只作用于已加载行这件事可见**（R-21）：做了客户端操作时结果区**常显**已加载行数，
   并提供「用筛选条件生成 WHERE」入口。
3. **不替用户改查询**（R-21 的实现口径）：生成 WHERE 后**只改编辑器文本、绝不自动执行**；
   已有 `WHERE`、多条语句、`UNION`、非查询语句一律**拒绝并说清原因**，不做条件合并。
4. **生成的是近似式**：客户端比较是自然序 / 大小写与变音符不敏感，SQL 无完全对应物，
   因此生成式必须显式标注为近似，不做"等价"承诺。

**实现（macOS 侧，2026-09-23）**：`Core/ResultGridState.swift`（状态机：三段排序循环 / 回第 1 页 / 页码夹取 /
`page(of:)` 一步到位）、`Core/ResultFilterSQL.swift`（条件 → 近似 WHERE，标识符与字面量按 SQL 规则转义）、
`Core/SQLFilterInjection.swift`（轻量词法扫描定位插入点，拿不准就拒绝）、`App/Views/ResultClientViewBar.swift` /
`ResultPagerBar.swift`（筛选条与分页条）、`ResultGrid` 表头接 AppKit 排序指示器。
**其余平台按同一契约实现**：行为表与四条不变量是契约，控件与指示器画法属实现。

### 3.15 事务模式（FR-EXEC-15）

**契约**：提供「自动提交」与「手工事务」两种模式，手工模式下多条语句在**同一事务**内执行，
可整体提交或回滚。事务**属于连接会话**（不是页签）—— 因为同一连接下的多个页签共用一条连接。

**不变量**：

1. **懒开启**：手工模式下第一条语句执行前才发 `BEGIN`；没有语句就没有事务。
2. **失败即封口**：事务内的语句失败或被取消后，事务进入**只能回滚**状态，
   继续执行被客户端拒绝（而不是把服务端的 `current transaction is aborted` 抛给用户）。
3. **不允许静默结束事务**：有进行中的事务时，不允许直接切回自动提交；
   切连接 / 切数据库 / 断开连接时一律**回滚并明确告知**（静默提交是数据事故，静默丢弃是欺骗）。
4. **命令失败即事务结束**：`COMMIT` / `ROLLBACK` 失败（连接断、延迟约束冲突）时，
   事务在服务端已结束 —— 状态必须回到「无事务」，绝不显示成「已提交」。
5. **状态常显**：事务进行中与失败态必须在界面上**一直可见**（含已执行语句条数），
   不能让用户「忘掉一个未提交的事务」。

**实现（macOS 侧，2026-09-23）**：`Core/TransactionSession.swift`（状态机，16 项单测）、
`AppState.transactionSessions`（按「连接 + 数据库」归属）、`App/Views/TransactionControl.swift`（工具栏控件与徽标）。
**已知边界**：手工模式下手写 `BEGIN` / `COMMIT` 会让状态机与真实连接状态漂移（见需求书 R-39），
按钮是可靠路径。**其余平台按同一契约实现**：五条不变量是契约，控件形态属实现。

### 3.16 查询记忆层与补全策略（FR-AI-13）

**契约**：从**已归档的 `.sql` 文件**（FR-EDIT-31）派生「我跑过什么」的记忆，并在编辑器里给出
**基于本人历史**的补全。**事实源是归档文件，索引是纯派生缓存** —— 删掉索引即可重建，
不丢任何数据；因此**不引入侧车日志**，也就不存在「文件和日志谁是真相」的一致性问题。

**不变量**：

1. **索引无隐藏状态**：只有归档文件能影响索引内容。同一目录重建两次结果逐字一致；
   把归档整体搬到新目录，索引等价（这是「纯派生」的可证伪判据，不能只写在注释里）。
2. **按连接隔离**：记忆的键是**连接名**；生产库的记忆绝不流进测试库的候选（双向都要成立）。
3. **结构骨架归一必须保留标识符**：字符串字面量 → `'?'`、数字 → `?`、空白折叠、大小写归一，
   但 `FROM orders` 与 `FROM customers` **必须是不同骨架** —— 归一化的松紧决定了补全是「懂我」还是「张冠李戴」。
4. **补全顺序不可漂移**：方言候选（关键字 + 内置函数）在**前**，记忆在**后**；
   记忆**只在有前缀时出现**，且**方言填满候选时不塞记忆**（记忆是补充，不许顶掉关键字）。
   同一前缀两次调用的顺序必须完全相同（前缀 > 词首 > 子串，同档按次数 / 最近 / 文本）。
5. **补全是替换半个词，不是灌文本**：超过 500 字符的 SQL 不参与补全（仍是记忆，只是不进候选列表）。
6. **记忆里不含结果集行数据**：归档只存 SQL 与元信息（耗时 / 影响行数 / 成功与否 / 备注），
   记忆出口的键只有 `sql` / `score` / `runs` —— **结构上就没有承载行数据的地方**（NFR-SEC-05 同纪律）。
7. **全程本地、纯统计**：不触网、不依赖模型端点（D1 不阻塞本项）。

**实现（macOS 侧，2026-09-23）**：`Core/QueryMemory.swift`（索引 / 指纹 / 打分，16 项单测）、
`Core/QueryCompletion.swift`（候选合并策略，15 项单测）、CLI `memory --dir … [--completion]` 与 `archive-add`、
App 侧 `AppState.queryMemoryIndex`（**后台重建**：解析不上主线程；失败退回空索引且不弹任何东西）
+ `SQLEditorView` → `SQLCompleter` → `QueryCompletion` 的补全回调接线。
目录解析（「单独指定 > 跟随工作区」）与归档写入**共用同一个入口**（`AppState.openQueriesDirectory`），
避免同一判定写两遍。**平台一致性**：不变量 1~7 与 Core 两个类型是跨平台契约（Core 侧无平台 API）；
索引的重建时机、候选列表控件形态属实现差异。**验证**：`Scripts/test-query-memory.sh`（退出码 0，
含补全链路的顺序 / 空前缀 / 超长句 / 隔离 / JSON 出口核对）。

### 3.17 工作区原生体验（FR-EDIT-35 / 36）

**不变量**

1. **工作区与数据库各有一套页签**，互不干扰；切活动栏只切"看哪一套"，不销毁任何一边的状态。
   页签集合的规则是**纯函数**（`WorkspaceTabSet`）：同一文件**复用页签**（开成两个、改一边存另一边
   是这类编辑器最经典的丢改动方式）、Home 页签**关不掉**（它是工作区的落脚点）、
   关闭后选中项落到右边、`dirty` 由"当前内容 vs 已保存内容"**比出来**而不是维护一个布尔。
2. **一个语言的语法只有一份定义**（`CodeSyntax`）：着色与补全共用关键字 / 内置名 / 注释与字符串形态 /
   大小写规则。SQL 那份的关键字与内置函数**取自方言**（`SQLDialect.keywords` / `builtinFunctions`），
   与 SQL 编辑器的着色是同一份来源。
3. **词法器只做词法**（`CodeLexer`）：字符串与注释里的关键字不得着色；SQL 的 `''` 转义、
   Python 三引号串、HTML 标签与正文边界、CSS 属性名（后面紧跟冒号）各自分开处理。
   **任何零宽匹配路径必须强制前进一格** —— 这一条是踩出来的（`@` 曾是"标识符起始"却不在"标识符体内"，
   于是 `@media` 消费 0 个字符、把进程挂死）。
4. **补全候选顺序固定**：关键字 → 片段 → 内置 → 文档词；**空前缀不给候选**（打开就刷屏不是补全）；
   同一 label 只出现一次；上限 20；文档词只取**真实标识符**（注释与字符串里的词不进候选）。
5. **片段插入后的光标落点由 Core 约定**（`CodeCompletion.caretOffset`：空行缩进处 → 标签之间 →
   末尾空对 → 末尾），界面只负责搬；换算要考虑 UTF-16 与字符的差别。
6. **打开文件三道闸**：目录不当文件打开；超过大小上限（2 MB）**如实拒绝**；含 NUL 字节视为二进制
   **如实拒绝**。编码按既有 `TextFileDecoder` 判决，非 UTF-8 时如实提示。
7. **不静默丢改动**：有未保存改动的页签**不关**，并说明"先保存（⌘S）再关闭"。
8. **"最近打开"只记路径与时间**（文件 20 / 工作区 10），**不存文件内容**；读坏 / 写坏都要如实说。
9. **语言集合可扩展**：新增语言只加 `CodeSyntax` 一份定义 + `TextLanguage` 的扩展名 / 文件名表，
   词法器与界面不动。当前覆盖 **JS / TS / SQL / HTML / CSS / JSON / Python**（+ YAML / Shell / Markdown 轻量），
   C / C++ / Java 等按同一入口追加。
10. **行号列的口径（三端必须一致）**：**一个逻辑行一个号** —— 软换行（自动折行）出来的续行**不补号**；
   行终止符按 AppKit 认的那一套（`\n` / `\r\n` / `\r` / `U+2028` / `U+2029` / `U+0085`）；
   **末尾是行终止符 ⇒ 多出一行空行**（各端的编辑器都为它留一个可停光标的位置，少给号就会出现
   「光标停在那行、左边没号」）；位置单位是 **UTF-16 单元**（与各端排版接口的字符索引同一单位；
   按「字符」数在含 emoji 的行上会偏）。各端怎么画（列宽、配色、是否显示分隔线）允许不同，
   **这三条必须一致** —— 否则同一个文件在两端显示的行号不同。

### 3.18 SSH 隧道（FR-CONN-18）

**目的**：数据库只在内网可达时，由跳板机转发。产品把隧道内置，用户只在连接表单里填跳板机。

**十条不变量**

1. **改写只作用于副本**：`SSHTunnelEndpoint.rewrite(configuration:localPort:)` 返回副本，
   `localPort == nil` 时**原样返回** —— 直连路径一个字节都不动；配置里永远保存用户填的真实地址。
2. **只监听 `127.0.0.1`**（不是 `0.0.0.0`）：隧道是本机到跳板机的通道，绝不能顺手把内网库暴露给局域网。
3. **隧道按连接缓存、按连接收场**：同一连接的多个库共用一条隧道（跳板机常限制并发通道）；
   收场发生在连接失效的唯一入口（`invalidateService`）与删除连接处，不留孤儿 `ssh` 进程占着本地端口。
4. **死掉的隧道不留在缓存里**：非 `ready` 状态一律收掉重建 —— 否则下一次连接会悄悄走一条不存在的转发。
5. **起不来就不连**：隧道失败时**不绕过隧道直连数据库**（那会给出误导性的网络错误），如实报隧道失败原因。
6. **绝不碰用户的 SSH 状态**：不动 `~/.ssh/known_hosts`（用我们自己的文件）、不动 ssh-agent（`ForwardAgent=no`）、
   私钥模式 `IdentitiesOnly=yes`（只用指定的那把钥匙）。
7. **口令不进 argv、不进配置**：走 `SSH_ASKPASS`（0700 临时目录 + 0600 文件，握手一结束立刻删），
   与数据库口令**分开存**（键由连接 ID 派生）。威胁模型是「防别的进程顺手看见」，不是「防同一用户」。
8. **参数合法性单一事实来源**：隧道参数的判定并进 `ConnectionConfig.isValid`，表单与模型不各写一套。
9. **沙箱下如实说明不可用**：沙箱子进程继承沙箱、起不了 `ssh`（R-18 / T-38），界面提前告知，不假装能用。
10. **配置必须存得住**：`ConnectionConfig` 有自定义 `init(from:)`（为容忍缺 `schemaVersion` 的老文件），
    因此新增字段**必须在 `CodingKeys` 与解码两侧同时加** —— 漏一处的症状是"配好了、保存成功、重启后没了"
    且**不报任何错**（本项做工时真踩到，靠持久化单测抓出）。

**【macOS】实现映射**：`Core/SSHTunnel.swift`（配置 / 问题枚举 / 参数拼装 / `SSHTunnelEndpoint`）、
`Core/SSHTunnelProcess.swift`（进程与就绪判定）、`Core/SSHTunnelSecrets.swift`（口令键与 `ssh` 可执行文件解析）、
`App/LocalPort.swift`（POSIX 端口探测与分配，App 侧注入 —— Core 不许 import Darwin）、
`App/Views/ConnectionFormView.swift`（隧道一段与「测试隧道」）、`App/AppState.swift`（`ensureTunnel` / 改写 / 收场）；
CLI 侧等价入口是 `doyah tunnel`。**已知边界**：只支持单跳板机（不做 ProxyJump 链 / SOCKS 代理 / 健康检查重连）；
真跳板机上的握手与认证未验（需一台跳板机）。**做工中抓到一个静默丢配置的真缺陷**：`ConnectionConfig` 有自定义
`init(from:)`，加字段却漏加 `CodingKeys` → 隧道配置能存出去、读回来是 nil（症状是"配好了、重启后没了"且不报错），
被新加的持久化单测抓出；已补 `CodingKeys` 与解码，并写成**不变量 10**。**App 侧接线的机器证据**：一次性启动探针
把连接的真实地址写成不可达的 `10.255.255.1:5432`，用替身 `ssh` 真转发到本机库，走 `ensureTunnel` → `ensureService`
这条路 —— 六条判据全过（隧道就绪 / 复用同一条 / 经隧道查到数据 / 服务连的是回环端口而配置仍存真地址 /
收场后缓存清空 / 端口释放），验完探针已删。

### 3.19 多库驱动边界（FR-DRV-09 MySQL，FR-DRV-08 GBase 8a）

**目的**：同一套界面与 Core 语义，接上第二个（第三个）数据库产品。这一层最容易出的问题
不是"连不上"，而是**悄悄不一样**：影响行数算法不同、取消变成了断连、方言文本两套并行维护。

**六条不变量**

1. **协议传输与方言分离**：驱动（`PostgresService` / `MySQLService`）只负责连接、认证、发语句、收结果；
   方言（`SQLDialect`）只负责 SQL 文本与语义判决。**驱动里不出现手写的产品方言 SQL**。
2. **协议实现不自己造**：用成熟的线协议实现（`PostgresNIO` / `MySQLNIO`），**随仓库带走**（`Vendor/`）。
   协议一个字节解错就是"看着成功、数据已错"，而它跨方言共用 —— 方言与产品语义才是我们的资产。
3. **影响行数问服务端要**：MySQL 路径用 `ROW_COUNT()` / `LAST_INSERT_ID()`，不在客户端自己数行
   （触发器、级联、`ON DUPLICATE KEY` 都会让"自己数"给出错数字，而界面显示得很确定）。
4. **取消只断语句、不断连接**：`KILL QUERY <连接号>`（而不是 `KILL`），且**必须在另一条连接上发** ——
   本连接的查询正忙，取消语句只会排在它后面（R-29 / R-30 的判据与 PG 侧共用同一个 `ExecutionRegistry`）。
5. **同族方言共享文本、但不许悄悄漂移**：`MySQLDialect` **组合转发** `GBaseDialect`（冻结纪律下不改既有类型），
   只覆盖"确实不同"的部分（这里是建库权限探测：MySQL 有 `mysql.user`，GBase 没有）；
   两边文本由一致性单测逐条比对，**故意不同**的那处另有专门用例钉住。
6. **能力缺失如实说、不静默降级**：`COPY` 通道不支持就抛"不支持"（不偷偷退回逐条 INSERT）；
   空结果集拿不到列定义这类驱动限制写进已知边界，不假装成"没有结果集"。
7. **同族驱动组合、不复制**：GBase 8a 与 MySQL 的差别只在方言，因此 `GBaseService` **组合**方言可注入的
   `MySQLService`，而不是复制一份 service；**未实测的能力留空**（`sessionMetadataQuery` 默认 nil →
   GBase 显示"影响行数未知"，不用客户端自己数的数字冒充服务端的 —— 那是很确定的错数字）。

**【macOS】实现映射**：`Core/MySQLService.swift`（方言**可注入**）、`Core/MySQLDialect.swift`、
`Core/GBaseService.swift`（组合前者 + `GBaseDialect`）、`Core/DatabaseType.swift`（`mysql` 档）、
`Core/DatabaseService.swift`（工厂）；`Vendor/mysql-nio`（1.9.1）；CLI `doyah mysql`；
验证 `Tests/MySQLDialectTests.swift` + `Scripts/test-mysql-driver.sh`（假服务器真跑线协议）+
`Scripts/test-mysql-real.sh`（真机，待实例）。
**已知边界**：真实 MySQL 实例未验（认证插件 / TLS / 字符集协商 / 多版本窗口）；
空结果集的 SELECT 拿不到列定义。

### 3.20 对话式诊断契约（FR-AI-03）

**目的**：让"模型说的话有依据"成为**代码里的规则**，而不是提示词里的一句请求。

**五条不变量**

1. **证据是一等公民**：`DiagnosisEvidence` 有编号、有可复跑的取证 SQL、有三种必须分得开的状态
   （有行 / 零行 / 根本没取到并写清原因）。**"查到了但没有行"与"没查到"不许混为一谈**。
2. **没取到的证据不能被引用**：引用校验只认已取到的证据 —— 否则模型可以引用一份根本不存在的统计
   来下结论，结论看起来有依据、实际上是空的。
3. **无依据的结论整条拒绝**：解析结果同时给出"采纳的条目"与"被拒绝的条目（含理由）"，
   拒绝要**显式呈现给用户**，不许降级成静默丢弃；认不出的行同样原样留着。
4. **建议 SQL 走同一道审批闸门**：每条建议过 `ExecutionSafety`（与编辑器里敲这条语句同一判据），
   裁决在 Core 里定 —— 界面不许自己判"这条能不能直接跑"。
5. **取证本身不许有副作用**：执行计划**只用 `EXPLAIN`，绝不用 `EXPLAIN ANALYZE`**（后者会真的执行语句）。

**【macOS】实现映射**：`Core/DiagnosisContext.swift`、`Core/DiagnosisAdvice.swift`；
CLI `doyah diagnose`；`Tests/DiagnosisTests.swift`、`Scripts/test-diagnosis.sh`。
**已知边界**：真实模型端点未接（提示词组装与回复解析均已验证）；编辑器界面入口未接；
慢查询统计依赖 `pg_stat_statements`（本机 PG 精简构建没有扩展目录，见 R-42）。

### 3.21 维护任务编排契约（FR-AI-04）

**目的**：让"一句话生成并执行一串维护命令"变成**看得见、逐条批、有上限**的动作。

**六条不变量**

1. **执行入口只收"已批准"的任务**：没有"跳过审批直接跑"的路径 —— 这是类型上的约束，不是纪律口号。
2. **认不出的行原样报出**：维护场景里静默丢一行可能丢掉一个 `DROP`；宁可报"没看懂"。
3. **写操作 / DDL 一律要审批**；只给语句、不改库的（索引建议）不要审批。**只读连接上的写任务直接拒绝，
   且连"批准"都不允许**（与 `ExecutionSafety` 同一条不可绕过的口径）。
4. **高开销限流**：`REINDEX` / 备份 / 恢复默认算高开销，一次计划最多一条；多条需要用户显式放行。
5. **外部程序类任务在沙箱构建下不可执行**（备份 / 恢复走 `pg_dump` / `pg_restore`，R-18），
   且**理由写在任务上** —— 不能等用户点了"执行"才发现。
6. **失败带服务端原话，且失败的任务不会因为再批准一次而复活**。

**【macOS】实现映射**：`Core/MaintenancePlan.swift`；CLI `doyah maintain`；
`Tests/MaintenancePlanTests.swift`、`Scripts/test-maintenance.sh`。
**已知边界**：真实模型端点未接；界面面板与界面内编辑未接；`VACUUM` 系语句是 PG 专属（GBase / MySQL 未验）。

### 3.22 MCP 互操作契约（FR-AI-10）

**目的**：把本客户端的能力以 MCP 暴露出去 / 接上外部 MCP 服务器，同时**不新增任何特权路径**。

**七条不变量**

1. **两个方向共用一套报文**：解析与生成只有一份实现，因此两个方向不可能行为不一致。
2. **未知字段一律保留**：MCP 的 `params` / `result` 是开放的；用强类型会变成"遇到没见过的字段就整条失败"。
   坏报文回 `-32700`、未实现方法回 `-32601`、**协议版本不一致时如实回报我们支持的版本**。
3. **能力从当前连接推导，外部请求改不了**：`hasConnection` / `isReadOnly` / 方言 / 目标由我们填；
   **没有会话就一律拒绝**（外部调用绝不另开连接）。
4. **只读连接上的写语句被拒，且"已批准"也救不回来**（与 `ExecutionSafety` 同一条不可绕过的口径）。
5. **审批按"次"算，不按工具名算**：写语句即使在只读工具里也要审批；批准单位是"这一次调用"
   （工具名 + 参数指纹）。**这条是脚本实测抓出来的**：按工具名放行时，"允许 `query_sql`"等于允许任何语句。
6. **刻意不暴露的能力**：连接管理与口令、备份恢复与维护任务（走 FR-AI-04 的审批链）、工作区文件读写（会绕过目录授权）。
7. **每一次调用进审计**（对端 / 工具 / 参数摘要 / 结果），可落盘 JSONL。
8. **界面审批走两侧共用的文件队列**：需要审批的调用**入队并等**，界面写决定，server 读决定再执行。
   **批准只对这一次有效**（指纹级）；**没人确认时默认不放行**（超时 = 拒绝 —— 这是最危险的默认值）；
   配了队列之后**一个请求只回一个响应**（先回"需要审批"再回结果会违反 JSON-RPC，
   客户端会把真结果丢掉；这个缺陷是脚本抓出来的）。

**【macOS】实现映射**：`Core/MCPProtocol.swift`、`Core/MCPToolCatalog.swift`、`Core/MCPSession.swift`（server 与 host 两个会话）；
CLI `doyah mcp serve` / `doyah mcp call`；`Tests/MCPTests.swift`、`Scripts/test-mcp.sh`。
**已知边界**：界面入口未接（审批目前只能在命令行表达）；host 方向是批处理式最小闭环；资源只做了 `resources/list`。

**装配形态（待拍板 Q20）**

| 选项 | 形态 | 优点 | 代价（本工程口径） |
|---|---|---|---|
| **A** | **同进程内模块**（编译期链接） | ① 视图直接嵌入（**SwiftUI 的 `View` 出不了进程边界**，这一条决定了 A 的压倒性优势）；② 上下文（连接 / 表 / 选中 SQL）是同进程对象，零序列化；③ 调试、单测、门禁都按现有套路；④ **现状就是 A**（`Core/Note*.swift` + `NotesPanel`），迁移成本 ≈ 0；⑤ 启动快、无常驻第二进程 | ① **崩溃域不隔离**：笔记侧挂掉会带走整个 app；② **不能独立发版**：笔记的更新必须跟宿主一起出；③ 越界（引用宿主类型）只能靠**门禁 + 纪律**守，编译器不管；④ 二进制在 macOS / Windows / Linux（自用第三端）上必然含笔记代码（可接受） |
| **B** | **独立进程 + IPC**（XPC / 命名管道） | ① **崩溃域隔离**（笔记进程崩了宿主还活着）；② 可单独升级 / 单独签名；③ 结构上拿不到宿主类型，"不反向依赖"变成**物理事实**而非纪律；④ 可给笔记进程更窄的权限（不联网、不见库） | ① **视图嵌入是硬伤**：跨进程嵌 SwiftUI 需要 remote-view / 自定义 surface，工作量大且体验有损（延迟、输入法、拖放、无障碍都要重做）；② 上下文与**编辑中的正文**都要序列化，交互式编辑的性能与一致性都变复杂；③ 生命周期 / 启动 / 崩溃重启要自己管；④ 词法层复用要么走 IPC 要么复制一份；⑤ 单人对单人项目，**维护成本明显不成比例** |
| **C** | **可卸载组件包** | ① 可显式安装 / 卸载（贴合"生活助手是可选件"的心理）；② 有独立的包与版本号；③ 未来可让另一方独立发布 | ① 需要**包格式 + 版本兼容矩阵 + 签名 / 公证**一整套机制；② **沙箱下"可卸载"实际受限**（组件包通常在 app bundle 内，删它等于改已签名的 app；放外部目录要处理容器可见性）；③ 卸载并不省磁盘、也不提升安全；④ 复杂度接在 A 之上（A 的问题它都有），收益主要是"可分发"，**而在我们的场景里没有第三方来分发** |

**已拍板（2026-09-26，Q20 关闭）：A 同进程内模块**（需求提出者：「那就选 A」）。理由三条：
① 解耦门禁已经存在（`Scripts/check-note-module-isolation.py`，扫 4 个笔记源文件的平台 import 与**数据库侧 / Ultra 侧**类型引用；2026-09-26 L-04 起禁用名单含 `DiagnosisContext` / `MaintenanceTask` 等 Ultra 侧类型，并对账 `Core/` 实际文件），**回归成本最低**；
② **SwiftUI 的视图出不了进程边界** —— B 的"崩溃域隔离"要用重做界面嵌入、序列化上下文与自管进程生命周期来换，**代价与收益不成比例**；
③ C 是在 A 之上再叠一层包格式与版本校验，而"可分发"这个收益在我们场景里**没有第三方来兑现**。
**B 的再议条件**：若将来笔记确实要由另一方独立发版，再评估；届时本节的契约就是迁移起点（边界已经契约化，不是口头约定）。

**Linux 上的笔记：装配，但必须是本地离线实现（2026-09-26 口径变更，原「Linux 不装配」作废）**

1. **装配**：与 macOS / Windows **同一形态**（同进程内模块，见上）—— Linux 目标**引入**笔记源文件，活动栏**出现**入口；

**6. 归属与通道（2026-09-27 需求提出者最终确认）**：**归属与通道（2026-09-27 需求提出者最终确认 —— 更正同日早先「三书推给公司的 Linux 平台负责」的说法）**：**三书继续出**，Linux 相关的需求与契约条文**仍由大河马侧维护**；**大河马与小河马都不实现 Linux 版本**；**三书由需求提出者**手工**带到公司的 Linux 环境（**不在公司电脑上填个人 GitHub 凭据**，无自动拉取）**，据此在其环境内自行开发 Linux 功能（本地离线、数据不外发，只服务需求提出者本人）。**Q35 关闭**：不是「移交第三侧」，而是「两侧不实现、公司环境按三书自行实现」。最终原话：「三书还是继续出，只是不在大河马和小河马实现Linux版本，公司的Linux环境只从GitHub上拉取三书来对其进行开发Doyah Studio和Notes功能，Retro没有」。

### 3.24 许可与版本呈现（FR-LIC-01~04，待登记）

**目标**：同一个 macOS app，按 license 里的**能力位**（工作区 / 数据库 / 笔记）呈现不同版本；
付费墙在许可证，**不在界面屏蔽**。

**四条不变量**

1. **离线可校验**：许可证是**签名的**文件，校验只在本机做 —— 本地优先的产品不该因为校验而依赖网络。
2. **按能力位呈现**：未授权的区**不出现**（不是灰掉诱导）；「关于」显示版本与到期时间。
3. **不锁数据**：到期或校验失败只**降级到 Standard**，用户的笔记始终可读可导出。
   **设备配额**：默认 **5 台**（备用能力，`FR-LIC-05`）——**只用随机设备标识，不做硬件指纹**，可**释放设备**（换机不锁）；
   配额清单要么放**签名许可证**（加设备＝换一张签名许可证），要么放**服务端账号**；
   **纯离线统计不出设备数**，所以这项能力在账号/云端（M2）之前**只有能力与语义、无法执行**（如实登记）。
4. **不做 DRM**：不联网激活、不混淆、不反调试（ADR-34）——签名挡住"手改许可证"就够了，剩余风险不值得用复杂度换。
5. **一套许可覆盖三个能力位**（**2026-09-26 拍板：Q21 关闭**）：**开发工作区 / 智能数据库助理 / 笔记共用同一份签名许可证** ——
   同一份文件、同一条校验路径、同一个到期时间；**不为笔记插件另立第二套许可**，也不做"插件单独付费 / 单独开关"。
   理由：**许可只能有一个判据**，否则不变量 2（未授权区不出现）会被绕过 —— 两套许可会造出"工具能用、笔记位却失效"这种
   半有效状态，界面还得回答"两个许可哪个说话"，用户与排障都跟着变复杂。
   边界如实写明：**移动端（Doyah Notes 应用）的授权不在这份许可证的管辖内**（属另一条产品线）；本工程只负责桌面三块。
   与 ADR-36 配套。

**实现落点（建议）**：`Core/License.swift`（解析 / 能力位 / 到期判断，纯逻辑可单测）+
签名校验用 `swift-crypto`（跨平台，不引 CryptoKit，Core 平台中立性不受影响）。

**两个可观测点（排障用，不是功能）**：① 启动时往 `startup.log` 记一行
`许可证：<档位> / 活动栏 [<可见项>] / <状态句>` —— 用户报"某个区不见了"时先看它；
② `DOYAH_LICENSE_PATH` 可把"从哪儿读"指到别处（同 `DOYAH_SSH_BINARY` / `DOYAH_LICENSE_PUBLIC_KEY`），
验收三档时用它就不必动用户数据目录里那份真许可证。

**界面呈现契约（2026-09-25 落地，`FR-LIC-02` 的界面那一半）**

5. **"哪一个区可见"只有一处判据**：`LicensePresentation.activityItems(for:)` 按能力位过滤
   `ActivityBarItem.allCases`，顺序沿用声明顺序（"谁在上面"只有一处定义）。
   界面（活动栏 / 「显示」菜单 / 无障碍标签）都读它，**不得各自再写一遍判断**。
6. **未授权区必须结构性不可达，而不是"画的时候跳过"**：`AppState.selectedActivityItem` 是
   `private(set)`，唯一写入口是 `selectActivityItem(_:)`，入口里过一遍
   `LicensePresentation.resolveSelection`。历史偏好（`ui.activityBarItem`）、快捷键、
   命令面板、对象树命令、工作区首页的"去数据库"、笔记入口——**所有路径都收在这一个入口上**，
   于是"Standard 下工作区与数据库不可达"是可被单测穷举的性质，而不是靠每个新入口自觉。
7. **快捷键序号按"当前可见项"算**：`ActivityBarItem.shortcutIndex(of:in:)`。
   Standard 下笔记就是 ⌘1，Ultra 下它才是 ⌘3 —— 序号写死在项上会让用户按 ⌘1 什么也没发生。
8. **「版本与许可证」页回答四件事**（少一件用户就得猜）：我现在是什么版 / 为什么是这一版
   （有效 · 到期 · 没放 · 坏了 · 签名不对 · 档位不认识）/ 许可证放哪儿、怎么让它不重启生效
   （路径 + 打开文件夹 + 重新读取）/ **别的版能做什么**（Q11：逐条列出）。
   只列**比当前更高**的档位（对 Ultra 列下面两档、对 Pro 列 Standard 都是噪音或向下推销）。
   这一条**修正** v3.211 记的"不显示被屏蔽的功能"——Q11 的口径是**逐条列出**。
9. **降级原因在界面上说，不静默降级**：状态句由界面按当前语言取键拼（`AppState.licenseSummary`），
   不直接用 Core 的 `LicenseLoader.summary`（那个固定中文，用在界面上就是"切到英文还是中文"，
   即 R-45 那一类）。Core 那份留给日志 / CLI。
10. **笔记是活动栏上的一栏，不是浮层**：`case notes`；Standard 下整个应用就是它
    （侧栏 = 笔记列表、正文 = 编辑器）。原 `isNotesPresented` 弹窗随之下线 ——
    两个入口并存会让人不确定"关掉窗口笔记还在不在"。

### 3.25 【契约】笔记存储分层（FR-PLUG-08，2026-09-27 拍板）

**分工一句话**：**主存进库，原始数据与附件留在文件系统。**

| 项 | 决定 |
|---|---|
| **进 SQLite** | 笔记元数据 / 正文 / 标签 / 时间线 / **附件索引（只存路径）**；将来复盘侧的成交明细、周报索引同引擎（同库另表或另库） |
| **不进 SQLite** | **原始行情快照仍 CSV/JSON**（可读、可 diff、喂脚本与 AI 零摩擦）；**附件二进制**走文件系统；导出产物照旧落盘 |
| **引擎接入** | **vendored `sqlite3.c`（公有领域）+ 本工程薄封装**，沿用 `Vendor/` 依赖纪律（版本可复现、离线可构建、许可留档、**Core 保持平台中立**）；**不引第三方 Swift 封装** |

**为什么不用现成的 Swift 封装**（与「Windows 与 macOS 完全一致」直接相关）：GRDB 官方支持 Apple 平台 + Linux，**Windows 仍是社区探索**；SwiftData / Core Data 为 **Apple 独占**。三者都会把「Windows 版」变成二等公民。

**四条不变量**

1. **事务与 WAL**：崩溃不坏库（替代现在「原子写 + 坏文件回退」的手写保障）。
2. **附件永不进 BLOB**：库里只存路径，字节在盘上（否则库体积与备份一起恶化）。
3. **迁移走脚本**：schema 版本位 + 幂等迁移；沿用既有纪律 —— 一次性迁移、旧文件留档改名（`*.migrated`，绝不覆盖已有备份）。
4. **备份 = 快照**：`VACUUM INTO` / `.backup` 产出的单文件快照才交给云同步；**不把活跃库文件直接同步**。

**验收（可机械判定）**：存储层增删改查与检索单测全绿；迁移脚本一次性跑通且可重跑；抽样断言「附件路径在库、字节在盘」；`verify-all` 第 10 项（笔记解耦与装配）保持全绿。

**入口层（`FR-PLUG-08` 第 3 批，2026-09-27 落地）**：界面与 CLI 走**唯一入口** `Core/NoteStorage/NoteLibrary.swift`（actor）。
「读一份列表 / 存一条 / 删一条 / 搜一下 / 快照」五件事收在一处 —— `notes.sqlite3` 的连接、schema 幂等升级、
事务（一次写 = 一个事务：本体 + 标签 + 时间线）全在这一层之下，界面与 CLI 不各自持有引擎。
**`loadOutcome()`（`.absent` / `.loaded` / `.unreadable`）与旧引擎同名同义** —— 换引擎**不改界面行为**，
调用点只换一行；`upsert` 保 `createdAt`（创建时间是事实）、`delete` 走库、`search` 返回所走路线。
**旧格式只作为迁移的输入留档**：`notes.json` 由 `NoteLibraryMigration` 一次性搬进库（幂等：库已在就一个字节不动），
搬完改名 `notes.json.migrated`；打开笔记这条路上先跑**数据家迁移**（§3.13 / FR-PLUG-04）再跑**引擎迁移**，两条都幂等。
**口径写成机械判据**：`App/` 与 `CLI/` 里出现旧引擎的构造点（`NoteStore(` / `NoteStore.defaultStore(`）即报红
（`Tests/NoteLibraryTests.swift` 的源树判据；改动前是 App 5 处 + CLI 2 处，现在是 0）。
**Linux 半边**按 §3.23 第 6 条（2026-09-27 平台口径）**不属本侧实现** —— 本侧交付 = 三书口径（`FR-PLUG-05`）+ 门禁（L-22）。

### 3.25.1 【契约】schema v1 与迁移 / 快照的形状（2026-09-27 落地）

**表**（版本号写在 `PRAGMA user_version`，打开即幂等升级；比代码更新的库**拒绝打开**，不拿旧代码改新库）：

| 表 | 装什么 | 关键约束 |
|---|---|---|
| `note` | 元数据 + 正文 + 来源 + 时间 | `uuid` 唯一；`contains_row_data` 带 `CHECK (0,1)`（**含行数据标记是永久留痕**）；时间存 **REAL 秒**（不是 ISO 字符串 —— 排序是数值语义） |
| `note_tag` | 标签 | 主键 `(note_id, tag)` ⇒ 集合语义；`ON DELETE CASCADE` |
| `note_timeline` | 时间线（流水，只增不改） | `ON DELETE CASCADE` |
| `note_attachment` | **附件索引（只存路径）** | `ON DELETE CASCADE`；字节永不进 BLOB |
| `note_fts` | 全文索引（FTS5，外部内容表 `content='note'`） | **`tokenize='trigram'`**（默认 `unicode61` 不切中文）；三个触发器与 `note` 同步 |

**两条容易漏的**：① **`PRAGMA foreign_keys = ON` 必须每连接设**（SQLite 默认关着，不开则级联删除是装饰品 —— 判据是单测**真查孤儿行**）；② **`NULL` 与空串不是一回事**（"没有连接来源" vs "来源名为空"）。

**检索口径**：查询串 **≥3 字**走 FTS5/trigram；**1~2 字中文**（很常见）trigram 切不出 token ⇒ 走子串兜底，并且**把所走路线返回给调用方**（别把"分词器不切中文"说成"没找到"）。

**迁移（`notes.json` → `notes.sqlite3`）**：中间库**先建完整再同卷换名**（中途崩了目标位置什么都没有）+ 读回**逐字段**核对 + 坏文件**原地保留**（`legacyUnreadable`）+ 旧文件改名 `notes.json.migrated`（不删、不覆盖既有备份）+ 覆盖变量生效时让路；交付的中间库切成单文件日志（不带 `-wal` 侧车）。

**快照（备份）**：`wal_checkpoint(TRUNCATE)` → `VACUUM INTO` 到 `.partial` → **读回来核对行数与 `integrity_check`** → 换名；目标已存在**拒绝覆盖**（备份顶掉备份等于把后悔药变成一颗）。

**跨端含义（`§10.9 P-15`）**：表结构与上面这些语义**三端必须一致**；允许不同的是**接入方式**（vendored C 源码 + 各语言薄封装、快照落点、WAL 侧车管理）。

## 6. 并发与生命周期（概念级）

| 对象 | 要求 |
|---|---|
| 应用状态 | **单一线程亲和**（UI 线程持有）；跨线程只传值类型 |
| 驱动连接 | 连接对象**串行化**访问（同一连接不并发执行两条语句） |
| 执行任务 | 每个页签一个任务；页签关闭后结果不再回写（不得下标越界） |
| 元数据加载 | 展开节点触发；同一节点并发展开需去重 |
| 连接去重 | 同一 `(连接, 库)` 的并发建连请求共享同一结果（成功与失败都要清理登记） |
| 大结果解码 | **不得在 UI 线程**（否则界面卡死） |
| 归档写入 | **串行化**（两次执行几乎同时结束时"读-改-写"会互相覆盖） |

**取消语义（契约）**：① 中断本地消费；② 请求服务端中断；③ 两者互不影响；
④ 取消后界面必须显示"已取消"、历史 / 归档必须记"未成功"。

| 层 | 错误形态 | 要求 |
|---|---|---|
| 领域层 | 分类错误（配置 / 连接 / 持久化 / 查询 / 协议），带错误码与可读原因 | 不吞错；必要时附上下文（表名 / 语句片段），**不含凭据** |
| 应用层 | 统一转成用户可读文案 | 状态栏 + 错误详情（可复制） |
| 界面 | 空 / 载入 / 失败三态明确，失败可重试 | 各端一致 |
| 文案 | **全部走文案键** | 单测校验各语言齐备；**领域层不得残留硬编码用户文案**（当前 macOS 侧 Core 仍有 ~302 处，见 §9） |

### 7.1 连接失败的可读化（FR-META-10 / R-46，2026-09-26 收口）

三条口径（都是"实测撞出来的"，不是设计偏好）：

- **驱动给的错误不等于原因，所以要「在能判定的时刻」判定**：Vendor 里的 PostgresNIO 会把
  「主机名解析不了」压成 `PSQLError(code: serverClosedConnection)` 且 **`underlying == nil`**（探针实测）——
  原因在驱动内部就丢了，文案层再怎么写也写不出"解析不了"。因此新增**建连之前的主机名解析检查**
  （`ConnectionFailure.requireResolvableHost`，走 NIO 的解析入口以保持 Core 平台中立；MySQL 侧早就有这道闸）。
  解析失败抛 `HostResolutionFailure`，文案为「主机名解析不了（host:port/库）」+ 建议 + 错误码 `hostUnresolvable`，
  原始串仍留在调试详情里。**同一条事实只写一份文案**：网络层文案分支与前置检查共用 `resolutionDescription`。
- **文案覆盖面必须机械可查**：驱动错误码（从 Vendor 的 `PSQLError.Code.Base` 机械提取）↔ 处置台账
  （`Scripts/connection-failure-dispositions.json`）逐条对账，即闭环**第 14 项**
  `check-connection-failure-coverage.py`。**为什么需要**：驱动升版新增一个码时，`switch` 的 `default:`
  兜底**不会报错、不会崩**，只会让新原因套上最泛的那句话 —— 那是"代码没坏、话指错方向"的退化，
  编译、单测、文档计数都看不见（与 R-46 是同一族）。
- **认不出就不猜（R-60，2026-09-26 第 8 轮收口）**：`switch` 的 `default:` 分支**不再给方向结论**，
  改为 `return nil` —— 认不出是什么原因还硬说「连接数据库失败／确认主机、端口、库名、用户名」，
  是**把猜测当结论**：驱动码里有一族（用户取消 / 我们主动断开 / 协议层 / 参数层 / LISTEN 通道）
  本就不是连接问题，用户按那句话去查网络与口令，方向从头就是错的。改法不是拼 9 句话，而是
  两条结构：
  - **那 9 个码由 `nonConnectionKeys` 表逐码给一句自己的实话**（键就是驱动的码名），
    出口是 `describeNonConnection(_:language:)`，调用方按 `describe(...) ?? describeNonConnection(...)`
    取文案（**顺序不能反**：连接类先说话，中性归因只补空）。文案全部落进语言表
    （`nonConnection*` 18 个键，中英各一份）—— Core 里不再写字面量，R-45 的棘轮数字不动。
  - **`describe` 返回 nil 时不能只剩英文调试串**：CLI / `ErrorPresenter` / 连接表单三处都接上这一档
    （`ErrorPresenter` 还要把原始串留在「技术细节」里，否则 App 在「未知码」这条路上比改动前少给信息）。
  - **真实现场取证**：那 9 个码在真库上触发不了（真库不会在认证阶段发协议外的字节），
    所以用 `Scripts/lib/fake-nonpostgres-server.py` 造一个「不是 PostgreSQL 的对端」——
    驱动报的是 `unexpectedBackendMessage`，旧文案让人去查库名与用户名，真因是
    「对端不是 PostgreSQL / SSL 协商被中间件改写」。这条现场钉在 `test-connection-errors.sh` §7。
  - **「查询被取消」要单独接住**（同一轮实测补上的）：拿 `SELECT pg_cancel_backend(pg_backend_pid())`
    打真库，回来的是 `PSQLError(code: server, serverInfo: [sqlState: 57014, message: "canceling
    statement due to user request", …])` —— 它既不进「连接类」、也不该被当成「SQL 写错」；
    改动前同样被说成「连接失败」，而按新口径（带 SQLSTATE 一律归调用方自己的路）不接住就只剩
    英文调试串。于是把 **`57014` 收进 `nonConnectionSQLStates`（只认这一个**，42P01 那种查询类
    错误一律不抢）。界面上「用户自己取消」那一档由 `CancellationNoise` 先拦下，这一句留给
    **服务端取消**（`statement_timeout` 到点 / 管理员 `pg_cancel_backend`）—— 那正是会弹给用户的一档。
    同时**把 CLI 的「查询失败」路径接上同一条链**（`describe(...) ?? describeNonConnection(...) ??
    简要信息`）—— 否则这条口径在命令行程序里永远走不到，成了「没人调用的好话」。现场钉在 §8。
- **兜底与出口都必须机械可查**（闭环第 14 项同步扩**四条**判据）：兜底分支的第一条语句必须是
  `return nil`；台账标「中性归因」的码必须在 `nonConnectionKeys` 里点名、且 `neutralKey`
  在语言表里对得上；台账 `neutralFallback` 登记的每个调用方都必须真的调了出口；
  **SQLSTATE 那一档要看两处**——`nonConnectionSQLStates` 名单里必须有它，且那段函数必须真的读这份名单
  （只看名单 → 清空名单能骗过门禁；只看函数 → 登记等于没生效）。
  **为什么要机械查**：这些都是"代码没坏、话指错方向"式的退化 —— 编译、单测、文档计数全看不见。

#### 8.3.2 「跳过」不是「通过」（平台不适用项的处置口径，L-33，2026-09-27）

`Scripts/verify-all.sh` 的十八项里，**第 1 项（Core 单测）与第 11 项（打包 `.app`）是 macOS 专属** ——
两者都要 Xcode 工具链（`DEVELOPER_DIR` → `/Applications/Xcode.app/Contents/Developer`）。
这两项在非 macOS 机器上原先以「命令 / 路径不存在」**硬失败**：看起来是门禁红了，其实只是平台不适用
（对侧逐项实测见 §8.5.6-4）。现在的口径：

- **平台声明**：`DOYAH_PLATFORM=macos|windows|linux` 显式声明平台；缺省按 `uname -s` 推断。
- **按平台跳过 + 提示**：非 macOS 时，第 1 / 11 项打印「跳过（平台不适用：`PLATFORM=…`）」并指向本节与 §8.5.3，
  **不再硬失败**；其余十六项该跑的一项不少（第 2 / 3 / 6 项是**静态扫描** `.swift` 源码，不依赖工具链，故不跳过）。
- **跳过 ≠ 通过**：收尾行如实写「十八项中跑 N 项、跳过 M 项」，**跳过项逐条列出** ——
  不允许把「没跑」说成「过了」，也不允许静默通过（这是本题的要点：等价物可以缺席，但缺席必须可见）。
- **`--require-all`**：令**跳过即红**（主开发机上自我证明 / CI 用）；不带该参数时跳过只出提示，不影响退出码。
- **文档缺失的两种语义**（作用于第 4 项）：**默认清单里不存在** → 跳过并高声提示（有 5 份文档被 `.gitignore`
  排除 —— `兼容性矩阵` / `GBase-技术验证` / `测试用例` / `发布方案` / `手工验收运行手册`，只在 macOS 主开发机上，
  任何干净克隆与另一平台都没有）；**显式点名**的文件不存在 → **判红**；`--require-all` → 判红；
  **`Docs/需求规范书.md`（文档单一来源）缺失始终判红**。跳过只覆盖「整份文档在不在」——
  文档一旦存在，它的表格 / 派生数字 / 版本号判据一条都不放宽。
- **边界（如实写）**：本节写的是**本侧入口如何跨平台不误报**、以及**另一平台必须有哪些项**；
  `verify-all.ps1` 本体由 Windows 侧落地（§8.5.3 是其登记），本侧不给 PowerShell 实现，也不代跑。
- **证据（第 29 轮实测）**：`Scripts/check-doc-tables.py --self-test` 四例（干净克隆缺 5 份 → 跳过 + exit 0 /
  `--require-all` 判红 / 显式点名判红 / 真仓库 11 份全在且无跳过行，末例核对真仓库逐字节未变）；
  `DOYAH_PLATFORM=windows bash Scripts/verify-all.sh` = **跑 15 项、跳过 2 项、exit 0**；
  `... --require-all` = **exit 1**（跳过即红）。

#### 8.5.1 技术栈与工程结构（本侧决策，2026-09-27）

| 层 | macOS 侧（现有，§8.1）| **Windows 侧（本节）** |

#### 8.5.2 平台适配点落地（对应 §2 的三处适配点）

1. **GUI 框架**：WPF —— 菜单 / 快捷键按 Windows 宿主约定（`P-19`）；结果网格、对象树、终端视图各自独立视图，沿用 §3.9 的设计令牌取值。
2. **系统能力**：
   - **凭据存储 = Windows 凭据管理器**（Generic 类型，目标名 `doyah-studio/<连接ID>`，`advapi32!CredReadW/CredWriteW` P/Invoke，零第三方依赖）。语义对齐 §3.1：不落配置文件、重启可恢复、可被明确清除、不进错误信息与日志（`P-17` 之外的差异不生造）。
   - **目录授权 = 用户自选目录 + NTFS 权限**（Windows 无沙箱等价物）：等价验收点 = 未授权目录的读写必须失败且给出可读原因（`P-18`）。

   - **进程与 PTY = ConPTY**（`CreatePseudoConsole`，Windows 10 1809+）跑 `pwsh` / `cmd`，对齐 §3.7 终端屏幕模型（`P-17`）；外部程序一律 `Process.Start(UseShellExecute = false)`，不经 shell 拼接。
