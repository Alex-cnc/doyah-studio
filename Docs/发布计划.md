## 1. 口径（三条不变量）

1. **自用版**：交付物 = 能装能跑的本机 `.app`（首次打开右键「打开」）；不签名、不公证、不分发。**2026-09-29 拍板：交付物 = 非沙箱 ad-hoc 包**（需求提出者原话「**改非沙箱，先验证功能，上架都不知道猴年马月了**」）—— 默认 `./Scripts/build-app.sh` 出的就是**不带 App Sandbox** 的包，沙箱改为**显式开关** `DOYAH_SANDBOX=1`（上架那天才用；两个 entitlements 文件都留在仓里）。三条被沙箱挡住的能力（终端 `⌃C` / 导入导出起 `pg_dump`·`pg_restore` / SSH 隧道起 `ssh`）按新默认可用。
2. **版本 = 收敛工具**（用户原话：「我只是想用版本把功能规划起来，现在感觉有点乱，无穷无尽」）⇒ 核心是 **§3 版本地图**：**每条未完成项都必须指派到一个版本格（含「不做」格）**，不许留在「待办池」里；**新需求入队必须同时给出「进哪个版本」**。
3. **达标判据 ≠ 清单清零**：① 该版声明的**使用场景闭环**（§4）；② 机械门禁全绿（`verify-all.sh` 18 项）；③ 自用版加一条 —— **连续用一周无阻塞性缺陷**。

## 4. Alpha 1 的「完整功能」怎么算（场景 + 逐条，而不是条数感觉）

**四个自用场景**（都是你真实用法）：

1. **日常查数**：连库 → 对象树找表 → 写 SQL → 跑 → 看结果 → 复制 / 导出
1.1 **多终端并行**：一个页签跑 `dsh-tui`（长驻），另一个页签执行命令 —— **不许再另开系统终端**
2. **改东西**：改数据（带事务）、改表结构（改列 / 变更集）、导入 CSV / Excel
3. **在终端里干活**：下方面板终端跑 `dsh-tui` 之类（例如写公众号）
4. **换外观**：① **跟随系统**（改系统深浅 → 应用与终端同时跟着变）；② 「外观」里**一键切主题**（科技蓝 / 豆芽绿 / 玫瑰金），切主题**不打回深浅档**、切深浅档**不打乱主题**；③ 深浅两态都过对比度门槛

判定：① 四场景都顺；② 数据库域 + 工作区域 🟡 **逐条落定**（能机器验的补证据；不能的进「Alpha 1 不含」清单）；③ `verify-all.sh` 18 项绿；④ `.app` 实测可装可跑。

## 5. 冻结与交付规则（每个 alpha 的交付纪律 · 2026-10-01 定）

**口径来源**：人类主人 2026-10-01 原话（派活单 `T-20261001-052`，未改写）——「**每个版本完成之后配套输出一份需要人工测试的测试清单，随之冻结版本不做新功能（如果有新增功能则更新需求说明书），只处理alpha版本的bug。完成bug处理之后10月7日出第一个全量功能的beta1版本。**」⇒ 逐条成文如下（**五条**）：

1. **配套产出（人工测试清单）**：每个 alpha 交付时**必须同时交出一份「需要人工测试的测试清单」**。口径 = **只列机器测不了的人工面**（机器能验的写进机械判据，不进本清单）。表列照 alpha 点验清单的 **`怎么点 ｜ 预期（可判定） ｜ 不算过 ｜ 结论 ｜ 理由 · 现象`**。**清单与该 alpha 的包身份绑定**：**版本 / 字节数 / sha256 / 提交号**四项写进清单抬头。**可复用模板 = `Docs/模板-人工测试清单-alpha.md`**（照 `Docs/人工点验-单击清单-macOS-20260927.md` 的列与写法抽出）；**Alpha 2 的清单落点 = `Docs/人工测试清单-alpha2-macOS.md`，出的人 = 本侧（大河马），出的时间 = 与 Alpha 2 包同时（10-02）**。
2. **随之冻结**：该 alpha 一旦交出，**版本冻结、不做新功能**（各交付日 00:00 起只接受**致命缺陷**修复 —— 崩溃 / 数据损坏 / 起不来，其余进下一版）。
