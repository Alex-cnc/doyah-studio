## 1. 口径（这一版最重要的一段）

1. **v1.0 是「自用版」，不是对外发布版** ⇒ 不需要 Developer ID 签名、公证、DMG、分发渠道、账号体系：
   - macOS：`Scripts/build-app.sh` 的 **ad-hoc 签名 + 本机运行**即达标（首次打开按右键「打开」即可）。
   - Notes：**APK 直接装自己手机**即达标；iOS / 鸿蒙**挂起**（不急）。
2. **版本 = 收敛工具，不是功能清单**（用户原话：「我只是想用版本把功能规划起来，现在感觉有点乱，无穷无尽」）⇒ 本表的核心不是日期，而是 **§3 版本地图**：**每一条未完成项都必须指派到某个版本格（或「不做」格）**，**不许留在「待办池」里**。
3. **达标判据 ≠ 清单清零**，而是：① 该版声明的**使用场景闭环**（§4）；② 机械门禁全绿（本侧 `verify-all.sh` 18 项 / Windows 侧闸门 14 项）；③ 自用版额外一条 —— **连续用一周没有阻塞性缺陷**。

## 3. 版本地图（治「无穷无尽」的那张表）

**规则（2026-09-29 起）**
- **每条未完成项必须落在下面某个格子里**（v1.0 / v1.1 / v1.2 / 不做）。
- **新需求进来时，必须同时给出「进哪个版本」**，否则不入队列 —— 这是防止待办池无限膨胀的机械约束。
- **「不做」是正式结论**，不是拖延：写进这里的项，不再出现在日常待办里，也不再占用注意力。
- 52 条 FR 🟡 中，凡「本机可验 + 影响自用场景」的都进 **v1.0**（多数只需一次点验即销账）。

## 4. v1.0 的「能用」怎么算（场景，而不是条数）

按你实际怎么用判定，四件事都顺 = v1.0 达标：

1. **日常查数**：连库 → 对象树找表 → 写 SQL → 跑 → 看结果 → 复制 / 导出
2. **改东西**：改数据（带事务）、改表结构（改列 / 生成变更集）、导入 CSV / Excel
3. **记笔记**：笔记模块里写、搜、留着（本地库、离线）
4. **在终端里干活**：下方面板终端跑 `dsh-tui` 之类（例如写公众号）

判定：**每件事连续做一周不被打断、不心惊** ⇒ 达标。**不要求 52 条 🟡 清零**。

## 5. 版本冻结规则

1. **冻结**：发布日当天 00:00 起 —— 只接受**致命缺陷**修复（崩溃 / 数据损坏 / 起不来）；其余一律进下一版。
2. **解冻**：需需求提出者一句话；本侧不得自行解冻（循环协议红线 14 引用本条）。
3. **发布齐套**：每版齐 **tag + 发布说明 + 「本版不做」清单 + 机械判据**（本侧 18 项 / Windows 侧 14 项）。
4. **顺延**：见 §2 顺延条款。

## 7. 风险与缓冲

1. **瓶颈是点验与环境实例**，不是开发量：实测循环约 15~20 分钟/轮、每轮稳定收一条。
2. **双写撞号**：本侧循环与 Windows 侧同仓并行，按既有「取并集 + 本侧版本号顺延」规则解。
3. **缓冲日**：10-07 白天不动，除非 RC 出事。
4. **最大风险已消除**：签名 / 公证 / 分发从范围内删除（自用口径），原计划里最紧的一天不再存在。
5. **iOS 装机的现实约束（P1 必读）**：用**免费 Apple ID + Xcode 直装**，证书 **7 天有效期** —— 到期需连一次 Mac 重新签名（自用可接受）；要免重签需**付费 Apple Developer 账号（$99/年）**或 TestFlight（同样需付费账号）。**当前按免费路线排期**，若你要免重签，说一声我调整 §6 依赖。
