## 契约性改动的三书同步纪律与 check-doc-sync
主人 2026-11-07 的原话：

> 「前门等所有改动记得要同步到详细设计里去，别事情干完了又不同步三书」

**现状审计（`git log --oneline -12`，2026-11-07 22:2x，含本节所在提交）**：最近 12 个提交里 **6 个碰了
`App/` 或 `Core/`**，其中 **1 个没碰 `Docs/`**（落笔时读数；窗口跟着新提交滑动 —— 本节提交进去后再跑一次
是 5 个碰代码、仍 1 个未碰文档，结论不变）（`check-doc-sync.py --limit 12` 的原文输出）：

```
979569a6  §3.33.4 形制补判据：Σ 行是「Σ ~324 total」…   代码：App/Views/AgentChatChrome.swift
（其余 5 个碰代码的提交都同批碰了 Docs/）
```

**这次审计抓到的第一个坑（如实登记）**：本脚本第一版用 `git show --name-only` 按行读路径，而本仓的
文档全是**中文文件名** —— git 默认把它们转义成 `"Docs/Doyah\344\272\247..."`（带引号 + 八进制），
`startswith("Docs/")` 一条都命中不了 ⇒ **每个提交都被判成「没碰文档」**（实测读数从 1 条待补变成 5 条）。
现在改成 `-z`（NUL 分隔、原始字节），并在 `--self-test` 里加了一份**中文名文档**当夹具锁住这条口径。
这条本身就是「判据假绿」的教科书例子：数字看着合理（5 个），结论全错。

**契约**
1. **凡改契约性行为，必须同批改详设**（同一批提交里出现 `Docs/Doyah产品详细设计说明书-macOS.md` 的改动），
   「先改代码、隔一两个提交再补书」不算 —— 那样 `check-doc-sync` 与人都看不出这一批改了什么。
2. **提交前跑** `python3 Scripts/check-doc-sync.py`（默认看最近 12 个提交，`--limit N` 可调）。
3. **判据只报告不拦截**（`Scripts/verify-all.sh` 第 4 项里以「提示」级接入）：改了代码 ≠ 改了契约性行为，
   硬拦只会逼出 `--no-verify` 与「代码一个提交、文档一个提交」的假同步。
4. **口径写死**：代码面 = `App/` + `Core/`；文档面 = `Docs/`；merge 不计；改名按新路径算；统计的是**提交**不是文件。
5. `--self-test` 5 例（代码未同步文档 / `Core` 也算代码面 / 同批改文档不误判 / 只改文档不误判 / `--limit` 生效）——
   读数为 `✓ check-doc-sync 自检 5 例通过`。

**边界**：它证明不了「文档改得对不对」，只证明「这一批提交里有人碰过文档」。契约是否真被写进详设，
仍然由 §3.37 这种**带判据号的条目**回答 —— 那才是三书同步的实体。

## 5 版本与发布

> 本节 2026-11-10 从《通用开发规范》§3 迁入（人类主人：「版本发布规则这种应该属于项目规范了吧」）。
> 写法按 §5 起的新格式：每条带 **是什么 / 不是什么 / 判据 / 负例**；写法本身由 `Scripts/rule-schema.json` + `Scripts/check-rule-schema.py` 管。

- **版本只写头部**
- **是什么**：活书 `v<冻结段>.NNN`，第三段 = 自冻结起第几次改动，上限 999；改正文就 +1。
- **不是什么**：不是「内容小改可以不升号」；也不是「文档版本行可以另写一个号」—— 头部版本行与「文档版本：」行必须同值。
- **判据**：【机判】`python3 Scripts/check-doc-versions.py`（头部三段式 + 步进 + 两行一致）。
- **负例**：把 Linux 详设的「文档版本：」留着 v1.2.1 而头部写 v1.3.0 ⇒ 必须判红（2026-11-09 真实发生过，六本书同病）。
- **读数口径**：报「头部版本 / 文档版本行」两个值，必须相等。
- **归属**：版本纪律正文；改本条须主人点头。

- **冻结 = 升一段**
- **是什么**：`v1.0.NNN` 定稿冻结 ⇒ 冻结件 `-v1.1-YYYYMMDD.md`，活书转 `v1.1.0` 继续；流水段到 999 即强制冻结，不等发话。
- **不是什么**：不是「冻结完活书接着 v1.0.NNN+1」；冻结件也不许手改（漂移即决策点，问过主人才动）。
- **判据**：【机判】`python3 Scripts/check-doc-versions.py` + `python3 Scripts/freeze-books.py --version vX.Y` 的派生自检 + `Scripts/check-frozen-sync.py`。
- **负例**：活书仍 `v1.0.999` 时直接跳 `v1.2.0`（跳过冻结件）⇒ `check-doc-versions` 必须判红；手改冻结件一行 ⇒ `check-frozen-sync` 必须判红。
- **读数口径**：报「冻结段 / 活书末位 / 冻结件文件名」三项。
- **归属**：版本纪律正文。

- **冻结号 = 软件号（2026-11-08 人类主人令，原话「冻结了四书哪个版本，软件就应该出哪个版本」）**
- **是什么**：三书一单冻结成 `v1.N` ⇒ 软件出 `beta1.N`（marketing `1.N.0`），同一个号，不再两套。
- **不是什么**：不是「活书末位跟软件号同步」—— 软件号只跟**冻结段**，活书末位留给逐次改动；重取同段冻结件不改软件号。
- **判据**：【机判】`python3 Scripts/check-release-freeze-parity.py`（A 段 / B 产物 plist / C 旧段）。
- **负例**：`Docs/frozen/` 最新段是 `v1.3` 而 `release-version.json` 写 `beta1.2` ⇒ 必须判红。
- **读数口径**：报「冻结段 / `release-version.json` / 包名」三项一致。
- **归属**：发布口径；改号须主人点头。

- **macOS 冻结 ⇒ 同日同步 Linux / Windows 详设（2026-11-08 人类主人令）**
- **是什么**：macOS 详设冻结一版，Linux 与 Windows 详设同日跟到同段，便于在公司侧拉最新详设同步开发。
- **不是什么**：不是「Windows 不开发就不用跟」——书跟着走，代码不跟着走（三列分离见概设 §1.4）。
- **判据**：【机判】`python3 Scripts/check-platform-derivation.py`（Linux / Windows 逐节表态）。
- **负例**：拿掉 Windows 详设 §0.2 的一行表态（`§3.1`）⇒ `check-platform-derivation` 判红「已表态 39/40 · 未表态 1 节：3.1」（2026-11-10 实测）；拿掉 Linux 详设的「派生自」声明 ⇒ 判红「缺『派生自 macOS 详设 vX』声明」（实测）。
  **判据边界**（2026-11-10 实测）：把 Linux 的 `派生自 v1.2.0` 改写成 `v1.0.0`（落后两个段），判据**照样绿** —— 它只判「声明在位 + 逐节表态」，**不判派生版本跟没跟到当前段**。原文把「仍派生自 v1.0 ⇒ 必须判红」写成机判负例，属错例，已改正；同段跟版由评审人核。
- **读数口径**：报「macOS 段 / Linux 段 / Windows 段」三项。
- **归属**：跨端同步纪律。

### 5.1 存量条文（格式未改造，逐条改造中；改造前仍有效）

- **活书段的含义**：`v1.N.NNN` 里的 N 对应 beta 序号，NNN 是这个 beta 周期内的第几次改动。
- **自动冻结（2026-11-01 人类主人令）**：`v1.0.NNN` 的流水段到 **999 就不再自增** —— 该段必须先冻结**这一版**（逐字一致：`python3 Scripts/freeze-books.py --version v1.0`），活书随即转下一段 `v1.1.0` 继续；**这两个动作都不等人发话**，是版本号本身触发的。
- **不是什么**：不是「等主人说才冻结」—— 流水段到 999 必须冻结这一版再转下一段，两个动作都不等人发话。
- **判据**：【机判】`python3 Scripts/check-doc-versions.py`（末位上限 999 + 升段须有冻结件）。
- **负例**：活书到 v1.0.999 后继续写 v1.0.1000 ⇒ 必须判红。
- **读数口径**：报「当前末位 / 段 / 冻结件」。
- **归属**：本节。

- **并发写版本号先重读文件**：`Scripts/next-doc-version.py`。
- **不是什么**：不是「凭上次记的号 +1」—— 两进程同时改必撞号。
- **判据**：【机判】`Scripts/next-doc-version.py`（重读文件取 max+1）+ `check-doc-versions.py`（步进校验）。
- **负例**：凭记忆把 v1.3.9 写成 v1.3.10 而文件已是 v1.3.12 ⇒ 必须判红（降号）。
- **读数口径**：报「读到的号 / 写入的号」。
- **归属**：本节。

- **冻结件只能冻结、不许手改**：漂移 40 行 = 决策点，问主人是否冻结，同意才 `Scripts/freeze-books.py --version vX.Y`。
- **不是什么**：不是「改一行也算维护」—— 漂移 40 行才 = 决策点，问主人同意才重取。
- **判据**：【机判】`Scripts/check-frozen-sync.py`（冻结件与活书同段一致）。
- **负例**：直接编辑 `Docs/frozen/*v1.3*.md` 一段正文 ⇒ `check-frozen-sync` 必须判红（2026-11-10 实测：此前该脚本只比漂移、完全不看冻结件被改，已补）。
- **读数口径**：报「冻结件 N 份 / 漂移 M 行」。
- **归属**：本节。
