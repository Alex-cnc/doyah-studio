**三层分工（同一件事该写在哪本书）**
| 层 | 归哪本书 / 哪个仓 | 判法 |
|---|---|---|

| Linux | 装配 + **必须本地离线**（`FR-STD-ALL-PLUG-005`）；**平台设计层不归我们**（公司环境自定栈与打包） | 评审 |

- **能力变 → 跟 Notes 的能力契约；装配与边界变 → 在 Studio 改**：判「这条规则该写进哪本书」只看变更类型（2026-09-26 定）。
- **不是什么**：不是「谁先发现谁改」；也不是「两本都写一份」—— 两本都写必然漂移。
- **判据**：【机判】`python3 Scripts/check-exclusive-sections.py`（越界改独占节即红）；【人判】变更类型归类由本人在提交信息写明。
- **负例**：笔记能力条款直接改进 Studio 概设 §15 而不走 Notes 仓 ⇒ `check-exclusive-sections` 必须判红。
- **读数口径**：报「本轮改动：能力面 N 条 / 装配面 M 条」。
- **归属**：《项目管理规范》§1 三层分工。

- **Linux 口径**：Linux 侧要求与验收条件写到「换台机器照着做就能验收」：本机 SQLite + 零网络出口 + 断网用例（2026-09-27 定）。
- **不是什么**：不是「本机跑得起来就算交付」；也不是「Linux 要我们实现」—— 两侧都不实现，循环不碰这条源码。
- **判据**：【人判】Linux 详设按「换台机器」标准自检，由本人在交接说明逐条列（依赖 / 网络 / 数据路径），接收方按同一标准复验。
- **负例**：【人判】Linux 详设写「依赖系统已装 PostgreSQL」「联网拉模型」⇒ 判错（违反零网络出口 / 本机 SQLite）。
- **读数口径**：报「验收条件 N 条 / 已满足 M 条」。
- **归属**：本文 + Linux 详设；`FR-STD-ALL-PLUG-005`。

- **不可丢的产品口径**：四条已落三书、此处只留结论：主搜索框范围（已打开工作区的文件 + Studio 自带命令）｜ Markdown 与 JSON 各有内置格式化档（不依赖外部工具、不联网）｜ 关闭有未保存改动的页签必弹「保存并关闭 / 不保存」且不阻塞 ｜ 桌面笔记存储统一 SQLite（交换面语言中立 JSON，存储面各端自治）。
- **不是什么**：不是「结论可以自由再解读」—— 四条的真值在三书条文，本文只是索引。
- **判据**：【人判】改这四条任一 ⇒ 必须同批改对应三书条文并指出版本号，由接收方核对两处一致。
- **负例**：【人判】把主搜索框扩大成「全仓检索」而未改需求书 `FR-STD-*` 对应条 ⇒ 判错。
- **读数口径**：报「四条：改动 0 条（应恒为 0，除非同批改三书）」。
- **归属**：三书为真值源，本文为结论索引。

- **交付包口径**：默认出**非沙箱**包；沙箱 = 显式开关 `DOYAH_SANDBOX=1`（上架才用）；两个 entitlements 文件不许删（2026-09-29 定）。
- **不是什么**：不是「沙箱是默认」；也不是「entitlements 用不上可以删」。
- **判据**：【机判】`Scripts/build-app.sh`（默认非沙箱 + entitlements 存在）；`Scripts/check-release-freeze-parity.py`（产物 plist 与冻结段一致）。
- **负例**：`build-app.sh` 默认带 `--sandbox` 或 entitlements 文件缺失 ⇒ 必须判红。

- **判据**：【机判】`Scripts/check-exclusive-sections.py`（越界按归属判）；【人判】任务分配是否写进派单。
- **负例**：把只能在 macOS 构建的 iOS 任务派给 Linux 侧 ⇒ 必须判红（构建不了）。
- **读数口径**：报「任务 N / 归属错 M」。
- **归属**：本节。

- **隔离撤销但红线还在**：Notes 仓的文档与 git 提交信息**不得出现宿主侧产品名**（`Doyah Studio` / `DoyahStudio` / `doyah-studio` / 单独 `Studio`，排除 `DevEco Studio`）；历史提交里的旧字样**不重写**（force push 会砸对侧副本）。
- **不是什么**：不是「隔离撤了就可以互相引用」—— Notes 仓文档与提交信息不许出现宿主侧产品名。
- **判据**：【机判】`Scripts/check-notes-capability-sync.py`（宿主名扫描，能力书已并但扫描逻辑仍适用）+ `check-no-user-data.py`。
- **负例**：notes 仓提交里写「同步到 Doyah Studio 的 Plugins 目录」⇒ 必须判红。
- **读数口径**：报「文件 N / 命中宿主名 M（应 0）」。
- **归属**：本节。

- **恢复备份**：勿把一侧的 `~/.dsh/memories` 覆盖到另一侧 —— 各机记忆各写各的。
- **不是什么**：不是「同步记忆更省事」；也不是「另一个仓可以整目录还原」。
- **判据**：【人判】恢复动作前后 `diff` 两机记忆目录清单，由本人贴出差异；覆盖式操作须先备份并写明范围。
- **负例**：【人判】用 `cp -R` 把 macOS 侧 memories 整体盖到另一侧 ⇒ 判错（另一侧独有记忆即丢）。
- **读数口径**：报「覆盖文件 0 / 新增文件 N」。
- **归属**：本文。

- **目录与轮询**：三仓统一 `platform/<平台>/`；一个目录一名 dev、一名一个独立克隆；轮询 = 3 分钟网格 + 相位（前门 `:00` · 大河马 `:01` · 小河马 `:02`）；`fatshark` 已作废，只留识别。
- **不是什么**：不是「谁空谁上」；相位错位 = 撞车，不是效率问题。
- **判据**：【人判】`ls platform/` + 克隆路径清单由本人贴出；相位按人核对最新一轮时间戳。
- **负例**：【人判】两名 dev 共用一个克隆并同时 rebase ⇒ 判错。
- **读数口径**：报「目录 N 个 / 克隆 N 个 / 相位是否错位」。
- **归属**：本文。

- **主人直接指令 > 三书定稿权 / 平台归属**：主人直接指令优先于定稿权与平台归属，但必须留痕：在改动处或提交信息写 `exclusive-allow：理由`（独占节）或 `contract-change：理由`（契约节），并登记进本件。
- **不是什么**：不是「留痕 = 免责」；也不是「没有指令可以自己豁免」。
- **判据**：【机判】`python3 Scripts/check-exclusive-sections.py`（缺标记的越界即红）；【人判】理由是否成立。
- **负例**：改了独占节但提交信息无 `exclusive-allow` ⇒ 必须判红。
- **读数口径**：报「越界改动 N 处 / 带标记 N 处」。
- **归属**：本文。

- **归口改判必须落判据例外台账**：`Scripts/button-icon-exceptions.json` + `Scripts/check-button-icon-only.py`。
- **不是什么**：不是「口头同意就行」—— 例外必须进 JSON 台账并说明理由。
- **判据**：【机判】`Scripts/button-icon-exceptions.json` + `Scripts/check-button-icon-only.py`。
- **负例**：给某个按钮加文字而不登记例外 ⇒ `check-button-icon-only` 必须判红。
- **读数口径**：报「例外 N 条 / 未登记 M」。
- **归属**：本节。

- **不是什么**：不是「自审 = 免检」—— 门禁照样跑；也不是「结论发长文」。
- **判据**：【人判】交接里自审结论是否一行、是否附门禁读数；接收方核对。
- **负例**：【人判】自审结论贴了 30 行 diff 与路径清单 ⇒ 判错（违反「不贴路径 / 日志 / diff」）。
- **读数口径**：报「自审：通过/不通过 + 一行结论」。
- **归属**：本文。

- **不是什么**：不是「报错像什么就是什么」；也不是「终端通了就说明应用该通」。
- **判据**：【人判】判卡点前必须贴出原始报错字面（不转述）+ 复现命令与输出，由接收方核对字面理由。
- **负例**：【人判】把 `pg_hba` 未放行某库报成「服务器拒绝整机连接」⇒ 判错（217 上真发生过）。
- **读数口径**：报「原始报错字面 / 复现命令 / 结论」三件。
- **归属**：本文。

- **每个版本配套人工测试清单**：每个版本配套人工测试清单（与包身份绑定）；发布即冻结，冻结期只修该版 bug，新增功能先更新需求说明书。
- **不是什么**：不是「清单可以事后补」；也不是「冻结期顺手加个小功能」。
- **判据**：【人判】清单必须写明包名 + 二进制 + sha256，与 `dist/` 实际产物一致，由接收方核对。
- **负例**：【人判】清单只写「beta1.3 主要功能自测通过」而无包身份 ⇒ 判错。
- **读数口径**：报「清单条目 N / 已过 M / 包身份是否绑定」。
- **归属**：本文 + 发布方案。

- **出包按实际交付面**：做完什么写什么；未交付部分移进「本版不做」并写明缺在哪，不许静默略过。
- **不是什么**：不是「没做的就不用写」；也不是「写了等于做了」—— 披露不是结项。
- **判据**：【人判】release notes 逐条对照一单状态（done / 未闭），由接收方抽查三条。
- **负例**：【人判】把已知限制（笔记检索、同步）只写进代码注释而不进 release notes ⇒ 判错。
- **读数口径**：报「交付 N 条 / 本版不做 M 条 / 已知限制 K 条」。
- **归属**：本文。

- **包标签 = 出包序号**：`Scripts/release-version.json` + `Scripts/check-release-version.py`。
- **不是什么**：不是「包名可以自己起」—— 标签与出包号必须一致。
- **判据**：【机判】`Scripts/release-version.json` + `Scripts/check-release-version.py`。
- **负例**：`release-version.json` 写 beta1.3 而 dmg 名写 beta1.2 ⇒ 必须判红。
- **读数口径**：报「标签 / 号 / 包名」三值。
- **归属**：本节。

- **冻结范围只做「必做」那一格**：冻结范围只做「必做」那一格，顺延去处写明（下一版 / 年底 / 不做），宁可顺延不塞半成品；交付日 00:00 起只修致命。
- **不是什么**：不是「临近交付可以加班塞功能」；也不是「顺延可以不写去处」。
- **判据**：【人判】冻结清单里每条顺延项必须带去处，由接收方核对一单。
- **负例**：【人判】冻结前一天把「可选」项改成「必做」并入包 ⇒ 判错。
- **读数口径**：报「必做 N / 顺延 M（各带去处）/ 半成品 0」。
- **归属**：本文。

- **门禁绿才落档、才出包**：`./Scripts/verify-all.sh`。
- **不是什么**：不是「先出包再补门禁」—— 红着出包等于发一个没验过的版本。
- **判据**：【机判】`./Scripts/verify-all.sh` 收尾行 + `Scripts/build-app.sh` 的前置检查。
- **负例**：`verify-all` 有红仍执行 `build-app.sh` ⇒ 必须拒绝出包。

## 契约性改动的三书同步纪律与 check-doc-sync
主人 2026-11-07 的原话：

> 「前门等所有改动记得要同步到详细设计里去，别事情干完了又不同步三书」

**现状审计（`git log --oneline -12`，2026-11-07 22:2x，含本节所在提交）**：最近 12 个提交里 **6 个碰了
`App/` 或 `Core/`**，其中 **1 个没碰 `Docs/`**（落笔时读数；窗口跟着新提交滑动 —— 本节提交进去后再跑一次
是 5 个碰代码、仍 1 个未碰文档，结论不变）（`check-doc-sync.py --limit 12` 的原文输出）：

```
979569a6  §3.33.4 形制补判据：Σ 行是「Σ ~324 total」…   代码：App/Views/AgentChatChrome.swift
（其余 5 个碰代码的提交都同批碰了 Docs/）
```

**这次审计抓到的第一个坑（如实登记）**：本脚本第一版用 `git show --name-only` 按行读路径，而本仓的
文档全是**中文文件名** —— git 默认把它们转义成 `"Docs/Doyah\344\272\247..."`（带引号 + 八进制），
`startswith("Docs/")` 一条都命中不了 ⇒ **每个提交都被判成「没碰文档」**（实测读数从 1 条待补变成 5 条）。
现在改成 `-z`（NUL 分隔、原始字节），并在 `--self-test` 里加了一份**中文名文档**当夹具锁住这条口径。
这条本身就是「判据假绿」的教科书例子：数字看着合理（5 个），结论全错。

**契约**
1. **凡改契约性行为，必须同批改详设**（同一批提交里出现 `Docs/Doyah产品详细设计说明书-macOS.md` 的改动），
   「先改代码、隔一两个提交再补书」不算 —— 那样 `check-doc-sync` 与人都看不出这一批改了什么。
2. **提交前跑** `python3 Scripts/check-doc-sync.py`（默认看最近 12 个提交，`--limit N` 可调）。
3. **判据只报告不拦截**（`Scripts/verify-all.sh` 第 4 项里以「提示」级接入）：改了代码 ≠ 改了契约性行为，
   硬拦只会逼出 `--no-verify` 与「代码一个提交、文档一个提交」的假同步。
4. **口径写死**：代码面 = `App/` + `Core/`；文档面 = `Docs/`；merge 不计；改名按新路径算；统计的是**提交**不是文件。
5. `--self-test` 5 例（代码未同步文档 / `Core` 也算代码面 / 同批改文档不误判 / 只改文档不误判 / `--limit` 生效）——
   读数为 `✓ check-doc-sync 自检 5 例通过`。

**边界**：它证明不了「文档改得对不对」，只证明「这一批提交里有人碰过文档」。契约是否真被写进详设，
仍然由 §3.37 这种**带判据号的条目**回答 —— 那才是三书同步的实体。

## 5 版本与发布

> 本节 2026-11-10 从《通用开发规范》§3 迁入（人类主人：「版本发布规则这种应该属于项目规范了吧」）。
> 写法按 §5 起的新格式：每条带 **是什么 / 不是什么 / 判据 / 负例**；写法本身由 `Scripts/rule-schema.json` + `Scripts/check-rule-schema.py` 管。

- **版本只写头部**
- **是什么**：活书 `v<冻结段>.NNN`，第三段 = 自冻结起第几次改动，上限 999；改正文就 +1。
- **不是什么**：不是「内容小改可以不升号」；也不是「文档版本行可以另写一个号」—— 头部版本行与「文档版本：」行必须同值。
- **判据**：【机判】`python3 Scripts/check-doc-versions.py`（头部三段式 + 步进 + 两行一致）。
- **负例**：把 Linux 详设的「文档版本：」留着 v1.2.1 而头部写 v1.3.0 ⇒ 必须判红（2026-11-09 真实发生过，六本书同病）。
- **读数口径**：报「头部版本 / 文档版本行」两个值，必须相等。
- **归属**：版本纪律正文；改本条须主人点头。

- **冻结 = 升一段**
- **是什么**：`v1.0.NNN` 定稿冻结 ⇒ 冻结件 `-v1.1-YYYYMMDD.md`，活书转 `v1.1.0` 继续；流水段到 999 即强制冻结，不等发话。
- **不是什么**：不是「冻结完活书接着 v1.0.NNN+1」；冻结件也不许手改（漂移即决策点，问过主人才动）。
- **判据**：【机判】`python3 Scripts/check-doc-versions.py` + `python3 Scripts/freeze-books.py --version vX.Y` 的派生自检 + `Scripts/check-frozen-sync.py`。
- **负例**：活书仍 `v1.0.999` 时直接跳 `v1.2.0`（跳过冻结件）⇒ `check-doc-versions` 必须判红；手改冻结件一行 ⇒ `check-frozen-sync` 必须判红。
- **读数口径**：报「冻结段 / 活书末位 / 冻结件文件名」三项。
- **归属**：版本纪律正文。

- **冻结号 = 软件号（2026-11-08 人类主人令，原话「冻结了四书哪个版本，软件就应该出哪个版本」）**
- **是什么**：三书一单冻结成 `v1.N` ⇒ 软件出 `beta1.N`（marketing `1.N.0`），同一个号，不再两套。
- **不是什么**：不是「活书末位跟软件号同步」—— 软件号只跟**冻结段**，活书末位留给逐次改动；重取同段冻结件不改软件号。
- **判据**：【机判】`python3 Scripts/check-release-freeze-parity.py`（A 段 / B 产物 plist / C 旧段）。
- **负例**：`Docs/frozen/` 最新段是 `v1.3` 而 `release-version.json` 写 `beta1.2` ⇒ 必须判红。
- **读数口径**：报「冻结段 / `release-version.json` / 包名」三项一致。
- **归属**：发布口径；改号须主人点头。

- **macOS 冻结 ⇒ 同日同步 Linux / Windows 详设（2026-11-08 人类主人令）**
- **是什么**：macOS 详设冻结一版，Linux 与 Windows 详设同日跟到同段，便于在公司侧拉最新详设同步开发。
- **不是什么**：不是「Windows 不开发就不用跟」——书跟着走，代码不跟着走（三列分离见概设 §1.4）。
- **判据**：【机判】`python3 Scripts/check-platform-derivation.py`（Linux / Windows 逐节表态）。
- **负例**：macOS 详设已 v1.3 而 Linux 详设仍 `派生自 v1.0` ⇒ 必须判红。
- **读数口径**：报「macOS 段 / Linux 段 / Windows 段」三项。
- **归属**：跨端同步纪律。
