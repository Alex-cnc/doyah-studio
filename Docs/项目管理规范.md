### 1.2 三层分工（谁写什么，2026-09-26 定）

| 层 | 归属 | 说明 |
|---|---|---|
| **产品能力定义**（能力清单、决策、里程碑、**数据契约**） | **Doyah Notes 仓** | 全产品唯一来源；Studio 侧**引用不复制** |
| 移动三端的**需求与代码** | **Doyah Notes 仓** | Android / 鸿蒙 归小河马；**iOS 归大河马**（只有 macOS 能构建 iOS） |
| 桌面端（macOS / Windows）的**装配需求与代码** | **Doyah Studio 仓** | 需求 = SRS `FR-STD-ALL-PLUG-001~07`；代码 = `Core/Note*.swift` / `Core/AICapture*.swift` / `App/Views/NotesPanel.swift` |

**判定性问句**：「这条需求写的是**笔记能做什么**，还是**它怎么被装进来**？」—— 前者写在 Notes 仓、后者写在 Studio 仓。
**变更方向**：能力变 → 跟随 Notes 的能力契约；装配与边界变 → 在 Studio 改（`FR-PLUG-*`）。

### 1.3 协作模型（2026-09-27 起：两侧平等 · 按平台分任务 · 信息隔离已撤销）

**2026-09-27 撤销信息隔离**：原设计（小河马只知 Notes/Retro、不知 Studio）**作废** —— 平台制要求它能读到 Studio 的 Windows 侧需求，隔离与平台制不可兼得。
现状：**两侧平等、信息对称**，三书与三仓互相可见；分工边界 = **平台**（谁能构建谁负责），不是项目保密。
**由此派生的门禁**：Notes 仓的**文档与 git 提交信息都不得出现宿主侧产品名**（`Doyah Studio` / `DoyahStudio` / `doyah-studio` / 单独 `Studio`，排除 `DevEco Studio`），由 `tools/logic-check/isolation-check.py` + `tools/hooks/pre-commit` 机械守；历史提交里的旧字样**不重写**（force push 会砸 Windows 侧副本）。
**恢复备份时的红线（保留，理由已变）**：勿把一侧的 `~/.dsh/memories` 覆盖到另一侧 —— 隔离撤销了，但**各机记忆各写各的**（覆盖会抹掉对方的平台约定与本地环境记录）。
