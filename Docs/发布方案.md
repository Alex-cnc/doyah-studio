| `CFBundleIdentifier` | `studio.doyah.DoyahStudio` | 2026-09-21 统一为 `com.vnull.*`；**2026-09-22 随产品改名换成 `studio.doyah.DoyahStudio`**（已配套一次性迁移脚本，连接档与钥匙串均已迁完）；此后发布再变更会丢失钥匙串历史授权，**冻结不得修改** |
| `LSMinimumSystemVersion` | `14.0` | 对应 NFR-COMP-01 |
| 架构 | `arm64`（本机）/ 可加 `x86_64` 通用二进制 | 见 §6 |

**版本号维护位置（2026-09-28 第 68 轮：`L-70` 已收口）**：**发布产物的版本唯一来源 = `Scripts/build-app.sh` 里的 Info.plist 模板**
（`CFBundleShortVersionString` / `CFBundleVersion`，组装 `.app` 时写入）—— 这是 alpha 产物实际携带的值，已用
`PlistBuddy` 实测核对。**同一个值现在必须逐字出现在另外两处**：XcodeGen 源 `project.yml`（应用目标的
`MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`）与它的**生成物** `DoyahStudio.xcodeproj/project.pbxproj`（XcodeGen 2.46 本机实测写入）。
三处 + 台账 `Scripts/release-version.json` 由门禁 **`Scripts/check-release-version.py`** 判住（**闭环第 18 项 · 生成物一致性 · 族 ②**）：
改一处不改另两处、**或改了 `project.yml` 忘记重生成工程**，都判红并点名是哪一处（实测：把工程换回改动前那份 ⇒ 判红 13 条）。
「生成物不许手改」由同一条判据一并判住（应用目标、目标集合、`Sources` 源文件集合、`PRODUCT_BUNDLE_IDENTIFIER` 逐项对账），
台账里还登记了产出它的 **XcodeGen 版本**——换版本重生成要更新台账，否则判红。
**当前的诚实口径（别读过头）**：alpha 产物以 `Scripts/build-app.sh` 为准，**发布链不依赖 Xcode 工程**；版本号这三处一致
已经由门禁保证，但**工程本身尚未通过 `xcodebuild` 构建验证**（实测卡在 `project.yml` 未声明 `Package.swift` 里的
`mysql-nio` / `sqlite3`（`CSQLite3`）/ `swift-crypto`）⇒ 已开队列 **`L-75`**（口径先定：工程算发布链一环，还是只是给人用 IDE 打开的入口）。

**Xcode 工程口径（2026-09-29 落档，队列 `L-75` 已收口）**：**`DoyahStudio.xcodeproj` 不参与发布链** ——
它只是**给人用 IDE 打开的入口**，发布永远走 `Scripts/build-app.sh` 的 ad-hoc 路径。据此：
① **「工程能否 `xcodebuild` 通过」不是发布判据**，发布前检查清单里不以它为准（本文件 §5）；
② 它与本仓 `Package.swift` 的**差异登记为已知边界**（不是待办、也不再作为发布阻塞）——
`project.yml` 的 `DoyahCore` 未声明同目标的 `MySQLNIO`（`Vendor/mysql-nio`）/ `CSQLite3`（`Vendor/sqlite3`）/ `Crypto`（`swift-crypto`），
且目标集合不一致（`Package.swift` **9** 个 vs 工程 **5** 个：`DoyahCLI` / `doyah-license-tool` / `DoyahUISnapshotTests` 不在工程里）；
③ 工程仍受**第 68 轮（`L-70`）**那条判据管：版本号三处逐字一致 + **生成物不许手改**（改 `project.yml` 要重生成）。
**依据**：需求提出者 2026-09-29 指令（本机空转时定案；`Docs/智能体助手-开发spec.md` v1.128 ④；
面向使用者的版本地图 `Docs/发布计划.md` 同口径写作「Xcode 工程口径（L-75，已定：不参与发布链）」）。
**一句话可推翻**：若日后要求工程参与发布链，则须补 `packages:` 声明与目标集合、并把它加进 §5 清单。

## 4. 正式签名与公证流程

### 4.1 前置

| 项 | 要求 |
|---|---|
| Apple Developer Program | 有效账号（付费） |
| 证书 | `Developer ID Application: <团队名> (TEAMID)` |
| 密钥 | 私钥在钥匙串；建议用 App Store Connect API Key（`--key` / `--key-id` / `--issuer`）做公证 |
| 工具 | Xcode 命令行工具（`codesign` / `xcrun notarytool` / `xcrun stapler`） |

### 4.2 步骤

1. 构建 Release 产物：
   ```bash
   ./Scripts/build-app.sh release
   ```
2. 用 Developer ID 重签（替换 ad-hoc 签名）：
   ```bash
   codesign --force --deep --options runtime --timestamp \
     --entitlements App/DoyahStudio.entitlements \
     --sign "Developer ID Application: <团队名> (TEAMID)" \
     dist/DoyahStudio.app
   ```
3. 校验签名与权限：
   ```bash
   codesign --verify --deep --strict --verbose=2 dist/DoyahStudio.app
   codesign -d --entitlements - dist/DoyahStudio.app
   spctl --assess --type execute --verbose=4 dist/DoyahStudio.app
   ```
4. 打包并提交公证（用 zip 提交最稳妥）：
   ```bash
   ditto -c -k --keepParent dist/DoyahStudio.app dist/DoyahStudio-0.1.0.zip
   xcrun notarytool submit dist/DoyahStudio-0.1.0.zip \
     --key AuthKey_XXXX.p8 --key-id <KEYID> --issuer <ISSUER> --wait
   ```
5. 装订公证票据（stapler）：
   ```bash
   xcrun stapler staple dist/DoyahStudio.app
   xcrun stapler validate dist/DoyahStudio.app
   ```
6. 制作 DMG（可选）：
   ```bash
   hdiutil create -volname "DoyahStudio 0.1.0" -srcfolder dist/DoyahStudio.app \
     -ov -format UDZO dist/DoyahStudio-0.1.0.dmg
   codesign --force --timestamp --sign "Developer ID Application: <团队名> (TEAMID)" dist/DoyahStudio-0.1.0.dmg
   xcrun notarytool submit dist/DoyahStudio-0.1.0.dmg --key … --key-id … --issuer … --wait
   xcrun stapler staple dist/DoyahStudio-0.1.0.dmg
   ```

> 注意：换签名身份（ad-hoc → Developer ID）或换 Bundle ID 后，**钥匙串授权与沙箱容器会变化**：用户需要重新输入一次密码，已保存的连接配置会重新落在新的容器目录（当前版本的配置迁移需手工导出 / 重填）。

## 6. 架构与兼容性

| 项 | 方案 |
|---|---|
| 通用二进制 | `swift build --arch arm64 --arch x86_64`（或 Xcode `ARCHS=arm64 x86_64`）后再打包；当前只产出本机架构 |
| 最低系统 | macOS 14.0；如需更低版本需下调 `LSMinimumSystemVersion` 并回归 NFR-COMP-01 |
| 依赖内置 | PostgresNIO 及传递依赖已内置 / 固定版本（`Vendor/` + `Package.resolved`），发布包无需外部依赖 |
| 分发渠道 | 官网 / 内网直链（DMG）；如走 Mac App Store，需去掉 Developer ID 流程，改用 App Store 签名与审核（沙箱权限需最小化，`.sql` 文件通过用户选择持有安全书签） |

| 场景 | 处理 |

## 8. 冻结与交付规则（每个 alpha 的交付纪律 · 2026-10-01 定）

**口径来源**：人类主人 2026-10-01 原话（派活单 `T-20261001-052`，未改写）——「**每个版本完成之后配套输出一份需要人工测试的测试清单，随之冻结版本不做新功能（如果有新增功能则更新需求说明书），只处理alpha版本的bug。完成bug处理之后10月7日出第一个全量功能的beta1版本。**」版本地图（Alpha 1 = Database 09-30 / Alpha 2 = Workspace 10-02 / Alpha 3 = Notes 10-04 / Alpha 4 = Retro 10-06 / Beta 1 = 全量功能 10-07）见 `Docs/发布计划.md`（PC-REL-001）。

1. **配套产出**：每个 alpha 交付时**必须同时交出一份「需要人工测试的测试清单」**（只列机器测不了的人工面）。表列 = **`怎么点 ｜ 预期（可判定） ｜ 不算过 ｜ 结论 ｜ 理由 · 现象`**；**清单与该 alpha 的包身份绑定**（版本 / 字节数 / sha256 / 提交号）。**模板 = `Docs/模板-人工测试清单-alpha.md`**；现成参照 = `Docs/人工点验-单击清单-macOS-*.md`。
2. **随之冻结**：alpha 一交出即**冻结版本、不做新功能**（只接受致命缺陷修复：崩溃 / 数据损坏 / 起不来）。
3. **新增功能的口子**：要加新功能 ⇒ **先更新需求说明书**（`Docs/需求规范书.md`）再动实现；**不许先做后补文档**。
4. **冻结期只修 bug**：只处理该 alpha 版本的 bug。
5. **出口**：bug 处理完 ⇒ **10-07 出第一个全量功能的 Beta 1**。

**排期处置（2026-10-02 跟版 · 派活单 `T-20261001-059` · 人类主人原话「1.Beta 1口径认；2.Alpha 2明天重点收尾工作区功能，不要预砍；3.要建」）**：① **10-07 的 Beta 1 是硬日（定案）** —— 旧标注「可一句推翻」**作废**；某一版出事时 = **当天二次构建 + 按 `Docs/发布计划.md` §3「裁的次序」砍范围**，**不推 Beta 1**；② **不等窗口预砍** —— 每个 alpha 按冻结范围做，**Alpha 2 的重点 = 收尾工作区功能**；「裁的次序」只作**应急口径**留存、本轮**不动用**；③ 各版冻结条数**出包时按实际交付面逐条定**（交付了的留、没交付的移进「本版不做」并写明缺在哪），**不许静默降级**。

**包标签口径（2026-10-02 掰直 · 与小河马侧一致 · 派活单 `T-20261002-009`）**：**「包标签 = `<里程碑>.<子号>`」**（**每个里程碑从 `.0` 起、小改动 +1**；例 `alpha1.0` → `alpha1.1`）；**「Alpha / Beta = 跨仓里程碑」**，里程碑号按人类主人版本地图（`1 = Database` / `2 = Workspace` / `3 = Notes` / `4 = Retro`；**10-07 全量那版 = `beta1.0`**）。**旧句作废并留痕**：~~「包标签 = 出包序号（alpha 阶段 `v0.x.0-alpha.N`）」~~ ⇒ **替换为本行**（依据 = 人类主人 2026-10-02 原话「**如果有小改动，你可以改子版本号，alpha1.0、1.1、1.2**」）。**本侧实际命名**：Alpha 1 = `alpha1.0`（历史 tag `v0.1.0-alpha` / `v0.2.0-alpha` / `v0.3.0-alpha.1` **一律不改名**）· **Alpha 2 = `alpha2.0`（今天 10-02）** · Alpha 3 = `alpha3.0` · Alpha 4 = `alpha4.0` · Beta 1 = `beta1.0`。**产物名怎么落**见本节 + `Docs/发布计划.md` §5「产物名」段：`DoyahStudio-<发布标签>.app`，判据 `Scripts/check-release-version.py`。

**与 §5 的关系**：§5 是**出包前的机械检查清单**（怎么出一个合规的包）；本节是**交付纪律**（每个 alpha 交什么、冻什么、能改什么）。两节都要过。
