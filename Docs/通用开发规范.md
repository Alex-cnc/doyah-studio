# 通用开发规范

## 1 铁律（违反就是返工）
1. **第一刀是纵切，不是横切**：从零起的功能，第一轮只许打通一条最小的端到端路径（存进去 → 拿出来 → 显示出来），哪怕只有一个按钮。
- **不是什么**：不是「先做完数据库层再做后台再做页面」；也不是「每层都完成一点」—— 三层接不起来要等全部写完才暴露。
- **判据**：【人判】交接说明写清本轮走通的那条纵切 + 它的验证命令与原始输出，由接收方核对这份输出；只报「某层完成」= 判错。
- **负例**：【人判】交接写「数据库层已完成、后台待接入」而没有任何一条端到端命令输出 ⇒ 接收方必须退回。
- **读数口径**：报「本轮纵切：命令 + 输出行数」，不报各层完成度。
- **归属**：本节；判据形态（人判）改机判需另立脚本。

2. **状态只在验证之后改**：代码写完不算完成，跑过脚本/单测拿到 `exit 0` 才算，宣称「已完成」必须附那行输出。
- **不是什么**：不是「写完代码就算完成」，也不是「跑了一条命令就算」—— 必须是本条要求的那个验收入口。
- **判据**：【机判】`./Scripts/verify-all.sh`（或只验 Core 的 `verify-core.sh`）收尾行 + `swift test` 的 `Executed N tests`。
- **负例**：改完代码没跑 `verify-all` 就写「已完成」⇒ 交接时无收尾行，接收方判错。
- **读数口径**：报「入口 / 收尾行原文 / 失败数」三件。
- **归属**：本节。

3. **开工先看工作区，提交只加本片文件**：先 `git status --short`，判清归属再动手；提交只 `git add` 本片文件。
- **不是什么**：不是「工作区干净才允许开工」；`git add -A` 一律禁止 —— 它会同时带上本机台账、派生件、私物、别人的未提交改动四类。
- **判据**：【机判】`git status --short` 逐字判归属 + 提交里出现 `.agent/`、`.build/`、`dist/`、`.secrets/`、`_transfer_*`、`*.xcuserstate` 任一即红【脚本：`Scripts/check-path-ownership.py`】；【人判】归属判断由本人在提交信息里写明（残余 / 另一助理 / 主人手改）。
- **负例**：改**对侧子树**（`platform/windows/App/README.md`）⇒ `check-path-ownership` 判红「对侧子树」（2026-11-10 实测）；改共享面（`Docs/`、`Scripts/`）而新增行不注 `shared-surface：理由` ⇒ 判红「共享面未登记」。
  **补正**：原文负例写「`git add -A` 后带上 `.build/derived/x.md`」—— 提交动作不在文件层，`.build/` 又在忽略清单里，`git diff` 根本看不到它；这条判据真正能拦的是「路径归属」，不是「`git add` 的写法」。
- **读数口径**：报「本片文件数 / 未提交残余数」。
- **归属**：本节；白名单另见 `.gitignore`。

4. **提交信息中文写清三件**：改了什么 + 派生出口 + 验证命令与结果，三件缺一即不合格。
- **不是什么**：不是「写了标题就算」；也不是「验证结果是『已跑』」—— 必须贴命令与输出行。
- **判据**：【人判】接收方读 `git log -1`，三件缺一即判错（提交信息是本条唯一被验对象）。
- **负例**：【人判】提交信息只有「修 bug」四个字 ⇒ 判错退回。
- **读数口径**：报「三件：齐/缺哪件」。
- **归属**：本节。

5. **不弹窗要授权**：需要授权或拍板的进队列，能做的一律先做，不许因等确认停工。
- **不是什么**：不是「等主人回话才继续」；也不是「把要授权的事自己做了」—— 前者停工，后者越权。
- **判据**：【机判】`python3 Scripts/check-queue-needs-user.py`（队列行**状态词**在词表内 + `needs-user` 行**点名**到仍待拍的号）；【人判】「这件事该不该问主人」「有没有绕过队列直接做了」由本人判。
  **曾经的错指向**（2026-11-10 实测）：原文写「待拍板项**必须在队列里**」。该脚本只做点名 / 仍未决 / 挂起理由 / 查无此号四件事，**没有第二份来源可比「是否都在队列里」**；队列文件还在 `.gitignore` 内（干净克隆整段跳过）。已按实改口径。
- **负例**：需要主人授权的动作没进队列而直接在提交里做了 ⇒ 判错（人判：`check-queue-needs-user` 判不了「该不该问主人」，它只判队列行的状态词与点名）。
- **读数口径**：报「队列新增 N 条 / 已自行完成 M 条」。
- **归属**：本节（要拍板的事进项目规范的队列，不进本件）。

6. **不擅自改外部状态**：不在别人的数据库上建库建号、不改数据库服务的**认证配置**、不为跑测试在本机装服务 —— 只给命令，不执行。
- **不是什么**：不是「只读操作也要问」（查连接、看报错、跑只读查询都不用授权）；也不是「本地环境随便装」—— 装服务同样算改外部状态。
- **判据**：【人判】执行记录里有没有对他人库 / 系统配置的写操作，由本人自查 + 交接说明注明；判定口径与**具体对象**（哪台机、哪份配置文件）属项目事实，本件不写，也不指节号。
- **负例**：【人判】为跑测试在自己机器上装一个数据库服务，并写进交接当「已就绪」⇒ 判错。
- **读数口径**：报「给出命令 N 条 / 已执行 0 条」。
- **归属**：本节。

7. **删除前确认范围**：「清理掉」先确认是部分文件还是整个目录，范围写进命令再执行。
- **不是什么**：不是「先删再问」；也不是「备份了就能删」—— 备份不是授权。
- **判据**：【人判】删除命令必须带明确路径通配并在此前贴出 `ls` 结果，由本人核对。
- **负例**：【人判】收到「清理掉旧包」直接 `rm -rf dist/` ⇒ 判错（只该删过期的单个文件）。
- **读数口径**：报「待删 N 个 / 实删 N 个 / 保留 N 个」。
- **归属**：本节。

8. **公开仓不留凭据 / 内网地址 / 个人内容**：会随提交进入公开仓的文件里不许有密钥、内网地址、他人的个人内容。
- **不是什么**：不是「删了提交历史就干净」（历史不重写，污染了就得换密钥）；也不是「私有仓可以放」—— 按每个仓自己的公开性判；**哪些仓是公开的属项目事实**，本件不写。
- **判据**：【机判】`python3 Scripts/check-no-user-data.py`（扫待推送文件的凭据/内网地址模式）；`git check-ignore -v <文件>` 确认忽略规则命中。
- **负例**：把 `sk-` + 32 位随机串（示例值不写全，否则自己被判红） 写进**已跟踪**的 `Docs/Doyah产品概要设计说明书.md` ⇒ `check-no-user-data` 必须判红（2026-11-10 实测）。内网地址在该脚本里只到**提示级**，不判红；是否脱敏由人判定夺。
- **读数口径**：报「扫描文件 N / 命中 0」。
- **归属**：本节（铁律 #8）。

9. **文档改动必过门禁**：`./Scripts/verify-all.sh`。
- **不是什么**：不是「审一遍读起来顺就行」—— 门禁清单见本文 §4，不是可选项。
- **判据**：【机判】`./Scripts/verify-all.sh` 文档项（含 `check-doc-versions/tables/layout/numbers/invariants/rule-schema`）；**入场判据 = `Scripts/action-router.py --changed --check --fast`** —— 按改动推断动作、把该动作的必跑判据全跑一遍（2026-11-10 修过一个洞：原来只看暂存区，暂存两个脚本就再也不看工作区，文档那套判据一条没跑，注入重复 `Q37` 仍 rc=0）。
- **负例**：删掉需求书某个 § 标题导致表格列数变化而不跑门禁 ⇒ `check-doc-tables` 必须判红；把 `| **Q37**` 那一行复制一份（同号两行）再跑 `action-router --changed --check --fast` ⇒ 必须 rc=1（2026-11-10 实测）。
- **读数口径**：报「文档项：绿/红 + 失败脚本名」。
- **归属**：本节。

10. **不擅自扩大文档体系**：只认 §2 的三书一单，不许新建第六本书 / 索引 / 台账 / 清单，门禁要的中间产物落 `.build/`。
- **不是什么**：不是「有用就可以新建一本」；也不是「索引不算书」—— 索引/台账一律进 `.build/derived/`。
- **判据**：【机判】`Scripts/check-doc-invariants.py`（`Docs/` 根 16 份白名单）、`check-doc-placement.py`、`check-doc-layout.py`。
- **负例**：在 `Docs/` 根新建《Doyah产品测试台账.md》⇒ `check-doc-invariants` 必须判红。
- **读数口径**：报「Docs 根 N 份 / 越界 M 份」。
- **归属**：本节。

11. **报数报「还剩多少」**：报数报「还剩多少 / 缺在哪」，不报「扫了多少」。
- **不是什么**：不是「已登记 = 已修完」；也不是「覆盖率 96% 可以当结论」。
- **判据**：【人判】结论句里有没有「还剩/缺在哪」，由接收方读（**本条主体是人判**）；【机判】`python3 Scripts/check-doc-numbers.py` 只兜「写死的数字必须与实测一致」。
  **曾经的错指向**（2026-11-10 实测）：原文把 `check-doc-numbers` 当主判据。它只对 `doc-numbers.json` 做台账 ↔ 实测 ↔ 文档三向对账，**不解析结论句** —— 往一单写「还剩 1 条未闭环」它照样绿。
- **负例**：报告写「已完成 391 条中的 379 条」而不说剩 6 条未闭 ⇒ `check-doc-numbers` 判不出，接收方判错（故本条保留人判）。
- **读数口径**：报「总数 / 已闭 / **未闭**」三值，未闭必须点名。
- **归属**：本节（铁律 #11）。

12. **一条拍板只落一处结论**：同一状态散在多本册子只改一处必留矛盾 ⇒ 状态唯一源 = 一单。
- **不是什么**：不是「多写几处更保险」—— 同一状态写两处必然只改一处，留下矛盾。
- **判据**：【机判】`Scripts/check-status-consistency.py`（跨册状态比对）。
- **负例**：在概设正文给已 ✅ 的编号 `FR-STD-ALL-BLD-001` 紧贴一个 ⬜ 括注（编号与全角括号之间不留字、不加反引号）⇒ `check-status-consistency` 判红「括注 ⬜，而台账为 ✅」（2026-11-10 实测）。
  **口径边界**：编号与括号之间夹字、括注里带说明的都不在它判据面（脚本自登记的 ④ 条边界）；需求书索引已不带状态列，原文负例里的「索引标 doing」已不存在。
- **读数口径**：报「状态项 N / 矛盾 M」。
- **归属**：本节。

13. **判据必须声明覆盖范围**：任何「报缺失/报异常」的判据，先说清扫了哪些目标源、哪些没扫。
- **不是什么**：不是「加了 `--json` 就算声明」；覆盖不全时**只许报「未知」，不许报「发现」**。
- **判据**：【人判】脚本 `--json` 输出有没有 `sources` / `uncovered` 两段、交接说明写没写，由评审人核；`uncovered` 非空而结论报「发现」即判错。
  **曾经的错指向**（2026-11-10 实测）：原文标的是**机判**（「`--json` 输出必须含 `sources`/`uncovered` 两段」）。全仓只有 3 个脚本输出 `uncovered`（`check-agents-index` / `check-button-icon-only` / `check-doc-chain`），**没有任何门禁核这条**，也没有 `--json` 契约检查 —— 机判是我自己写上去的声称，已降为人判。
- **负例**：悬空引用检测扫了 48 个源报「23 处异常」，实际漏扫分仓 ⇒ 必须报「未知」而不是「23 处」。
- **读数口径**：报「覆盖 N 源 / 未覆盖 M 源 / 结论：发现｜未知」。
- **归属**：本节（铁律 #13）。

14. **每条判据配一条「必须判红」的负例**：正例只证明能通过，负例才证明真会拦；新写或改写的门禁必须同时交一个故意违规的样本。
- **不是什么**：不是「有单测就算」—— 必须有一条**故意违规**的用例，且它必须判红。
- **判据**：【机判】`python3 Scripts/check-self-test-counts.py`（各门禁自测计数与登记一致）+ `python3 Scripts/test-verify-all-gate.py`；新增门禁无负例用例即红。
- **负例**：把 `self-test-counts.json` 里 `doc-versions` 族的 `cases` 改大 1（`--no-run` 只做台账与锚点对账）⇒ `check-self-test-counts` 判红「写的是 8、台账值是 9」（2026-11-10 实测）；新门禁只写「合规输入 ⇒ 绿」同样被发现负例数 0 即红。
- **读数口径**：报「负例数 / 断言数」两个数，不报「自检通过」。
- **归属**：本节（铁律 #14）。

15. **独立验收层：判「对」的依据不许由被判方提供**：判「对」只认三样：人类主人原话 / 契约条文（三书判据行）/ 外部权威系统（编译器、测试框架、真机）。
- **不是什么**：不是「自己跑通了就算对」；生成 spec/代码/测试的同一个模型不能同时判定它对。
- **判据**：【人判】交接说明里每条「已完成」必须指名依据属于哪一类（口径编号 / 主人原话 / 命令输出）；只写「我验过了」= 判错。
- **负例**：【人判】交接写「已按我最新的理解实现并自测通过」而不指名契约条文号 ⇒ 判错。
- **读数口径**：报「已完成条目数 / 其中指明依据的条数」。
- **归属**：本节（铁律 #15）。

## 2 三书一单（唯一文档体系）
| 位置 | 书 | 写什么 |
|---|---|---|
| ② | 《X产品需求规格说明书》 | 需求条目（编号 / 需求 / 判据 / 优先级 / 状态 / 来源）、验收判据 |
| ③ | 《X产品概要设计说明书》 | 组件表、契约 `P-xx`、ADR、跨端约束；不写实现细节 |
| ④ | 《X产品详细设计说明书-<端>》 | 七件套契约、追溯矩阵、用例定义、实现约束 |

### 2.1 一单：活件、唯一进度源、与详设同构

- **一单只给正在开发的端建、每端一份活件**：`Scripts/check-end-sheets.py`（判据 A2）。
- **不是什么**：不是「每端都先建一份备着」—— 只给正在开发的端建，未开发端不建。
- **判据**：【机判】`Scripts/check-end-sheets.py`（判据 A2）。
- **负例**：给不在允许端清单里的端建一单（`任务清单-Web端.md`）⇒ `check-end-sheets` 判红「不属于允许的端（只许 macOS / Android / Windows / Linux / HarmonyOS / iOS）」（2026-11-10 实测）。
  **补正**：`ALLOWED_SHEETS` 现含六端 ⇒ 原文「给尚未开发的 Windows 端建一单」**不拦**（Windows 有详设与清单）；能拦的是清单外的端。
- **读数口径**：报「一单份数 / 对应端」。
- **归属**：本节。

- **一单永远只有一份活件，不做版本快照**：一单是活件，任何时点只有一份，历史差异看 git，不拍快照。同上。
- **不是什么**：不是「每版留一份做对照」—— 历史看 git，快照只会漂移。
- **判据**：【机判】`Scripts/check-end-sheets.py`（判据 A2）。
- **负例**：在 `Docs/frozen/` 留一份一单快照 ⇒ 必须判红（v1.3 起已删两份历史快照）。
- **读数口径**：报「活件份数（应 1）/ 快照份数（应 0）」。
- **归属**：本节。

- **一单与详设同构、按端分册，只认同端详设活书**：不许引别端详设、不许把 `Docs/frozen/` 冻结件当上游。
- **不是什么**：不是「可以引别端详设」；也不是「冻结件能当上游」。
- **判据**：【机判】`Scripts/check-end-sheets.py`（判据 I）。
- **负例**：macOS 一单引用 Linux 详设 §4 作为落点 ⇒ 必须判红。
- **读数口径**：报「引别端 N 处 / 引冻结件 M 处（应 0）」。
- **归属**：本节。

- **一单是唯一进度源**：日报 / 周报 / 进度表一律从它取，不许另开「里程碑清单」「按平台任务清单」当第二本。
- **不是什么**：不是「日报里另记一份进度」；也不许另开「里程碑清单」当第二本。
- **判据**：【机判】`Scripts/check-plan-coverage.py` + `check-status-consistency.py`；【人判】日报数字是否只从一单取。
- **负例**：在一单 §3 台账里加一条需求书索引没有的编号（`FR-STD-DB-DRV-014`）⇒ `check-plan-coverage` 判红「一单多 1 条」（2026-11-10 实测）；另在别处另写一份进度（周报写「本版进度 80%」）⇒ 脚本判不了，接收方判错。
- **读数口径**：报「未闭条数（只从一单取）」。
- **归属**：本节。

### 2.2 分册只有「截取」，不许按端拆

- **分册的需求书与概设不许按端拆**：分册来自全量书、**只裁剪不增删**（`分册 ⊆ 全量`：分册出现的每个编号都必须能在全量书里找到）；一个产品各一本需求规格 + 一本概要设计，端差异不写进这两本；详设按端一本、从本族基准派生，只改落点与读数口径，不许另起契约正文。
- **不是什么**：不是「各端可以有自己的需求书」—— 需求与概设一个产品各一本，端差异只进详设；也不是「分册可以自己加条文」—— 只能裁，不能增。
- **判据**：【机判】`Scripts/check-book-subset.py`（分册 ⊆ 全量）、`check-platform-derivation.py`（详设逐节表态）。
- **负例**：在分册里写一条全量书没有的正文行 ⇒ `check-book-subset` 判红（2026-11-10 实测）；另建一本《需求规格说明书-<端>》⇒ 判红。
- **读数口径**：报「分册 N 本 / 按端拆 M 本（应 0）/ 全量书里找不到的编号 X（应 0）」。
- **归属**：本节；**哪个产品分几本、哪端归哪个仓属项目事实**，本件不写。

### 2.3 目录与派生件

- **`Docs/` 根只许三书 + 一单**：`README.md`、本件、项目规范、详设模板）；发布说明 / 点验清单 / 功能清单 / 调研书 / 各类记录等过程件一律进 `Docs/archive/`。
- **不是什么**：不是「发布说明也是书」—— 过程件一律进 `Docs/archive/`。
- **判据**：【机判】`Scripts/check-doc-invariants.py`（判据 H，16 份白名单）。
- **负例**：把《发布方案.md》放回 `Docs/` 根 ⇒ 必须判红。
- **读数口径**：报「根目录 N 份 / 白名单外 M 份」。
- **归属**：本节。

- **跨端视图不是书**：平台矩阵 / 按平台清单 / 需求索引 / 追溯表 / 各种台账都是派生件 ⇒ 落 `.build/derived/`，不得与三书并排。
- **不是什么**：不是「矩阵也算文档」—— 派生件落 `.build/derived/`。
- **判据**：【机判】`python3 Scripts/check-doc-invariants.py`（`Docs/` 根 16 份白名单，多一份即红）。
  **曾经的错指向**：本条原写 `check-doc-placement.py`，2026-11-10 实测——它在 `Docs/` 根建 `平台矩阵.md` **照样绿**，那个脚本管的是「书里的内容归位」（详设不许写轮次/版本/日期），不判根目录新建；错指门 = 规矩形同没有。
- **负例**：在 `Docs/` 根建 `平台矩阵.md` ⇒ `check-doc-invariants` 输出 `Docs 根不是 16 份白名单：多 ['平台矩阵.md']`（2026-11-10 实测）。
- **读数口径**：报「派生件 N / 误置 M / 白名单外新增 X」。
- **归属**：本节。

### 2.4 端详设从本族基准派生

- **端详设从本族基准派生，不各写一本**：每本《X产品详细设计说明书-<端>》（本族基准端除外）必须 ① 头部写「派生自 <基准端详设> vX」；② 有一节差异登记，对着**本族基准**详设 §3 的每一节表态 —— `沿用` / `差异` / `不适用`，后两者必须给依据或本端落点；③ 基准详设每新增一节，各端差异登记同批补行，不是等排期。本条判的是「有没有逐节表态」，判不了「表得对不对」——后半由各端测试与骨架判据负责。
- **不是什么**：不是「各端独立写详设」—— 同族其余端从本族基准派生，只改落点与读数口径。
- **判据**：【机判】`Scripts/check-platform-derivation.py`（逐节表态：派生自 / 差异 / 无差异）。
- **负例**：Linux 详设自写一套契约正文而非派生自基准 ⇒ `check-platform-derivation` 判红（逐节表态缺行；2026-11-10 实测）。
- **读数口径**：报「逐节表态 N/M」。
- **归属**：本节。**哪一端是本族基准属项目事实**，本件不指定。

### 2.5 编号与登记

- **编号形制五段式**：`<FR|NFR|AC>-<产品码>-<面>-<域>-<三位序号>`（例 `FR-STD-DB-DRV-005`），`DATA` / `IFACE` 是合法域码。
- **不是什么**：不是「短码也行」；`DATA`/`IFACE` 是合法域码，不许自造。
- **判据**：【机判】`Scripts/check-req-ids.py`。
- **负例**：写 `FR-STD-05`（缺段）或 `FR-STD-DB-01`（两位序号）⇒ `check-req-ids` 必须判红。
- **读数口径**：报「条目数 / 形制不符 M（应 0）」。
- **归属**：本节。

- **风险不是需求**：风险用 `R-001` 形制，`NFR-*-RISK-*` 不许再出现；状态符号不许进需求定义行。
- **不是什么**：不是「风险也可以挂 FR 号」—— 风险用 `R-001`，状态符号不进需求定义行。
- **判据**：【机判】`Scripts/check-req-ids.py` + `check-doc-tables.py`。
- **负例**：写 `NFR-STD-RISK-001` ⇒ 必须判红。
- **读数口径**：报「风险条 N / 冒充需求 M（应 0）」。
- **归属**：本节。

- **新需求登记一次性落齐派生出口**：正文定义行 → 需求索引 → 追溯表 → 平台等价矩阵 → 能力地图，漏一个门禁红。
- **不是什么**：不是「先登记正文，索引回头补」—— 漏一个门禁即红。
- **判据**：【机判】`Scripts/check-req-index.py`、`check-req-ids.py`、`check-plan-coverage.py`、`check-doc-numbers.py`。
- **负例**：需求书加了 `FR-STD-DB-DRV-014` 而需求索引未跟 ⇒ `check-req-index` 必须判红。
- **读数口径**：报「出口 6 项：各绿/红」。
- **归属**：本节。

## 3 计数与留痕
- **不许有「变更记录」文件，书里也不写变更历史**：逐轮改了什么看 git 提交。
- **不是什么**：不是「留个 changelog 更规范」—— 逐轮改动看 git。
- **判据**：【机判】`Scripts/check-doc-versions.py`（出现变更记录节或引用旧变更记录件即红）。
- **负例**：在概设末尾加「## 变更记录」小节 ⇒ 必须判红。
- **读数口径**：报「变更记录节 N / 引用 M（应 0）」。
- **归属**：本节。

- **数字与路径都不写死**：项数 / 例数唯一来源 = `verify-all.sh` 收尾行 + `Scripts/doc-numbers.json` + `Scripts/self-test-counts.json`，需求计数 = `Scripts/report-requirements.py`；计数在仓根调仓内脚本、别仓走各自入口，文档里不写本机绝对路径。
- **不是什么**：不是「写个大概数字方便读」—— 写死的数必然漂移。
- **判据**：【机判】`Scripts/check-doc-numbers.py`（`doc-numbers.json` 对账）+ `check-script-portability.py`（路径）。
- **负例**：把 `core-tests` 写死 5000 而实测 5572 ⇒ `check-doc-numbers` 必须判红。
- **读数口径**：报「受检数字 N / 不符 M」。
- **归属**：本节。

- **版本、冻结、发布规则不在本节**：本件不含版本 / 冻结 / 发布条文，这类规则整条写在项目规范里（2026-11-10 人类主人：「版本发布规则这种应该属于项目规范」）。
- **不是什么**：不是「本节留一份副本更保险」—— 副本必漂移，规则只有项目规范那一份。
- **判据**：【人判】本件不得出现版本 / 冻结 / 发布条文，由评审人核 —— 判「条文写在哪一节」没有脚本；本条与「不引用项目规范」同由 `check-rule-schema` 兜一半（见 §4）。
  **曾经的错指向**（2026-11-10 实测）：原文标的是**机判** `check-rule-schema.py`。该脚本只验六字段在场与机判/人判标记，**不读条文归属** —— 在本节前插一条完整六字段的「冻结 = 升一段」，它 rc=0 照样绿。
- **负例**：在通用规范 §3 重新写一条「冻结 = 升一段」⇒ 判错（人判：评审人核本节有没有版本条文；无脚本可跑，见上「曾经的错指向」）。
- **读数口径**：报「本节版本条文 0 / §5 版本条文 N」。
- **归属**：本节。

## 4 门禁

**条文写作格式（本节总则，2026-11-10 人类主人：「规范本身其实不规范，没写人判还是机判，没写负例判红」）**

规范是行为规格书，条文不写清验收方式就不算规则。每条条文必须带六字段，缺一即不合规：

| 字段 | 写什么 | 省掉的后果 |
|---|---|---|
| **是什么** | 要求一句话，可引用 | 判据无处挂靠 |
| **不是什么** | 边界与常见误读 | 同一句话被两种解读执行 |
| **判据** | 【机判】命令 + `exit 0` ／【人判】谁判 + 判错的表现 | 条文变口号，或人判伪装成机判 |
| **负例** | 故意违规时哪条必须变红 | 判据假绿而无人知 |
| **读数口径** | 报什么、什么算通过 | 报「全绿」而书里三个版本号 |
| **归属** | 规则正文落在哪本哪节、谁有权改 | 两本规范各写一套 |

- **判据两种，必须点名**：【机判】给命令；【人判】写清「谁判 + 判错时他说什么」。只写「评审」不算判据 —— 它既不说谁判，也不说判错什么样。
- **模板的元规范在代码里，不在文档里**：`Scripts/rule-schema.json`（六字段定义）+ `Scripts/check-rule-schema.py`（执行者）。**不另立《模板规范》文档** —— 再套一层就会丢（人类主人：「随着项目深入推进，这些模板的模板也会丢失」）。
- **存量条文允许暂缺字段**：数量记 `Scripts/rule-schema-baseline.json`，**只许降不许升**；新条文一律不许裸奔。
- **不是什么**：不是「新条文也可以先裸奔」—— 只许降不许升。
- **判据**：【机判】`python3 Scripts/check-rule-schema.py`（棘轮：缺字段数不得升、完整数不得降；**单向引用**：本件条文正文出现项目规范的书名或节号即红 —— 只许项目规范引用本件，不许本件指回去）。
- **负例**：新写一条只有「判据：评审」的条文 ⇒ 缺字段数 +1，必须判红。
- **读数口径**：报「条文 N / 完整 M / 缺字段 K」。
- **归属**：本节。

- **负例（本条自己也要有）**：新写一条缺 **负例** 字段的条文 ⇒ `check-rule-schema.py` 必须判红（该例已固化在 `--self-test`）；在本件任一 条文里写「见项目规范的 §5」这类指回 ⇒ 同样判红（2026-11-10 实测，`--self-test` 5/5 含这条正反例）。

## 5 交接
- **接手第一天四步**：① 读 §1 → ② 跑门禁确认基线绿（不绿先修基线，别做功能）→ ③ 从一单挑「不需用户到场」的直接做 → ④ 做完更新文档并提交。
- **不是什么**：不是「先做功能再说」—— 基线不绿先修基线。
- **判据**：【人判】接手人按四步逐条报，接收方核对第②步是否有门禁收尾行。
- **负例**：基线有红却直接开工做功能 ⇒ 判错。
- **读数口径**：报「四步：①②③④ 各绿/红」。
- **归属**：本节。

- **换环境 / 换助理**：本件 + 项目规范整份贴过去即可接手；拍板原话与逐笔记录在 `Docs/archive/过程记录-20261026/`，只在追溯时查。
- **不是什么**：不是「只贴一部分就够」—— 两本规范整份贴过去。
- **判据**：【人判】新接手方能否据这两本独立跑通门禁；跑不通即说明贴得不全。
- **负例**：只贴本件不贴项目规范，接手方找不到版本规则 ⇒ 判错。
- **读数口径**：报「贴上件数 2/2」。
- **归属**：本节。

- **日报三段**：做了什么（对应一单条目号）· 门禁/读数 · 阻塞；数字只从一单取；一单状态词只许 `todo / doing / blocked / done`。
- **不是什么**：不是「写散文进度」—— 三段固定：做了什么 / 门禁读数 / 阻塞；状态词只许四值。
- **判据**：【人判】接收方按三段核对，数字须能指到一单条目号。
- **负例**：日报写「今天进展顺利」而无条目号与读数 ⇒ 判错。
- **读数口径**：报「三段：齐/缺哪段」。
- **归属**：本节。

- **引用他的话与数字必须逐字**：引号内必须是原话与原始数字，不许润色、不许跟着新口径改写。评审。
- **不是什么**：不是「意思对就行」—— 引号内必须是原话，不许跟着新口径改。
- **判据**：【人判】接收方比对原话出处；改口径时引文不动。
- **负例**：把主人原话「冻结了四书哪个版本」润色成「三书」⇒ 判错（已发生过一次，已还原）。
- **读数口径**：报「引文 N 处 / 与原文不符 M（应 0）」。
- **归属**：本节。
