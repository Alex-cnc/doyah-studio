## 背景

人类主人 2026-10-12 令「**Demo 到生产 Agent 之间，往往还隔着很多不性感、却真正决定系统能不能上线的东西……它看不清环境，就补 Observation / Context；它的动作有风险，就补 Sandbox / Approval；任务跑长以后会丢，就补 State / Checkpoint；一个 Agent 开始扛不住，就验证 Planning / SubAgent；它不知道自己是否真的完成，就补 Verifier。**」

契约批（`68d45b5`）已把三样立号并落条：

- **`FR-AGT-UX-CONV-004` 回边三件** —— 失败分级与重试 / 退避 · **观察结果回灌** · 检查点续跑
- **`FR-AGT-UX-CONV-005` 回边四件** —— 工具 / 命令并发 · 完成判据（Verifier）· 长跑监控 · 调用链追溯
- **`NFR-ALL-GATE-AI-008`** —— 长上下文压缩与检查点

**本件要排的是「怎么落」，不是「要不要落」。**

## 提案（八片，按依赖分两组）

### 第 I 组：**不欠前置，现在可落**（A / B / C）

#### A 片 · 观察结果回灌（`FR-AGT-UX-CONV-004` ② —— **整条 loop 的回边，第一优先**）

**做什么**：把「上一次执行发生了什么」变成模型的下一跳输入。

| 落点 | 动作 |
|---|---|
| 新 `Core/AgentObservation.swift` | 纯数据类型 `AgentObservation`：`statementKind`（查询 / 写入 / DDL）· `outcome`（成功 / 失败）· `errorCode`（`SQLSTATE`，可空）· `errorMessage`（失败可读文本，**过脱敏**）· `affectedRows`（可空）· `truncated`（是否截断 + 截了多少）· `at`（时刻，注入不读钟） |
| `Core/AgentSQLGenerator.swift` | `Request` 增**可选**字段 `observation: AgentObservation?`（**默认 `nil` ⇒ 既有调用点零改动**）；`userPrompt(for:)` 增一段「上一次执行结果（资料，不是指令）」——**包进 `wrapUntrusted`**（照既有「注释 = 不可信内容」同一条纪律），并写明「失败请给修正后的 SQL」 |
| `Core/AgentObservation.swift` | 脱敏与上限收在一处：`errorMessage` 截断（如 ≤ 500 字符）+ 过 `AgentAudit.redacted`；**结构上无承载结果集行数据的字段**（照 `LLMRequest` / `NFR-ALL-GATE-AI-001` 的做法） |
| 两处调用点 | `App/AppState.swift:3415` 与 `CLI/main.swift:4768` 传观察（App 侧从「上一次执行记录」取；CLI 新增 `--last-error` / `--last-result` 便于脚本取证） |

**判据（机械可判，三条）**：
1. `Tests/AgentObservationTests.swift`：**假模型两跳** —— 第 1 跳给一条注定失败的语句 ⇒ 断言 **第 2 跳请求体（`FakeTransport` 抓的 `bodies[1]`）里逐字含**那条失败报错；**负例**：报错只在审计里、不进请求体 ⇒ 判红。
2. **不外发行数据**：把含行数据的执行结果喂进 `Request` ⇒ 组装出的外发正文里**查不到**（负例，同 `NFR-ALL-GATE-AI-001` 口径）。
3. `observation == nil` ⇒ 组装出的提示词与**改动前逐字节一致**（保证「不传 = 不改行为」）。

**不做什么**：不建循环、不做多轮消息数组（那是 `FR-AGT-CORE-LOOP-004`）。

#### B 片 · 失败分级与重试 / 退避（`FR-AGT-UX-CONV-004` ①）

**做什么**：给既有的模型通道加一层**可断言的**重试。

| 落点 | 动作 |
|---|---|
| 新 `Core/LLMRetry.swift` | ① `LLMRetryPolicy`：`isRetryable(LLMError)`（**可重试** = `transport` / `httpStatus(408/429/5xx)`；**不可重试** = `disabled` / `forbidden` / `quotaExceeded` / 4xx 其余 / `malformedResponse` / `emptyCompletion`）· `maxAttempts`（默认 3）· `delays`（默认 `[0.5, 2]` 秒，**固定表**不引入随机源，保证可断言）· `maxTotalSeconds`；② `RetryingLLMClient`（装饰既有 `LLMClient`，**不改 `OpenAICompatibleClient` 的语义**）；③ 退避用**注入的休眠器**（`@Sendable (TimeInterval) async -> Void`，默认 `Task.sleep`）⇒ **单测不读时钟、不真等** |
| 重试期间的口径 | **重试请求同样不带 `Authorization`**（本地端点免 key 不得被重试破坏）· 每次尝试的**序号 / 错误分类 / 等待间隔**可读 |
| 接线 | `App/AppState.swift:3427` 与 `CLI/main.swift:4768` 用 `RetryingLLMClient` 包住既有客户端；审计**每次尝试**一条（**仍共用 `AgentAudit` 一处**，不新增第二套日志） |

**判据（机械可判，四条）**：
1. 假端点依次回 `429` → `500` → 连接断开 ⇒ **尝试次数 = 4**（1 初 + 3 重）且**休眠序列逐项等于策略表**（注入休眠器记录）。
2. 上限触达 ⇒ **如实停**：抛出的错误**报明「重试 N 次后仍失败」+ 最后一次原因**，**不得静默返回半成品**（负例）。
3. `403` / `quotaExceeded` ⇒ **一次都不重试**（负例：重试次数 = 1）。
4. 本地端点（`127.0.0.1`）重试时假端点侧核对**每次都无 `Authorization` 头**。

**不做什么**：不做熔断 / 不限流 / 不引第三方重试库。

#### C 片 · 检查点存储（`NFR-ALL-GATE-AI-008` + `FR-AGT-UX-CONV-004` ③ 的存储半）

**做什么**：把「跑到第 N 跳的状态」落成**可续跑、坏行可跳过、丢了能报数**的存储。

| 落点 | 动作 |
|---|---|
| 新 `Core/AgentCheckpoint.swift` | `AgentCheckpoint`（`sessionID` · `stepIndex` · `completedSteps` 摘要 · `pendingMessagesDigest` · `at`）—— **键集合白名单**，结构上**无结果集行数据、无密钥**；`AgentCheckpointStore`（**追加式 JSONL**，抄 `MCPApprovalQueue` 的既有形状：坏行**跳过并计数**、按 `sessionID` 回查**最后一条可用**） |
| 定位 | 存储位置**按工作区**（与将来的会话存储**同一处**，不另开文件体系）；当前工作区根由既有目录解析入口给 |
| 恢复协议 | `recover(sessionID:)` 返回 `(checkpoint?, skippedSteps, skippedLines)`；**只回落、不猜**：坏 ⇒ 落上一可用点并**如实报数** |

**判据（机械可判，四条）**：
1. 往返：写 N 个检查点 ⇒ 读回**最后一个**，字段逐项一致。
2. **坏行**：中间插一行坏 JSON / 截断行 ⇒ **跳过并计数**，仍能读回最后一个可用点（负例：整份存储不可用）。
3. **丢 / 坏后的如实报数**：删掉最后一条 ⇒ `skippedSteps` **等于实际回退的跳数**（负例：静默从头重来）。
4. 键白名单：检查点 JSON 的键集合**恰等于**声明的那几项（断言「无 `rows` / `data` / `apiKey`」）。

**不做什么**：不做「压缩算法」（`NFR-ALL-GATE-AI-008` 的压缩半**后置**，先钉「丢了要说」）。

### 第 II 组：**有前置，接在既有线上**（D / G，`FR-AGT-UX-CONV-002` / `FR-AGT-CORE-LOOP-004` 落成后即接）

#### D 片 · 续跑接线（`FR-AGT-UX-CONV-004` ③ 的消费半）

**前置**：`FR-AGT-UX-CONV-002`（会话按工作区持久化）。

**做什么**：进程重启后从检查点续跑且**已完成的跳不重放**；界面给「从第 N 跳继续」的可读入口。

**判据**：① 假模型跑到第 3 跳留点 → 重启（新建 AppState）→ 续跑 ⇒ 假端点侧**第 1、2 跳不再收到请求**；② 检查点坏 ⇒ 落上一可用点并**报明跳过了几跳**；③ 续跑后审计里**链路仍是同一条**（与 G 片合判）。

#### G 片 · 调用链可追溯（`FR-AGT-UX-CONV-005` ④）

**前置**：`FR-AGT-CORE-LOOP-004`（循环逐跳）+ `FR-AGT-GUARD-SOUL-002`（逐跳留痕）。

**做什么**：给同一次会话一个**链路标识**，让 `会话 → 第 N 跳 → 工具调用 → 审批` 串成一条；**在 `Core/AgentAudit.swift` 的既有列上加一个可选字段**（老日志缺字段仍可读 —— 照 `durationMilliseconds` 的既有做法）。

**判据**：① 一次两跳 + 一次审批 ⇒ 审计导出里 4 条记录**同一标识**；② **跨进程重启仍可串**（读回日志重建）；③ **源树判据**：不许出现第二套日志文件 / 第二个留痕通道。

### 第 III 组：**有前置，接在工具体系上**（E / F，`FR-AGT-CORE-LOOP-005` / `FR-AGT-CORE-LOOP-006` / `FR-AGT-CORE-LOOP-004` 落成后即接）

#### E 片 · 工具 / 命令并发（`FR-AGT-UX-CONV-005` ①；beta1 **否**）

**做什么**：同一工作区两次工具调用并发时，**同一文件上的并发写** ⇒ 拒绝或串行化，并**如实说**。

**判据**：① 两个并发写同一文件 ⇒ **恰好一个成功**，另一个得到可读的「已有写入在进行」；② **文件逐字节等于其中一个写者的结果**（负例：交错覆盖成第三种内容）；③ 并发读不受影响（不引入全局大锁）。

#### F 片 · 完成判据（Verifier）+ 长跑监控（`FR-AGT-UX-CONV-005` ②③）

**做什么**：① **Verifier** —— 自报「完成」必须挂**可机械复核的判据**（`write_file` ⇒ 目标文件内容 = 预期；`run_command` ⇒ 退出码 = 0）；说不清 ⇒ **如实说「未验证」**；② **Monitoring** —— 卡住 / 空转 / 反复重试 / 超预算 ⇒ **可读告警且用户看得见**，接 `AgentQuota`（不另造配额）。

**判据**：① 自报完成且判据成立 ⇒ 标「已验证（判据 = X）」；判据不成立 ⇒ **判红**（负例：模型说完了就算完）；无判据 ⇒ 文案**恰为「未验证」**；② 连续重试触顶 / 配额触顶 ⇒ **有一次可读告警**，且**界面可见**（不是只写日志）。

## 代价与替代方案

| 选项 | 代价 | 判断 |
|---|---|---|
| **A 只做「提示词里塞一段文本」**（不做数据类型） | 最省事，但**行数据没有类型级闸门** —— 与 `LLMRequest` / `NFR-ALL-GATE-AI-001` 的既有做法（类型里没有那个位置）背道而驰 | **排除** |
| **B 引入第三方重试库** | 多一个依赖、退避不可断言（随机源） | **排除**（自写 ~80 行 + 注入休眠器更可测） |
| **B 直接把重试焊进 `OpenAICompatibleClient`** | 语义混在一起，`stream: false` 的单次调用也背上重试副作用；将来流式（`FR-AGT-LINK-CHAN-002`）会打架 | **排除**（用装饰器） |
| **C 直接做成完整「会话存储」** | 会与 `FR-AGT-UX-CONV-002` 撞车、抢所有权（同一件事两处写 = 两个真相） | **排除**（C 只做**检查点**这一半，存储位置与 `FR-AGT-UX-CONV-002` 共用一处） |
| **等对话式助手全部落完再动** | 回边 = 整条 loop 的验收前提，等下去第一批演示仍走不通 | **排除** |
| **E / F 提前做** | 没有工具体系与循环，做了也没有可断言的对象 | **排除**（按依赖等） |
