## 背景

Notes 的 Windows 桌面版此前只有"支持 Windows"这一句，**落点形态未定**：是进 Notes 主仓的 `windows/` 目录、
还是另开一个独立仓。Windows 侧（小河马）在提案清单里把它列为待拍项（U-4，形态 ①/②）。

## 提案

**Windows 桌面版进 Notes 主仓，同仓多端**：

- 目录：主仓内 `windows/`（与 `macos/` 并列），平台互不越界 —— 做法与 Doyah Studio / Doyah Retro 一致
- **共用核心契约**：笔记数据模型、存储分层（本地 SQLite）、导入 / 导出格式、离线口径等，
  **以三书为单一事实源**，两端不得各写一份
- 平台实现差异只落在各自平台目录与 `[独占:windows]` / `[独占:apple]` 节内

## 代价与替代方案

- **代价**：单仓变大、两端构建工具链共存（Gradle / Xcode / MSBuild），CI 要按平台分流
- **被排除**：另开 `doyah-notes-windows` 独立仓 —— 会把"契约单一事实源"拆成两份，
  违背 2026-09-27 的契约层锁定拍板；两端契约漂移的代价远大于单仓的复杂度

## 结论与落笔

- 采纳方：需求提出者（2026-09-27）
- 落笔：Notes 三书（规划书 §8 / SRS §1.3）+ Notes 仓 `windows/` 目录说明 —— 由 macOS 侧（大河马）执行
