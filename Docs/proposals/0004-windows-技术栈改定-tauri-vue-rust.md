## 背景

2026-09-28 需求提出者给本侧**开工令**：三条线同栈 = **前端 Tauri 2 + Vue 3 + TypeScript、后端 Rust**，**原 .NET（C# / WPF / xUnit）路线作废**（随之作废「本机装 .NET SDK 8」的放行）。本侧已在**自己的独占节**落笔（`概要设计 §8.5.1`：技术栈表 / 换栈留痕 / 结构树；§8.5.6-3 改口径；§8.5.6-5 ⑦ 记拍板结果），并落地首片（`windows/Core`〔Rust〕+ `windows/Bench/grid`〔40 万行 × 20 列基准台〕+ 闸门第 12 项）。

契约层里仍写着旧栈，且与本侧新栈**字面冲突**（本侧按目录独占纪律**不改契约层**，故走本提案）：

1. `概要设计.md` §8.2 树：`├── Core/  # 领域层（C# / .NET 8；项目引用强制不得依赖 GUI）`、`├── App/  # 表示层（WPF）`、`├── Tests/  # 单测（xUnit）`；
2. `概要设计.md` §3 第 1 条（GUI 框架）：「另一平台（Windows）= **WPF**」；
3. `需求规范书.md` §10.9 的 `P-19` / `P-23` / `P-24` 行内含 WPF 专名（`P-24` 明写「WPF `Clipboard`…」）；
4. 更根本的一条：`需求规范书.md` §1.2-1 写「**原生体验**：使用各平台**原生界面栈** …… **无 JVM / 无 Electron**」、`产品能力规划说明书.md` **P6**「不为功能引入重量级运行时」。

## 提案

1. §8.2 树三处字样改为：`Core/`（领域层，**Rust**）· `App/`（表示层，**Tauri 2 + Vue 3 + TypeScript**）· `Cargo.toml`（Rust 工作区）· `Bench/`（基准台）；`Tests/` 行改为「**`cargo test` + `vitest`**」。
2. §3 GUI 框架行改为「Windows = **Tauri 2（系统 WebView2 外壳）+ Vue 3 + TypeScript**；后端 **Rust**」。
3. §10.9 的 `P-19` / `P-23` / `P-24` 去掉 WPF 专名，改成「Windows 宿主约定」这类**与实现无关**的措辞（**编号不变** —— 两侧对账判据 `Scripts/check-p-parity.py` 要求同号同物）。
4. **请契约侧明确「原生界面栈」的宽严**，二选一：
   - **(a) 宽读**（本侧倾向）：判断标准是「**不打包浏览器内核、不用 Electron / JVM**」⇒ 系统 WebView2 合规，与 P6「不为功能引入重量级运行时」一致。此读法下契约条文**不必改实质**，只需把三处 WPF 字样改成平台中立措辞。
   - **(b) 严读**：必须是**系统控件** ⇒ Tauri 不合规，需契约侧裁决后本侧改栈（代价见下）。

## 代价与替代方案

- **按 (a)**：代价最小 —— 三处字样改措辞；本侧首片（Rust 领域层 + 基准台 + 闸门）不回退。
- **按 (b)**：本侧改为 **WinUI 3 + .NET（或 WinUI 3 + Rust 核心）**，代价 = 表示层重做 + 分发需随附 Windows App SDK 运行时；Rust 核心与基准台可留。
- **被排除项**：**Electron**（P6 明禁、Linux 侧那条已作为发现上报）；**Avalonia**（Skia 自绘，严读下同样不满足「原生界面栈」，且绑定 .NET）。
