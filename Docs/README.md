# 文档（Docs）

> **给新接手者**：先读仓库根目录的 [`AGENT-SPEC.md`](../AGENT-SPEC.md)（角色 / 边界 / 纪律 / 命令集 / 常见坑），再回到本文件看三书怎么用。

本目录分两类：**三书（跨平台共享事实源）** 与 **产品文档**。其余工程内部文档
（调研、测试用例、兼容性矩阵、发布方案、评审与过程记录）保存在开发者本地，不随仓库发布。

## 三书：跨平台的共享事实源

**目标端（2026-09-26 口径）**：**macOS 与 Windows 版必须完全一致**（同一个产品的两个平台实现，
只有平台与编程语言不同）；**Linux = 自用第三端**（只服务需求提出者，由需求提出者手工带三书到本仓实现）；
**移动端不属本工程**（移动端 = Doyah Notes）。三书**必须入库**，用 GitHub 同步版本 ——
任何一侧改了契约，另一侧跟着改。

| 文档 | 定位 | 变更规则 |
|---|---|---|
| [Doyah产品需求规格说明书.md](Doyah产品需求规格说明书.md) | **做什么**：需求条目、验收标准、优先级、风险 | 契约（`【契约】`）改动需两侧同时确认；`【macOS】` 段只是实现记录 |

配套文件：

| 文件 | 说明 |
|---|---|
| [平台实现状态.json](平台实现状态.json) | 各平台实现状态的**唯一**登记处：`platforms.<名>.overrides`（编号 → 状态）；**macOS 不在台账里登记**（它是基线） |
| [平台对齐-Studio-Windows对macOS.md](平台对齐-Studio-Windows对macOS.md) | **Windows 侧对齐 macOS 的逐条派生索引**（编号 → 域 → 层次 → macOS 状态 → **macOS 落点（实现文件）** → Windows 现状）：`fatshark` 对齐开发进度时的查询入口；由 `Scripts/gen-studio-win-align.py` 产出、**勿手工编辑** |
| [任务清单-按平台.md](任务清单-按平台.md) | **按平台的完成度面**（项数 / ✅ / 🟡 / ⬜ / 完成度 + 逐域 × 逐端 + 本侧残项）：需求提出者问「各家到哪了」时的查询入口；**计数派生自 SRS §10.10**，由 `Scripts/check-board-parity.py` 逐列重算看守、**勿手工改计数** |

三书里的术语约定见 `Doyah产品需求规格说明书.md` §0.8：`【契约】` = 两侧必须一致，
`【macOS】` = 可替换的实现细节。需求书 §3/§4 的「状态」列是 **macOS 基线**，
其他平台（当前 Linux / Windows）的状态只在 `平台实现状态.json` 里记，避免同一件事有两个真相。

### 三书自动校验（与代码同一个验证闭环）

```bash
python3 Scripts/gen-platform-parity.py --check      # §10.10 等价矩阵与台账（Docs/平台实现状态.json）一致
python3 Scripts/gen-platform-parity.py --self-test  # 上一半自己的证据（11 例负例）
python3 Scripts/check-platform-neutrality.py        # 需求书里的平台专属词汇不得比基线更差
python3 Scripts/check-doc-tables.py                 # 表格列数与派生计数一致
python3 Scripts/check-doc-versions.py               # 变更记录版本号唯一 / 头部版本格可判 / 队列条目号唯一（L-32）
python3 Scripts/check-board-parity.py            # 《任务清单·按平台》的计数与 §10.10 逐列一致（判据从 §10.10 独立重算）
python3 Scripts/gen-studio-win-align.py --check # 上述「平台对齐件」与三书 §10.1/§10.2 + 平台实现状态.json 一致（闭环第 7 项）
```

七项都已挂进 `Scripts/verify-all.sh`（第 4 / 7 / 8 项），改完文档跑它即可。
