## 一、三条验收（Studio `FR-PLUG-05`）

| 编号 | 判据 | 怎么自测 | 通过标准 |
| --- | --- | --- | --- |
| ① | 数据落**本机 SQLite**，且在**独立数据家**（不写进工程数据家） | 找到笔记库文件，确认是 SQLite 且路径在笔记自己的数据目录下 | 库文件存在、可 `sqlite3 <库> .tables` 打开；路径不在工程/构建目录内 |
| ② | **进程内零网络出口**：笔记模块源码不引用任何网络 API | 在笔记模块源码目录内查网络 API：`grep -rn -E 'URLSession|NSURLConnection|requests\.|urllib|http\.client|OkHttp|Retrofit|fetch\(|net/http' <笔记模块目录>` | **0 命中** |
| ③ | **随包引入笔记模块**且在**活动栏有入口** | 启动应用，看活动栏/侧边栏是否有笔记入口；再从主程序模块确认对笔记模块有依赖引用 | 入口可见且能打开笔记列表 |

> 另外一条口径（写在端表里）：Linux 端应与 macOS **能力等价**（不是"能打开就算"）。

## 二、契约符合性（Notes，`C1~C13`）

本包带上了 `Notes/核心契约.md`。若环境里有 Python 3：

```bash
python3 Notes/tools/check_contract.py   # 若随包带；否则按 核心契约.md 逐条核对
```

逐条对照 `C1~C13` 自查，重点是：

- **数据模型 / 存储分层**：主存进库、附件与原始数据留文件系统（库里只存路径）
- **导入导出格式**：与契约里定义的字段、时间格式、编码一致
- **离线口径**：无网络出口、备份只走文件复制（`VACUUM INTO` 快照）
- **外部来源入口唯一**：负载只从约定的单一入口进（不得各处自己解析）
