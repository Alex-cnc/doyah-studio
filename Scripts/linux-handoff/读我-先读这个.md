# 读我 · 先读这个（Linux 侧交接包）

本包 = **Doyah Studio / Doyah Notes 的「三书」快照 + 验收自检清单**。
用途：在公司的 Linux 环境里实现这两个产品的 **Linux 端**，**不需要**任何账号、凭据或网络。

## 一、边界（先看这段，能省很多返工）

| 事项 | 谁负责 |
| --- | --- |
| **三书**（功能规划 / 需求规格 / 概要设计） | 家族侧（macOS 侧助理「大河马」）维护并定稿，**Linux 端只读** |
| **契约层**（概要设计里**没有** `[独占:*]` 标记的节） | **不可改** —— 架构骨架、数据契约、接口不变量都在这里；Linux 端必须实现它 |
| **平台设计层**（概要设计里 `[独占:linux]` 之类的节、以及本包之外的实现细节） | **Linux 侧自由决定**：技术栈、打包、界面细节 |
| **验收口径** | 家族侧定义（见「自检清单」），Linux 侧照做即可 |
| **Doyah Retro** | **与 Linux 无关**（该产品不做出 Linux 端） |

## 三、两条硬要求（Linux 端特有）

1. **本地离线实现**：数据只落**本机 SQLite**（在独立数据家，不写进工程数据家）；**进程内零网络出口** —— 不同步、不遥测、不调用任何云端服务。
2. **随包引入笔记模块**且**在活动栏有入口**。

## 五、你的设计落在哪（回传格式）

Linux 侧的平台设计层有**固定落点**，不需要另起文档：

| 写什么 | 落在哪 |
| --- | --- |
| Studio 的 Linux 平台层（技术栈 / 构建打包 / 桌面集成 / 契约对应表 / 自检输出） | `Studio/概要设计.md` → **§8.6 契约 → Linux 实现 `[独占:linux]`** |
| Notes 的 Linux 平台层（同上 + 与 `C1~C13` 的对应） | `Notes/概要设计.md` → **§2.3 契约 → Linux 实现 `[独占:linux]`** |

写好后**整段回传**（贴回来即可，也可以直接改本包中的对应节），由家族侧贴入正式三书。
`[独占:linux]` 的意思是：**这两节只有 Linux 侧的内容进得去**，我们两侧不会去动它。

## 四、回传后我们会怎么做（透明起见）

你回传的 Linux 平台层内容贴入 `[独占:linux]` 节后，家族侧会做两件收尾：① 删除该节的**首建豁免行**（`exclusive-allow-section`），使这一节恢复"只有 Linux 侧内容进得去"的严格判定；② 追加一条变更记录。也就是说：**你写的东西会被锁起来保护，不会被我们顺手改掉。**

## 四、怎么更新

三书会继续维护。更新方式 = **人工替换本包**（公司电脑上不配置任何个人 GitHub 凭据，也无自动拉取）。
拿到新版后，对比本包内 `版本与快照日期` 即可确认。
