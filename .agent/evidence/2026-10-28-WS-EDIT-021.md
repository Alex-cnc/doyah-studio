# R39 · 2026-10-28 · `FR-STD-WS-EDIT-021` 自动缩进与智能粘贴

## 需求（《需求规格说明书》§3.3 那一行，逐字）

> **自动缩进与智能粘贴**：回车时**继承上一行缩进**；`{` / `(` / `[` 之后回车**多一级**、`}` 单独一行**回退一级**；
> **粘贴多行文本**时按上下文重排缩进（不把外来的缩进硬塞进来）
> 判据：① 回车继承上一行缩进；② { ( [ 之后回车多一级；③ } 单独成行回退一级；
> ④ 粘贴多行文本按上下文重排缩进，不把外来缩进硬塞进来 —— 不是「全自动排版」，只做局部、可预测的辅助。

## 落法（判定全在 Core，界面只搬计划）

`Core/AutoIndent.swift`：

- `AutoIndentPlan`（`range` / `replacement` / `caret`）—— 一次整块替换 = 一步 ⌘Z（与 `LineMovePlan` / `MarkdownEditPlan` 同口径）；
- `AutoIndent.newline(in:selection:)`
  - ① 缩进 = **当前行的实际前导空白**（`\t` 与不规则缩进原样带走，不按层级重算）；
  - ② 光标紧前一字符是 `{` `(` `[` ⇒ 再 +一级；
  - ③ 当前行**第一个非空白字符**是 `} ) ]` ⇒ 先 −一级（减到 0 为止，不出现负缩进）；②③ 同时成立时先退再进（`} else {` 回到本行那一级）；
  - ④ 行终止符 = 当前行自己的（末行没有终止符时退到文档第一个终止符）⇒ `\r\n` 文档里不插裸 `\n`；
  - ⑤ 光标正夹在一对**真成对**的括号中间（`{|}`）⇒ 把闭合符挪到下一行、新行落内层（`[}` 这种错对不拆）；
  - ⑥ **不动**四种：有选区 / 光标后面还有正文 / 顶格且无级可继承 / 空文档 ⇒ `nil`（交还系统默认回车）；
- `AutoIndent.paste(_:into:selection:)`
  - 多行：剥掉外来块**自己的公共缩进**，再接**上下文那一级**；**首行不加上下文缩进**（光标前那段文本已经在提供它，否则在缩进过的空行上叠成双倍）；
  - 空白行保持空白（不留尾随空格）；外来行尾归一到文档行尾；
  - 单行 / 空块 / 顶格粘顶格 ⇒ `nil`（不把默认粘贴换成自己那一份）。

界面接线（两个编辑面，同一个动作同一份判定）：`App/Views/CodeEditorView.swift` 的 `insertNewline` + `paste` → `applyEditPlan`；
`App/Views/SQLEditorView.swift` 的 `insertNewline`（单光标分支）+ `paste` → `applyAutoIndentPlan`。

## 口径取舍（留由头，别下一轮再纠结）

1. **一级 = 4 空格**，取 `CodeBuiltinFormatter.indentUnit`（内置格式化器同一份）；本批不读用户设置、也不做软硬 tab 检测（那是 `FR-STD-WS-EDIT-022`）。
2. **粘贴首行不加前缀**：把「上下文缩进」只施加在第二行起 —— 光标前那段文本本身就是第一行的上下文。第一版按「每行都加」写，在缩进过的空行上粘 8 空格块会叠成 12 空格（判据当场抓出，未进仓库）。
3. **闭合行在顶格时返回 `nil`**：结果与系统默认回车逐字相同，没必要多一条自造路径（判据钉的就是 `nil`）。
4. **不吞按键**：所有「不适用」都返回 `nil` 交还系统 —— 吞掉按键却什么都不做是本族最难查的失效形态（与 `⌘L` / `⌥↑` 同一教训）。
5. **两个编辑面同批接线**：只接工作区会留下「同一个动作在 SQL 编辑器里表现不同」的第二处不一致。
