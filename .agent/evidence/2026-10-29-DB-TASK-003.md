## 1. 需求与缺口

需求书 `FR-STD-DB-TASK-003`：「记录成功 / 失败、影响行数、耗时、错误原文与执行时刻，挂在会话上可作为审计依据；
回执不含口令与敏感字面量。」验收三条：① 含四项读数与执行时刻；② 可复制 / 导出且已脱敏；③ 失败也有回执（不因报错丢失）。
否定面：**不把「完成」当回执**。

缺口（动手前实测）：本侧只有 Output 日志（`QueryTab.outputLog`），它**每次执行清空重来**（2026-09-27 需求提出者原话），
回答「这一跑中间发生了什么」；审计要的四项读数与执行时刻**没有任何一处**留着 —— 查询归档（`Core/SQLArchive`）按天存
「同一条 SQL 的累计」，也没有逐跑回执，更没有「被拦下」这一类。

## 2. 落法（`Core/ExecutionReceipt.swift`）

| 件 | 口径 |
|---|---|
| `ExecutionOutcome` | 四档：`succeeded` / `failed` / `cancelled` / `refused`。取消不许记成成功（R-31）；「被拦下」（一条语句都没发）与「执行失败」分开。 |
| `affectedRows: Int?` | `nil` = 这一跑没报过行数 ⇒ 渲染「未测到」；与「动了 0 行」分开读。 |
| `ResultReading` | 结果集个数 / 行数之和 / 最宽列数 / 被截断的结果集个数。 |
| `SensitiveTextRedactor` | 四类形状：口令子句（`PASSWORD '…'` / `IDENTIFIED BY '…'` / `TOKEN = '…'`）· 等号冒号式（`password=…`）· 命令行开关（`--password …`）· 连接串 userinfo（`scheme://user:…@host`）。抹成 `***` 并记账（几处、哪一类）。文本幂等。 |
| `init` | **脱敏在这里做**：原文根本不进结构；`init(from:)` 走同一个入口（外部文件读回来仍只有抹过的形态）。 |
| `render(labels:)` | 可复制的一段文本；文案由界面从语言表传进来（Core 不留面向用户的字面量）。 |
| `exportData()` | 确定性 JSON（sortedKeys + prettyPrinted + ISO8601）。 |
| `ExecutionReceiptLog` | 挂在查询页签上，满 200 条丢最旧；`exportText` / `exportData` / `removeAll`。 |

接线：`QueryTab.receiptLog` + `AppState.recordReceipt`（唯一写入口）接六处出口（成功 / 失败 / 取消 / 只读连接拦下 /
任务定义拦下 / 事务态拦下；BEGIN 失败记 `failed`）；下方面板新增「回执」页（`LowerPaneTab.receipts` 排在「变更」与
「历史」之间 + `App/Views/ExecutionReceiptPane.swift`）；语言表 35 键中英齐；`clearLowerPaneLog` 明确**不吃**这枚 trash
（清日志不许顺手抹审计读数）。
