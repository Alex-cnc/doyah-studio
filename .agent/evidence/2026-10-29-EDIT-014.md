# 2026-10-29 · `FR-STD-WS-EDIT-014` 撤销语义粒度（第六十五批）

## 需求三条验收

1. 一段连续输入合并为一次撤销（逐字符输入后一次撤销回到输入前）；
2. 移行 / 注释切换 / 补全各算一步；
3. `FR-STD-WS-EDIT-007` 那类**等长替换**不顶掉选区与光标。

## 本轮之前的状态

- 撤销**完全靠 `NSTextView` 默认行为**：`grep -rn "undoManager|breakUndoCoalescing" Core App` 只命中
  `App/Views/SQLEditorView.swift` 的 `removeAllActions()` 与两处 `allowsUndo = true`；
- 编辑菜单那一行永远是通用「撤销」（没有任何 `setActionName`），**用户看不出这一步是什么**；
- `applyEditPlan` 无条件把选区改成计划里的落点 ⇒ 「等长替换不动光标」没有任何机制保障；
- 文本落地口散在 9 处（工作区 4 / SQL 5），谁都能自己写一句 `didChangeText()`。

**为什么不 `beginUndoGrouping` / `endUndoGrouping`**（探针实测）：空分组会在管理器里留一层废步 ——
`groupingLevel` 停在 1、`canUndo` 变真、按一次 ⌘Z 什么都不发生；而「这次动作会不会落地」开组时无法预判。
本仓的落地口径是「一次用户动作 = 一次 `shouldChangeText → replaceCharacters → didChangeText`」，
一次登记天然一步，只在边界断开即可（该口径由源树判据钉住）。

## 探针（无事件流下的真实读数，决定了「哪一半只能人工验」）

```text
PROBE undoManager(a) = Optional(NSUndoManager<0x…>)
PROBE A ungrouped depth = 1 text=          # 三次不分组替换
PROBE B grouped depth = 1 text=            # 三次替换包在一个 undo group 里
PROBE C break-between depth = 1 text=      # 打字 → breakUndoCoalescing → 打字
PROBE D actionName = Optional("移动行")     # setActionName 生效
PROBE2 level after edit = Optional(1)
PROBE2 name after setActionName(no group) = Optional("移动行")   # 不显式开组也能命名
PROBE2 empty group: level=Optional(1) canUndo=Optional(true)     # ⚠️ 空分组留下废步
```

⇒ 撤销**层数**在探针里恒为 1（分组与不分组一样）⇒ ① 这一条**判不了**，只能人工按 ⌘Z 点验；
实现列因此保持 🟡。可机械判的是「在哪断开」（纯函数）与「这一步叫什么」（真 `NSTextView` 上的
`undoActionName`）。

## 仍差（人工点验，不是实现缺口）

1. 连打一行字，按一次 ⌘Z 应整段回到输入前（不逐字符）；
2. 移行 / 注释切换 / 补全各按一次 ⌘Z 只回退那一步，再按一次不许只退一半；
3. 编辑菜单那一行应读得出「撤销 移动行」而不是光秃秃「撤销」；
4. Markdown 任务行上按 ⌘L，光标与选区不许跳。
