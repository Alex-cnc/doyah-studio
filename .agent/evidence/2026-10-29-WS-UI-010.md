## 1. 缺口（都是实测出来的，不是读代码猜的）

量法：`WorkspaceTabStrip` 挂进离屏 `NSWindow`（宽度确定）→ `layoutIfNeeded()` → 跑 0.25s
runloop（SwiftUI 布局下一跳才落；不跑拿到的是 0×0 退化帧，实测过）→ 找横向 `NSScrollView`
读 clip 宽 / documentView 宽 / `hasHorizontalScroller`。

**基线（R46 代码）读数**，420pt 窗口：

```text
tabs=2  clip=134.0  doc=215.0x22.0  hasH=false
tabs=5  clip=134.0  doc=629.5x22.0  hasH=false
tabs=11 clip=134.0  doc=1467.0x22.0 hasH=false
```

1. `hasH == false` ⇒ 需求 ③「溢出时横向滚动条出现」**不成立**（只能靠触控板横滑，看不见「有得滑」）。
2. 页签区只拿到 134pt 而可用是 146pt —— `Spacer(minLength: Spacing.s)` 与滚动容器同为可伸缩者，白占 12pt（等于少露半个页签）。
3. 判据侧：11 个页签的「高度不变 / 不换行 / 内容不被压扁」没有任何人量。

## 2. 落法（两处产品改动 + 一个新判据文件）

产品（`App/Views/WorkspaceTabStrip.swift`）：

- `ScrollView(.horizontal, showsIndicators: true)` —— 溢出时滚动条开着（需求 ③）；
- 删掉页签区与右侧固定件之间的 `Spacer(minLength: Spacing.s)` —— 页签区吃满可用宽度；
- 文档注释补上宽度那半边的两条不变量（唯一出处）；
- **没有**写 `.frame(maxWidth: .infinity)`：反例注入证明它在当前形状下**一个像素都不改变**
  （量出来 146/366/626/1166 与不写时逐值相同）⇒ 不写这句「看着像机制」的话。

判据（新 `TestsUISnapshot/WorkspaceTabStripOverflowProbeTests.swift`，**7 例**，都在 `verify-core` 里跑，
不挂 `DOYAH_UI_SNAPSHOT` —— 它不渲染位图，只量几何）：

| 例 | 判什么 | 判据本体 |
| --- | --- | --- |
| `testTabAreaAbsorbsWindowGrowthRegardlessOfTabCount` | ② | 窗口加宽 1020pt ⇒ 页签区加宽 1020±1；2/5/11 个页签同宽；行宽 − 页签区 ≤ 276（= 右侧固定件实测 274 + 2） |

## 5. 口径取舍（写清，免得下一轮重新开始）

1. **实现标 `✅` 而不是 `🟡`**：需求书给的三条验收全是**可量**的（±1pt 同高 / 2→10 高度不变 / 溢出时滚动条出现且不换行），
   本轮把它们全部量到了真布局上。观感（滚动条外观、页签间距好不好看）**不在这条验收里**，所以不构成「只能人判」的半边；
   这与本系列其它片为了「点一次」留 🟡 的做法不同，理由如上。
2. **量法只此一条**：`sizeThatFits` 只说「这一行要多高」，量不出页签区宽 / 内容有没有被压扁 / 滚动条在不在 ⇒
   必须离屏窗口 + runloop + 读 `NSScrollView`。别为了省事退回 `sizeThatFits`（它会静默给出「看起来合理」的假值）。
3. **`maximumTrailingOccupancy = 276`** 是「右侧固定件宽度」的实测口径（274 + 2 余量）。**往页签条右侧再加一枚按钮，
   把这里一起改** —— 那条断言量的就是「页签区是唯一伸缩者」这件事；不改就会红，这是有意的。
4. **没写 `.frame(maxWidth: .infinity)`**：反例注入证明它在当前形状下是 no-op。写一句「看着像机制」的话比不写更坏
   （下一个人会以为拆了它才出问题）。
5. **`ScrollView` 里没加 `.fixedSize`**：横向 `ScrollView` 本来就不压缩子视图（11 个页签的内容宽 1625pt 与窗口宽度无关），
   加了反而多一处要维护的口径。

## 6. 未覆盖 / 边界（如实登记，别当已验）
