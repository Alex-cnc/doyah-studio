# R70 · `FR-STD-DB-IO-002` 整库导出接线 + 修掉一处入口接错渲染器（2026-10-29 第七十一批）

## 取活

每轮卡的下一条活（R69 收尾时写下）：① 整库导出的界面入口。做的时候先撞到一个更严重的问题：
**上一批的「导出整表…」只加进了 SwiftUI 那份菜单渲染（`App/Views/ObjectTreeContextMenu.swift`），
而生产右键走的是 AppKit 那份（`App/Views/ObjectTreeAppKitMenu.swift`，`ObjectTreeRightClick.swift::menu(for:)` 现建 `NSMenu`）**
⇒ 上一批交付的入口用户其实点不到。证据：`grep -rn "ObjectTreeContextMenu\." App/` 在 `App/` 下**零命中**（只有探针在用它），
而 `ObjectTreeView.swift:140` 的 `makeMenu` 交给 `ObjectTreeAppKitMenu.build`。

为什么上一批的探针没红：`ObjectTreeContextMenuProbeTests` 的两套菜单对账只比**动作项**（`ObjectTreeAction.allCases` 过滤
`ObjectTreeActions.isAvailable`），导出入口不在 `ObjectTreeAction` 里 ⇒ 两套菜单各缺一项也不判红。

## 本批做了什么

1. **生产菜单补上「导出整表…」**（`App/Views/ObjectTreeAppKitMenu.swift`）：新增
   `exportFormats`（五档文本格式，唯一出处）+ `exportMenuItem(title:action:)` + `exportFormatTitle(_:)`；
   SwiftUI 那份（`ObjectTreeContextMenu.swift`）改成遍历同一份 `exportFormats`，不再各写五个按钮
   （两处各写一份清单 = 上一批那种错法的温床）。
2. **整库导出接线**：
   - `Core/TableExport.swift`：`Candidate` / `Job` / `Skipped` / `DatabasePlan` + `databasePlan(_:format:)`
     —— 只导表与视图、其余跳过并报数、同一 `(schema, table)` 只导一次、跨 schema 时文件名与账里的称呼都带前缀、
     净化与撞名顺延走与整表导出**同一条** `uniqueFileName`（新抽的私有函数，`entries` 也改用它）。
   - `App/AppState.swift`：把「一张表 → 一个文件」的取数写盘循环从 `exportTable` 抽成 `streamTable`
     （整表与整库共用一处，空表 / 取到一半失败的口径因此必然一致）；新增 `exportDatabase(_:format:)`
     （选目录 → 逐张调 `streamTable` → 逐表记 `Ledger` → 小结 = 逐表「行数 → 路径」+ 合计 + 跳过数）与
     `exportCandidates(for:)`（用与树同一个 `loadMetadataChildren`，schema 节点再展开一层）。
   - 右键数据库 / schema →「导出整库…」五档（两套渲染都挂），复用同一块 `TableExportSheet`。
3. **语言表** +6 键（`treeActionExportDatabase` / `tableExportDatabaseTitle` / `tableExportDatabaseRunning` /
   `tableExportChooseFolder` / `tableExportNoTables` / `tableExportSkipped`），中英齐。
4. **判据**：`Tests/TableExportTests` +7 例（15 → 22）；`TestsUISnapshot/ObjectTreeContextMenuProbeTests`
   新增 `testProductionMenuCarriesExportEntries`（直接构造**生产那份 NSMenu**，不渲染、不需要快照模式）。
