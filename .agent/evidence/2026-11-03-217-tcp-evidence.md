# 2026-11-03 · 217 可达性证据换成判得住的那种 + 派生件的 `next_try` 不许覆盖规则表

条目：**无台账行**（修的是卡点证据的判据口径与派生件取词方向，不改任何需求状态）。

由来：开轮按 skill `doyah-real-db-verification` §「连不上时先分诊」复核 217，发现台账 §4.2 两格与
`.agent/plan.yaml` 三处 `next_try` 都把不可达的证据写成「**217 ping 全丢**」——而该 skill 明写
`ping` / `nc` / `arp` 在这个 shell 里**会假阴性**、可达性只认 Python TCP 握手（并记着实测：三项全红
的同一时刻 socket 0.01 s 连上、真库判据 5/5 通过）。即：卡点理由用的是**判不住的证据**。

⇒ 结论仍是「217 不可达（🟡 保持）」，但理由从「ping 丢包」换成**判得住的那条**：
同一网段 / 直连路由在 / 网关 0.00 s 可连 / 目标主机 `EHOSTDOWN` + ARP 无条目 ⇒ **是那台机器没开**，
不是网段、不是防火墙、不是凭据。

1. 台账 §4.2 v0.3.0 / v0.9.0 两格「217 ping 全丢」→ TCP 复测证据（状态符号一字未动）。

   `NFR-ALL-GATE-PERF-004`）同批改写。

   `blocked.update(read_blocked())` —— 上一次 `plan.yaml` 盖掉本版规则表，于是**规则表改了、
   `--emit-plan` 重出仍是旧话**（派生件成了第二事实源，正是本片这三处旧话的成因）。
   现在规则表优先，并把 `BLOCKED_V050/V060/V070` 合成 `ALL_BLOCKED`（旧 → 新，同 id 新表为准）
