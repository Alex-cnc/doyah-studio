# R54 · `FR-STD-WS-EDIT-022` 缩进检测与状态栏切换

日期：2026-10-29 · 轮次：R54 · 证据人：自主开发循环（macOS 端）

## 做了什么

- `Core/IndentProfile.swift`（新）：按**内容**判软 / 硬 tab 与宽度（不看扩展名、不看语言、不看时钟）。
  - 证据行 = 非空且有前导空白的行（只有空白的行不算）；证据不足两行 ⇒ `origin == .fallback`。
  - 软 / 硬取多数派，并列取空格；混用时 `conflictingLines` = 少数派行数。
  - 宽度 = 相邻行**增量众数**（含「顶格 → 缩进」那一步）；并列取能整除其余候选的那个，谁也整除不了取小的一档；
    没有增量才退回绝对缩进的**最小公分母**，公分母 1（对不齐）⇒ 缺省 4；硬 tab 的宽度不可从内容推出 ⇒ 缺省 4。
  - `choosing(...)` 记 `chosen`；`adopting(_:)` 不覆盖 `chosen`。
- `Core/WorkspaceTab.swift`：`WorkspaceTab.indent` 一格；`WorkspaceTab.file(...)` 打开即 `IndentProfile.detect(in: content)`。
- `Core/WorkspaceSession.swift`：会话恢复出来的页签同样按内容算（否则重启后「缺省」与正文相抵）。
- `App/WorkspaceTabsModel.swift`：`indentProfile(for:)` / `chooseIndent(tabID:style:width:)` / `redetectIndent(tabID:)`。
- `App/Views/CodeEditorView.swift`：`CodeTextView.insertTab` 按口径插单位（灰字优先那条路保留）；回车与粘贴把 `indentUnit`
  传给 `AutoIndent`；`applyIndent(_:forceRelayout:)` 设制表位（宽度 × 空格宽度），换字体重算。
- `App/Views/WorkspaceAreaView.swift`：提示条右侧「空格 · N / 制表符 · N」菜单（空格 / 制表符 · 2/3/4/8 · 按内容重新判定），
  状态行那句「按内容判定 / 已手动设置 / 内容里没有缩进证据」，混用行数与来源如实标注。
- `Core/Localization.swift`：11 个键（中英齐）。
- `Tests/IndentProfileTests.swift`（新）：**25 例**。

## 开发期被自己判据抓出的四处真错（留档）

1. 证据行数写错（把闭合行的缩进漏算）；
2. 「绝对缩进公分母」把 `1` 当成合法宽度（缩进对不齐时给出「一格一级」）；
3. 增量流只数「有缩进的行」⇒ 顶格 → 缩进那一步没进直方图，一份 4 空格文件被读成 8（**这条最像「看起来对」**）；
4. 打开文件那条判据喂了只有一行缩进的内容 ⇒ 走 `fallback`，判据自己暴露了「证据不足两行」这个口径没被覆盖。
