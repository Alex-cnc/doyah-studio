# 循环规约（v0.3.0 数据库运维面）

**队列**：`.agent/plan.yaml`（派生草稿）；**唯一事实源** = `Docs/Doyah产品开发计划任务清单-macOS.md`。

## 一跳（tick）的唯一形状

1. 读 `.agent/plan.yaml` + `.agent/checkpoint.md`；
2. `next` = 第一个 `status: todo` 的项（只认领一项）；
3. 只做这一项的最小一片（十几分钟到一小时）；
4. 跑它的 `done_when` 拿读数（`python3 Scripts/ledger-row.py <ID> | grep -q '✅'`）；
5. 落盘：台账那一行翻 ✅ + 写 `.agent/evidence/<日期>-<ID>.md`（命令原文 + 读数尾部 + 提交号）+ `git commit`；
6. 更新 `checkpoint.md` 的「下一项」；回第 1 步。

## 四出口（除此之外不许结束一跳）

1. 没有 `todo` 项 ⇒ 全部完成，写收口；
2. 只剩 `blocked` 且无替代 ⇒ 阻塞退出，写清停在哪、需要什么；
3. 预算耗尽 ⇒ 写检查点，**必须写明下一项 id**；
4. 只有三类允许提问：判据互斥 / 需要授权（越权·花钱·删数据·外发）/ 判据不可判且盘上无可推默认值。

其余一切自行决定，写 `decisions.md` 一行，继续。

## 判据纪律

- 完成 = 跑命令拿到期望读数；模型自述、截图「看起来对」、空壳探针都不算。
- 新判据要验反例（改坏一处 ⇒ 判红 ⇒ 还原复绿），三段读数进证据文件。
- 实现列与判据列分开翻；界面点不到的，判据可以 ✅、实现留 🟡 并写清差哪个入口。
- 台账行翻 ✅ 必须同时有：可跑的用例/探针 + 实测读数；**跳过不算通过**。
- 改测试条数要同批同步 `Scripts/doc-numbers.json` 与文档里的现状数字。

## 每项收尾

- 一项一片提交，信息写「做了什么 + 判据读数」；推前 `git fetch && git rebase`（同仓常有别的写者）。
- 汇报只给：已完成读数 + 下一项 id。**不写「要不要继续」**。
